# ホロドリ編成お助けツール（HolodoriOptimizer）

『hololive Dreams』（ホロドリ）のユニット編成を比較する**非公式ファンツール**です。所持カード、開花、ホロメンボード、固定メンバー、曲などを指定し、ユニットスコアの**試算値**が高い編成を探索します。

**[ホロドリ編成お助けツールを開く](https://hoshock.github.io/HolodoriOptimizer/)**

使い方と計算の説明: [編成シミュレーターの使い方](https://hoshock.github.io/HolodoriOptimizer/guides/simulator/) / [ユニットスコア計算と内訳](https://hoshock.github.io/HolodoriOptimizer/guides/unit-score/)

> **免責**: 本ツールはファンによる非公式ツールであり、カバー株式会社・株式会社 QualiArts とは関係ありません。ゲーム内の名称等の権利は各権利者に帰属します。表示するスコアは試算値で、ゲーム内の値と一致することを保証しません。実際に楽曲をプレイしたときのライブスコアを計算するツールではありません。

## 主な機能

- ★5 カード・楽曲・スキルのテキストデータ
- リーダー + メンバー 5 人の編成探索（リーダーはカード、またはホロメンで指定。ホロメン指定はそのホロメンの全カードからおまかせ）
- 所持カードと開花段階の登録
- 赤・青・黄・緑ホロメンボードの登録（ホロメンランクを登録すると、そのランクまでのボードPt の範囲でだけ解放できます。未登録は制限なし。コネクトマスは 1 Pt で明示的に解放します）
- メモリー効果・メンバー強化ボーナスの登録
- 余っているキューブ・コアキューブの色ごとの登録（アカウントの「リソース」。未登録は ∞。使うのは「育成すると」と「育成プラン」だけで、手動でボードを開ける操作は個数に左右されません）
- 曲条件を含めた表示ユニットスコアの試算
- お気に入り編成の保存（所持カードで組んだ編成のみ。番号 1〜10 は詰めて使います）
- さがすオプション（いまの育成で / 育てきったら / 全カード・リーダー / メンバーの除外・選択）の保存（設定の「オプションの保持」で OFF にできる。リーダー・メンバー・曲は保存しません）
- 育成の前提の切り替え（いまの育成で = 登録している開花とボード / 育てきったら = 開花最大・ボード全解放 / 全カード。コネクトは常にボードで置いたものを使います。アカウントの入口には未登録のものだけ「未登録」と出ます）
- 結果の「いまのまま / 育成すると」のタブ（育成すると: 結果が出たら裏で、ボードを開け直すと伸びそうな編成を見込みで選び、探索の上位 30 件と合わせて最適化。計算中はタブの中に進み具合、終わると育成したあとのユニットスコアの順に並ぶ。探索の結果にない編成も出ます。ボード未登録では使えません）
- 結果詳細の「育成プラン」: この編成のまま、ホロメンランクのボードPt・所持リソース・持っているコネクト（アカウントの「コネクト」で形・％・枚数を登録）の範囲で、ボード → コネクト → 発動頻度のうち選んだものを最適化して反映（頻度は理論値重視・期待値重視・ユニットスコア重視。所持リソースは余りに加えてこの編成に効かないマスの分まで使い（外して回す）、考慮を外すこともできます。足りないぶんはマイナスで残ります。ほかのホロメンのボードとコネクトも変えるかを選べます。近似で、最大を保証しません。「いまの育成で」探した結果でだけ使えます）
- 結果の共有（共有シート / X の投稿画面 / テキストのコピー）
- ライト / ダーク表示

保存データはブラウザ内に置き、サーバーへ送信しません。

## 試算モデルの現在地

ユニット編成画面の総合力は、ゲーム内の 6 項目を別々に計算して加算するモデルです。表示ユニットスコアは、実機観測から次の式が 1 点単位で一致しています。

```txt
ユニットスコア = ceil(総合力 × (1 + スコアボーナス / 100) × 2.03734)
```

一方、スコアボーナスの内部式は完全には解明できていません。

- アクティブ欄: 200 秒の共通タイムラインを使うモデルが実測に非常によく一致
- 黄ボード: 曲のボーナスがどのカテゴリへ入るかは実機で確認済み
- 青ボード、衣装・パッシブ・赤ボードのスコアサポート: 合計への効きと、5 欄への按分のしかたは 2026-09-13 にモデル化し、衣装 / ボード / パッシブの誤差は実測 51 件で最大 0.4 ポイントです（`docs/human/display-score.md`）
- SP 欄: 2026-09-13 に閉じた形が決まり、カードデータに記録のある実機 23 編成で誤差 0 です（2026-09-15 に恒常 0凸 の実機値が入って 3 編成増えました）
- 青ボードの重み: 2026-09-13 に「青は実効スコアサポート % として配分に効く」形へ替え、衣装 / ボード欄の最大誤差が 0.8 → 0.4 pt になりました（確定ではなく現時点の最有力です）
- 衣装欄の 0.1% 量子化: 2026-09-15 に「アクティブ欄との差として切る」形へ絞れました（実装はまだ差し替えていません）
- 残る未解明は、青の重みの発動頻度側の正規化と、衣装 / ボード / パッシブへ按分するときの**メンバーごとの重み**の 2 件です

現在の確定事項・棄却済み仮説・実測コーパスは [表示ユニットスコアの逆解析](docs/human/display-score.md) を参照してください。

## ゲームデータと権利

公式画像・音声・映像などのアセットは収録せず、テキスト情報だけを管理します。方針は [権利ポリシー](docs/human/rights-policy.md) と [ADR-002](docs/adr/002-game-data-text-only-hand-entered.md) にあります。

## 開発

```bash
pnpm install
pnpm dev
pnpm check
pnpm test
pnpm build
```

ドキュメントの入口は [docs/index.md](docs/index.md) です。ゲーム仕様は [docs/human/game-spec.md](docs/human/game-spec.md)、再現用の実測値は [docs/human/repro/](docs/human/repro/) に分離しています。
