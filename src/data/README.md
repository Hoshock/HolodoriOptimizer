# ゲームデータ

『hololive Dreams』の★5 カード・楽曲・所属・ホロメンのデータセット。**テキスト情報のみ**を持ち、画像・音声等の公式アセットは一切含めない（[ADR-002](../../docs/adr/002-game-data-text-only-hand-entered.md)）。

| ファイル            | 内容                                                                                                   |
| :------------------ | :----------------------------------------------------------------------------------------------------- |
| `types.ts`          | スキーマ定義（スキルは構造化表現 + 原文 raw の二重持ち）                                               |
| `affiliations.json` | 所属（世代・ユニット）                                                                                 |
| `holomen.json`      | ホロメン（タレント）と所属の対応、名前の読み、ボード配置                                               |
| `cards.json`        | ★5 メンバーカード（読み・パラメータ・4 系統スキル）                                                    |
| `songs.json`        | 楽曲（アーティスト・演奏時間・難易度別レベル・コンボ数）                                               |
| `events.json`       | イベント（開催期間・獲得ボーナスの対象カードとホロメン・課題曲のスコアボーナス対象カード・チャプター） |
| `events.ts`         | イベントの補助（共通の開花ボーナス表・開催中のイベントとチャプターの解決）                             |
| `meta.json`         | 出典・確認日・検証状態の注記                                                                           |
| `validate.ts`       | 整合性検査と構造化率の算出（`dataset.test.ts` / `events.test.ts` から実行）                            |

## 更新の約束事

- 値の出典はゲーム内表示または公開情報のみ。**推測で埋めない**。ソースにない値は `null` / 省略（楽曲のコンボ数が確認できない難易度は `combo: null`）。楽曲の並びはゲーム内配信順で、新曲は末尾に `song-NNN` を連番で追加する。
- スキルの `raw` にはゲーム内の説明テキストを原文のまま入れ、`structured` は確実に解釈できる場合のみ設定する。**衣装・パッシブは全カード構造化済み（2026-08-31）で、テストが 100% を強制する** — 新規カードは構造化まで済ませてから追加する（解釈に迷う原文は先にスキーマ拡張を検討する）。
- スキル本体の `raw` / `structured` と `stats` は**開花（凸）最大時**の内容とみなす（2026-09-01 ユーザー確認）。開花段階で文言が変わるスキルは `bloomVariants` に**確認できた段階だけ**を昇順で持つ（構造化必須・推測で埋めない）。未確認の段階は仮定倍率による割り戻しで試算される — 段階仕様と仮定値は `src/data/bloom.ts`（1凸=アクティブ / 2凸=パラメータ / 3凸=SP / 4凸=パッシブが強化。パラメータの 2凸 +10% は実測で確定、スキルの実数値は非公開のため ×1.1 と仮定）。2026-09-08 に実機で確認した 5 枚（usada-pekora-01 1凸 / inugami-korone-02 2凸 / shirakami-fubuki-02 0凸 / ookami-mio-02 1凸 のパッシブ・SP・アクティブ）は `bloomVariants` に記録済みで、`raw` は開花最大の文言の数値だけを実機の値に置き換えた表記。
- **アクティブの追加条件と SP の発動率 UP は構造化する（2026-09-08）**: 「ピュアタイプが 2 人以上でスコアが 120%UP」のような追加条件は `active.structured.conditionalScoreUp`（`condition` は編成条件 / ライフ / コンボの `SkillTrigger`、`percent` は条件成立時のスコア UP）、「◯◯が 2 人以上でスキル発動率が 50%UP」は `special.structured.skillRateUp` に持つ。`extraCondition` / `extra` の原文がある限り対応する構造化フィールドを `validate.ts` が必須にする。表示スコアボーナス（`src/engine/displayScore.ts`）はライフ・コンボ条件を成立扱い、編成条件は判定する。
- **公開済みのカード・ホロメン ID は不変。** ユーザーのブラウザ（localStorage）に所持カード等の登録がこの ID で保存されているため、削除・改名すると登録が消える。全 ID は `published-ids.json` に凍結し、`dataset.test.ts` が削除・改名と追記漏れを検知する。新規カード・ホロメンを追加したら `published-ids.json` にも追記する。表記を直したい ID があっても改名しない（必要なら保存層 `src/storage/` で別名対応する）。（2026-09-02 ユーザー指示）
- **所属の改名（2026-09-08 ユーザー共有）**: ID1期生 → AREA15、ID2期生 → holoro、ID3期生 → holoh3ro。表示名（`affiliations.json` の `name`）・カードのスキル文言・楽曲のアーティスト表記・所属対応表を新名称にした。ID（`id-gen1` / `id-gen2` / `id-gen3`）は保存データとの互換のため変えない。
- **楽曲の追加手順（2026-09-05）**: 初期出典（Ahoge0510/holodri-optimizer）は 181 曲で更新が止まっており、攻略サイト・公式サイトは開発環境から閲覧できない。追加曲は、収集用の検索プロンプト（曲名・アーティスト・オリジナル/カバー・演奏時間・難易度別 Lv とコンボ・出典 URL を JSON で。ゲーム内配信順）をユーザーに渡し、別エージェントの結果から手入力する。`artists` はホロメン名を `holomen.json` の表記に合わせる（EN / ID は日本語表記。例: Mori Calliope → 森カリオペ）、ユニット名はそのまま入れて `src/ui/labels.ts` の所属対応表に追加する。実装日は持たず、食い違いは `meta.json` の notes に記録する。
- **読み（`reading`）はひらがなで手入力する**（2026-09-05）。ホロメン名・カード名の読みで、一覧のあいうえお順と検索にだけ使い、表示はしない。英字はカタカナ読みをひらがなにし（AZKi → あずき、Go! Go! → ごーごー）、空白・記号は入れない。長音「ー」はそのまま書く（比較時に直前の母音として扱う — `src/ui/labels.ts` の `readingSortKey`）。`validate.ts` がひらがな以外を弾く。
- **ホロメンボードの配置（`board`）はホロメンごとの固定データ**（2026-09-07 ユーザー共有、全 54 名）。`blueSide` = 全体配置で青ボードが左か右か（黄はその反対。青ボードのマス配置は左のとき左型、右のとき左右反転）、`lifeSide` = 赤ボードのライフ系エリアが左か右か（ステータス系はその反対）。赤は常に上・緑は常に下。ユーザーに左右を選ばせず、ここから引く（`src/components/BoardSheet.vue`）。新規ホロメンを追加するときは実機で確認した値を入れる。
- 更新したら `meta.json` の `asOf` と出典を更新し、`pnpm test` で整合性検査を通す。
- スコア計算はコミュニティの解析モデルに基づく試算。`scoreSupport` 効果（ライブ中効果）は構造化して保持するが基礎スコアには反映されない。衣装スキル複合文のスコアサポート条件の解釈は `meta.json` の notes を参照。
- **最適化（編成探索）の対象は★5 のみを維持する**（2026-08-31 ユーザー指定）。★3/★4 は仮想ガチャ等の別機能の表示にのみ使い、`cards.json` に混ぜず、探索プールにも入れない（現状はカード名未確認のためホロメン単位で扱う — `gacha.ts` 参照）。
- **イベント（`events.json`、2026-09-08 ユーザー共有）**: サービス開始後の全イベントを持ち、新イベントはデータ 1 件の追加で対応する（UI・エンジンは編集しない）。対象カード・対象ホロメン・課題曲は表示名でなく `cards.json` / `holomen.json` / `songs.json` の**既存 ID を検索して保存**し、ID を新しく発明しない（`validateEvents` が未定義 ID を弾く）。初期出典の表記が実機と違っていた 4 件（`shirakami-fubuki-02`「海で魅せる」→「渚で魅せるtwinkle」、song-162「Boom! Boom! Tropica Vacation」→「爆夏!!トロピカバケーション」、song-163「HOT DUCK!」→「ホットダック！」、song-181「You & aIzu」→「You & 合図」）は表示名だけ実機表記に直し、ID は改名していない（2026-09-08 ユーザー確認）。リーダー枠は獲得ボーナス・スコアボーナスの判定に入らない（同日確認）。チャプター制（`spotlight`）はメンバーボーナスの新★5 を本体に、ホロメンボーナスの対象人物と課題曲をチャプター側に持つ。獲得ボーナス（メンバー + ホロメン + 開花）とイベントスコアボーナス（課題曲のライブスコア +10%、重複なし）の計算は `src/engine/event.ts`。イベント Pt の絶対値は換算しない。
