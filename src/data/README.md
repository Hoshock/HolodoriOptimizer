# ゲームデータ

『hololive Dreams』の★5 カード・楽曲・所属・ホロメンのデータセット。**テキスト情報のみ**を持ち、画像・音声等の公式アセットは一切含めない（[ADR-002](../../docs/adr/002-game-data-text-only-hand-entered.md)）。

| ファイル            | 内容                                                     |
| :------------------ | :------------------------------------------------------- |
| `types.ts`          | スキーマ定義（スキルは構造化表現 + 原文 raw の二重持ち） |
| `affiliations.json` | 所属（世代・ユニット）                                   |
| `holomen.json`      | ホロメン（タレント）と所属の対応                         |
| `cards.json`        | ★5 メンバーカード（パラメータ・4 系統スキル）            |
| `songs.json`        | 楽曲（難易度別レベル・コンボ数）                         |
| `meta.json`         | 出典・確認日・検証状態の注記                             |
| `validate.ts`       | 整合性検査と構造化率の算出（`dataset.test.ts` から実行） |

## 更新の約束事

- 値の出典はゲーム内表示または公開情報のみ。**推測で埋めない**。ソースにない値は `null` / 省略。
- スキルの `raw` にはゲーム内の説明テキストを原文のまま入れ、`structured` は確実に解釈できる場合のみ設定する。**衣装・パッシブは全カード構造化済み（2026-08-31）で、テストが 100% を強制する** — 新規カードは構造化まで済ませてから追加する（解釈に迷う原文は先にスキーマ拡張を検討する）。
- 更新したら `meta.json` の `asOf` と出典を更新し、`pnpm test` で整合性検査を通す。
- スコア計算はコミュニティの解析モデルに基づく試算。`scoreSupport` 効果（ライブ中効果）は構造化して保持するが基礎スコアには反映されない。衣装スキル複合文のスコアサポート条件の解釈は `meta.json` の notes を参照。
- **最適化（編成探索）の対象は★5 のみを維持する**（2026-08-31 ユーザー指定）。★3/★4 は仮想ガチャ等の別機能の表示にのみ使い、`cards.json` に混ぜず、探索プールにも入れない（現状はカード名未確認のためホロメン単位で扱う — `gacha.ts` 参照）。
