# ADR の規約 (adr-convention)

ADR は決定の**理由**を記録する — 将来コードを読む人が、コードからは復元できない部分。書くかどうかから 1 文の要不要まで、同じ試験を当てる: **コードを読めば分かることか？** 分かるなら書かない。

## 書くとき

覆しにくい・覆すと高くつく決定、モジュールの境を越える決定、コードだけでは見えない形で将来を縛る決定に書く。具体的には:

- 妥当な案が複数あり、結果からは分からない理由で 1 つを選んで他を退けた。
- スキーマ・API の形、依存の選択、データ形式、安全性との取引を固定した。
- コードで表せない制約を決めた: 利用者の要求、「バグに見えるが意図」の凍結、期限や資源の制約が設計を決めた。

書かないとき:

- 守るべき代替案がない — 唯一の妥当な選択、通常のバグ修正、依存の更新、争点のないリファクタ。
- 局所的で安く戻せ、レビューアが差分とテストから理由を復元できる — コードのコメントで足りる。

1 つの関数に閉じていることは不適格の理由にならない。範囲ではなく上の試験で決める。

## 粒度

**1 ADR 1 決定、おおよそ 1 ページ。** 長さ自体が信号で、超えるなら決定を束ねているか、設計文書に置くべき実装の細部に流れている。

2 つの決定を 1 本に束めてよいのは、必ず一緒に置き換えられるとき — 同じ取引、同じ原因、片方だけ Status が変わりえない — だけ。段階を踏む決定（短期 / 中期 / 長期）は段階ごとに 1 本（それぞれ別の時期に Accepted / Superseded になる）。迷ったら分ける: 薄い ADR は安く、後から分けるのは高い。

## 命名

- `NNN-short-kebab-case-title.md`（3 桁ゼロ埋め。既存の最大番号から連番）。`index.md` は例外。
- 置き場は `docs/adr/`。

## Status と編集

| From     | To                             | いつ                   |
| :------- | :----------------------------- | :--------------------- |
| Proposed | Accepted                       | 合意したとき           |
| Accepted | Superseded by [ADR-NNN](NNN-…) | 新しい決定が置き換えた |
| Accepted | Deprecated                     | もう関係なくなった     |

**Accepted 後、Decision / Context / Consequences の本文は凍結する** — この規約自体と合わなくなっても変えない（最後に触った人の見方より、信頼できる記録を優先する）。例外は 2 つ: 体裁の修正（誤字・切れたリンク・整形）と、**決定を変えない新情報**を節の末尾に日付つきで足す追記（`**Update (YYYY-MM-DD):** …`。元の文を置き換えない）。

**決定が変わったら新しい ADR を書き、旧 ADR の Status を Superseded にする。** Update で決定を書き換えない。画面の見た目・文言・操作の変更はコードと `.claude/rules/` から復元できるので ADR に書かない。Superseded / Deprecated の ADR を `docs/adr/` から消したり書き換えたりしない — 決定の記録は永続で、探しやすさは `index.md` が担う。

## 索引

`docs/adr/index.md` に重要な記録だけの表を置く。

- 将来の作業がそれを必要とする・破りうる ADR を載せる。些末なもの・純粋に歴史的なものは載せない（全体はディレクトリ一覧が持つ）。
- 載せる価値のある ADR と同じコミットで索引も更新する。

## 言語と形

本文は日本語で書く（このリポジトリの方針。CLAUDE.md「注意」参照。元の規約の英語の規定より優先）。コード識別子・パスは原文のまま。日付と Status は既存の ADR と同じく見出し直下の箇条書き（`- Date:` / `- Status:`）で書く。

## スケルトン

```markdown
# ADR-NNN: 題

- Date: YYYY-MM-DD
- Status: Accepted

## Decision

<決定を結論として 1〜2 文で — 何を、なぜ。経緯の物語にしない。>

## Context

<なぜ必要だったか: 制約・取引・本気で検討して退けた代替案（と負けた理由。通りすがりに触れただけの案は書かない）・選択を決めた自明でない事情（利用者の要求、事故、期限、プラットフォームの限界）。>

## Consequences

### Pros

- <楽になったこと、できるようになったこと>

### Cons

- <難しくなったこと、承知で受け入れた危険 — どの決定にも必ずある>
```

索引（`docs/adr/index.md`）:

```markdown
| ADR                        | 概要           |
| :------------------------- | :------------- |
| [ADR-NNN](NNN-filename.md) | <何についてか> |
```
