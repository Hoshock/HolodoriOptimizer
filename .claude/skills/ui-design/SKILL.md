# Ui-Design

このスキルは、HolodoriOptimizer の画面をどう作るかを定める。本文は全画面に効く原則で、画面ごと・部品ごとの規則と、プラットフォームの落とし穴・ブラウザでの確認手順は外部リファレンスに分けてある。規則が見つからないときは、リファレンスを横断して探す。

## 進め方

- 機能追加でも新しいデザインを持ち込まず、既存のコンポーネント・トークン・デザイン言語を踏襲する。既存のパターンと形が違う UI を入れるときは、提案の時点でその差の意図(単一選択と複数選択の区別など)を説明する。ユーザーが違いの理由を判断できるようにするため。
- 遊び機能(仮想ガチャなど)は、ゲーム仕様の忠実な再現より操作の単純さを優先する。通貨 2 種・割引枠・天井などは求められるまで再現しない。
- 「UI どうする？」のような設計相談には案を示すところで止め、明示の着手指示を待ってから実装する。方針への一言を着手の合図と取って実装・push すると、差し戻しと退避の手間が生じる。「push までする」運用は指示された変更に適用し、設計相談の回答には適用しない。
- 提案では、ユーザーから見て何が変わるか(画面・結果・待ち時間)を先に言い、中身の変更は「いまの手順 → 変えたあとの手順」の具体例で示す。内部の言葉(覚えておく・キャッシュ・分担)は、どこに・いつまで・何をもとに、まで言い換える。内部の言葉のままでは何が変わるのかが伝わらないため。
- モーダルの上にモーダルを重ねない。重なったモーダルは不自然に見えるため。1 つの入力の中で段階が進むもの(形 → 倍率 → 持ってくる場所)は、同じモーダルの中身を切り替え、つながりをアニメーションで見せる(選んだ図形がそのまま拡大して移る・選んだ行がその場で広がる)。モーダルの出方(中央・サイドバー)も画面ごとに変えない。実装例は `ConnectSheet.vue`(`references/boards.md`)。シートの上に `ConfirmDialog` を出す既存の確認ダイアログは、まだこの形にしていない。
- 調整ツール(配色の管理用画面など)は、対象そのものを見ながら触れる形(実画面の上に固定する操作バー)にする。全画面のシートと縮小プレビューでは、実際の見え方を判断できないため。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法を 1px も変えない(レイアウトシフトを起こさない)。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測する。モード切替で出し入れする要素は同じ高さの枡に置き換え、下の要素を動かさない(ボードの「すべて解放 / 解除」の行は、説明モードでは同じ 44px の帯になる)。
- 表・一覧の行は固定順で全項目を常に出し、選択順・解放順で行を増減させたり並びを変えたりしない。値がないときは +0 などの空値で行を残す。選ぶ順で並びが変わると、同じ項目を毎回探し直すことになるため。
- 重ねる装飾・アイコンのために元の部品の寸法を変えない(はみ出しは親側の描画範囲で処理する)。補助のアイコン(ⓘ など)は、主の部品の幅と中央を崩さない場所(見出しの行)に置く。セグメントの横に並べると、セグメントが細くなって中央がずれ、空間も取りすぎる。
- 同じ形の行を縦に何度も繰り返す入力は、まとまり(色など)ごとのカードにして一目で見渡せるようにする(例: リソースの画面は、色の見出し + 設定行 × 8 ではなく、色ごとのカード 2 列)。
- 可変長の見出し(人名・曲名)と固定幅のコントロールを同じ行に並べない。見出しに 1 行を占有させ、コントロールは次の行に左右で並べる。同じ行に置くと長い名前が省略されるため。
- ヘッダなどの常時表示領域も、タブ・モード切替で高さを変えない。画面遷移(フルスクリーンモーダル)にも当てはめ、シートのヘッダはページヘッダと同じ寸法(padding 16px・h3 24px/900・高さ 77px)と同じ下罫線にして、両方の boundingBox を実測する。規則があっても実測しないと、寸法の違うヘッダ(60px のピッカーなど)が混ざる。切替内容に依存するもの(手順リストなど)をヘッダに置かない。
- はみ出すテキストは動かさない。1 行は省略記号、複数行は行数固定 + 省略記号にする。横スクロール表示(往復・巻き戻し・看板型)は不具合に見えるので使わない。装飾的な動きは、実機で確認できない限り入れない。
- 並ぶ要素は縦・横の線を揃える。同種のアイコンは全行で同じ列に置き、常に出るもの(開花)を最右の固定列、条件つきのもの(固定ピンなど)をその左の列に置く。アイコンの有無で行の高さを揺らさない(min-height で担保)。
- カード類の高さを文字列長で揺らさない(行数固定 + 省略)。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all` にする(「55%UP」などの英数字トークンの手前で早く折れる、不自然な改行を防ぐ)。
- ゲーム側で決まっている値(ホロメンボードの左右型など)はユーザーに選ばせず、データ(`src/data/holomen.json`)に持って引く。
- モバイルファーストで設計する。iPhone 実寸(390px 級)での崩れ・不自然な改行は、出す前に playwright-cli で確かめる(`references/verification.md`)。

## アイコンとラベル

- 静的なメタ情報ラベル(スキル種別・役割)に、矩形の枠つきバッジ(チップ)を使わない。AI が作るデザインの典型で、押せる / 押せないのアフォーダンスも壊すため。
- 自明なメタファーがあるものは図のアイコン(衣装 = T シャツ / 固定 = ピン / おかゆモード = おにぎり)、ないものは文字アイコン(SP / A / P)にし、すべて 26px の正円の細線で囲んで統一する。ただし同じ一覧の中では様式を揃える(サイドメニューの項目は丸で囲まない 24px の線画なので、おかゆモードの行もおにぎり単体)。制約で入ったカードの印(おにぎり)はピンと同じ列に出す。開花(凸)は花びらの輪郭 + 段階の数字で、花の輪郭が正円の枠を兼ねる。実装は `src/components/SkillIcon.vue`(自作の SVG だけで、公式アセットは使わない — ADR-002)。
- フォントにある合成済みの記号(①②… などの丸数字)をアイコン代わりに使わない。自作の図形にするか、別の表現に置き換える。
- 計算の前提になっている値(開花段階など)は、既定値でも省略せず常に表示する(0凸も出す)。逆に、計算に関係しない値のアイコンをその枠に出さない(リーダー行には開花アイコンを出さず、最右列は衣装アイコン。詳細モーダルにピンは出さない)。値を変えられない画面(メンバーピッカー)では値をアイコンだけで見せ、± などの操作は出さない。
- アイコンのテキストラベルは画面に出さず、aria-label に退避する。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行 / 2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- 同じ属性の表現方法を 1 つの画面の中で混ぜない(タレント名の文字色でタイプを示す一覧に、タイプ淡色の面を混ぜない)。
- タイプ色の正は キュート = ピンク / ハッピー = 黄 / ピュア = 緑(`docs/ai/game-spec.md`)。カードのタイプはタイプ淡色の面(背景)で表し、タイプ名のテキストバッジを置かない。タイルでない場所(結果一覧)では、タレント名の文字色(タイプ濃色)で見分けさせる。タイプ色の黄は淡地 + 濃文字でだけ使い、白抜きにしない。ホロメンボードの黄はこの規則の外で、解放マスの文字は白。
- 等価な選択肢(回数違いの同じ操作など)には primary / secondary の階層をつけず、同じ配色のボタンにする。
- 操作できない表示(キャプション・選んだ対象の説明・状態)は枠線を使わず淡色の地(`var(--bg)`)で示し、枠線つきの角丸はボタンに限る。枠線があるとボタンと誤解されるため。空のときも点線にせず、形は同じで中身だけ空にする。
- タイプ色パネルに枠線を付けない。例外は、空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠だけ。選択の強調にはそのカードのタイプ色を使い、無関係な固定色を当てない。
- コントロール(セグメント・チップ・番号バッジ・トグル)の選択スタイルは、全画面で `--selected` の地 + `--selected-ink` の文字の 1 種類にそろえる(ライトは濃色地 + 白文字、ダークモードでは明るい地 + 暗い文字に反転する)。`--ink` を地に使うと、ダークモードで白文字が消える。選択肢の意味色(タイプ色)で選択状態を塗り分けない。
- スキルの発動状態は、テキストバッジ(「反映中」「条件未達」など)ではなく、発動 = 通常表示 / 不発動 = 行のグレーアウトで表す。スキルの行を出さない画面では、そのスキルを指すアイコンをグレーアウトする(結果詳細のリーダーの衣装アイコン)。「未反映(未構造化)」という状態は UI に設けず、データ側を 100% 構造化して状態そのものをなくす(`dataset` のテストが強制する)。
- エラー・状態・空の表示は次の 3 種類にそろえる。書き方と警告色を統一し、不要な文を減らすため。
  - エラー(実行できない・失敗した・止めている)は、共通の `.error-text`(`src/style.css`。`--error`・13px・600・行間 1.5。背景・枠・アイコンなし)の 1 文にする。置き場は原因になった操作のすぐ下で、間隔 8px(さがす・組み直すとの失敗はボタンの下、おかゆモードはアカウントのボタンの下)。シートでは本文の先頭(組み直しプランはタブの上)、ダイアログでは本文とボタンの間。灰色の箱には入れない。
  - 状態の赤(超過・不足・マイナス・未登録)は文にせず、数字やラベルだけを `--error` にする(「230 / 9 Pt」「残り -2」「未登録」)。0 は淡い色。選択中の濃い地の上では、赤を地の文字色へ寄せる(`color-mix`)。
  - 空(結果がないだけ)は、淡い色の 1 文「〜がありません」。その前に、中身が空になる入口を押せなくして、空の画面を作らない形を考える(`references/flow.md`)。
  - 文は起きている事実の 1 文にし、句点を付けない。直し方は見ても分からないときだけ足し、「〜ため、」の理由・全角括弧の補足・言い直しの二文目は書かない。数字は半角で、単位の前にスペースを入れる(「ボードPt が 3 Pt 足りません」)。計算の失敗はどこでも「計算に失敗しました」(`src/ui/messages.ts` の `CALC_FAILED`)とし、Worker の中の文は画面に出さず、各 composable の `error` に残す。
  - 知らせのダイアログ(`NoticeDialog`)は、ボードの操作を断るときだけ使う(盤面の下に文を出す場所がないため)。戻るで戻せる操作(ボードの解除・コネクトマスの解除)には確認を挟まない。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同じ角丸 + 影、装飾の絵文字。地・罫線は無彩色に保ち、色は意味(タイプ・状態)にだけ使う。
- 機能的な意味を持たない装飾・記号を付けない(選択済みカードのチェックマーク、所属チップやしぼりこみチップの ✓。濃色地で選択は伝わる)。状態を表す記号(並び順の ▼/▲)は使ってよい。グラフは、表で表せている情報に重ねて置かない。
- ヘッダなどの `--chrome` の帯の上に載る 44px の正円(ハンバーガー・✕)は面の色(`--surface`)にして、帯と区別する。
- デザイントークンの正は `src/style.css` の `:root`。配色モードは同じトークンを差し替えて表す(`:root.dark-mode` = ダークモード、`:root.okayu-mode` = おかゆモード、併用は `:root.dark-mode.okayu-mode`)。役割の割り当て(面・文字・タイプ 3 色の淡 = 面 / 濃 = 文字、ヘッダ・下端の固定エリア・注釈のフッタの `--chrome`)はモードによらず同じにする。`--chrome` は地との差がぎりぎり分かる薄さにとどめ、色みは無彩色寄り(おかゆモードだけ紫系)にする。

## 文言と情報量

- 状況を説明する文を UI に足さない。数字や構造(「残り -2」・選んだ行が広がる)で伝わるなら文を置かず、読み上げ用の aria-label に回す(例: コネクトの「〜は 2 枚とも使っています。どこから外して持ってきますか？」は置かない)。操作の結果は、短い言葉で操作の側に付ける(「青ボードから外す」)。
- 冗長な文字情報を置かない。背景色や見出しで伝わることをテキストで繰り返さない(枠名「リーダー」、タイプ名「ピュア」、要らない合計値)。注記に当然の否定(「（リーダー自身には効かない）」のような括弧)も書かない。
- 空プレースホルダは中央の 1 行の値だけにし、字送りもプレースホルダ同士で揃える(14px / 600 の淡色 = `UnitSlot` / `SongRow` の `.empty-msg`。充填時の値の字送りを継がない)。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記や言い訳(「（登録済み n 枚）」「（おまかせでもOK）」など)を付けない。セクション見出しも短い名詞 1 語で、括弧の補足を付けない(「衣装スキル」「リーダー」)。件数はコントロールの中の右寄せの値として置き、任意項目は既定値「おまかせ」を実値として表示する(結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は付けてよい)。
- 既定値が文脈で決まるなら、実値まで具体化して見せる。ただし決まった時点で出し、先回りして出さない(おかゆモードの最後のメンバー枠は、4 枚選んでもおかゆんがいないときだけ「おかゆん（おまかせ）」)。
- 「おまかせ」は、ツールが実際に最良を選ぶ枠(リーダー・メンバー)にだけ使い、選ばなくても計算が成り立つ枠(曲)は「指定なし」と書く。試算に効かない値を実値のように見せない(曲の指定なしに代表値の曲長を並べない。行の高さだけ充填時に合わせる)。
- 手順の説明文で UI を補わず、UI 自体に情報を語らせて本文のコピーを最小にする。補足の注記(単価・確率の説明、★別集計などの統計文、選択対象の再掲)も、操作方法の説明文(「タップで◯◯」など)も置かない。コスト・件数はボタンや見出しのラベルの中に含める(「10回 2,500」「結果（n回）」)。件数はメイン画面の行ボタンの中の値としてだけ示し、ピッカーのヘッダには出さない。免責・試算値の注記はフッタに集約する。例外は 2 つで、検索から来た人にこの画面が何なのかを示す本線最下部の説明カード(`AboutSection.vue`。ページ自体の説明なので、この規則を根拠に消さない。置き場と中身は `references/flow.md`)と、見出しの行の ⓘ から開く説明。
- シートの中の注記(試算の前提・未確認の断り)は本文の途中に置かず、末尾の脚注(`.footnotes`、※n)にまとめ、本文側は見出しや値の直後の上付き `※n`(`.fn`)で参照する。番号は画面の上から出てくる順に振り、並べ替えたら振り直す。脚注は番号列(`.fn-num`、固定幅)と本文の 2 列にして、2 行目以降の左端を本文の左端に揃える。脚注・注記に観測日や「実機観測に基づく」のような根拠の来歴を書かない(利用者には要らず、根拠はコードのコメントとドキュメントに置く)。脚注は実装が変わったら同じターンで追随させ、全ページの脚注にずれや冗長な表現がないかを確かめる。脚注を初期表示で隠す方法は `references/parts.md`。
- ⓘ から開く説明(`InfoButton.vue` → `InfoDialog.vue`。中身は `src/ui/infoContent.ts`)は、画面には ⓘ だけを置き、押したときだけ中央のダイアログで出す。置き場はメイン画面のアカウント・リーダー・メンバー・曲・さがす(3 択)・結果(いまのまま / 組み直すと)、絞り込みのダイアログ、組み直しプランの「最適化するもの」「発動頻度の選び方」、リソースとホロメンボードのシート、ティア表(一覧と 1 枚の評価画面の両方。評価画面へ進んでも消さない)の 12 か所。
  - ⓘ は見出しの行の右端に置く(図 20px・押せる範囲 40px を負のマージンで重ね、見出しの行の高さを変えない)。右端が閉じるボタンのシートの見出しでは、文字のすぐ右に置く。
  - 形は中身に合わせる。違いがいくつもある 3 択は「列 = 選択肢、行 = 違い」の表、言葉の意味が分かればよいものは名前と段落、名前の要らないもの(シートの使い方)は段落だけにする。意味が伝われば足りるものまで表にしない。表の中の言葉(「登録のまま」「全解放」)は表の前の段落で言う。
  - 表の中の言い方はそろえる(同じ状態は同じ語。「登録の段階 / 登録のマス / 登録のまま」を混ぜない)。表には違いだけを置き、両側が同じ行・細かすぎる行・ほかの画面への案内の行は置かない。思い込みを正す行(育てきったらでもコネクトは登録のまま)は残す。
  - 入力の仕方・選択肢の意味の説明は、脚注ではなく ⓘ に置く。脚注は初期表示で見えず、結果のタブの脚注は実行したあとにしか出ないため。試算の前提・近似・実機未確認の断りは脚注のまま。
  - ⓘ に書くのは操作で選べることの意味だけで、計算の仕組み(何がスコアに入るか)の解説は置かない。ⓘ は短く保ち、長くなる細かい規則(どの場合に何を変えるか・値の求め方)と断り(相対値であること・試算であること)は脚注へ回す(例: 「最小限で組み直す」の ⓘ は何を組み直すかだけで、ほかのホロメンの変え方の規則は組み直しプランの脚注 ※1)。
- 画面に出す説明の文(ⓘ・脚注・使い方のページ・説明カード)は、初見の人が分かるように書く。その画面で初めて出る言葉は言い換えるか、先に意味を言う。文ごとに改行せず段落にまとめ、長いときだけ段落を分ける。同じものは、画面・ⓘ・脚注・使い方のページで同じ言い方にする。
- タップできることの手掛かりに、誘導のテキスト・記号(「詳細 ›」など)を置かない。大きな行(結果一覧の 1 件)の押下で面を暗くしない。
- スワイプで隠れた操作を出す UI を使わない。操作できることが初見で分からないため(行の左スワイプで削除する形は撤去した)。判断させたいものは、見えるボタンかダイアログで聞く。左右スワイプはページ送り(`PageCarousel`)だけに使い、結果一覧では見える代替として三角ボタンを同じ画面に置く(詳細シートの送りは `references/parts.md`)。
- 押下の視覚効果を付けない。OS のタップハイライトは全要素で無効にしてあり(`src/style.css`)、`:active` の暗転・減光も付けない(iOS Safari で `:active` が当たる条件は `references/platform.md`)。
- ヘッダには識別情報(タイトル・機能アイコン)以外のテキスト(手順リスト・キャッチコピー)を置かない。メイン画面のフッタは免責の 1 段落だけにする(データ確認日・GitHub リンクは置かず、リンクはサイドメニューへ)。
- 数値に対する操作(追加・リセットなど)は、説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる(課金額の隣の課金 +、リセット ↺)。
- 並ぶ選択肢のラベルは、主語と構文(自動詞か他動詞か)と文体を揃える(さがすの 3 択「いまの育成で / 育てきったら / 全カード」)。ぶら下がりの短いラベルは、主の設定の中身を指す名詞でよい。ラベルは短くする(「持っているカードのみからさがす」ではなく「所持カードから探す」)。
- 同名の別種があるものは種類を明示する。種類の切り替えが見込まれるなら見出しに入れず、切替コントロールで示す(見出し「ホロメンボード」+ 赤・青・黄・緑のセグメント。用意できていない種類は disabled で置く)。
- 回数は「n回」と書き、「n連」などの言い回しを使わない。
- 同種の操作(カード選択)は、見た目も操作も同じ形に揃える(リーダーとメンバーで別の UI にしない)。
- UI に内部用語(「構造化」「structured」のような実装の語彙)を出さない。状態表現の冗長な修飾も削る(「スコアに反映中」ではなく「反映中」)。
- 値を見せる画面(詳細モーダルなど)の注記で、数値・スキルの前提を明示する: レベル最大であること、設定した開花段階に応じた試算であること、実機で確認できていない段階は文言を「未確認」と出し、試算にはいちばん近い段階の内容をそのまま使っていること。
