## サイドメニューと入口

- 本線の外の入口(一覧・遊び機能・外部リンク・管理用・モード切替)は、ヘッダ右上のハンバーガー → 右のサイドメニューに集約する。1 本のリストにしてセパレータは置かず、グループは折り畳みの行で作る(セパレータだと、境目の感覚が一定にならないため)。並び:
  - トップレベル(折り畳みなし)= 使い方 / お気に入り / ティア表 / カード一覧 / 曲一覧 / 仮想ガチャ。「使い方」は一番上で、行き先はアプリの外の解説ページ `guides/simulator/`(通常のリンクで遷移)。「お気に入り」= 登録ユニットの詳細シート `UnitSheet.vue`。「ティア表」= ★5 の評価のシート `TierSheet.vue`(カード一覧の上。タイルを押すと評価画面 `TierCardSheet.vue`。中身は `references/parts.md`、評価は ADR-024)。
  - 折り畳み「設定」(歯車)= ダークモード / 絶対おかゆんモード。
  - 折り畳み「開発用」(コードの括弧。設定の下)= GitHub / データの出力 / 開花文言。
- 開発用のホロメンボード・ペルソナ風 UI・「カラー確認」「文言・配置」の入口と、「おまけ機能」のグループは廃止した。作り直さない。
- 「データの出力」(`ExportSheet.vue`)は、登録しているホロメンの 4 色ボードとコネクト・所持メンバーと開花・イベントメモリー・メンバー強化ボーナスを、1 つの JSON `holodori-optimizer/account` でコピーする。ヘッダ + 右上の「コピー」だけの画面で、JSON は読み取り専用の欄にして枠を本文いっぱいに広げ、枠の中だけをスクロールする。
- モードの 2 つ(ダークモード・絶対おかゆんモード)は、遷移ボタンではなく設定項目。ラベルは状態で変えず、現在値は行の右端のトグルと `aria-checked` で示す。行そのものを `role="switch"` のボタン 1 つにして、トグルは `aria-hidden` の見た目だけにする(別々の押せる要素にすると、二重に発火しうるため)。トグルの ON はほかのコントロールと同じ `--selected` の地(`--selected-ink` のつまみ)。切り替えてもメニューは閉じず、スクロールもしない(配色の変化はメニュー自身に出る)。
- 折り畳みは最初は畳んでおく。押すと右端の山形が回り、行の下に一段(24px)インデントした項目(アイコン + 内容)が開いて、その位置より下の行が下へ動く(下端に貼り付けない)。メニューを閉じたら畳み直す。片方を開いても、もう片方は閉じない。項目は 1 段小さい 15px / 600・高さ 48px、アイコンは親と同じ 24px。リストの最下部は安全領域ぶんの余白を持つ。
- サイドメニューは常時表示領域(ヘッダ)に掛けず、開く瞬間のヘッダの下端から出す。ヘッダがスクロールで画面の外に出ているあいだは、同じハンバーガーを右上に浮かせて出す(`App.vue` の `.menu-float`。`IntersectionObserver` でヘッダの可視を見る。開いている間は ✕ として残り、メニューは画面の上端から出る)。
  - 位置はヘッダのハンバーガー・各シートの ✕ と同じ 右 16px・上 16px で、出入りは 0.22 秒のフェード + わずかな沈み込み(`prefers-reduced-motion` では無効)。開閉の操作は同じ場所で形を変える(ハンバーガー ⇄ ✕)。
  - 閉じる手段は ✕・外側タップ・Escape の 3 つで、開けるのはメイン画面だけ。地は不透過にし(透過 + ぼかしにしない)、背後は scrim で少し暗くする。
- 解説ページとの往復では、縦位置を覚えて戻す:
  - 解説ページへ出ていくときは、そのときの縦位置を覚え、戻ってきたら復元する(`src/storage/returnScroll.ts`、入口は `src/ui/guideReturn.ts` の `rememberGuideReturn()`)。通常のリンクでの遷移なので、ブラウザのスクロール復元は効かない。メニューを開いている間はスクロールロック中で `window.scrollY` が 0 なので、`currentScrollY()`(`useModalChrome`)が返すロック前の位置を使う。
  - 解説ページへ行くリンクは、全部 `rememberGuideReturn` を通す(サイドメニューの「使い方」と説明カード)。一部だけ覚える形にすると、覚えた値が使われないまま残り、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ。
  - 位置へ戻すのは解説ページのヘッダの「←」だけで、本文の「編成シミュレーターを開く」(`guides/**` の `.guide-cta`)からは先頭へ出す。CTA は遷移の前に覚えた値を捨てる(各解説ページ末尾の小さな `<script>` が `sessionStorage` のキーを消す。`src/seo.test.ts` で固定)。
  - 復元はマウントの途中(最初の描画より前)に同期で当てる(`App.vue` の `restoreScroll`)。`requestAnimationFrame` に入れると、先頭に描かれたフレームが 1 枚見えてから飛ぶ(ちらついて戻る)。高さがまだ足りないときだけ、届くまで数フレーム追いかける。
- 検索から来た人向けの説明は、本線の一番下の 1 枚(`AboutSection.vue`)だけに置く。入力の導線より上へは出さず、ファーストビューを押し下げない。中身は `src/ui/siteCopy.ts`。できることの箇条書きは重要度順を優先し、同じくらいのものは画面の操作順にする(試算値であることはフッタの免責に書いてあるので重ねない)。検索用の隠しテキストは使わない。
- データの取り込みはない(貼り付け画面 `ImportSheet`・確認の `QuestionDialog`・`src/storage/import.ts`・スキル `structure-import` は削除した)。所持カードの登録はメンバーのピッカー、ボードはホロメンボードのシートで行う。
- 開発用の「開花文言」(`BloomTextSheet.vue`。「開発用」の GitHub の下)は、カードごとに、開花段階ごとのスキル文言を実機を見ながら入れ直すための入力フォーム。量のある入力をする道具なので、実画面の上に固定せず全画面のシートにする。
  - 中身は 3 つだけで、説明文は置かない: 「カードを選ぶ」(`CardPicker`)→ 開いたカードの切り替えチップ → スキル 4 種(衣装 → スペシャル → アクティブ → パッシブ)× 文言が変わらない区間 の欄 →(末尾に)共有用データ + コピーボタン。区間ごとの欄にもコピーボタンを付け、入力欄は 16px。
  - 欄は開花段階ごとには出さない。どのスキルがどの段階で強くなるかは決まっている(`BLOOM_UPGRADE_STAGE`。衣装は変わらない / アクティブ 1凸 / SP 3凸 / パッシブ 4凸)ので、区間ごとに 1 つ(衣装 1・ほか各 2 の計 7 欄)。欄の既定値は、いまのカードデータから出した文言(`cardAtBloomWithProvenance` の raw を区間の先頭の段階で引く)で、区間ごとに出所の印を添える。見出しはホロメン名が主で、カード名は下に小さく添える。
  - 上書きは既定値と違う文字列だけを持ち、既定値に戻すと上書きも消える。開いたカードはチップで行き来でき、共有用データ(`kind: "holodori-optimizer/bloom-text"`)には開いた順に全部入る(直していないカードも「この内容で合っている」の記録として出す)。入力は localStorage にだけ残し、カードデータは書き換えない。
  - ピッカーに出すのは対応がまだのカードだけ(`bloomTextPickerPool`: 実機確認を通したカード `BLOOM_TEXT_VERIFIED_CARD_IDS` と、このフォームで開いて記録したカードを外す)。「外す」で記録を捨てるとピッカーへ戻る。未入力のカードが残っていないときは「カードを選ぶ」を無効にして「未入力のカードはありません」と出す。ピッカーには「すべて / 所持」の絞り込みが付く(部品側は `references/parts.md`)。

## さがすの条件

- 再読み込みで残すのは、さがすの「オプション」(育成の前提の 3 択 / 役割別の除外・選択)だけ。オプションは常に保存し、保存を切り替える設定は置かない。枠の選択(リーダー・固定メンバー・曲)は毎回まっさらから始め、保存する形に戻さない。
- 詳細な最適化条件(曲指定・ボード補正などの高度な設定)は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する。モード全体に効くグローバルな詳細設定を増やさない。既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダルの中で設定する。
- さがすステップは「育成の前提」の 3 択 → 「絞り込み」の 1 行 → 実行ボタン。モードを分けず、全員が同じ画面を使う(ADR-017)。「シンプル / 詳細」の切り替えは置かない。旧「オプション ▼」の開閉と、その中のチップ(「所持カードから探す」「ボード状況を考慮する」「開花状況を考慮する」)、色ごとのボードのサブオプション、コネクトのチップは撤去済みで、戻さない。
- 3 択は いまの育成で / 育てきったら / 全カード(排他なので 40px のセグメント。`src/ui/searchPremise.ts`):
  - いまの育成で = 所持カード・登録している開花とボード。育てきったら = 所持カード・開花最大とボード全解放。全カード = 未所持を含む全カード(開花最大・全解放)。
  - ボードと開花の片方だけを考慮する組み合わせは持たない(それで調べる場面がないため)。ボードを考慮しないことは全解放であって 0 ではない(育てきった前提で比べたいため)。保存の形は変えない(`.claude/skills/storage-compat/`)。
  - コネクトは前提によらず、登録している(ボードで置いた)コネクトで常に計算する(全解放として試算するときも、登録したコネクトの範囲が全解放のマスに掛かる)。「OFF なら最適な形で試算」「OFF なら増幅なし」の切り替えは撤去済みで、戻さない。メモリー・メンバー強化ボーナスも登録値をそのまま使う。
- さがすの見出しの行の右端に ⓘ を置き、押すと 3 択の違いの表(カード・開花・ボード・頻度マス・コネクト × 3 択。いま選んでいる列の見出しは選択の色)を中央のダイアログで出す(置き方は SKILL.md の ⓘ の項目)。
- 「絞り込み」は、押すと中央のダイアログ(`PoolFilterDialog.vue`。除外 / 選択のセグメント → 「リーダー n枚」「メンバー n枚」→「閉じる」)を開き、行の右に今の状態(除外は合計の枚数か「なし」、選択は合計の枚数か「すべて」)を出す。ダイアログからピッカーを開くあいだはダイアログを隠し、ピッカーを閉じると戻る。見出しの行の右端の ⓘ で、除外 / 選択の意味を出す。
- リーダー・メンバーの絞り込み: 「除外 / 選択」のセグメント(既定は除外)の下に「リーダー n枚」「メンバー n枚」の 2 ボタン。除外は選んだカードを候補から外し、選択は選んだカードの中だけからおまかせで探す(ピッカーは「リーダー候補」「メンバー候補」の複数選択)。リストは種類ごとに別々に持ち、効くのは現在の種類のほうだけ。選択が 0 枚のときは絞らず、件数の欄は「すべて」にする(0 件になる設定を作らない)。エンジンは役割別の除外しか持たないので、選択は補集合として渡す(`src/ui/poolRestriction.ts`)。
- ★4 は、自分で枠に置いたときだけ編成に入る(ADR-022):
  - リーダーのピッカー・メンバーの固定のピッカー(と所持の登録・カード一覧)は すべて / ★5 / ★4 の切り替え(既定 ★5)を持ち、おまかせの候補は ★5 だけ(固定していない ★4 はエンジンの除外に足す — `star4Pool.ts`)。除外・候補の選択のピッカーは ★5 だけを出す(★4 はおまかせに入らないので、絞る意味がない)。
  - リーダーをホロメンで指定したとき(おかゆモードのおかゆんも)は、そのホロメンの ★4 もリーダーの候補に入れる(メンバーの枠には入らない)。
  - ★5 を 1 枚も持っていないホロメンの ★4 も、リーダーのおまかせの候補に入れる。「持っていない」は所持カードから探すときの除外で決め、「全カード」ではどのホロメンにも ★5 があるので入らない。★5 のあるホロメンの ★4 は入れない(衣装スキルは基本 ★5 が強く、全部入れると さがす が 3〜4 割遅くなるうえ、計測では上位 30 件に ★4 のリーダーは入らなかった)。
  - この決まりはリーダーとメンバーの見出しの ⓘ に書く(選べることの意味なので、脚注ではない)。
- 枠での指定は除外・選択より優先する。自分で指定したリーダー・固定したメンバーに、エンジンは除外を適用しない。
  - リーダー・メンバーのピッカーでは、選択の外のカードも、除外中のカードも選べる。ホロメンで指定したリーダー・おかゆモードのおかゆんのカードは、除外・選択のどちらでも候補に残す。
  - 除外のピッカーでも、指定中のリーダー・固定中のメンバーを除外にも解除にもできる。おかゆモードのおかゆんだけは新たに除外できない(すでに入っているものは外せる)。
- 絞り込み系オプションの既定は、保守的な OFF ではなく実用上おすすめの状態にし、既定のまま実行すれば一番よい結果が出るようにする(育成の前提は「いまの育成で」)。
  - 候補を減らすだけのしぼりこみ(衣装スキル発動に限る / パッシブ全員発動に限る)は撤去済みで、戻さない。常に全探索して不発の編成も並べ、発動しているかどうかは結果側で見せる(プールが小さいと、条件 1 つで 0 件になるため)。
  - 登録がないと必ず 0 件になる設定は、定数ではなく登録状態から既定を決める(所持カードが 1 枚もなければ、既定は「全カード」。`.claude/skills/storage-compat/`)。
- 順位に影響の薄い要素(課題曲のイベントスコアボーナス +10%)は UI に出さない。
- まとまりのある設定を枠で囲む形(`.option-group`)は、いまは使う画面がない(さがすは 3 択へ、組み直しプランは小見出しの区分へ組み替えた)。主とぶら下がりの関係を示す必要がまた出たら、この形で作る: 地を一段落とした角丸の枠 + 主の設定を上の行・ぶら下がりを下の行の左右半分ずつ(ぶら下がりのチップは文字だけ一回り小さく)。枠の中に区切り線は引かない。枠どうしは同じ高さ(上下とも 32px の行で 84px)。親が OFF のあいだ、ぶら下がりは白 + disabled。

## ステップと操作の構成

- ステップは意味の単位で切り、同じ意味に属する設定を別のステップに分けない。同じ操作を役割で分けるときは、1 つの入口の中に状態を重ねるより、目的別の入口を名前で分ける平たい構造にする(例: 「リーダーから除外」「メンバーから除外」の 2 つの入口)。
- モードの二者択一は、画面全体のタブの複製ではなく、1 フローの中の状態選択(セグメンテッドコントロール)にする。機能・状態の切替で操作ボタンの構成・位置を変えず、使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない。
- 使えない操作の disabled は入口(ボタン)の段階で行い、開けるのに何もできないモーダルを作らない。中身が空になる入口も押せなくする(お気に入りが 0 件のときのサイドメニューの「お気に入り」、コネクト効果を 1 つも置いていないときの「一覧」)。
- 前提が満たされず操作を止めるときも、赤いエラーメッセージではなく、「方針」をボタンのラベルで示す(おかゆモードでリーダー・メンバー・実行を disabled)。例外: Step 0 の入口はラベルを変えると収まらないので、おかゆモードで未登録のときだけ、ボタンの下に 1 行「所持カードにおかゆんがいません」を出す。出ていないときは余白も取らない。
- ある条件で効かなくなる設定は、その条件のあいだ disabled にするが、見た目は 2 通りに分ける。一時的に効かないだけの設定は、保持している設定値の見た目(選択中の濃色地)を変えず減光だけにする。そのモードでは意味を持たない設定は、未選択(白)+ disabled にする(例: ボードもコネクトも選んでいないときの、組み直しプランの「最小限で組み直す」)。どちらも保存値は保持し、条件が外れれば戻す。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置(ページ先頭)へ視点を移す。例外はサイドメニューの中のトグル(メニューを開いたまま切り替えるので、閉じもスクロールもしない)。
- 同種の連続スロット(メンバー枠など)は順序に意味がない入力なので、飛び石の自由度を与えない。追加は常に先頭の空き枠へ入れ、解除時は上へ詰める。枠自体はどれもピッカーの入口として押せてよい(固定は複数選択ピッカーで入れる)。
- パネル内の主要操作ボタンは、secondary(白背景)も含めて全幅にする。primary との階層は背景色(濃色 / 白)で分ける。選択モーダルを開く行ボタンは、ラベル左・現在値(件数)右の設定行パターンにする。
- 数値を入力する設定(Step 0 の「イベントメモリー」「メンバー強化ボーナス」)は、同じパネルのボタンと同じ器にし、ボタンの中でラベルを左端・値(%)を右端に寄せる(押すと +/- の `StepperDialog`。刻み・既定・上限は `references/parts.md`)。ラベルと値が重なるなら 1 行に押し込まず、1 行 1 つの縦積みにして、名前も略さない。ラベルの文字サイズはパネルのボタンの中と揃える(小さく淡くしない)。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は、選択肢が全部見える形(セグメンテッドコントロールなど)で示す。選択コントロールを実行ボタンに隣接させるときは、形・高さ・幅・色で役割を分ける。選択は内容幅・32px のピル形チップ(ピッカーの所属チップと同形)で濃色地(`--ink`)、アクションは全幅・48px の角丸矩形で実行専用の緑(`--action`。おかゆモードは紫のまま)。
- 並ぶ選択肢は、指定された順を保ったまま 2 列 × n 行の等幅グリッドに収める(縦 1 列にしない)。ラベルが収まらなければ文言を短くし、文字サイズを落とすのはそのグリッドの中だけにとどめる(375px 幅でも収まることを実測する)。性質の違う要素(ON/OFF のチップと、ピッカーを開くボタン)を同じグリッドに並べるときは、1 行を全幅にせず左右に置き、形で区別する(チップはピル、ボタンは角丸矩形。高さ 32px と文字はチップに揃え、ラベル左・件数右で、件数はボタンの中)。
- 処理の進行は、押した実行ボタンの中だけで示す(ボタンの寸法は保ち、中止ボタンは置かない)。
- 「ベスト編成をさがす」は、スピナーではなくボタン全体をゲージにする(全カードだと待ち時間が長いため):
  - 地を淡い緑(`--action` と面の色の混色)にして、済んだぶんを左から `--action` で満たす。ゲージはボタン自身の背景のグラデーション `--gauge` で描き、文字も絶対配置にせず、隠したラベルと同じ枡に重ねる(子に % の幅で重ねると、iOS Safari では短く描かれる — `references/platform.md`)。
  - 左に「済んだ組合せの数 / 全体」(万・億で 3 けたほど。`src/ui/searchProgress.ts`)、右に「残り 約 n 分 n 秒」を出す。残り時間は「計算中」とは出さず、最初の進み具合が届いたときから出して、届くたびに直し、そのあいだは 1 秒ごとに減らす。数え終えたら右は「仕上げ中」(上位を正確に計算し直す。全カードでは上位 20 万件を全部計算し直すので 10 秒ほど)。
  - 全体の数は、探索が実際に数える組合せの数(同じホロメンを 2 人入れない — `optimize.ts` の `total`)。同じホロメンの排他を数えない概算にすると、ゲージが途中(全カードで 91%)で止まる。
  - 組み直しプランの「最適化を実行」も同じゲージで、中央に残り時間だけを出す(下の「下端の固定エリアと反映」)。
- 再実行のあいだは前回の結果を消さず、薄く(opacity 0.5・触れない・`aria-busy`)残して、結果が届いたら置き換える。結果セクションをアンマウントするとフッタが繰り上がってちらつくので、非同期の更新で領域を空にしてレイアウトを動かさない。結果の描画に使うスナップショット(開花・ボード・リーダー指定など)も、開始時ではなく結果が届いたときに差し替える(前回の候補を今回の設定で描かない)。

## Step 0「アカウント」

- アカウントの状態(持っているカードと開花段階・ホロメンボード・リソース)は Step 0「アカウント」にまとめ、そこでだけ変更する。探索の条件(枠・曲・オプション)と混ぜない。お気に入りユニットの登録・解除は結果側の星から行い、登録ぶんを見る入口はサイドメニューの「お気に入り」。
- 入口は 2 列 × 2 段の 4 ボタン「ボード / カード / コネクト / リソース」(1 段目 ボード・カード、2 段目 コネクト・リソース。コネクトは見るだけの画面)。
- 入口のボタンに件数・値は出さない。ただし登録がまだのものだけ、ボタンの右端に注意色の小さな「未登録」を出す(ラベルは中央のまま動かさず、右上の角に重ねる)。登録済みとみなすのは、ボード = 4 色のどれかのマスかホロメンランク、カード = 所持カード、コネクト = 所持カードから導いた所持が 1 枚でもある、リソース = どれか 1 つの個数。
- 見出し「アカウント」の行の右端の ⓘ で、4 つの入口が何で、どこで使うかを出す(`ACCOUNT_INFO`)。同じ形で、Step 1「リーダー」(指定しないときのおまかせと ★4 の扱い)と Step 3「曲」(曲で変わるもの・指定なしのとき)の見出しの行にも ⓘ を置く。
- ホロメンボードはカードでなくホロメンに属するので、入口もホロメン一覧から入る(カードタイルの上に入口を置かない)。
- 持っているコネクトは登録しない。所持カードと開花段階から導く(カード 1 枚 = コネクト 1 枚、％ はカード固有の効果の Lv1 / Lv2。★4 のカードのコネクトも入り、コネクトの最適化はその全部の範囲で置く。ADR-023)。枚数を ＋ / － で入れる操作は置かない。
- 「コネクト」は見るだけの画面(`ConnectInventorySheet.vue`):
  - 範囲の形 17 種を図形のタイルで 1 行 4 列に並べ、置いているか持っている形に「使用 / 所持」(ボードに置いている数 / 持っている枚数。％ を合わせた合計)を右上に出す(図形にかかる上十字だけ右下 — `badgeAtBottom`)。どれかの ％ で所持を超えて置いていれば、赤の地にする。
  - タイルを押すと、その形の ％ ごとの 使用 / 所持 を見るダイアログ(`ConnectInventoryDialog.vue`)が開く。取りうる ％ を全部並べ、両方 0 の ％ は淡色、超えている行は赤の数字にする。使っているホロメンの名前と列の見出しは置かない。数え方は `connectInventory.ts` の `connectUsage`。
  - カード 1 枚のコネクトは、カード詳細の「コネクト」(`references/parts.md`)で見せる。形の名前の文字(「右へ 3」など)は画面に出さず、図形で示す。
- リソース(`ResourceSheet.vue`)は、ボードを開けた上で余っているキューブ・コアキューブの個数を、色ごと(赤・青・黄・緑)に登録する画面:
  - 色ごとのカードを 2 列(広い画面は 4 列)に並べ、カードの中に「キューブ」「コアキューブ」のボタン(その色のキューブのアイコン + 小さな名前の下に大きな値。押すと自前のテンキー `NumberPad` で整数を入れる。上限 999,999)を置く。カードの地はその色の淡い面(`color-mix`)、コアキューブのアイコンは半透明のキューブの中の核。値は 360px 幅で 999,999・−99,999 が省略されない寸法にする。
  - 未登録は ∞(制限なし。0 とは別の値)、マイナスは不足(最適化の推奨を反映したときだけ入る。注意色で「−74」のように出す)。テンキーの小数点のキーを ∞ のキーにしてある(`NumberPad` の `infinity-key` — `references/parts.md`)。値のボタンにも、未登録は ∞ と出す(絵文字ではなく文字の ∞)。
  - 使い方(余りを入れる・どこで使うか・未登録は ∞・マイナスは不足)は、見出しのすぐ右の ⓘ から開く(脚注は置かない。中身は `RESOURCE_INFO`)。
  - ゲームではボードを開けるのにボードPt に加えてこの 2 つが要るが、このツールで手動でボードを開ける操作は個数に左右されない(手動の編集でこの登録値を自動で増減もしない)。使うのは組み直しプランと結果の「組み直すと」(ボードの段)だけで、いまのボードへ投入済みの資材 + 登録した余りを総量として、全ホロメンで共有して配り直す。推奨を反映すると、この余りも新しい盤面に合わせて置き換わる。保存は `board-resources`(`.claude/skills/storage-compat/`)。
- 「お気に入り」で見せる値は、ゲームのユニット編成画面と同じ入力(曲なし・登録している開花と 4 色ボード・コネクト・アカウント補正そのもの)で出し、メイン画面の曲も「さがす」のオプションも渡さない。ゲームのユニットと同じく、自分のボードやカードの状況だけを反映した値にするため(曲やオプションを変えるたびに登録ユニットの値が変わると不自然)。
  - 曲の反映(黄のボード欄・赤の歌唱者条件・イベント)は「さがす」の結果側だけ。登録している開花・ボードを変えれば反映される(`registeredBlooms` / `boardMap` / `greenMap` / `yellowMap` / `redMap` / `connectMap` を直接渡す。`current*` は、育てきったら・全カードで最大状態に切り替わる探索専用の値)。
  - ゲーム内の画面に対応する表示は、その画面と同じ入力だけで出す。
- お気に入りに登録できるのは、所持カードで組んだ編成だけ(6 枚すべてが所持リストにあること。開花段階は問わない)。全カードから探した結果は登録できない(入口の見せ方は `references/parts.md`)。効かせるのは登録の時点だけで、登録済みのユニットはあとで所持から外れても消さず・隠さず、お気に入り画面に出して自分で外せるようにする(`.claude/skills/storage-compat/`)。

## 組み直しプラン(`OptimizePlanSheet.vue`)

結果詳細・ユニット詳細の下端の 1 つのボタンから開く(`references/parts.md`)。名前に「育成」は使わない(さがすの「育てきったら」と紛らわしいため)。

### 何をどう最適化するか

- この編成のまま、選んだものを ボード → コネクト → 頻度 の順に最適化する。変更量を最小にするのが方針で、置いても置かなくても結果が変わらない場所は、いま置いているものをそのまま残す。
  - ボードは、ホロメンごとのボードPt の予算(ホロメンランク。未登録は制限なし)と共有の資材の範囲で、コネクトは、所持カードから導いた持っているコネクトの範囲で、いま置いている配置から、その編成の表示ユニットスコアが上がる変更だけを出す。
  - 頻度は、その盤面からメンバーごとに発動頻度マスを選ぶ。目的関数・守る制約・近似は `.claude/skills/engine-structure/` と ADR-012〜016。
  - 基準は、いま登録している状態(ボード 4 色・コネクトの解放と配置・ホロメンランク・開花・アカウント補正。探索の前提の 3 択に関わらない)と、シートの曲。
- 頻度を選んだときは、ボードは青の発動頻度マスをすべて OFF にして選び、その盤面から頻度マスを選び直して反映する。選び直しは登録の頻度マスに足す・減らすだけで、数が同じなら場所を変えない(ADR-014 / 015)。キューブ・コアキューブは、ボードの段も頻度の段も、余り + この編成に効かないマスの分の範囲で使う(ADR-016)。
- 頻度を選ばないときは、登録している頻度マスとそこまでの経路を残したまま、ボードとコネクトを選ぶ(頻度の最適化を外しただけで、登録の頻度マスを外した盤面にならないようにするため)。コネクトの評価は、頻度を選んだときは頻度マスを外した世界、選ばないときは登録の頻度マスを残した世界で行う。
- 現在のユニットスコアは、いつも登録そのまま(結果一覧と同じで、設定で変わらない。脚注 ※1)。
- キューブ・コアキューブが足りなくなるぶんは、ほかのホロメンの、この編成に効かないマスを外す変更として推奨に入る(ボードのタブの区分に出て、反映の確認で行ごとに外せる)。
- 余りが負になる推奨(所持リソースを考慮しなかった色・外せるマスが足りないとき・効かないマスを外すホロメンの行を外したとき・前から負の余り)は画面には出さず、反映の確認に一言を添える: 「赤のキューブ 10 が不足します」(共通の赤いエラー文。複数は「・」でつなぐ。不足がなければ何も添えない)。マイナスはリソースの画面に赤で出るので、「余りはマイナスで登録されます」とは書かない。余りは負のまま登録し、リソースの画面で注意色のマイナスで見せる。

### シートの構成

- 開いただけでは計算しない。シートは条件のページで、計算は下端の「最適化を実行」を押したときだけ。
- 上から順に: 現在 / 推奨のユニットスコア → 注意 → タブ「ボード / コネクト / 発動頻度」+ その右に離した「条件」のボタン → タブの中身 → 脚注。
  - タブまでは固定で、スクロールするのはタブの中身と脚注だけ。表の列見出しは、本文のスクロールの上端に貼り付く。スクロールする場所は本文の 1 か所だけにする(上部に開閉行を置くと 2 か所がスクロールし、境目が白く見切れる)。
  - ユニットスコア: 伸びの % は出さない。実行する前は現在だけ。編成 1 つの評価なので、UI スレッドで出す。
  - 注意: コネクトの登録が足りない・実行の失敗。資材の不足は出さない。
  - 脚注: ※1 は推奨の欄、※2 からは開いているタブの中身のぶんだけ出す。条件のタブは ※1 だけ。初期表示で隠す扱いは `references/parts.md` の「脚注」。
- タブ: 条件は入力で、ほかの 3 つは 1 回の結果の見方なので、同じ列の 4 択にしない。結果の 3 つは排他のセグメント、条件はピル形のボタンで、開いているときは選択の色。
  - 開いた直後は条件(いまの条件の結果を覚えているときと、結果の「組み直すと」から計算済みの結果を渡されたときは、最初の結果のタブ)。
  - 結果のタブは実行するまで disabled。実行したあとは、表示中の結果で対象にしなかったものが disabled。結果が届くと、最初の結果のタブへ移る。条件へ戻って変えても、推奨は上部に見えたまま薄くなる。

### 条件のタブ

曲 → 最適化するもの → 発動頻度の選び方 の 3 区分を、小見出しで分ける(枠では囲まない)。効かないあいだは白 + disabled にする(効いていないものを、効いているように見せないため)。

- 曲: 曲の行はメイン画面の Step 3 と同じ `SongRow` / `SongPicker`。曲は、黄の楽曲スコアボーナス・赤の歌唱者条件と、頻度のライブ側の評価区間に効く。
  - 開いた直後の曲は入口で決まる。結果詳細からは探したときの曲(メイン画面の曲をあとで変えても合わせない。結果の一覧・詳細・「組み直すと」と同じ曲)、お気に入りからは毎回「指定なし」(メイン画面で曲を選んでいても合わせない)。
  - ここで選び直す・解除できるが、選び直した曲は覚えず、次に開くとまた入口の曲で始める(`OptimizerPanel` の `optimizeSongId`)。選び直して計算した結果はキャッシュに残るので、曲と条件を合わせれば計算し直さずに出る。
- 最適化するもの:
  - 上の行に「ボード / コネクト / 発動頻度」の 3 つのチップ(独立した ON/OFF で、既定は全部 ON。最後の 1 つは外せない)。所持カードのコネクトも、ボードに置いたコネクトもないときは、コネクトは OFF で始まり、チップも disabled。下の行の左右半分に「最小限で組み直す」と「所持リソースを考慮する」。小見出しの行の右端の ⓘ で、3 つのチップと 2 つの意味を出す。
  - 「最小限で組み直す」ON(既定)は、この編成に効くところだけを組み直す:
    - ボードはリーダーとメンバーのホロメンを組み直す。ユニット外は、同じ所属の人の緑の所属マス(と経路。上限 900 まで)と、曲に効く黄を足し、その Pt はその人の効かない赤・青を外して空ける。ユニットの緑は、赤・青・黄のあとの残り Pt で、伸びの効率順に足す。緑の資材は、この編成に効かない緑(ほかの所属の所属マス・上限を超えた所属マス)を、その先のマスごと取り崩す。
    - コネクトはリーダーとメンバーだけを置き直し、ユニット外が使っているコネクトが必要で枚数が足りないときだけ、ユニット外から外す。曲を選んだときは、その曲に効く黄のマスを持つユニット外にも、そのマスに掛かるコネクトを置く(その曲のスコアを最大化するため。例: トウキョウ・シャンディ・ランデヴなら 莉々華 のソロの黄)。黄はアカウント全体に効くので、これで順位が変わらないのは想定どおり。
  - OFF は、スコアを詰めにいくときに使う。ユニット外にも効く緑ならどのマスでも足し(伸びの効率順。新しく緑を変える人には 1 人分の手間を差し引く — ADR-026)、コネクトは全ホロメンで置き直す。変えるホロメンは増える。
  - 範囲はボードとコネクトの両方にかかり、どちらも選んでいないときは disabled。計算の規則は `.claude/skills/engine-structure/`、決定は ADR-019 / 020 / 021。
  - 名前は範囲(「ユニットのみ」)ではなく、意図(最低限組み直すか、理論上限を目指すか)で付ける。ON でも、同じ所属のユニット外を変えるため。
  - ⓘ には何を組み直すかの意味だけを書く(リーダーの赤・メンバーの青・曲に効く黄・リーダーとメンバーのコネクト。ほかのホロメンは、効くマスを足すときと、効かないマスを外して Pt・キューブを回すときだけ変える)。ほかのホロメンをどう変えるかの細かい規則は脚注 ※1 に置く。
  - 「所持リソースを考慮する」は 1 つのチップで、色ごとの ON / OFF は置かない。既定 ON で、保存しない。外すと、「リソース」に登録している色をすべて、ボードと頻度の段で個数を見ずに選び、足りないぶんは不足になる。ボードを選んでいないとき・登録している色がないときは disabled。
- 発動頻度の選び方:
  - 期待値重視 / 理論値重視 / ユニットスコア重視 の 3 択のセグメント(既定は理論値重視)。小見出しの行の右端の ⓘ で、3 つの決め方と、ユニットスコアが下がることがある注意を出す。
  - その下に「頻度マスの数」の 1 行。右に固定の状態(「おまかせ」/「n人を固定」)を出し、押すと中央のダイアログ `FrequencyFixDialog.vue` で、メンバーごとに「おまかせ / 0マス / 1マス / 2マス / 3マス」を選ぶ(名前の行の下にセグメント)。発動頻度を選んでいないあいだは、両方 disabled。
  - 頻度の固定は、実効 % ではなく頻度マスの数で選ぶ。コネクトも同じ実行で変わると、実行する前には % が決まらないため。届かない数は固定しない。

### タブの中身

タブの中身は見るだけの純粋な結果で、推奨の列を固定する操作・リセット・再最適化のボタンは置かない。変更のないタブは空のままにする(「いまの置き方が最良です」の類の文は置かない。現在と推奨のユニットスコアが同じなら分かる)。

- ボード: 変更のあるホロメンだけの「ホロメン / 推奨」の 2 列(現在の列・Pt・Rank・予算・増減の数字は出さない)。頻度だけを選んだときも、頻度マスとその経路を開けるのはボードの変更なので出す。
  - 各行の推奨の欄に「ボードを開く」ボタンを置き(名前の横の矢印は置かない)、押すとそのホロメンの推奨のボードを図で開く(`BoardSheet` の見るだけの表示 `preview`)。追加するマスはそのマスの色が点滅し、解除するマスは丸の右上から左下への斜線(斜線も点滅。外れる頻度マスもこれで見える)。注釈・凡例は出さない。
  - 必須のコネクトがランクの予算に収まらず変更できなかったホロメンは、ボードのタブに警告文で出す。
- コネクト: 「ホロメン / 現在 / 推奨」(違う置き場所だけ。形の図 + ％。どのコネクトマスかは名前の下に小さく。同じホロメンの中は 中心 → 赤 → 青 → 黄)。「なし」は、外す(回す)か、新しく置く場所を示す。
- 発動頻度: 全メンバーの「ホロメン / 現在 / 推奨」と、選んだ案の見込み 3 つ(`references/parts.md`)。メンバーしかいないので、区分はリーダー・メンバーだけが押せる(見出し「メンバー」は置かない)。
- 区分のタブ: 結果のタブ(ボード・コネクト・発動頻度)の下に「リーダー・メンバー / 所属グループ / その他」の区分のタブを置く(上部の固定エリアの一番下の 32px のセグメントで、スクロールしない)。
  - 条件のタブには出さない。条件はほかのタブと扱いが違うので、高さを揃えるために disabled の枠を置くこともしない。
  - 行のない区分は disabled で、選んでいる区分に行がなければ、行のある最初の区分へ移る。区分はタブごとに覚え、本文のスクロール位置はタブと区分の組ごとに覚える(`useTabScroll` の鍵。区分を切り替えたときに、前の区分の位置から始まらないように)。
  - 並び: リーダー・メンバーは対象の編成の順(リーダー → メンバー)。所属グループ(メンバーと所属を共有するユニット外)とその他は、ホロメン順(`holomen.json` の並び。五十音順にしない)。所属グループはリーダーの所属を見ない(緑の所属マスはメンバーのカードにだけ効くので、リーダーとだけ所属が同じホロメンには効く変更がない)。`src/ui/planSections.ts`。

### 設定を変えたとき・キャッシュ

- 設定を変えたとき、いまの設定の結果を覚えていれば、計算せずにそれを出す。覚えていなければ、前の結果を消さずに薄くして残す(スコア・注意・タブの中身。「最適化を実行」で置き換わる)。薄い結果は反映できない。
- 最適化の結果は、サイトを更新するまでキャッシュし、結果詳細・お気に入りのどちらから開いたシートとも共有する(`usePlanCache.ts`)。キーは編成・開花・曲・範囲・対象・頻度の選び方と固定・資材の考慮・登録の指紋(ボード・コネクト・ランク・リソース・持っているコネクト・アカウント補正)。登録が変われば鍵も変わるので、反映しても捨てる必要がない。シートを開き直すと入口の既定の条件で始まり、条件をそのときの計算に合わせれば、その結果がすぐ出る。
- コネクトを選んだまま、ボードに置いているコネクトが所持カードのコネクトに収まっていないときは、タブの上に赤いエラー文「所持より多くコネクトを置いています」を出し、「最適化を実行」を押せなくする(`connectShortage`。所持カードが未登録でも同じ文で、未登録である旨は書かない)。設定でコネクトを外せば実行できる。超えて置くことはボードでは禁止しないので、ここで止まる(`pending.md` 18)。

### 下端の固定エリアと反映

- 下端の固定エリアは左右半分ずつ: 左「ボードに反映」(secondary)・右「最適化を実行」(実行専用の緑 `--action`)。固定エリアは結果詳細と同じ寸法(65px・ボタン 48px)。
- 「最適化を実行」は、計算中・コネクトの登録が足りない・いまの設定の結果がすでにある、のときは押せない。計算中はボタン全体をゲージにして、中央に残り時間だけを出す(段の名前・件数・中止は置かない)。計算は段(ボード → コネクトを最大 3 周 → 発動頻度)の切れ目でしか知らせないので、段ごとの目安の時間(`src/ui/planProgress.ts` の `PLAN_STEP_MS`)で見積もり、段が済んだら実測の速さで直す。周が早く止まれば、残りも減る。表示中の結果はそのまま残す。計算は Web Worker(`optimizeWorker.ts` → `optimizePlan.ts` の `planOptimize`)。
- 「ボードに反映」は、いまの設定の結果で変更があるとき(スコアが同じでも、予算の超過や頻度マスを外すなどの変更があるとき)だけ押せる。押すと反映の確認 `ApplyPlanDialog` を挟む。確認ダイアログは、シートのオーバーレイの子として出す。
  - 文言は反映する内容に合わせる: 「推奨のホロメンボードとコネクトの配置を反映しますか？」/ ボード・頻度だけ「推奨のホロメンボードを反映しますか？（コネクトの配置は変わりません）」/ コネクトだけ「推奨のコネクトの配置を反映しますか？」。
  - その下に、タブ「ボード / コネクト」(頻度マスはボードに含む)→ 区分のタブ「リーダー・メンバー / 所属グループ / その他」→ 変更のあるホロメンの行(行ごとのトグル)。ボードとコネクトは、ホロメンごとに別々に外せる。どの行も最初は ON。外したボード・配置は登録のまま残り、外したボードのぶん余りを戻す。行のないタブ・区分は disabled。ダイアログの高さはタブを切り替えても変えない。全部外すと「反映する」は押せない。余りが負になるときは上の一言を添え、外したぶんで数え直す。
  - 行は基本は独立で、片方だけでは成り立たない特殊なケースだけ連動する。連動は「この行を反映するには、あの行も反映しなければならない」という前提 1 種類で表し、入れたら前提も入れ、外したらそれを前提にする行も外す(`src/ui/planApply.ts` の `requires` / `toggleApply`)。前提になるのは次の 3 つだけで、どれにも当たらない同じホロメンのボードとコネクトは連動させない。
    1. 推奨の配置が、推奨のボードで開けたコネクトマスにある → ボードを外すと、そのホロメンのコネクトも外れる(コネクトだけ外すのは自由)。
    2. いまの配置のコネクトマスを、推奨のボードが閉じる → コネクトを外すと、そのホロメンのボードも外れる(ボードだけ外すのは自由)。
    3. コネクトを回し合うホロメン(形 × ％ ごとに、外す側を全部残しても枚数が足りないとき)→ 互いに連動する。
  - 連動はトグルが一緒に動くことで示し、「コネクトマスが開いていないので外れます」のような文や、相手を示すサブタイトルを行の下に添えない。
  - OK で、確認した時点の結果(外した行を除く)を登録して、シートを閉じる。ボード(頻度マスを含む)は、解放マスとコネクトの解放の置き換え + 余りのリソースの置き換え(不足は負)。コネクトは、全ホロメンの `connect-placements` の置き換え(`replaceConnectPlacements`。推奨に含まれない配置は外れる)。
- 「検索画面に入力」はボタンを外し、ロジック(`load` のイベントと `loadIntoSearch`)は残してある。
