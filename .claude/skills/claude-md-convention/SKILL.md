# CLAUDE.md の規約 (claude-md-convention)

Claude は毎セッションまっさらなコンテキストで始まる。CLAUDE.md は毎回説明し直さなくて済むように書き下ろしておくコンテキストであり、**毎セッション開始時に全文が**、必要かどうかにかかわらず読み込まれる — つまり全行が、その行に触れない作業にも課金される。リポジトリの鏡ではなく、「有能なエンジニアがコードを読んでも復元できない最小の事実」を選び抜いた索引として扱う。

## One Test

すべての行に、書くときも後で編集するときも問う: **この行を消したら Claude は間違えるか?** 間違えないなら削る。肥大したファイルはトークンの無駄なだけでなく、負荷のかかる規則がノイズに埋もれて半分無視される。帰結:

- **広く適用されるものだけ載せる。** 一部のタスクでしか効かないなら、他の全タスクへのオーバーヘッドでしかない。
- **書き写さず指す。** パス・スキル名・リンクの 1 行が、よそに書いてあることの再説明に勝る。
- **200 行以下を目標にする。** 強調（IMPORTANT など）は遵守が本当に懸かる少数の規則に取っておく。矛盾する 2 行を残さない — Claude はどちらかを恣意的に選ぶ。
- **行を足すのは「同じ説明を繰り返している」と気づいたときだけ。** セッションを跨いで同じ訂正を 2 回打ったらそれが合図 — ただしまず次節の振り分け表を通す。候補の大半はよそに置くべきものである。

| 載せる                                                       | 載せない                                     |
| :----------------------------------------------------------- | :------------------------------------------- |
| 推測できないコマンド（正確な起動方法・パッケージマネージャ） | コードを読めば導けること                     |
| ツールや言語の既定と異なる規約                               | Claude が既に知っている標準的な規約          |
| エントリポイントへの索引としてのディレクトリ構成             | ツリーの全ファイル解説                       |
| このリポジトリ固有の設計判断・制約                           | 詳細な API ドキュメント（リンクで指す）      |
| 他で強制されないリポジトリ運用（ブランチ・PR の作法）        | 頻繁に変わる事実（バージョン・進行中の作業） |
| 環境の癖（必須の環境変数・セットアップの罠）                 | 自明な助言（「きれいなコードを書く」）       |

## よそへ振り分けるもの

CLAUDE.md は指示の置き場のひとつにすぎない。置き場を間違えることが「無視される」か「肥大する」かの原因になる。この表は却下フィルタであって作業指示ではない: 書こうとした行が該当したら CLAUDE.md には書かず、正典である CLAUDE.md「ドキュメントの分担」の表に従って置く。

| 内容が…                                        | 置き場                                                                              |
| :--------------------------------------------- | :---------------------------------------------------------------------------------- |
| 多手順のワークフロー・ときどきしか要らない知識 | スキル — 毎セッションでなく必要時に読み込まれる（skills-convention）                |
| 特定のディレクトリ・ファイル種別に限る規則     | `.claude/rules/<topic>.md` + `paths:` glob（rules-convention）                      |
| 毎回機械的に必ず起きるべきこと                 | フックや CI — 散文は依頼、ハーネスは保証                                            |
| 作業中に見つけた規則候補・ユーザーの好み       | `docs/ai/tmp/rules.md` に induction スキルで記録（振り分けは housekeep が後で行う） |
| リンタ・フォーマッタが強制できるスタイル       | リンタ・フォーマッタの設定 — リンタの仕事を LLM にやらせない                        |
| 人間向けの説明（何であるか・使い方）           | README や `docs/human/`                                                             |

書き込み時に振り分けを考えなくてよい唯一の例外が `docs/ai/tmp/rules.md`（induction の記録先）で、たまった負債はユーザーが `/housekeep` を実行したときにこの表と照らして清算される。

## 節構成

このリポジトリの CLAUDE.md の節構成（ディレクトリ構成・コマンド・技術スタック・ドキュメントの分担・注意点）を正とし、勝手に節を増やさない。どの節にも収まらない内容は上の振り分け表を通す。本文は日本語で書く（「注意点」参照）。
