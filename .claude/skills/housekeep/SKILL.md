# 棚卸し (housekeep)

あなたはこのリポジトリのドキュメントを棚卸しし、すべての内容を正しい置き場に戻す。分担表の正典は CLAUDE.md の「ドキュメントの分担」、読者向けの索引は `docs/index.md`。棚卸しはコンパクション直前に行われることが多く、タスク完了のタイミングとは限らない — クローズ(手順6)は完了しているときだけ行う。指示がない限り commit / push はしない。

## 手順

`docs/ai/tmp/` の各ファイルに関する項目は、該当ファイルがないときはスキップする。

1. 全部読む: `docs/index.md`、`docs/ai/rules/` の全ファイル、`.claude/rules/` の全ファイル(あれば)、`docs/ai/tmp/` の全ファイル(あれば)、このプロジェクトのネイティブメモリの索引。メモリはポインタと習慣として尊重し、メモリの内容をリポジトリのドキュメントへ書き写したり、その逆をしたりしない。
2. `docs/ai/tmp/rules.md` を昇格する — ファイルが存在する限り必須で、昇格しないまま棚卸しを終えてはならない。昇格先は CLAUDE.md の「ドキュメントの分担」の判定に従う:
   - パス単位のルール → `.claude/rules/<topic>.md`(必ず `paths:` glob つき)
   - 覆しにくい決定だったと判明したもの → `docs/adr/`(形式は `docs/adr/index.md` 冒頭)
   - ドメイン・プロジェクトの事実だったもの → `docs/human/` + `docs/index.md` への行追加
   - それ以外の恒久ルール → `docs/ai/rules/<topic>.md` + `docs/ai/rules/index.md` への行追加
   - まだ一般化できない事例は tmp/rules.md に残す。昇格済み・無効化された項目は削除する
3. `.claude/rules/` を棚卸しする: 各ルールの glob が実在するファイルにマッチするか、制約が今も正しいかを確認する。陳腐化したものは修正し、削除はユーザーに提案してから行う。
4. 揮発性ドキュメントを現状に合わせる:
   - tmp/plan.md: 完了したフェーズは完了サマリへ縮約する。未解決の項目は tmp/pending.md へ移す
   - tmp/progress.md: 完了済み項目の詳細を要約に縮める
   - tmp/pending.md: 各項目を現状と突き合わせ、解消済みのものを落とす(削除前に現状を確認して裏取りする)
   - `docs/human/tmp/` は棚卸しの対象外 — 日付つきスナップショットの削除はユーザー自身の判断で行う
5. tmp/progress.md にコンパクション地点のログを書く: 未コミット / 未 push の変更、次のアクション、参照すべき方針の場所。
6. タスクが完全に完了している場合のみクローズする: 残す価値のあるものを昇格(残すべき意思決定 → ADR へ、ルール → 手順2の昇格先へ、人間向けの事実 → `docs/human/` + `docs/index.md` への行追加、残す価値のある事例 → 関連するルールファイルへ例として統合)したうえで、`docs/ai/tmp/` を丸ごと削除する。`docs/index.md` の tmp の行は予約リンクなのでそのまま残す。
7. `docs/index.md` を更新する: 実在する全ドキュメントに行があり、移動した内容を指す行がない状態にする。
8. 報告する: 昇格・移動・削除したものと、ユーザーの判断が必要なものを報告する。
