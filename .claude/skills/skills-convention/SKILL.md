# Skills-Convention

スキルには **noun 型** と **verb 型** の 2 種類がある。noun 型は知識のスキルで、Claude が `description` との一致を見て自動で読み込む。三人称で「何であるか／どうあるか」を定める。verb 型はコマンドのスキルで、ユーザーが `/<name>` で呼び出す。二人称で、手順を順番に実行させる。書き始める前に、どちらの型にするかを決める。型によって frontmatter、本文の語り口、下のどのリファレンスを開くかが変わる。

## 段階的開示（Progressive Disclosure）

スキルは 3 段階で読み込まれる。以下のルールはどれも、コンテキストの消費を抑えるためのものである。

- **本文は 150 行以下を目標にする。** 本文が長いと、スキルが起動するたびにその分のトークンを消費し、一度読み込まれるとセッションが終わるまでコンテキストに残り続ける。
- **リファレンスは 1 階層に留め**、すべてのファイルに `SKILL.md` から直接リンクし、「いつ読むか」を 1 行添える。リンクされていないファイルや深くネストしたファイルは、Claude に読まれない（Claude はリンクを何段もたどる途中で部分的にしか読まず、内容を取りこぼす）。
- **100 行を超えるリファレンスファイルには目次（Contents）を付ける。** ルールや対応関係は、散文より表を優先する。

## 書き方

- **MUST/NEVER を積み上げるより、理由を説明する。** 理由が書いてあれば、Claude は書かれていない場面にもルールを当てはめられる。強い ALWAYS/NEVER は、実際に観測された落とし穴のために取っておく。
- **Claude は賢いと仮定する。** 一般的な説明は削り、自分たちの規約、落とし穴、正確なコマンドだけを足す。5 つの選択肢を並べるより、既定を 1 つ選ぶ。
- **`description` は本文と同じく日本語で書く。** 起動の手がかりになるファイル名・コマンド・製品名は原語のまま残す。
- **H1 はスキル名にする。** ディレクトリ名のハイフン区切りの各語の先頭を大文字にする（`changelog-convention` → `# Changelog-Convention`）。スキルが何かは `description` と本文の見出しで分かるので、H1 で説明し直さない。
- **ディレクトリ構成**: `assets/` には画像などの静的ファイルを、`references/` にはオンデマンドで読み込まれるリファレンスファイルを、`scripts/` には実行可能なスクリプトを置く。
- **すべてのスキルにバージョンを付ける。** `SKILL.md` やそれに同梱されるファイルを編集する変更と同じ変更で、frontmatter の `version` フィールドを更新する。形式は `yyyy-mm-dd-nn`（例: `2026-07-15-01`）とし、semver は使わない。更新が簡単で、並べ替えもできる。
