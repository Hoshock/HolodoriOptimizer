# コネクトの最適化

- コネクトの最適化は、所持のコネクトの範囲で、いま置いている配置から良くなる変更だけを重ねる、探索とは別の計算(`connectOptimize.ts` の `assignConnects` + `connectPlan.ts` の `planConnects`。ADR-008)。
- 所持(形 × ％ × 枚数)は、所持カードと開花段階から `connectInventory.ts` の `connectInventoryOf` が導く(ADR-023)。
- 確定するのは、その編成 1 つのユニットスコアが厳密に上がる変更だけ。変更量を最小にする方針で、置いても置かなくても同じ場所は現状維持にする。返す配置のスコアは、いまの配置以上になる。
- 空から置き直さない。空から置き直すと、所持にない形を置いている場所や効果が 0 の場所が「なし」へ落ち、変更が膨らむ。
- 変えてよい範囲は `scope`(`ConnectScope`。組み直しプランの `minimal` は `unit` に当たる)。
  - `unit`: リーダーとメンバーのホロメンだけ。枚数が足りないときだけ、外して失うスコアが最小の場所(同じならユニット外を先に)から回す。曲を指定したときは、その曲の楽曲スコアボーナスに入る黄のマスを持つユニット外にも、その黄のマス(解放済み)に掛かる置き方だけを足す(`songYellow`。`connectPlan.ts` が `yellowNodeAffectsSong` で作る)。
  - `all`: 全ホロメン。
- 評価は、6 枠固定の依頼と同じ値になる経路にする(`createTeamScorer` が編成の 6 枚だけを解決し、`scoreTeam` で評価する)。画面の値と「同じ配置を登録して出した値」が一致するようにするため(`connectOptimize.test.ts`)。
- 選び方は遅延評価の貪欲法。変更先ごとに 1 枚置いたときの増分を測り、大きい順に取り出して、置く直前に測り直す。近似であることを脚注に書く。精度は `docs/ai/tmp/pending.md` 18。
- 効かない候補は試さない(解放済みのマスに掛からない、スコアに効かないマス、効かない色)。
- いまの配置が所持に収まっていることは、呼び出し側(OptimizerPanel の `placementShortage`)が先に確かめる。収まっていなければ最適化せず、エラー「所持より多くコネクトを置いています」を出す(所持カードが未登録でも同じ文)。
- 目的は表示ユニットスコアだけで、ライブの理論値を最大にする置き方とは一致するとは限らない(`.claude/skills/parameter-calculation/references/connect-effect.md`「コネクトの最適化の性質」)。
