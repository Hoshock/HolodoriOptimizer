# 発動頻度マスの最適化

青ボードの発動頻度マス(B-013 / B-020 / B-031)をどう選ぶかの約束。発動頻度は表示モデルとライブモデルの両方に効くので、モデルを混ぜないことがいちばん効く。

## 3 つの目的関数を混ぜない

- 発動頻度マスの目的関数は 3 つある。ライブ側の 2 つ(期待値 / 理論最大 — `liveFrequencyOptimizer.ts`)と、表示ユニットスコアを最大にする 1 つ。モデルは混ぜない。
- 3 つとも最適化の頻度の段(`frequencyStage.ts`。ADR-015)が持つ。候補(メンバーごとの頻度マスの部分集合とその盤面)を作るのはこの段で、評価は各モデルが自分の式で行う。表示側の評価は `createTeamScorer` を使い、`frequencyStage.ts` 側に閉じ込める。
- 推奨のユニットスコアは頻度マス込みの値を出し、`W_blue` を通る近似であることを脚注に書く。
- 目的関数と推薦ポリシーを混同しない。ゲーム仕様の仮定(周期・確率の式)と、どの案を勧めるかの方針(`FREQUENCY_RECOMMEND_POLICY` の「0.1 ポイント以内なら省素材を選ぶ」など)は別の定数に分け、UI の脚注でも「ゲームの仕様ではなくこのツールの方針」と書く。主目的関数はユーザーに見せる 2 つ(期待値 / 理論最大)だけにし、カバレッジ・空白は tie-break と表示にとどめる(ADR-007)。
- `liveFrequencyOptimizer.ts` の `enumerateFrequencyCandidates` / `buildFrequencyMembers` は画面からは使っていない。

## 候補の作り方

- 候補はボードの連結性から作る。「マスを開ける」選択肢を `[0, 4, 8, 12]%` と仮定せず、`blueBoard.ts` の `unlockNode` で、いまの解放マスから到達できる状態を列挙する。
- 列挙は「いまの値から増やす方向」だけにしない。発動頻度マスは 3 つとも葉なので、いま ON のマスをそのマスだけ外す候補(`removedNodeIds`)も含めて、ON / OFF の全組合せを比べる。頻度マス以外の解放済みマスは固定する。コスト(`additionalNodeCount`)は新しく開けるマスだけ数える。外すと素材は返ってくるので、この値はこれから払う素材の上限になる。いまの状態そのもの(追加 0・外す 0)は必ず候補に含める。
- 候補は登録の頻度マスの部分集合か上位集合だけにする。同じ数なら登録のまま、増やす・減らすときも登録に足す・減らすだけ。3 マスとも +4% で違いは経路だけなので、同じ数で場所だけ替える推奨には意味がない。
- 頻度の固定は頻度マスの数(0〜3)で行う。実効 % はコネクトも同じ実行で変わるので、実行前には決まらない。固定で候補を絞ると `FrequencyPlan.choice` の添字が変わるので、案は絞ったあとのメンバーから引く(候補の同一性で元の添字へ戻す)。
- 経路は、前の段の盤面から追加のボードPt が最小のもの(`BoardGraph.planUnlock`。コネクトの明示解放を含む)だけを使う。遠回りして P/T/S を多く拾う開け方は探索していないので、UI の脚注にもそう書く。
- ホロメンランクの Pt は超えない。足りない候補は経路を必須にしたまま、そのホロメンの 4 色のマスから「外して失う表示ユニットスコア ÷ 空く Pt」が小さいものを外して空ける。空けられなければ候補にしない。
- 資材は、余りとこの編成に効かないマス(外して回せる — `recoverableMaterials`)の範囲に収める(ADR-016。`materialLimits`)。所持リソースを考慮しない色は制限なし。余りは外して回すぶん負になる。

## 候補の畳み方

- 発動率 % / 発動頻度 % が同じだからといって候補を畳まない。青ボードには P/T/S のマスが並び(`src/data/blueBoard.ts`)、どの頻度マスへ行くかで経路上に拾うパラメータが変わる。畳んでよいのは、解放マスの集合が同じ候補だけ。ライブ側は P/T/S を見ないので畳み方が違い、これも「混ぜない」理由の 1 つ。

## コネクトの増幅

- 青ボードの実効値は、ライブ側も表示側もコネクトの増幅込みにする。`liveFrequencyOptimizer.ts` は `buildFrequencyMembers(..., connect)` → `enumerateFrequencyCandidates(currentNodeIds, factors)` → `blueBoardEffects(unlocked, factors)` で、いまの状態と全候補に同じ倍率表(`src/data/connect.ts` の `connectFactorsOf(...).blue`)を当てる。範囲・倍率の計算を `live*.ts` 側へ作り直さない。
- 候補の畳み込みは効果の値で決まるので、増幅で値が割れると、同じマス数の候補が分かれることがある。
- 発動頻度の最適化(`liveFrequencyOptimizer.ts`)は、青のコネクトを解放済みとして扱う。
