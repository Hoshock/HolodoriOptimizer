## 目的と評価

- ホロメンボードの最適化は、固定した編成の表示ユニットスコアを、ホロメンごとのボードPt と共有の資材の範囲で大きくする、探索とは別の計算(`boardOptimize.ts` の `optimizeBoards` + `boardPlan.ts` の `planBoards` + `optimizeWorker.ts`。出所・前提は ADR-012、資材は ADR-013)。ライブスコアの式は目的にしない。
- 選び方の決まりの正典は [ADR-029](../../../../docs/adr/029-rebuild-board-rules.md)。このファイルには、決まりと実装の対応と、実装で壊しやすいところだけを置き、決まりの本文は書き直さない。決まりを変えたら ADR を書き、ここは識別子の対応だけを直す。
- 評価はコネクトの最適化と同じ `createTeamScorer` の経路を通し、画面の値と一致させる(`boardOptimize.test.ts`)。
- グラフの規則は `src/data/boardGraph.ts`、状態と操作は `boardState.ts`。
- コネクトの最適化は、解放済みのコネクトマス(と中心)にだけ置く(`assignConnects` の `unlockedConnects`)。

## どの結果も守る制約

1. ボードPt: ランク登録済みのホロメンは「通常マスの Pt + 解放した非中心コネクトの Pt ≤ 累積ボードPt」。未登録は制限なし。
2. 連結: 解放済みのセルは、すべて中心から解放済みのセルだけで届く。
3. コネクト: 配置は変えない。配置のある非中心コネクトは必ず解放済みにする(1 Pt を予算に含む)。足りないホロメンは変更せず、`infeasible` に載せる。
4. 資材: キューブ・コアキューブは色ごとにアカウントで共有する資材(マス別の消費量は外部 master 由来の `src/data/boardMaterials.ts`)。
   - 再配分できる総量は、変える可能性のあるホロメンの投入済み + 余り + 変えないホロメンのこの編成に効かないマス(`recoverableMaterials`。端から外せるものだけ。緑は静的に入れず、取り崩し `release` が扱う — ADR-016)。未登録の項目は制限なし、0 は「余りが 0 個」。
   - 候補は、ボードPt と資材の両方に収まるときだけ採る。資材に上限のある色では、Pt・cube・core の非劣な経路をすべて試す(`BoardGraph.planUnlockRoutes`)。
   - 推奨を反映するときは余りも置き換える(`remainingAfter`)。手動のボード操作は資材で止めず、余りを増減する(ADR-013)。
5. スコアに効かないマス(報酬系、ユニットにいない所属向けなど)は、ランク未登録でも開けない。

## 選び方(近似)

- 遅延評価の貪欲法。ターゲットのマスまでの未解放の経路一式を 1 つの候補とし、追加の Pt と伸びで測る。最大は保証しない(`docs/ai/tmp/pending.md` 8)。
- 出発点は「必須だけ(ゼロから)」と「登録」の 2 つ。
- 順は「伸び ÷ Pt」「伸び」「伸び ÷ 資源の消費の割合」の 3 通り。資源の消費の割合は、残りの Pt・共有の残りの資材に対して測る(`scarcity`)。予算・総量に対して測ると、Pt の余っているユニット外でも Pt が勝って、キューブあたりの効率を拾えない。
- 出発点どうしは、選ばれなかった登録済みのマスを予算が許す限り戻したあとのスコアから、緑を変えたユニット外の人数分の手間を引いて比べる。同点は登録に近いほう。土台を下回れば土台を返す。

## 決まり(ADR-029)と実装の対応

ルールごとの意図は `boardOptimizeMinimal.test.ts` で固定する。

- 順位の例外: `tier`(最小限のリーダー・メンバーの緑と、形 A の「先へ」`beyond` は最後)。
- 外してよいマス: `removable`(巻き込みは認める)。
- 手間: 範囲ごとの `NEW_HOLOMEN_COST_RATIO`(最小限 0.05%・全整理 0.02%)。緑が変わったか(`touchesGreen`)だけを見て、赤・青・黄だけの変更は入れない。
- 緑の形: `unitRoleOf`(効く所属マス)→ `alignedGreen`(形 B は `GREEN_TRUNK`、形 A は `GREEN_UPPER`)/ `shapeOf`(経路まで外れるなら取らない。そろえて外すマスは `reclaim` の緑に入れて損を差し引く)。
- 「先へ」を始めるのは、登録を戻したあとの 2 周目だけ(`allowRelax` / `relaxed`)。
- 範囲(`scope`。画面の「最小限で組み直す」ON / OFF)で違うのは、ユニット外に足してよいマス(`extendedTarget`)と、整合していないユニット外を組み直すかどうか。
- 緑をホロメンの間で移さない取り置き: `greenRoom`。

## 壊しやすいところ

- 待ち行列の候補を測り直したら、外して空けるマス(`reclaim`)と順位の印(`relaxed` / `beyond`)も測り直した値に差し替える。古い `reclaim` のまま確定すると Pt が予算を超え、`collect` の安全弁でそのホロメンの変更ごと結果から落ちる。
- 「先へ」(`tier` 3)を取る前に、同じ周で確定したホロメンのマスを測り直して列に入れる。確定で取れるようになったマスを次の周まで待たせると、先を越される。
- ユニット外の Pt が足りないときは、外してよいマスを端から Pt の大きい順に外す(`reclaimFor`。配置のあるコネクトへの経路は残す)。赤・青・曲に効かない黄の資材は総量に静的に入れてあるので、`avail` へは戻さず `reclaimed` に記録する。緑と上限を超えた黄の資材は戻す。
- 緑の資材が足りないときは、`release` を 1 人ずつ試す(空く資材が多い人 → 失うスコアが小さい人 → 依頼の順)。報われなければ(伸び − 失った分 ≤ 手間)戻して止める。
- 登録の足し戻しのあと、緑が登録と違う人を形にそろえ直す(新しく開けたユニット外を先に)。最小限オンのユニット外で効く所属マスが残らない人は、新しく開けたマスを取り消す。

## 発動頻度マスの扱い(ADR-014)

- 頻度の段を選んだときは、青の発動頻度マス(B-013 / B-020 / B-031)をすべて OFF にしてボードを最適化する。頻度の配分は、そのあとの頻度の段が担当する。頻度マスは葉なので、外しても他のマスは孤立しない。
  - 変えてよいホロメンは、登録の頻度マスを外した状態(`withoutFrequencyNodes`)から出発し、頻度マスはターゲットにも経路にもしない。
  - 「現在」のスコアも頻度マスを外した状態の値で、評価器(`planBoards`)は変えないホロメンの頻度マスも外して評価する。
  - 結果は土台(頻度マスを外した登録)を下回らない。例外は登録が予算を超えているホロメンで、予算内へ直すので下がってよい。
- 頻度の段を選ばないときは逆に、登録の頻度マスとそこまでの経路を必須として残す(`keepFrequency`)。

## 組み直しプランの段(ボード → コネクト → 頻度)

- ボードとコネクトは、1 つの入口(組み直しプラン)の中で、選んだものだけ最適化する(`boardConnectPlan.ts` の `planBoardConnect`。ADR-014)。
  - 両方を選ぶとボード → コネクトの順で、スコアが上がらなくなるまで最大 3 周する。各段は土台を下回らない。
  - 段の間では、ボードは最適化後の盤面と余りのリソース(`remainingAfter`)を、コネクトは最適化後の配置を、次の段の出発点にする。
  - 範囲(`scope`)はボードとコネクトの両方にかかる。
- 頻度は最適化の最後の段(`optimizePlan.ts` の `planOptimize` + `frequencyStage.ts`。ADR-015)。ボード → コネクトのあとの盤面から頻度マスを選び、経路が盤面で一意に決まるので反映もする。「現在」はいつも登録そのまま(頻度マス込み)。
- 資材は色ごとに考慮を外せる(`relaxedMaterialColors`。画面は全色まとめての 1 つ — ADR-017)。外した色はボードの段で制限なしとして選び、`remainingAfter` は登録の値から出すので、負(不足)になりうる。ランクの Pt は外せない。
- 最後に、余りが負になった資材(考慮する色だけ)を、この編成に効かないマスを外す差分として推奨に入れる(`coverDeficits`。ADR-029 のルール 2)。順は、すでに変えるホロメン → 効かないマスの資材が多いホロメンで、端から足りるまで外す。外してもスコアは変わらない。
- 各段の途中の余りは、外して回すぶん負になりうる。推奨の余りが負になるのは、所持リソースを考慮しなかった色と、外せるマスが足りないときだけ。

## 結果の「組み直すと」(ADR-016)

- 見込みのボードで候補を選んでから `planOptimize` をかける(`trueRanking.ts` → `rankingWorker.ts`)。
  1. ホロメンごとに、ランクの Pt の範囲で最適化した見込みの盤面を、探索の 1 位にそのホロメンを入れ替えた仮の編成で作る。
  2. 見込みの盤面で、探索と同じ条件で探す。
  3. 見込みの上位 100 件と探索の上位 30 件を最適化する。
- 見込みは候補を選ぶだけの近似で、探索(`optimize.ts`)の順位づけには入れない。
- 3 段はどれも互いに独立した仕事の集まりなので、Worker を何本か立てて配る(`useTrueRanking`。ADR-018)。仕事は 1 件ずつ空いた Worker へ渡し、段の切れ目で全部の結果を仕事の並びの順にまとめる(`assembleProxyBoards` / `pickRankingTeams`)。こうすると、何本で計算しても 1 本と同じ結果になる。
