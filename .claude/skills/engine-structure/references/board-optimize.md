## 目的と評価

- ホロメンボードの最適化は、固定した編成の表示ユニットスコアを、ホロメンごとのボードPt の予算内で最大にする、探索とは別の計算(`boardOptimize.ts` の `optimizeBoards` + `boardPlan.ts` の `planBoards` + `optimizeWorker.ts`。出所・前提は ADR-012、資材の共有制約は ADR-013)。ライブスコアの式は目的にしない。
- 評価はコネクトの最適化と同じ `createTeamScorer` の経路を通し、画面の値と一致させる(`boardOptimize.test.ts`)。
- グラフの規則は `src/data/boardGraph.ts`、状態と操作は `boardState.ts`。
- コネクトの最適化は、解放済みのコネクトマス(と中心)にだけ置く(`assignConnects` の `unlockedConnects`)。

## どの結果も守る制約

- 資材: キューブ・コアキューブは色ごとにアカウントで共有する有限の資材(マス別の消費量は外部 master 由来の `src/data/boardMaterials.ts`)。「リソース」の登録値は余りなので、再配分できる総量は次の和になる。
  - 変える可能性のあるホロメンの、いまのボードへ投入済みの資材
  - 余り
  - 変えないホロメンの、この編成に効かないマス(`recoverableMaterials`。ADR-016 / 019 / 026)。赤はリーダー以外・青はメンバー以外の全部、黄は指定した曲の楽曲スコアボーナスに入らないマス、報酬のマス。効くマスや、配置のあるコネクトへの途中のマスは外せないので、端から数える。緑の全員・パラメータ・所属のマスは静的には入れず、取り崩し(`release`)が動的に扱う。
  - 未登録の項目は制限なし。0 は「余りが 0 個」。
- 候補は、ホロメンのボードPt と共有の資材の両方に収まるときだけ採用する。資材に上限のある色では、Pt・cube・core の非劣な経路をすべて評価する(`BoardGraph.planUnlockRoutes`)。
- 推奨を反映するときは、余りのリソースも新しい盤面に合わせて置き換える(`BoardPlanResult.remainingAfter`)。手動のボード操作は資材で制限しない。
- ボードPt: ランク登録済みのホロメンは「通常マスの Pt + 解放した非中心コネクトの Pt ≤ 累積ボードPt」。未登録は制限なし。
- 連結: 解放済みのセルは、すべて中心から解放済みのセルだけで届く。
- コネクト: 配置は変えない。配置のある非中心コネクトは必ず解放済みにする(1 Pt を予算に含む)。足りないホロメンは変更せず、`infeasible` に載せる。
- ランク未登録でも、スコアに効かないマス(報酬系、ユニットにいない所属向けなど)は開けない。

## 選び方(近似)

- 遅延評価の貪欲法。ターゲットのマスに必要な未解放の経路一式を 1 つの解放プランとして、追加 Pt と増分で評価する。
- 出発点は「必須だけ」と「登録している状態」の 2 つ。順は「増分 ÷ Pt」と「増分」の 2 通り(資材に上限があるときは「増分 ÷ 資源の消費の割合」も)で、最良を選ぶ。同点は登録に近いほう。
- 土台を下回るときは土台を返す。効かず選ばれなかった登録済みのマスは、予算が許す限り戻す。戻すのは出発点ごとで、出発点どうしは、戻したあとのスコアから新しく触った人数分の手間を引いて比べる。
- 最大は保証しない(`docs/ai/tmp/pending.md` 8)。

## 組み直しの 3 つのルール(ADR-026)

本質は「Pt あたりのステータスの伸び」と「変えるホロメンを少なく」の 2 つで、ルールはそれを実装に落としたもの。ルールごとの意図は `boardOptimizeMinimal.test.ts` の「組み直しの 3 つのルール」で固定する。

1. 開ける順は効率だけで決める。「伸び ÷ Pt」「伸び」「伸び ÷ 資源の消費の割合」の 3 通りで最良を採り、色の順位や十字の特別扱いはしない。例外は「最小限」のリーダー・メンバーの緑で、赤・青・黄とユニット外の緑のあとに、残った Pt で効率順に開ける(`tier`)。
2. 外してよいのは、この編成に効かないマスだけ(`removable`)。ユニット外の赤・青の全部、曲に効かない黄、報酬、メンバーの所属に効かない所属マス、上限で頭打ちのマス。頭打ちかどうか(+900 を超えた所属マス、10.0% を超えた黄)は、外しても伸びが減らないことをスコアで確かめる。
   - ユニット外の全員・パラメータの緑は外す対象にしない。ただし効かないマスを外すとき、その先にあって中心から切れるマス(全員・パラメータも)は一緒に外れる(巻き込み)。巻き込みは認め、その損は取り崩しの損得で差し引く。
   - リーダー・メンバーは組み直すので、何を外してもよい。
3. 新しく触る手間を数える。まだ緑を変えていないユニット外のホロメンの緑を初めて変えるときは、伸びからいまのスコアの 0.05%(`NEW_HOLOMEN_COST_RATIO`)を差し引く。取り崩しの損得・出発点どうしの比較も同じ。赤・青・黄だけの変更は数えない。手間をいちばん考えたいのは緑で、ほかの色は変えるユニット外が少ないため。

## 範囲(scope)と、ユニット外の Pt・資材の空け方

- 範囲(`scope`。画面の「最小限で組み直す」ON / OFF)の違いは、ユニット外に足してよいマスだけ。
  - リーダー・メンバーは、どちらでも組み直す。
  - ユニット外(登録が整合している人)は、どちらでも登録から足す・外すだけ(`extended`)。
  - `minimal` で足せるのは、メンバーの所属に効く緑の所属マス(G-008 / G-011 / G-021。`affiliationEffectOf` で所属を引く。そのマス自体が効くときだけで、+900 に達していれば経路の全員マスを口実に開けない)と、指定した曲に効く黄のマス(`yellowNodeAffectsSong`)。
  - `all` で足せるのは、緑ならどのマスでもと、曲に効く黄。
  - 全整理で登録が整合していないユニット外だけ、ゼロから組み直す。
- 緑をホロメンの間で移さない。ゼロから組み直したリーダー・メンバーが外した登録の緑の資材は、登録を戻す段まで、ほかのホロメンの全員・パラメータの緑に使わない(取り置き `greenRoom`)。
- 待ち行列の候補を測り直したら、外して空けるマス(`reclaim`)も測り直した値に差し替える。古い `reclaim` のまま確定すると Pt が予算を超え、`collect` の安全弁でそのホロメンの変更ごと結果から落ちる(`boardOptimizeMinimal.test.ts` で固定)。
- ユニット外の Pt が足りないときは、外してよいマスを端から Pt の大きい順に外して空ける(`reclaimFor`。配置のあるコネクトへの経路は残す)。赤・青・曲に効かない黄の資材は `recoverableExtended` で総量に静的に入れてある(この段ではボードを変えない)ので、`avail` へは戻さず `reclaimed` に記録する。緑と上限を超えた黄の資材は戻す。
- 緑の資材が足りなくなったら、`release`(効かない緑を先のマスごと外す)を 1 人ずつ試す。順は、空く資材が多い人 → 失うスコアが小さい人 → 依頼の順。報われなければ(伸び − 失った分 ≤ 手間)戻して止める。

## 発動頻度マスの扱い(ADR-014)

- 頻度の段を選んだときは、青の発動頻度マス(B-013 / B-020 / B-031)をすべて OFF にしてボードを最適化する。頻度の配分は、そのあとの頻度の段が担当する。頻度マスは葉なので、外しても他のマスは孤立しない。
  - 変えてよいホロメンは、登録の頻度マスを外した状態(`withoutFrequencyNodes`)から出発し、頻度マスはターゲットにも経路にもしない。
  - 「現在」のスコアも頻度マスを外した状態の値で、評価器(`planBoards`)は変えないホロメンの頻度マスも外して評価する。
  - 結果は土台(頻度マスを外した登録)を下回らない。例外は登録が予算を超えているホロメンで、予算内へ直すので下がってよい。
- 頻度の段を選ばないときは逆に、登録の頻度マスとそこまでの経路を必須として残す(`keepFrequency`)。

## 組み直しプランの段(ボード → コネクト → 頻度)

- ボードとコネクトは、1 つの入口(組み直しプラン)の中で、選んだものだけ最適化する(`boardConnectPlan.ts` の `planBoardConnect`。ADR-014)。
  - 両方を選ぶとボード → コネクトの順で、スコアが上がらなくなるまで最大 3 周する。各段は土台を下回らない。
  - 段の間では、ボードは最適化後の盤面と余りのリソース(`remainingAfter`)を、コネクトは最適化後の配置を、次の段の出発点にする。
  - 範囲(`scope`)はボードとコネクトの両方にかかる。
- 頻度は最適化の最後の段(`optimizePlan.ts` の `planOptimize` + `frequencyStage.ts`。ADR-015)。ボード → コネクトのあとの盤面から頻度マスを選び、経路が盤面で一意に決まるので反映もする。「現在」はいつも登録そのまま(頻度マス込み)。
- 資材は色ごとに考慮を外せる(`relaxedMaterialColors`。画面は全色まとめての 1 つ — ADR-017)。外した色はボードの段で制限なしとして選び、`remainingAfter` は登録の値から出すので、負(不足)になりうる。ランクの Pt は外せない。
- 最後に、余りが負になった資材(考慮する色だけ)を、この編成に効かないマスを外す差分として推奨に入れる(`coverDeficits`。ADR-026)。順は、すでに変えるホロメン → 効かないマスの資材が多いホロメンで、端から足りるまで外す。外してもスコアは変わらない。
- 各段の途中の余りは、外して回すぶん負になりうる。推奨の余りが負になるのは、所持リソースを考慮しなかった色と、外せるマスが足りないときだけ。

## 結果の「組み直すと」(ADR-016)

- 見込みのボードで候補を選んでから `planOptimize` をかける(`trueRanking.ts` → `rankingWorker.ts`)。
  1. ホロメンごとに、ランクの Pt の範囲で最適化した見込みの盤面を、探索の 1 位にそのホロメンを入れ替えた仮の編成で作る。
  2. 見込みの盤面で、探索と同じ条件で探す。
  3. 見込みの上位 100 件と探索の上位 30 件を最適化する。
- 見込みは候補を選ぶだけの近似で、探索(`optimize.ts`)の順位づけには入れない。
- 3 段はどれも互いに独立した仕事の集まりなので、Worker を何本か立てて配る(`useTrueRanking`。ADR-018)。仕事は 1 件ずつ空いた Worker へ渡し、段の切れ目で全部の結果を仕事の並びの順にまとめる(`assembleProxyBoards` / `pickRankingTeams`)。こうすると、何本で計算しても 1 本と同じ結果になる。
