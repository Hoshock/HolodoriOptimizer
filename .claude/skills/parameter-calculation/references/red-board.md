赤ホロメンボードは全体配置の**上**にあり、リーダー用の効果を持つ（カード詳細の P/T/S には反映されない — 2026-09-06 実機確認）。構成は全ホロメン共通で、**上エリア / ライフ系エリア / ステータス系エリア**の 3 エリアからなる。ライフ系が左か右かはホロメンごとに固定で `src/data/holomen.json` の `board.lifeSide`（ステータス系はその反対。青の左右 `blueSide` とは別）。座標は青・緑・黄と同じ向きで、x は右が正・**y は上が正**、`(0, 0)` が全ボードの中心のコネクト。効果は**そのホロメンをライブのリーダーにしているとき**だけ効き、「全員の」は**メンバー 5 人**（リーダーは含まない。リーダーとメンバーは別枠で、同じホロメンとは限らない — 2026-09-08 ユーザー確認）。解析由来の情報は参考にとどめ、確定は実機確認で行った（`.claude/rules/game-facts.md`）。実装は `src/data/redBoard.ts`（ツールのマス内の記号は A / P / T / S / 支 / 命 / 判 / 回 / 経 / 金 — 2026-09-08 ユーザー承認）。

## 仕様（確認済み）

- 全体配置の上。`(0, 0)` の人物アイコン（全ボードの中心のコネクト）から上へ幹が伸びる。
- 幹の中央から 7 マス目 `(0, 7)` に**赤ボード内のコネクトマス**（人物アイコン）があり、そこから左右へ枝が分かれる。青・黄と同じく入力対象ではなく、通路として常に通れる扱い。
- 左右の枝の一方が**ライフ系エリア**（ライフ・判定強化・ライフ回復・メンバー Exp・ホロゴールド）、他方が**ステータス系エリア**（P/T/S・全パラメータ・スコアサポート）。`lifeSide = left` のホロメン（ときのそらなど）はライフ系が左、`lifeSide = right`（白上フブキなど）は**上エリアを含めて**全体が左右反転 `(x, y) -> (-x, y)` で、形は同じ。
- 座標は `lifeSide = left` を基準に書く。
- 効果はリーダー用: そのホロメンをリーダーにしたライブで、**メンバー 5 人**の「全員の〜」に効く。リーダー自身のパラメータには効かず、カード詳細の P/T/S にも反映されない。
- 歌唱者条件のマス（R-002・R-044・R-062・R-063）の文言は「このホロメンが楽曲歌唱者に含まれる時、全員の〜」。
- マスの表示値は表記値（コネクト増幅前）。実機の合計表示はコネクト増幅込み（アカウントの現在値は `docs/ai/tmp/status.md`）。

## ツールでの扱い

- **入力**: Step 0 の「ホロメンボード」→ ホロメン → 赤タブ。63 マスを下 / 左 / 上 / 右の 4 エリア（下 = 中心から C を経て R-021 までの幹、上 = 最上部の格子、左右 = ライフ系とステータス系で、どちらが左かは `lifeSide`）に分けて描き（最初は下）、枝が画面の外へ続く位置の出口（◀左 / ▲上 / 右▶ / ▼下）をタップして移動する（別のトグルやスワイプは置かない — 2026-09-08 ユーザー指示。解放のグラフは 1 つ）。マスの間隔はステータス系エリアだけ 40px（大マス同士が隣り合う組の線を見せる。ほかは他の色と同じ 34px）。「すべて解放 / 解除」は表示中のエリア単位。保存は `holodori-optimizer:red-boards`。
- **試算**（2026-09-08 の実機内訳で確定。旧「(本体 + 固定値) × (1 + 割合) にしてからパッシブを掛ける」連鎖乗算の仮定は**廃止**）: リーダーのホロメンの赤ボードだけが効く（緑・黄のようにアカウント全体を合算しない）。パラメータ効果は総合力の**ホロメンボード効果の項に加算**する — 固定値はメンバー 5 人それぞれに足し、割合は同じパラメータの % を合算して素値合計に掛けて切り上げる（`src/engine/power.ts`。実機の 41190 と完全一致。パッシブ・衣装とは掛け合わせない — ADR-004）。歌唱者条件は曲を指定し、リーダーのホロメンがその曲の歌唱者（`src/data/songSingers.ts`）に含まれるときだけ足す（全体楽曲は含まれないと仮定）。歌唱者条件の P/T/S +10% も同じホロメンボード効果の項に入り、メンバー強化ボーナスの基準にも入ることは 2026-09-11 の実機（水着ミオリーダー、OFF → ON でボード効果 +12,251・強化 +367）で確定（`docs/ai/tmp/status.md`「赤の歌唱者条件」）。
- **スコアサポート効果**: 総合力には入らないが、表示スコアボーナスの**合計を X × 基準候補秒率 pt 増やす**（2026-09-11 の実機 2 編成で支持される強い仮説。`src/engine/displayScore.ts` の `redScoreSupportDisplayGain` / `baseCandidateSeconds`。基準候補秒率 = 青ボード補正なしのアクティブの周期・効果時間だけで作る 200 秒タイムラインで候補が 1 人以上いる秒の割合）。根拠は同一条件の単独差分 3 組: 水着おかゆの R-002 +10 が旧編成（候補秒 175/200）で 合計 +8.8、恒常ぺこら → 水着ノエル 0凸の編成（168/200）で 合計 +8.5、水着ミオの歌唱者条件 +24 → 合計 +21.1（`docs/ai/tmp/status.md`「赤スコアサポートの候補秒率換算」「恒常ぺこら → 水着ノエル 0凸」）。同日に一度置いた編成非依存の固定係数 0.88 × X は 2 編成目で棄却（0.85 などへの置き換えもしない）。ゲーム内部がこの占有率を掛けていると断定しない。ボード欄とパッシブ欄への配賦は未解明（実機は +10 で ボード +8.4 / パッシブ +0.4 と +8.0 / +0.5、+24 で +20.9 / +0.2 と頭打ち）で、ツールは全部ボード欄に入れる近似（合計は量子化の範囲で一致、内訳 2 欄が ±0.5 程度ずれる — pending 12）。
- **表示のみ**: ライフ・判定強化・ライフ回復・ライブ報酬（ボード画面の効果表に出すが、試算には入れない）。

## 未確認事項
