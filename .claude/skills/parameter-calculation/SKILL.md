# パラメータ計算仕様 (parameter-calculation)

このスキルは、ゲーム内のカード詳細画面に表示される P/T/S（パフォーマンス / テクニック / センス）の成り立ちと、ユニットスコア計算でカード詳細値とは分離して扱うべき要素を定義する。内容はユーザーの実機観測（2026-09-06 共有）で確定した事実に限り、アカウントごと・時点ごとに変わる値（メモリーの倍率、強化ボーナスの現在値、ボードの解放状況、実測したカードの数値）は持たない — それらは `docs/ai/tmp/status.md`（棚卸し対象外の時点情報）にある。ゲーム仕様の全体像は `docs/human/game-spec.md`、ツールが採用するスコアモデルは ADR-003。

## カード詳細画面の P/T/S に反映されるもの・されないもの

| 反映される                                                              | 反映されない                                          |
| :---------------------------------------------------------------------- | :---------------------------------------------------- |
| カードのレベルによる基礎パラメータ                                      | 赤ホロメンボード（実機で確認済み）                    |
| 開花によるパラメータ上昇（★5 の 2凸 = 全パラメータ +10%）               | メモリーの「ユニットパラメータ +X%」                  |
| 青ホロメンボードの固定値 UP と P/T/S の割合 UP                          | メンバー強化ボーナス（+X%）                           |
| 緑ホロメンボードのパラメータ UP                                         | アクティブスキル（スコア UP・発動率 UP・発動頻度 UP） |
| コネクトマスで増幅された青・緑ボードの効果（増幅後の値として反映）      | SP スキル効果                                         |
| 期生・ゲーマーズ等の所属グループ向けパラメータ UP（同一効果の上限あり） | パッシブスキルの編成条件つきパラメータ UP             |

ボード色ごとに言い直すと: 赤 = 反映されない / 青 = 反映される / 緑 = 反映される / 黄 = パラメータの効果がない（楽曲スコアボーナスとホロワーク報酬）。

## カード詳細値の計算モデル

属性 X を P/T/S のいずれかとして:

```txt
カード詳細 X = カード本体の Lv・開花反映後 X
             + 青ボード固定値（X 対象分 + 全パラメータ対象分）
             + 青ボード割合補正（X の N% UP）
             + 緑ボードの全員対象固定値（+ 該当する所属向け固定値）
             + 該当する所属ボーナス
```

- コネクトマスの増幅は、ボードの各マスに表示される値にすでに含まれている。別途コネクト倍率を掛けない。
- 青ボードの割合補正（P/T/S 5.0% UP 等）は端数を**切り上げ**にすると実測と整合する（例: ceil(6984 × 0.05) = 350、ceil(10346 × 0.05) = 518、ceil(6184 × 0.05) = 310）。割合が本体値と固定値のどちらに掛かるかは、この例が本体値相当に見える以上のことは未確認。
- 所属グループ向けパラメータ UP は、**同一効果の上限が全パラメータ +900**。フブキのように複数グループに所属するホロメンでも、この効果でその上限を超えることはない。
- 青ボードを 1 マスも解放していないホロメンでも、緑ボードと所属ボーナスはカード詳細に反映される（マリンで確認）。

## 開花の効果（★5、確認済みの範囲）

| 段階 | 強化対象                                | カード詳細 P/T/S への影響 |
| :--- | :-------------------------------------- | :------------------------ |
| 1凸  | アクティブスキル（周期・確率・効果量）  | なし                      |
| 2凸  | 全パラメータ +10%                       | あり                      |
| 3凸  | SP スキル（+ 条件つきスキル発動率 UP）  | なし                      |
| 4凸  | パッシブスキル（条件つきパラメータ UP） | なし                      |
| 5凸  | コネクト関連                            | なし                      |

`src/data/bloom.ts` の仮定倍率（パラメータ ×1.05）は 2凸 = +10% の実測で置き換えられる — 変更するときはこのスキルの値を正とする。

## 青ボードの構成と効果の種類

青ボードはメンバー編成時にそのホロメン自身へ効き、ノード構成は全ホロメン共通（左型・右型は左右反転で、どちらかはホロメンごとに固定 — `src/data/holomen.json` の `board.blueSide`。コネクトマスは 1 つ）。全体配置は赤が上・緑が下・青と黄が左右（ホロメン別）で、赤ボードのライフ系 / ステータス系エリアの左右もホロメン別（`board.lifeSide`）。マスの効果は全パラ +50 / P・T・S の固定値 +100・+150 / P・T・S の +5.0% / アクティブスキルの**発動率 UP**（+2.0〜6.0%）/ アクティブスキルの**発動頻度 UP**（+4.0%）の 5 種で、全取得の単純合計は全パラ +300、P・T・S 各 +400 +5.0%、発動率 +30.0%、発動頻度 +12.0%（詳細は references/blue-board.md）。実機のボード表示値はコネクト増幅込みでこの合計を超えうる。頻度 UP はカード詳細には反映されず、ライブ中の期待値（`src/data/live.ts` の仮定値）に効く。

## 緑ボードの構成と効果の種類

緑ボードは全体配置の下で全ホロメン共通（左右反転なし）。効果は**アカウント全体**に効く — 編成の有無にかかわらず、登録した全ホロメンの緑ボードの「全員の〜UP」が全カードに、「○期生の全パラメータ UP」（3 マス）がその所属のカードに足される。マスの効果は全員の全パラ +5 / 全員の P・T・S +5・+10 / 所属向け全パラ UP（+50・+150・+100、3 人の所属は +75・+225・+150。フブキは 1期生 +100・ゲーマーズ +300・1期生 +200）/ 報酬・獲得量 +0.5%（7 マス、パラメータに効かない）の 4 種で、1 人分の全取得の単純合計は全員の P・T・S 各 +55、所属向け +300 か +450（詳細は references/green-board.md）。所属向けの合計は 1 カードあたり +900 が上限。

## 黄ボードの構成と効果の種類

黄ボードは全体配置の青の反対側で、形は青の左右反転と同じ 31 マス（右型・左型はホロメンごとに固定 — `board.blueSide` の反対。コネクトマスは中心から 7 マス目に 1 つ）。効果はパラメータでなく、**楽曲のスコアボーナス**（本人のソロ楽曲 +0.5% × 11 と +2.0% × 1、本人を含むユニット楽曲 +1.0% × 2 と +2.0% × 1、全体楽曲 +0.1% × 2 と +0.5% × 1）と**ホロワークの報酬の獲得量**（レッスン Pt / キューブ / 特訓アイテム、各 +20%）の 2 種。全取得の単純合計はソロ +7.5%、ユニット +4.0%、全体 +0.7%（詳細は references/yellow-board.md）。フワワ・モココのソロ系マスは「楽曲歌唱者が FUWAMOCO のみの楽曲」が対象。楽曲スコアボーナスは合計 10.0% が上限、楽曲の区分はホロメン 1 人の曲がソロ・複数人の曲がユニット・hololive IDOL PROJECT の曲が全体（`src/data/songSingers.ts` が `artists` から導く）。効果は緑と同じくアカウント全体に効き（編成外でも乗る）、表示値はコネクト増幅後（ツールは表記値）。ゲーム内の「スコアボーナス」が最終スコアにどう掛かるかだけ未確認で、ツールは総合期待スコアに (1 + X%) を掛ける仮定（`src/engine/live.ts`）。

## 赤ボードの構成と効果の種類

赤ボードは全体配置の上で全ホロメン共通（63 マス。ライフ系エリアが左か右かはホロメンごとに固定 — `board.lifeSide`。右なら上エリアも含めて全体が左右反転）。中心から 7 マス目に赤ボード内のコネクトマスがあり、そこから上エリア（22 マス。幹と最上部の格子）・ライフ系エリア（20 マス）・ステータス系エリア（21 マス）に分かれる。効果は**リーダー用**: そのホロメンをリーダーにしたライブで**メンバー 5 人**（リーダーは含まない）の「全員の〜」に効き、カード詳細には反映されない。種類は 全員の全パラ +50 / +70、全員の P・T・S +100 / +150、全員の全パラ +1.0% / +3.0%、全員の P・T・S +3.0% / +4.0%、歌唱者条件（「このホロメンが楽曲歌唱者に含まれる時」）の P・T・S +10.0% とスコアサポート +10.0%、全員のスコアサポート効果 +2.0〜4.0%、ライフ +50、ライブでの獲得メンバー Exp / ホロゴールド +5.0% / +20.0%、判定強化（習得・強化）・ライフ回復（習得）のホロメンスキル。全取得の単純合計は全パラ +680、P・T・S 各 +500、全パラ +6.0%、P・T・S 各 +7.0%（歌唱者条件で各 +10.0%）、スコアサポート +20.0%（+10.0%）、ライフ +300、報酬 各 +55.0%（詳細は references/red-board.md）。ツールはメンバー各自の P/T/S を (本体 + 固定値) × (1 + 割合) にしてからパッシブを掛ける**仮定**で試算し、スコアサポート・ライフ・スキル・報酬は表示のみ。

## 総合力（ユニット編成画面）の構造 — 2026-09-08 実機内訳で確定

メニューのユニット編成画面に出る「総合力」は、次の 6 項目を**別々に**求めて加算した値（同じメンバー 5 枚でリーダー 2 通りの内訳 6 項目とメンバー別表示値で確認。実装は `src/engine/power.ts`、ゴールデンケースは `src/engine/power.test.ts`、決定は ADR-004）:

| 項目                 | 計算                                                                                               | 実機との一致                                  |
| :------------------- | :------------------------------------------------------------------------------------------------- | :-------------------------------------------- |
| メンバーパラメータ   | メンバー 5 人の素値（開花後・ボード前の本体値 = `Card.naturalStats`）の合計。リーダーは入らない    | 確定（素値の復元誤差で −2）                   |
| 衣装スキル           | メンバー × パラメータごとに ceil(素値 × %)                                                         | 素値基準は確定、切り上げ単位は仮説（±2）      |
| ホロメンボード効果   | 青・緑の増分（カード詳細値 − 素値）+ 赤の固定値 × 5 + Σ_パラメータ ceil(素値合計 × 赤の % 合算)    | 青緑は確定、赤は 41190 と完全一致（強い推定） |
| パッシブスキル       | 対象メンバー × 対象パラメータごとに ceil(素値 × %)。「◯◯2人の」は対象パラメータの高い順に count 人 | 20340 と完全一致（強い推定）                  |
| メモリー効果         | メンバー × パラメータごとに ceil(素値 × メモリー%)                                                 | 7359 と完全一致（強い推定）                   |
| メンバー強化ボーナス | メンバーごとに ceil((素値 + ボード + 衣装 + パッシブ) × 強化%)。メモリーは基準に含めない           | 8709 / 7161 と一致（強い推定）                |

- 割合効果の基準は**カード詳細値ではなく素値**。「赤 → パッシブ → 衣装」のような連鎖乗算は実機と合わない（旧 `src/engine/score.ts` のモデルは廃止）。
- 曲を選ばないこの画面では、赤の歌唱者条件（「このホロメンが楽曲歌唱者に含まれる時」）と黄ボードは効かない。
- 表示の「ユニットスコア」は 総合力 × (1 + スコアボーナス/100) × 約 2.03734 で、スコアボーナス（アクティブ + ホロメンボード + パッシブ + スペシャル）の内部式は未確定（`docs/human/game-spec.md` の「ユニット編成」、pending 12）。ツールは総合力までを再現し、ユニットスコアは表示しない。

## ユニット計算で別枠として扱うもの

カード詳細値には入っていないので、ユニット編成・総合力の計算で追加する:

- メモリー: ユニットパラメータ +X%（アカウント共通。現在値は status.md。Step 0 の入力欄）
- メンバー強化ボーナス: +X%（アカウント共通。メモリーを除く合計に掛かる別枠）
- 赤ホロメンボード（リーダーのホロメンの解放マスがメンバー 5 人の P/T/S に。上の「赤ボードの構成と効果の種類」と「総合力の構造」）
- 黄ホロメンボード（楽曲のスコアボーナス。曲を指定したときに総合期待スコアへ (1 + X%) を掛ける仮定。総合力には入らない）
- パッシブスキル・衣装スキル（素値基準の加算）
- アクティブ / SP などの条件つき効果（総合力の外。スコアボーナス側）
- リーダー・メンバーなどの編成条件

## 実測値とデータを照合するとき

`src/data/cards.json` の stats は**ボード・所属ボーナスを含まない、レベル最大・2凸以上の本体値**である（2026-09-06 に実測 4 枚 × 3 パラメータ = 12 値すべてを ±1 以内で再現して確認。1凸のカードは stats ÷ 1.10 を本体値とすると一致し、÷ 1.05 では +300〜+500 ずれる）。実機のカード詳細値と比べるときは、上の計算モデルで青・緑ボードと所属ボーナス（現在値は status.md）を足してから比較する。逆に実測値から本体値を割り戻すときは、割合補正の切り上げを考慮する。cards.json のスキル文言（アクティブ・SP・パッシブ）も開花最大（1凸・3凸・4凸の強化後）の内容で、実機の開花文言と一致した。

カード詳細値から検証できるのはここまで。ユニット側（素値基準・加算・切り上げ・「2人の」の選び方・メモリーと強化ボーナスの掛かり方）は 2026-09-08 のユニット編成画面の内訳で検証した（上の「総合力の構造」）。開花途中のスキルの実数値も同日に 5 枚分が判明し `bloomVariants` に記録した（ぺこら恒常 1凸: パッシブ 24%（開花最大 32%）・SP 95%（115%）/ ころね水着 2凸: パッシブ 8%（11%）・SP 100%（120%）/ フブキ水着 0凸: アクティブ 95%（115%）・パッシブ 8%（11%）・SP 110%（135%）/ ミオ水着 1凸: パッシブ 32%（43%）・SP 110%（135%））— 強化前後の比は ×1.2〜1.375 で、`src/data/bloom.ts` の仮定倍率 ×1.1 より大きい。未確認のカードは仮定倍率のまま。
