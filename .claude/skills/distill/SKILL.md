# Distill

あなたはリポジトリのドキュメントを棚卸しする。記録された訂正を規則にまとめ、すべての内容を正しい置き場に戻す。

置き場と各置き場での扱いは、そのリポジトリの CLAUDE.md にある「ドキュメントの分担」表が正典(見出しが違っても役割で探す。表がなければ `docs-convention` の表を使う)。このスキルはその表に従って動かす手順だけを定め、置き場の考え方は `docs-convention` に、訂正の分類と書き方は `journal` に委ねる。CLAUDE.md が複数あるとき(ルートのものと、作業ディレクトリに近いローカルのもの)は、分担表を持つ最も近い CLAUDE.md を正典にし、ルートの CLAUDE.md はリポジトリ全体の規則として併せて読む。以下のパスは、表が示す文書ルート(既定 `docs/`)からの相対。表の下にリポジトリ固有の追加点検が書かれていれば、手順3で行う。

目的は、毎セッション読まれる CLAUDE.md とスキルを、少なく、食い違いがなく、今も正しい状態に保つこと。何も変えずに終わる棚卸しも正しい結果で、減らすために減らすことはしない。

次の操作は、移動元 → 移動先の計画をまとめて示し、AskUserQuestion で承認を得てから行う。ここで入った誤りは、毎セッション読まれ続けるため。

- CLAUDE.md・スキル・hook への書き込み
- 既存の行・auto memory・`ai/tmp/` のファイルや項目の削除

指示がない限り commit / push はしない。

## ワークフロー

`ai/tmp/` の各ファイルについての項目は、そのファイルがなければ飛ばす。

1. 読む: CLAUDE.md、分担表が「特定の作業でだけ要る手順・ルール」の置き場として指すディレクトリ(既定 `.claude/skills/`)の `*/SKILL.md`、文書ルートの `index.md`、`ai/tmp/` の全ファイル、このプロジェクトの auto memory。あわせて、このセッションで受けた訂正のうち journal.md に記録していないものがないか振り返り、あれば `journal` の分類で記録する。
2. 記録を規則にまとめる。項目を残したまま次のセッションへ持ち越すと、その間は学びが効かないので、毎回行う:
   - journal.md で同じ種類の事例が2件以上たまっていれば、規則にまとめる。1件だけの事例は残す
   - auto memory にこのリポジトリに関わる訂正や規則があれば、journal.md の項目と同じように扱い、移したものはメモリから消す
   - 規則の移し先は分担表に従う
   - 移す前に、同じことを言っている既存の行を探す。あれば新しい内容に合わせて古い行を消す。追記だけで済ませると、食い違う2行が残る
   - 規則には理由と、効き目が分かる代表例を1つ添える。経緯の物語や日付は書かない
   - 移した項目と、無効になった項目は journal.md から消す
3. 食い違いと古くなった記述を点検する:
   - CLAUDE.md とスキルで同じことを別々に書いている箇所、矛盾している箇所を探す。見つけたら両方を引用してユーザーに示し、どちらに合わせるか決めてから直す
   - CLAUDE.md のディレクトリ構成・コマンドなどの記述を、実際のリポジトリと照らし合わせる
   - 強い表現(必須・〜してはならない・多用された太字)は、理由を添えた平叙文に直す。ただし取り消せない操作と機微情報の扱いについては残す
4. 作業中のメモを現状に合わせる。各置き場での扱い(状況ログは要約に縮める、`ai/snapshots/` と `human/` は触らない、など)は分担表の「扱い」列に従う:
   - tmp/plan.md: 終わったフェーズは完了の要約に縮める。未解決の項目は tmp/pending.md へ移す
   - tmp/progress.md: 終わった項目の詳細を要約に縮める
   - tmp/pending.md: 各項目を現状と照らし合わせ、解決済みのものを消す。消す前に現状を確かめる
5. 整合を検査する: リポジトリのルートで `python3 <skill-dir>/scripts/check-docs.py [文書ルート]` を実行する(文書ルートが `docs/` 以外なら引数で渡す。ルートに `index.md` がなければ何もせず終わる)。出てきた `index.md` の行の漏れ、存在しないファイルを指す行、相対リンク切れを直す。`human/` の文書の中で見つかったものは、直す案をユーザーに示す。
6. tmp/progress.md にコンパクション地点のログを書く: 未コミット・未 push の変更、次にやること、参照すべき方針の場所。
7. タスクが完全に終わっている場合だけ、クローズする。残す価値のあるものを先に移す(決定は ADR へ、ルールは手順2の移し先へ、残したい事実は `ai/` のリファレンスへ移して `index.md` に行を足す)。そのうえで `ai/tmp/` を丸ごと消す。`index.md` にある tmp/ の行は、次のタスクで使うので残す。
8. 報告する: 移したもの・消したもの、食い違いの点検結果、ユーザーの判断が要るもの。
