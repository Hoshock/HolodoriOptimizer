# ルールの規約 (rules-convention)

`.claude/rules/` は Claude Code がスコープつきで読み込む Markdown ルールの置き場。`paths:` glob を持つファイルは、glob にマッチするファイルを Claude が読んだときだけ読み込まれる。このスコープこそがルールの価値 — 一部のサブツリーにしか適用されない指示を、それに触れるセッションだけに負担させる。

## ルールが正しい置き場になる条件

| 指示の性質                                 | 置き場                     |
| :----------------------------------------- | :------------------------- |
| リポジトリ全体・毎セッション適用           | CLAUDE.md                  |
| 特定の glob にマッチするファイルにのみ適用 | ここに `paths:` つきで置く |
| 多手順のワークフロー・随時参照の知識       | スキル                     |
| 毎回機械的に必ず実行させたい               | フックや CI                |

**必ず `paths:` を設定する。** `paths:` のないルールは無条件で読み込まれ、コストも優先度も CLAUDE.md と同じなのに、複数ファイルに散って矛盾が隠れる。本当に無条件の指示なら、唯一の索引である CLAUDE.md へ置く。

## ファイルの規約

- 1 トピック 1 ファイル。内容が分かるケバブケースのファイル名（`ui-design.md` など）。探索は再帰的なのでサブディレクトリも使える。
- 常時読込と同じ厳しさで各行を吟味する: マッチしたファイル自体を読めば分かることは書かない。
- 本文は日本語で書く（このリポジトリの方針。CLAUDE.md「注意点」参照）。コード識別子・パスは原文のまま。

## `paths:` glob

| パターン            | マッチ対象                               |
| :------------------ | :--------------------------------------- |
| `**/*.ts`           | 任意のディレクトリの全 `.ts` ファイル    |
| `src/**/*`          | `src/` 配下のすべて                      |
| `*.md`              | プロジェクトルート直下の Markdown のみ   |
| `src/**/*.{ts,tsx}` | ブレース展開 — 2 パターンを 1 つで書ける |

- 少数の広いパターンを好む: 1 ファイルの `paths:` 全体でブレース展開後 1,000 パターンの予算を共有し、超過したパターンは黙って何にもマッチしなくなる。
- 発火条件は Claude がマッチするファイルを「読む」こと。それ以外の操作での発火に依存する設計をしない。

## スケルトン

```markdown
---
paths:
  - "<glob>"
---

# <トピック>

- <このパス配下でのみ成り立ち、コードを読んでも導けない制約>
```
