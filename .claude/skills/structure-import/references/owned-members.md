# 所持メンバー（kind: "owned-members"）

ツールの「持っているカードのみからさがす」で使う登録内容。保存されるのは**どの★5 カードを持っているか**と**開花段階（0〜5凸）**だけ（レベル・P/T/S・スキルはツール側のデータにある）。封筒と守ることは [SKILL.md](../SKILL.md)（raw: `https://raw.githubusercontent.com/Hoshock/HolodoriOptimizer/main/.claude/skills/structure-import/SKILL.md`）。

## 入力のスクショ

ゲームの**メンバー一覧（カードが並ぶ画面）**で、1 行あたり 6 枚のタイル。**ホロメン名・カード名はタイルに書かれていない**（2026-09-10 ユーザー確認）。

| タイルの場所 | 出ているもの                                     | 使い方                                                      |
| :----------- | :----------------------------------------------- | :---------------------------------------------------------- |
| 中央         | カードのイラスト                                 | **本体**。ホロメンと衣装を見分け、名前は web 検索で特定する |
| 星の並び     | レア度                                           | **★5 だけ対象**（それ以外は飛ばす）                         |
| 左上         | タイプのアイコン（キュート / ハッピー / ピュア） | 検索で絞る手がかり。出力には入れない                        |
| 右上         | ユニット名                                       | 同じく手がかり。出力には入れない                            |
| イラスト上   | 開花状況                                         | `bloom`（0〜5）として読む                                   |
| イラスト上   | レベル                                           | 使わない                                                    |

スクロールした複数枚になるのが普通で、途中まででも構わない（★5 で絞れる画面なら絞ってから撮ってもらうと楽）。

## 読み取り

1. 星の数で★5 か判定する。
2. イラスト・タイプ・ユニット名を手がかりに、**web 検索でホロメン名とカード名を特定する**（★5 カードの一覧が載っている攻略サイトなど）。
3. **カード名まで確定できたら `card` に入れ、ホロメンまでなら `card` を省略する**（★5 が 1 枚のホロメンなら取り込み側が確認の質問つきで特定する。2 枚あるホロメンは特定できないので、そのホロメンだけ詳細画面を追加で撮ってもらう）。ホロメンも分からなければ `cards` に入れず `unreadable` へ。
4. 開花状況を読む。判断できなければ `bloom: null`。
5. 名前は検索で見つけた**正式表記のまま**入れる（「サクラBloom」を「サクラブルーム」にしない）。表記ゆれや 1〜2 文字の違いは取り込み側が吸収する。
6. 1 枚のカードにつき 1 行（重複入手は開花段階に出るので行を増やさない）。同じカードが複数のスクショに写って開花の読みが違うときは、鮮明な 1 枚を採って `note` に書く。

ホロメンボード・メモリー・強化ボーナスはこの種別に含めない（別の `kind` として後から追加する）。

## スキーマ

`cards` は封筒の直下に置く配列。並び順そのものが情報（画面の左上 → 右下）。

| フィールド | 必須 | 型                   | 意味                                                                                              |
| :--------- | :--- | :------------------- | :------------------------------------------------------------------------------------------------ |
| `holomen`  | ○    | string               | ホロメン名。**これだけ必須**                                                                      |
| `card`     | —    | string               | カード名（サブタイトル）。★5 の 73 枚で重複しないので、あれば実質の照合キー。読めなければ省略する |
| `bloom`    | ○    | integer 0〜5 \| null | 開花段階。`null` = 未読取                                                                         |
| `cardId`   | —    | string               | ツール側の ID（例 `azki-01`）。あれば名前より優先される                                           |
| `note`     | —    | string               | 判断の根拠。人の確認用で取り込みでは無視される                                                    |

## 例

```json
{
  "format": "holodori-optimizer/import",
  "version": 1,
  "kind": "owned-members",
  "cards": [
    {
      "card": "咲き誇る一途な花",
      "holomen": "AZKi",
      "bloom": 3
    },
    {
      "holomen": "ときのそら",
      "bloom": 0
    },
    {
      "card": "叡智を灯し、アートに導く",
      "holomen": "儒烏風亭らでん",
      "bloom": null,
      "note": "開花の表示が指で隠れている"
    }
  ],
  "unreadable": [{ "reason": "イラストが見切れて特定できない", "hint": "4 枚目の右下" }]
}
```

## 取り込み側（サイト）の扱い

入口はサイドメニュー最上段の「データの取り込み」。実装は `src/storage/import.ts`（解釈とプランの純関数）+ `src/components/ImportSheet.vue`（貼る → 質問 → 取り込むカードの確認）。保存先は `holodori-optimizer:owned-card-ids`。**スキーマを変えたらコピー用プロンプト（`src/ui/importPrompt.ts`）と合わせて直す。**

- 名前 → ID の解決はサイト側（`src/data/cards.json`）。表記ゆれ（全角半角・大小・空白・中黒）は正規化し、**1〜2 文字のブレは 1 つに絞れるときだけ読み替える**（「探究心」→ 探**求**心、「ビットフィールド」→ **ラビット**フィールド）。`cardId` があれば最優先。
- **人が決めることは実行前の「はい / いいえ」の質問**にする: 名前の読み替え、`card` 省略時の「★5 は 1 枚です。これとして取り込みますか？」、`bloom: null` の新規を 0凸で登録するか。
- **人が決められないもの**（カード名が見つからない・似た名前が複数・ホロメン名と食い違う・同じカードが 2 回・開花段階が範囲外・`unreadable`）は「取り込みエラー n 件」として件数だけ出す。
- **取り込みで登録が減ることはない** — JSON に無いカードの登録はそのまま残る。`bloom: null` で登録済みのカードは現在の段階を保ち「登録済み」に数える。
