# 所持メンバー（kind: "owned-members"）

ツールの「持っているカードのみからさがす」で使う登録内容を作る。保存されるのは**どの★5 カードを持っているか**と**その開花段階（凸数）**の 2 つだけで、レベル・P/T/S・スキルはカードデータ側にあるので出力しない（`.claude/rules/storage-compat.md`）。

## 対象

- **★5 のカードだけ**を出す。最適化の対象は★5 のみで、★3・★4 は出さない（カード名・種類数が未確認でもある — `docs/human/game-spec.md`）。
- 1 枚のカードにつき 1 行。ゲーム内で重複入手したぶんは開花段階に反映されるので、行を増やさない。
- ホロメンボード・メモリー・強化ボーナスはこの種別に含めない（別の `kind` として後から追加する）。

## 必要なスクショ

- 所持カードの一覧が写っていること。1 画面に収まらないので、**スクロールして全件**（重なりがあってよい。重なりは最後に 1 件へまとめる）。
- **ホロメン名・カード名（サブタイトル）・開花段階**が読める倍率であること。カード名が省略表示で切れている場合は、そのカードだけ詳細画面を撮ってもらう。
- ★5 で絞り込める画面なら絞ってから撮る（★3・★4 が混ざると選別の手間と誤りが増える）。
- 開花段階の表示（花アイコンの数など）が判断できること。判断できない表示形式のときは、値を推測せず人間に確認する。

## スキーマ

`cards` は封筒（[SKILL.md](../SKILL.md)）の直下に置く配列。

| フィールド | 必須 | 型                   | 意味                                                                                                         |
| :--------- | :--- | :------------------- | :----------------------------------------------------------------------------------------------------------- |
| `card`     | ○    | string               | カード名（サブタイトル）。★5 のカード名は全 73 枚で重複しないので、これが実質の照合キー                      |
| `holomen`  | ○    | string               | ホロメン名。`card` と食い違う行は取り込まず「要確認」に出る（どちらが正しいか決められない）                  |
| `bloom`    | ○    | integer 0〜5 \| null | 開花段階（凸数）。0 = 未開花、5 = 最大。読み取れないときは `null`（取り込み側は 0凸 として登録し件数を報告） |
| `cardId`   | —    | string               | `src/data/cards.json` の `id`（例 `azki-01`）。分かる場合のみ。あれば名前より優先して照合する                |
| `note`     | —    | string               | 判断に迷った点・読み取りの根拠。人間の確認用で、取り込みでは無視される                                       |

- レベル・パラメータ・スキル文言・所属・タイプは**入れない**（カードデータ側にあり、入れると二重管理になる）。
- 開花段階と「開花Pt の残数」「カードのレベル」を混同しないこと。0〜5 を外れた値は丸めずに取り込まず「要確認」に出る。

## 例

```json
{
  "format": "holodori-optimizer/import",
  "version": 1,
  "kind": "owned-members",
  "capturedAt": "2026-09-10",
  "cards": [
    { "card": "咲き誇る一途な花", "holomen": "AZKi", "bloom": 3 },
    { "card": "サクラBloom", "holomen": "さくらみこ", "bloom": 0 },
    { "card": "真夏のもふもふフロートタイム", "holomen": "角巻わため", "bloom": 5 },
    {
      "card": "叡智を灯し、アートは生まれる",
      "holomen": "儒烏風亭らでん",
      "bloom": null,
      "note": "開花アイコンが指で隠れている"
    }
  ],
  "unreadable": [{ "reason": "カード名が途中で切れている", "hint": "4 枚目の右下、白上フブキの★5" }]
}
```

## 照合の指針

- **カード名を第一のキーにする。** ホロメン名だけでは特定できない（19 名は★5 が 2 枚ある）。
- 表記ゆれ（全角と半角、英字の大小、中黒や空白の有無）は取り込み側で正規化するので、読めたとおりに書けばよい。**勝手に整えない**（「サクラBloom」を「サクラブルーム」にしない）。
- OCR が怪しい字（旧字・記号入りの名前）はネット検索で正式表記を確かめる。確認できなければ `unreadable` へ回す。**スクショと検索結果が食い違えばスクショを優先**（ADR-002 のとおり、解析ダンプ由来の一覧は使わない）。
- 同じカードが複数のスクショに写っていて開花段階の読みが違うときは、**いちばん鮮明な 1 枚**の値を採り、`note` にどちらを採ったか書く。

## 取り込み側（サイト）の扱い

入口はサイドメニュー一番上の「データの取り込み」。実装は `src/storage/import.ts`（解釈とプランの純関数）と `src/components/ImportSheet.vue`（貼る → 差分の確認 → 取り込む の 3 段）。

- 保存先は `holodori-optimizer:owned-card-ids`（v2 の封筒 `{version, cards: [{id, bloom}]}` — `src/storage/owned.ts`）。JSON の名前から `id` への解決はサイト側が `src/data/cards.json` を使って行い（全角半角・大小・空白・中黒の違いは吸収する）、`cardId` があればそれを優先する。
- 取り込まない行（見つからないカード名・`holomen` の食い違い・同じカードの重複・範囲外の開花段階）は、黙って捨てず理由つきで確認画面の先頭に出る。`unreadable` もそこに並ぶ。
- **マージの方針**: JSON にある行は登録し、開花段階は JSON の値で上書きする。**JSON に無いカードの既存の登録は消さない** — スクショが全件そろっている保証がないので、取り込みで登録が減るのは危ない。全消しは明示的な別操作にする（未実装）。
- `bloom: null`（未読取）は、新規なら 0凸で登録し、登録済みなら現在の段階を保つ（推測で上書きしない）。どちらも確認画面に理由が出る。
