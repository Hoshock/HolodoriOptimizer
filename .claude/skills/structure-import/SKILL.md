# スクショからの構造化インポート (structure-import)

ホロドリ編成お助けツールが**貼り付けて取り込める JSON の形**を定義する。流れは「ユーザーがゲーム内スクショを手元の LLM に渡す → このスキルに従って JSON を作らせる → その JSON をサイトの取り込み欄に貼る」。画像はどこにもアップロードされず、貼った内容はそのブラウザの `localStorage` に入るだけ。

**このファイルは URL で渡されて読まれる**（サイトが渡すのは「スクリーンショットを添付します。次のスキルに従って取り込み用 JSON を作ってください」+ この raw URL だけ — `src/ui/importPrompt.ts`）。読み手はリポジトリを持っていないので、相対リンクは辿れない前提で書く。

## 手順

1. **添付のスクショを読む。** 添付が無いときだけ、何をどう撮ってほしいか伝えて止まる。**あるなら写っている範囲で作る** — 一覧が途中まででも、読めない項目があっても止まらない（取り込みは既存の登録を減らさないので部分的でも安全）。
2. **種別を決める**（既定は所持メンバー `kind: "owned-members"`）。**入力の読み方とスキーマは References にしかない**ので、必ず取得してから書き始める。
3. **左上から右下の順に読む**（1 枚の中では左から右、行が終わったら次の行。複数枚は渡された順）。**配列の並びはこの順のまま**にし、並べ替えない — 人が画面と JSON を上から見比べて検算するため。複数枚にまたがる重なりは 1 件にまとめる。
4. 封筒に入れた JSON を**コードブロック 1 つだけ**で出す（前置き・解説を書かない）。コードブロックの外に、件数・`unreadable` の中身・迷った行だけを短く添える。
5. このファイルや References の URL を取得できないときは、**形式を推測せず「読めなかった」と伝える**。作るのは JSON だけで、リポジトリのファイルは書き換えない。

## 共通の封筒

種別が増えても貼り付け口を 1 つに保つため、どの種別も同じ封筒に入れる。

```json
{
  "format": "holodori-optimizer/import",
  "version": 1,
  "kind": "owned-members",
  "capturedAt": "2026-09-10",
  "unreadable": [{ "reason": "指で隠れている", "hint": "3 枚目の右下" }]
}
```

- `format` / `version` / `kind` は必須。`format` は無関係な JSON を弾くための固定文字列で、`version` は互換を壊す変更のときだけ上げる。
- 種別ごとの本体（所持メンバーなら `cards`）は `kind` に対応するキーへ入れる。
- `capturedAt` と `unreadable` は任意。`unreadable` は**読めなかったものを黙って落とさないため**の枠（人が後から手で埋める材料）。

## 守ること

- **推測で埋めない。** 読めないものは省略か `null`、対象そのものが分からなければ `unreadable` に理由つきで置く（間違った値は取り込み側で見分けられない）。
- **スクショ・画像そのものを出力に含めない**（base64 も不可）。**プレイヤー名・ユーザー ID・フレンドコードなど個人を特定する情報も入れない。**
- **解析・データダンプ由来のマスターデータを使わない**（ADR-002）。名前は web 検索で特定してよいが、**スクショに写っている事実（星・タイプ・ユニット名・開花）と食い違えばスクショを優先する**。
- **カードの数値（P/T/S・レベル）は出力しない。** ツールはカードデータ側の値を使い、保存するのは「どのカードを持っているか」と育成状態だけ。
