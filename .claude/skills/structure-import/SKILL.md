# メンバー一覧スクショからの構造化インポート

『hololive Dreams』のゲーム内**メンバー一覧画面**のスクリーンショットから、
ユーザーが所持している **★5カードと開花段階**を読み取り、
ホロドリ編成お助けツールへ貼り付けて取り込めるJSONを作る。

このスキルが対象とするのは**メンバー一覧画面だけ**。

ホロメンボード、メモリー、強化ボーナス、カード詳細画面など、
他の画面の構造化には使用しない。

このファイルはURLで直接LLMへ渡される。
読み手がリポジトリ内の他ファイルを参照できるとは限らないため、
**このファイルだけで処理を完結させること。**

---

## 最重要ルール

### 一覧画面だけから特定する

メンバー一覧のタイルには、
**ホロメン名やカード名が文字では表示されていない。これは正常な状態である。**

そのため、

- ホロメン名が書かれていない
- カード名が書かれていない
- 同じホロメンに複数の★5カードがある

ことを理由に処理を止めたり、
最初からカード詳細画面を要求したりしてはいけない。

**カードイラストそのものを主要な識別情報として使用する。**

LLMの画像認識と公開Web情報の検索・照合を組み合わせ、

1. カードイラストからホロメンを識別する
2. 衣装やカードイラストの特徴を識別する
3. タイプ・所属ユニットを補助情報として使う
4. Webでそのホロメンの★5カード候補を調べる
5. 候補カードの名称・イラスト・衣装・タイプ・ユニット等を照合する
6. カード単位まで特定する

という手順を取る。

**画像認識 → Web検索 → 複数の視覚情報・表示情報による照合**
によって一意に決まったものは「推測」ではなく、
このスキルで要求する通常の特定処理として扱う。

---

## 入力画面

対象はゲーム内の**メンバー一覧（カードがタイル状に並ぶ画面）**。

通常は1行に6枚程度表示される。
スクロールして複数枚のスクリーンショットになることを想定する。

スクリーンショット同士で上下の行が重なっていても構わない。

### タイルから使う情報

| 表示             | 用途                                          |
| :--------------- | :-------------------------------------------- |
| カードイラスト   | **最重要。** ホロメン・衣装・カードを識別する |
| 右側の星         | レアリティ判定。**★5だけを取り込む**          |
| タイプアイコン   | カード候補を絞る補助情報                      |
| 右上のユニット名 | カード候補を絞る補助情報                      |
| 開花数字         | `bloom` として出力                            |
| レベル           | 使用しない                                    |

タイプ・ユニット名・レベルはJSONには出力しない。

---

## 処理手順

### 1. 添付画像を確認する

スクリーンショットが1枚以上添付されているなら、
**写っている範囲だけでも必ず処理を開始する。**

一覧の最下部まで撮影されていなくてもよい。

一部のカードが見切れていても、
判別可能なカードまで巻き添えにして処理を止めてはいけない。

添付画像が1枚もない場合のみ、
メンバー一覧画面のスクリーンショットを添付してもらうよう依頼して終了する。

---

### 2. 画面順にタイルを見る

各スクリーンショットについて、

**左上 → 右 → 行末 → 次の行**

の順で読む。

複数枚ある場合は、ユーザーが添付した順に処理する。

JSONの `cards` 配列もこの順番を保つ。

あとからホロメン名順・カード名順などに並べ替えてはいけない。

これはユーザーがスクリーンショットとJSONを目視比較するために重要である。

---

### 3. スクリーンショット間の重複を除く

スクロール位置を少しずつ動かして撮影すると、
同じカードが複数枚のスクリーンショットに写る。

同じカードだと判断できるものは**1件にまとめる**。

原則として最初に完全に確認できた位置の順序を採用する。

同じカードについて表示の鮮明さが異なる場合は、
より鮮明なスクリーンショットを読み取りに使用する。

スクリーンショット間で開花段階の読み取り結果が食い違った場合は、
表示がより完全かつ鮮明な方を採用し、必要なら `note` に残す。

---

### 4. ★5だけを対象にする

タイル右側の星を確認し、
**★5カードだけを `cards` に入れる。**

★4以下は読み取れていても出力しない。

カードの上下が見切れていてレアリティそのものを確認できない場合は、
周辺の並びだけから★5だと決めつけない。

ただし、別のスクリーンショットに同じタイルが完全に写っている場合は、
そちらを使って判定する。

---

### 5. ホロメンを画像から識別する

カードイラストからホロメンを識別する。

使用できる特徴の例：

- 顔
- 髪色
- 髪型
- 瞳
- 耳・角・翼などの特徴
- 衣装
- アクセサリー
- モチーフ
- 背景
- ポーズ

**名前がタイルに文字として書かれている必要はない。**

画像認識だけでかなり確度が高い場合でも、
カード名を決める段階ではWeb情報との照合を行う。

---

### 6. Web検索で★5カード候補を探す

識別したホロメンについて、
公開Web情報から『hololive Dreams』の★5カード候補を調べる。

検索例：

- `ホロドリ 猫又おかゆ ★5`
- `hololive Dreams 猫又おかゆ カード`
- `ホロドリ 猫又おかゆ カード名`
- `ホロドリ Advent ピュア ★5`

検索語は対象に応じて自由に変えてよい。

攻略サイト、公式サイト、公開Wiki、公開カード一覧などを利用してよい。

画像検索や検索結果中のカード画像が利用できる場合は、
スクリーンショットのカードイラストと積極的に比較する。

### 使用してはいけないもの

解析・データダンプ・抽出master・protobuf等から得た
非公開のゲームマスターデータをカード特定の根拠にしてはいけない。

公開Webページに通常掲載されているカード情報は利用してよい。

---

### 7. カード単位で照合する

同じホロメンに★5カードが複数あっても、
それだけを理由にカード特定を諦めてはいけない。

候補間で以下を比較する。

- カードイラスト
- 衣装
- ポーズ
- 背景
- 髪型
- アクセサリー
- タイプ
- ユニット名
- その他視覚的特徴

スクリーンショットの情報とWeb上の候補を照合し、
一意に決まったカードを採用する。

カード名はWeb上で確認できた**正式表記**をそのまま使用する。

例：

- 漢字を勝手に変えない
- カタカナ表記を勝手に変えない
- 記号を勝手に省略しない
- サブタイトルを意訳しない

---

## 「推測禁止」の意味

**根拠のない穴埋めは禁止する。**

一方で、

- スクリーンショットのイラストを画像認識する
- Web上のカード候補を検索する
- イラストを比較する
- タイプを比較する
- ユニット名を比較する
- 衣装や背景を比較する

といった複数情報の照合によって一意に特定することは、
禁止される「推測」ではない。

むしろ、このスキルではその照合を積極的に行うこと。

---

## 開花段階の読み方

`bloom` は整数 `0`〜`5` または `null`。

カードタイル上に表示される開花数字を読む。

- `1` と表示 → `"bloom": 1`
- `2` と表示 → `"bloom": 2`
- `3` と表示 → `"bloom": 3`
- `4` と表示 → `"bloom": 4`
- `5` と表示 → `"bloom": 5`
- 開花数字の表示がなく、表示領域を完全に確認できる → `"bloom": 0`
- 見切れ・重なり・低解像度などで判断不能 → `"bloom": null`

「数字が見えない」と
「数字が表示される位置そのものが画面外」を混同しない。

後者は0凸ではなく `null`。

---

## 特定できない場合

### カード名だけ特定できない

ホロメンは一意に特定できたが、
十分にWeb検索・画像照合してもカード名だけが一意に決まらない場合は、
`card` を省略してよい。

```json
{
  "holomen": "猫又おかゆ",
  "bloom": 2
}
```

ただし、

**「同じホロメンに★5が複数ある」という理由だけで `card` を省略してはいけない。**

必ずカードイラストまで照合してから判断する。

---

### ホロメンも特定できない

十分な画像認識・Web検索・比較を行っても
ホロメンまで一意に決められない場合のみ、
そのタイルを `cards` には入れず `unreadable` に記録する。

例：

```json
{
  "reason": "イラストが大きく見切れておりホロメンを特定できない",
  "hint": "3枚目の最下段右端"
}
```

---

## 禁止する挙動

以下を理由に**処理全体を止めてはいけない。**

- ホロメン名がタイルに文字で表示されていない
- カード名がタイルに文字で表示されていない
- 同じホロメンに複数の★5カードが存在する
- 一覧がスクロール途中までしか撮影されていない
- 最終行が途中で見切れている
- 一部のカードだけ判別できない
- 一部の開花段階だけ読めない
- 複数枚のスクリーンショットが重複している

判別可能なカードはすべて先にJSON化する。

追加画像を依頼してよいのは、
**十分な画像認識とWeb検索・照合を実際に行ったあとでも判別できなかった対象が残った場合だけ**。

その場合でも、判別済みカードのJSON出力を取りやめてはいけない。

---

## 出力する情報

保存するのは、

- どの★5カードを持っているか
- そのカードの開花段階

だけ。

以下は出力しない。

- レベル
- Performance
- Technique
- Sense
- スキル数値
- タイプ
- ユニット名
- プレイヤー名
- ユーザーID
- フレンドコード
- スクリーンショット画像
- base64画像データ

---

## JSON形式

ルートは次の形式。

```json
{
  "format": "holodori-optimizer/import",
  "version": 1,
  "cards": [],
  "unreadable": []
}
```

### `format`

必須。

常に次の固定文字列。

```json
"holodori-optimizer/import"
```

### `version`

必須。

現在は：

```json
1
```

互換性を壊すスキーマ変更時のみ変更する。

### `cards`

必須。

読み取った★5カードの配列。

画面の左上から右下への順序を保持する。

### `unreadable`

任意。

画像内に対象カードらしきものが存在するが、
十分な確認を行っても特定できなかった場合に記録する。

0件なら省略してもよい。

---

## cards のスキーマ

### `holomen`

必須。

```text
string
```

ホロメンの正式名称。

例：

```json
"holomen": "猫又おかゆ"
```

---

### `card`

任意。

```text
string
```

★5カードの正式なカード名・サブタイトル。

Web照合によりカード単位まで特定できた場合は必ず入れる。

例：

```json
"card": "咲き誇る一途な花"
```

カードまで一意に特定できなかった場合のみ省略可能。

---

### `bloom`

必須。

```text
integer 0〜5 | null
```

開花段階。

読み取れない場合は `null`。

---

### `note`

任意。

```text
string
```

人間が確認するために、
判断上重要な事情がある場合だけ使用する。

通常のカードには付けない。

例：

```json
"note": "開花表示のみ下端で見切れている"
```

---

## 重複カード

1枚のカードにつき `cards` には1件だけ入れる。

スクロールの重なりによって同じカードが複数画像に写っていても、
複数件として登録してはいけない。

同一カードが複数回写っている場合は、
イラスト・ホロメン・カード・開花表示・前後の並び等から同一性を判断する。

---

## 出力例

```json
{
  "format": "holodori-optimizer/import",
  "version": 1,
  "cards": [
    {
      "card": "咲き誇る一途な花",
      "holomen": "AZKi",
      "bloom": 3
    },
    {
      "holomen": "ときのそら",
      "bloom": 0
    },
    {
      "card": "叡智を灯し、アートに導く",
      "holomen": "儒烏風亭らでん",
      "bloom": null,
      "note": "開花表示が画面下端で見切れている"
    }
  ],
  "unreadable": [
    {
      "reason": "イラストの大部分が画面外でホロメンを特定できない",
      "hint": "4枚目の最下段右端"
    }
  ]
}
```

## 最終出力ルール

ユーザーがスクリーンショットから取り込み用JSONを求めている場合、
最終回答では**完成したJSONを1つの `json` コードブロックにして出力する。**

JSONの前に長い説明を書かない。

必要ならコードブロックの後に、

- 読み取れたカード件数
- `unreadable` の件数
- 特に確認が必要な対象

だけを短く書いてよい。

カードを完全には特定できなかったものがあっても、
判別できたカードのJSONは必ず出力する。

---

## 判断の優先順位

情報が食い違った場合は次の順で優先する。

1. ユーザーが添付したゲーム内スクリーンショット
2. ゲーム内で視認できる表示
3. 公式の公開情報
4. 複数の公開攻略サイト・Wiki等で一致する情報
5. その他の公開Web情報

Web上の情報がスクリーンショット上の

- イラスト
- ★
- タイプ
- ユニット名
- 開花表示

と矛盾する場合は、
Web側に合わせてスクリーンショットの読み取りを変更してはいけない。

矛盾が解消できなければ、その項目を未確定として扱う。
