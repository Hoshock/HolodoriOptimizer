# フィードバックの帰納 (induction)

ユーザーのフィードバックを記録された知識に変える手順を定める。ルール候補の記録先は `docs/ai/tmp/rules.md` の一箇所のみ(なければ作成する)。恒久の置き場への昇格は後で housekeep スキルが行う — ここから直接昇格しない。記録はフィードバックと同じターン内に行う。

## ネイティブメモリとの分界

- プロジェクト固有の判断(このリポジトリのドキュメントの書き方、このツールの決め方) → `docs/ai/tmp/rules.md`
- リポジトリを跨ぐエージェントの挙動やユーザーの特性 → Claude Code のネイティブメモリ。メモリはポインタと習慣にとどめ、ルール本文をメモリとリポジトリで二重管理しない。

## 分類

| 分類       | 判定                                                                | 扱い                                                           |
| :--------- | :------------------------------------------------------------------ | :------------------------------------------------------------- |
| その場限り | 事実の修正・文脈依存の調整。好みが読み取れない                      | 反映するだけ。記録しない                                       |
| 事例       | 好みは読み取れるが、根拠がその1回しかない                           | 具体のまま記録: 日付・対象・何がどう変わったか・読み取れる好み |
| 規則       | ユーザーが一般化を明言した(「今後は…」「他も…」)、または同種の2回目 | 規則文として記録し、吸収した事例は削除する                     |

迷ったら事例として記録する。規則は少ないほど強い。

## 規則にする前のテスト(全部通す)

- 別のドキュメントでのユーザーの次の修正を予測できるか
- ユーザーが既に承認したドキュメントに当てはめて、修正が発生しないか(発生するなら過剰一般化)
- 固有名詞を消しても意味が通るか(通らないならそれは事例)

## tmp/rules.md の構成

`## Rules` と `## Cases` の2セクション。特定のパス配下でのみ適用されるルール候補には想定 glob を添える — housekeep がそれらを `.claude/rules/` へ、それ以外の恒久ルールを `docs/ai/rules/` へ移す。
