# UI デザインの制約（2026-08-31〜09-08 ユーザーフィードバック由来。棚卸し 23 回目で結果詳細の表の並びと設定行の事例を統合）

機能追加でも新しいデザインを持ち込まない — 既存のコンポーネント・トークン・デザイン言語（例: 状態選択はピッカーのセグメンテッドコントロールと同形）を踏襲する（「見た目に関しては既存を尊重すること」）。遊び機能（仮想ガチャ等）はゲーム仕様の忠実な再現より操作の単純さを優先する（通貨 2 種・割引枠・天井などは要求されるまで再現しない — 2026-08-31）。お遊び機能の入口は本線のフローに混ぜず、説明文も付けない（おかゆモードは 2026-09-02 にフッター最下部の一番右のアイコン、2026-09-07 からサイドメニュー最下部の 1 行「絶対おかゆんモードを ON / OFF」。URL パラメータは作らず、状態も保存しないので再読み込みで解除）。サイドメニューの地は不透過で、背後は scrim で少し暗くする（透過+ぼかしは試して「やっぱ透過しないように」— 2026-09-07）。詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01）。さがすステップのオプション（持っているカードのみ / ボード / 開花 / 衣装 / パッシブの 5 チップ）は「オプション ▼」の 1 行で既定は畳む（2026-09-06 に「今は少ないし全部見せておこう」で常時表示にしたが、2026-09-08 に旧 Step 1「さがす対象」を統合して 5 件になった時点で「デフォルトたたむ」に戻した）。絞り込み系オプションの既定は保守的な OFF ではなく実用上おすすめの状態にする — 既定のまま実行すれば一番よい結果が出る（スキル発動のしぼりこみは両方 ON が既定 — 2026-09-05）。既存パターンと形が違う UI を入れるときは、提案時にその差の意図（単一選択と複数選択の区別など）を明示する（2026-09-05「意図が知りたい」）。「UI どうする？」のような設計相談には案の提示で止め、明示の着手指示を待ってから実装する — 方針の一言（「欲しいのは獲得ボーナス最大化」）を着手の合図と受け取り、本線の Step 4 に目的セグメントと結果の主数値の差し替えを実装して画像つきで push したところ「微妙だ。一旦戻して別ブランチに退避」となった（2026-09-08。実装はブランチ `claude/event-bonus-objective` に退避、main は revert）。「push までする」運用は指示された変更に適用し、設計相談の回答には適用しない。機能は「ゲーム内で何を最大化したいか」から決め、順位に影響の薄い要素（課題曲のイベントスコアボーナス +10% は一律の倍率で対象カードの有無以外で順位が変わらない）は UI に出さない（「イベントスコアボーナスはあんまいらんかも」— 2026-09-08）。モード全体に効くグローバルな詳細設定を増やさない — 既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダル内で設定する（2026-09-01 一律開花セグメントの却下）。探索には「いま組める最強」と「将来に向けて育てる目標」の 2 つの用途がある — 全カードは将来向けなので現在の育成状態（開花・ボード）を混ぜず、持っているカードでは「ボード状況を考慮する / 開花状況を考慮する」を Step 5 で選べる（既定は両方 ON。2026-09-06 ユーザー判断）。育成状態を考慮しないときは素の値（0凸・ボードなし）ではなくマックスの状態（開花最大・4 色ボード全解放）として試算する — 育てきった前提で比べたい（2026-09-08 ユーザー指示）。本線の外の入口（一覧・遊び機能・外部リンク・モード切替）はヘッダ右上のハンバーガー → 右のサイドメニューに集約する: 上に「カード一覧 / 曲一覧 / 仮想ガチャ / ソースコード（GitHub）」をアイコン左+ラベルで、最下部に固定した行（一覧がスクロールしても下端）にモード切替「絶対おかゆんモードを ON / OFF」（ラベルが状態で変わり、アイコンは同じ）。サイドメニューは常時表示領域（ヘッダ）に掛けず、開く瞬間のヘッダ下端から出す。開閉の操作は同じ場所で形を変える（ハンバーガー ⇄ ✕、CSS トランジション）。閉じる手段は ✕・外側タップ・Escape の 3 つで、開けるのはメイン画面だけ（モーダルの右上は従来どおり閉じるボタン。2026-09-07、4 往復で確定）。一覧 → 詳細の導線は既存のピッカー部品（`CardPicker` / `SongPicker`）をそのまま一覧として開き、選んだら詳細シートを上に重ねる。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法が 1px も変わってはならない（レイアウトシフト禁止）。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測確認する。モード切替で出し入れする要素は同じ高さの枡に置き換え、下の要素を動かさない（ボードの「すべて解放 / 解除」の行が説明モードでは同じ 44px の帯になる — 2026-09-07「他の位置がずれないようにすること」）。
- 内訳表で和を見出しの値と一致させるための丸め誤差は、常に大きい値の行へ寄せる。0 のはずの行は +0 と出し、帳尻合わせを 0 や小さい値の行に見せない（曲未選択の楽曲スコアボーナス行に -1 が出て「+-1 となるのがあったがこれはなんだ」— 2026-09-08）。
- 1 つの図を画面幅に収まらない部分に分けて見せるときは、独立した切替部品（セグメント・トグル）やスワイプを足さず、内容が画面の外へ続く位置に出口（◀左 / ▲上 / 右▶ の小さな丸角四角）を描いてタップで移る。名前は意味（ライフ系 / ステータス系）でなく物理的な位置（左 / 上 / 右）で、接続線も出口まで引く。出口で移ったらスクロールを一番上へ戻し、「すべて解放 / 解除」のような一括操作は表示中の部分だけに掛ける（赤ボードの 3 エリア。セグメント案は「別トグルを用意したくない。スマートな UI を。スワイプ切替は嫌。名前も左上右にして」で置き換え — 2026-09-08）。
- 表・一覧の行は固定順で全項目を常に出す — 選択順・解放順で行が増減したり並びが変わったりしない。値がないときは +0 などの空値で行を残す（緑ボードの効果表で解放した報酬系だけを解放順に出して「選ぶ順によって上から並ぶ順が変わるのきもい」— 2026-09-07）。
- 可変長の見出し（人名・曲名）と固定幅のコントロールを同じ行に並べない — 見出しは 1 行を占有させ、コントロールは次の行に左右で並べる（ボードの名前と色セグメントを同じ行に置いて「名前が長いと省略されてしまっている」— 2026-09-07）。
- ヘッダなどの常時表示領域も同様に、タブ・モード切替で寸法（高さ）が変わってはならない。この不変則は画面遷移（フルスクリーンモーダル）にも適用する — 画面のヘッダはページヘッダと同寸法（77px）・同文字サイズ（24px/900）・同じ下罫線にし、両画面の boundingBox で実測して確かめる（2026-08-31。2026-09-05 にピッカーが 60px で「開くとヘッダの高さが変わる」と指摘され、規則があっても未実測だった）。切替内容に依存するもの（手順リスト等）をヘッダに置かない。
- 同じ対象（カード・曲）はメイン画面とピッカーで同じ部品（`CardTile` / `SongRow`）を使い、見た目と固定高を一致させる — 別部品で似せない（UnitSlot と CardTile の二重実装は片方だけ直して齟齬が出た）。幅はそれぞれの置き場に従ってよい（メイン=パネル内 324px / ピッカー=シート 358px @390px）。メイン画面は白いパネル（ページ左右 16px + 内余白 16px）が基準で、ピッカーは白い 1 枚のシート（ヘッダ → 絞り込み → 一覧）— 幅まで揃えるための全幅の白い帯・左右 8px の角丸ブロック・罫線+接続線のステッパー・ピッカー内のカード入れ子+内側スクロールはすべて却下（「びみょう」「キモすぎるしわかりにくすぎる」— 2026-09-05、6 往復）。画面の構造は単純に保ち、部品の一致より入れ子の少なさを優先する。
- ステップは意味単位で切る — 同じ意味に属する設定を別ステップに分けない（除外は探索プールを狭める操作なので「さがす対象」のセグメントの下に行ボタンとして置き、旧 Step 2 を統合 — 2026-09-06。2026-09-08 に「さがす対象」自体をさがすステップのオプション「所持カードから探す」へ移し、除外の入口は一度外したのち同日に戻して「リーダーから除外 n枚」「メンバーから除外 n枚」の 2 ボタンにした）。同じ操作を役割で分けるときは、1 つの入口の中に状態を重ねる（除外したタイル上で役割ピルを切り替える案）より、目的別の入口を名前で分ける平たい構造にする（「リーダーから除外、メンバーから除外の二つのタイルを用意しよう」— 2026-09-08）。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする（2026-09-01 タブ統合）。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない（選択肢がなくなったら畳む）。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない（2026-09-01。モーダル内全グレーアウト実装を訂正された）。前提が満たされず操作を止めるときも、赤いエラーメッセージでなく「方針」をボタンのラベルで示す（例: おかゆモードでリーダー・メンバー・実行を disabled — 2026-09-02）。例外: Step 0 の 3 ボタンはラベルを変えると 3 列に収まらないので、おかゆモードで未登録のときだけボタンの下に 1 行「おかゆんを持っているカードに指定してください」を出し、出ていないときは余白も取らない（2026-09-06 ユーザー指示「これは例外的処理」）。ある条件で効かなくなる設定は、その条件のあいだ disabled にして効いていないことを示すが、見た目は 2 通りに使い分ける: 一時的に効かないだけの設定（6 枠すべて固定のときの発動条件チップ）は保持している設定値の見た目（選択中の濃色地）を変えず減光だけにする（白地化は「設定保持のままでいい」で却下 — 2026-09-05）。そのモードでは意味を持たない設定（全カードでの「ボード状況を考慮する / 開花状況を考慮する」）は未選択（白）+disabled に見せる（「選択が外れた状態で disabled にしろ」— 2026-09-06）。どちらも保存値は保持し、条件が外れれば保存した状態で復帰する。
- モーダルを開いたときにテキスト入力へ自動フォーカスしない（モバイルでキーボードが勝手に開く）。フォーカスはシート自体（`tabindex="-1"` の dialog 要素、`outline: none`）へ移し、キーボードはユーザーが入力欄をタップしたときだけ出す（2026-09-01）。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置（ページ先頭）へ視点を移す（おかゆモードの ON / OFF どちらでも先頭へスクロール — 2026-09-02）。
- 同種の連続スロット（メンバー枠等）は先頭の空き枠だけ有効にし、順序に意味がない入力に飛び石の自由度を与えない。解除時は上へ詰める（2026-09-01）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色/白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする（2026-09-01）。数値を入力する設定（Step 0 のメモリー % ・強化ボーナス %）も同じ設定行パターンで 1 項目 1 行にし、ラベルを左端・入力欄を右端に両端揃え、ラベルの文字サイズは同じパネルのボタン内の文字と揃える（小さく淡くしない）— 2 列横並びの小さなラベル + 数値欄は「ださい」（2026-09-08、案 3 つから選択）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す（2026-09-01）。選択コントロールを実行ボタンに隣接させるときは形・高さ・幅・色で役割を分ける — 選択は内容幅・32px のピル形チップ（ピッカーの所属チップと同形）で濃色地（`--ink`）、アクションは全幅・48px の角丸矩形で実行専用の緑（`--action`。おかゆモードは紫のまま）（2026-09-05 しぼりこみチップで形を分け、2026-09-06「色が同じで分かりにくいから緑っぽい色に」で色も分けた）。
- 数秒で終わる処理の進行は、押した実行ボタンの中だけで示す — ラベルを白い細線のリング（22px・2.5px、`.spinner`）に置き換え、ボタンの寸法・色は保つ。進捗バー・評価件数のテキスト・中止ボタンは置かない（「バーの近くの文字は不要。ステータスバーも中止も不要。ボタンにスピナー」— 2026-09-07）。
- 並ぶ選択肢は指定された順を保ったまま 2 列 × n 行の等幅グリッドに収める（縦 1 列は「2 行に収められない？」で却下 — 2026-09-06）。ラベルが収まらなければ文言を短くし、文字サイズを落とすのはそのグリッド内だけにとどめる（375px 幅でも収まることを実測する）。性質の違う要素（ON/OFF のチップと、ピッカーを開くボタン）を同じグリッドに並べるときは 1 行を全幅にせず左右に置き、形で区別する（チップはピル、ボタンは角丸矩形。高さ 32px と文字はチップに揃え、ラベル左・件数右で件数はボタンの中に入れる）。左の 1 つを 2 行分（`grid-row: span 2`）にして右の 2 つと高さを揃えてよい（さがすのオプション 1〜2 行目: 「所持カードから探す」+「リーダーから除外 / メンバーから除外」— 2026-09-08、2 往復）。
- キーと向きを持つ選択（並び順）は、キーのセグメント 1 つにまとめ、選択中のセグメントの再タップで向きを反転する — 4 択の全列挙や向きの別ボタンにしない（「同じボタンでトグル」）。ラベルは現在の向きを言葉で示し（「長い順」「短い順」）、選択中には現在の向きを ▼（降順）/ ▲（昇順）の片方で添える — ラベルの変化だけでは反転できることが伝わらないが、⇅ のような「反転できる」抽象記号は「微妙」（2026-09-05 曲ピッカーの並び順、3 往復で確定）。
- スキル行は常に 2 行ぶんの固定高を占有する。本文には固定高を持たせず、行コンテナの `align-items: center` で本文が 1 行でも 2 行でも実高の真ん中に自動整列させる（2026-09-01。旧「1 行なら下を 1 行空ける」を置き換え）。スロット・ピッカーは 2 行クランプ+省略記号（原文は基本 2 行に収まる。3 行に伸ばす・3 行固定にする・縦に送るはいずれも却下 — 2026-09-05）、詳細モーダルは min-height で全文表示。行同士の隙間は 2px、名前ブロックと効果の間隔はタイルの上下 padding と同じ 9px にして縦の余白を対称にする（「サブタイトルと効果の余白と一番下の余白が対称じゃない」）。
- はみ出すテキストは動かさない — 1 行は省略記号、複数行は行数固定+省略記号。横スクロール表示は往復・巻き戻し・看板型の 3 形態を試した末「バグってる」で廃止（2026-09-05）。装飾的な動きは実機で確認できない限り入れない。
- 並ぶ要素は縦・横の線を揃える。同種のアイコンは全行で同じ列（縦の線）に置き、常に出るもの（開花）を最右の固定列、条件つきのもの（固定ピン等）をその左の列に置く。アイコンの有無で行の高さを揺らさない（min-height で担保 — 2026-09-01）。
- カード類の高さは文字列長で揺らさない（行数固定+省略）。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all`（「55%UP(」等の英数字トークン手前で早折れする不自然な改行の防止）。
- 結果一覧はホロメン名とサブタイトル（カード名）を隣接させ（カード名 line-height 14px・margin-top -3px）、メンバー同士の間隔 6px・パネル上下 10px と密にする（2026-09-05）。詳細モーダルも同じ隣接。
- アカウントの状態（持っているカードと開花段階・ホロメンボード・お気に入りユニット）は Step 0「アカウント」にまとめ、そこでだけ変更する。入口は横並びの 3 ボタン「ホロメン / メンバー / ユニット」で件数は出さない（ヘッダの件数削除と同種 2 回目 — 2026-09-06「枚数表示とかいらん」）。探索の条件（枠・曲・オプション）と混ぜない。ホロメンボードはカードでなくホロメンに属するので入口もホロメン一覧から（カードタイル上の入口は却下 — 2026-09-06）。
- 詳細シート（カード詳細・曲詳細）の見出しは入口の一覧名と同じ（「カード一覧」）にし、対象の名前は本文の色つきカード（タレント名+サブタイトルだけ）で示す。所属のような分類はカードの中に文字で書かず、カードの直下に表示専用の小さなピル（24px・12px、ピッカーの所属チップの縮小形）を左から並べる — 静的ラベルにチップを使わない規則のユーザー指示による例外。データにない項目（コネクト効果の内容、作詞・作曲・編曲、開花途中の文言）は行ごと消さず「未確認」で残して将来入る場所を見せる。並び順はパラメータ → 衣装スキル → スキル → 開花 → コネクト効果（2026-09-07、2 往復で確定）。
- ゲーム側で決まっている値（ホロメンボードの左右型など）はユーザーに選ばせず、データ（`src/data/holomen.json`）に持って引く（左型 / 右型のセグメントを廃止 — 2026-09-07）。
- ゲーム内の画面を写す部品（ホロメンボード）は実機の形に忠実にする: マスの配置・向き、大きさの差（大マスは 1.5 倍）、接続点の形（丸角の四角）、マスを繋ぐ線の長さ（正方格子）まで再現し、横スクロールは許さない（縦横で線の長さを変えるのは可 — 2026-09-06、4 往復）。描画領域は格子の外に数 px の余白を取り、端の大マスの輪（選択の線幅 3px）が切れないようにする（2026-09-07）。ボードの操作は「解放 | 説明」の 2 モード（名前の下の行に、左に色の 4 択・右にモードの 2 択）。説明モードはタップしても状態を変えず、選んだマスに濃色の輪（未解放・解放済みで同じ色）をつけ、効果文言を「すべて解放 / 解除」と同じ高さの帯に出す。帯は枠線なしの淡色地で、文言の前に選んだマスの縮小（記号入りの丸）を置く。マス以外をタップすると選択が外れ、直前の選択は色ごとに覚える（保存しない — 2026-09-07、3 往復）。空間配置の仕様を図から写すときは、実装前に向きの基準（上下・左右・どちらから見るか）を一言確認する（ASCII 図の上下と 5 マス塊の左右が実機と逆だった）。 隣り合うマス同士を繋ぐ線は「あることが見える」幅（数 px）を確保する — 大マス同士が隣り合う組がある赤のステータス系エリアだけ間隔を 34 → 40px にし、他のエリア・他の色は 34px のまま（「大マスが隣り合う時接続線が狭すぎる」「それ以外は他の色の線の長さと一緒でいい」— 2026-09-08）。
- モバイルファーストで設計する。iPhone 実寸（390px 級）での崩れ・不自然な改行は出荷前に playwright-cli で確認する（確認手順は `.claude/rules/ui-verification.md` — このパス群を読むと自動で読み込まれる）。

## アイコンとラベル

- 静的なメタ情報ラベル（スキル種別・役割）に矩形の枠つきバッジ（チップ）を使わない — 「AI デザインの典型」であり、押せる/押せないのアフォーダンスも壊す（2026-09-01、サンプル画像 3 往復で確定）。
- 自明なメタファーがあるものは図のアイコン（衣装=Tシャツ / 固定=ピン / おかゆモード=おにぎり）、ないものは文字アイコン（SP / A / P）にし、すべて 26px の正円細線で囲んで統一する。ただし同じ一覧の中では様式を揃える — サイドメニューの項目は丸で囲まない 24px の線画なので、おかゆモードの行もおにぎり単体（丸囲みの `SkillIcon` を混ぜて「他のサブメニューと同じく」と直された — 2026-09-07）。制約で入ったカードの印（おにぎり）はピンと同じ列に出す（2026-09-02）。開花（凸）は花びらの輪郭+段階の数字で、花の輪郭が正円の枠を兼ねる。実装は `src/components/SkillIcon.vue`（自作 SVG のみ。公式アセット禁止 — ADR-002）。
- 計算の前提になっている値（開花段階など）は既定値でも省略せず常に表示する（0凸も出す — 2026-09-01）。逆に、計算に関係しない値のアイコンをその枠に出さない（リーダー行に開花アイコンは出さず最右列は衣装アイコン。詳細モーダルにピンは出さない — 2026-09-01）。値を変更できない画面（メンバーピッカー）では値をアイコンだけで見せ、± などの操作は出さない（開花は Step 0 でのみ変更 — 2026-09-06）。
- 図の中のマス・ノードの記号は 1 文字まで（全パラ = A、P / T / S、緑の所属向け = ユ（ユニット。2026-09-08 に「グ」から変更）、報酬系 = 酬、黄 = ソ / ユ / 全 / レ / キ / 特、赤 = A / P / T / S / 支 / 命 / 判 / 回 / 経 / 金 — 2026-09-08 ユーザー承認）。種類の差（割合か固定か）は文字を足さず大きさ・形で表す（「全」→「All」→「A」、「P%」→「P」と 2 段階で削られた — 2026-09-06）。ゲーム内表示にない記号を新しく作るときは候補を先に見せる — 「所」「報」は「グループのグ、報酬は酬」に直された（読みの 1 文字目や意味の中心の字 — 2026-09-07）。ホロメンボードのアイコンは六角形の輪郭+解放マス数（開花の花びら+数字と同じ構成）。
- 役割の違い（リーダー枠）はアイコンの付加でなく構造で示す — 結果一覧はリーダー行とメンバーの境をセパレータ（罫線）で区切る（無彩色の面バンド案は「不要」で却下 — 2026-09-01）。王冠アイコンは使わない。
- アイコンのテキストラベルは画面に出さず aria-label に退避する（「アクティブ」「パッシブ」「固定」等）。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行/2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- 同じ属性の表現方法を 1 つの画面の中で混在させない — タレント名の文字色でタイプを示す一覧に、タイプ淡色の面を混ぜない（2026-09-01 リーダー行のタイプ色バンドを却下）。
- タイプ色の正はキュート=ピンク/ハッピー=黄/ピュア=緑（docs/human/game-spec.md）。カードのタイプはタイプ淡色の面（背景）で表し、タイプ名のテキストバッジを置かない。タイルでない場所（結果一覧）ではタレント名の文字色（タイプ濃色）で判別する。黄は淡地+濃文字でのみ使う（白抜き禁止）。
- 等価な選択肢（回数違いの同一操作など）には primary/secondary の階層をつけず、同じ配色のボタンにする（例: ガチャの 1回/10回 — 2026-08-31）。
- 操作できない表示（キャプション・選んだ対象の説明・状態）は枠線を使わず淡色の地（`var(--bg)`）で示し、枠線つきの角丸はボタンに限る（説明モードの帯を枠線つきにして「ボタンと勘違いすると思う」。空のときも点線にせず、形は同じで中身だけ空 — 2026-09-07）。
- タイプ色パネルに枠線を付けない。例外は空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠（複数選択では該当する全カード）のみ。選択強調はそのカードのタイプ色を使い、無関係な固定色を当てない。
- コントロール（セグメント・チップ）の選択スタイルは全画面で 1 種類（濃色地+白文字）に揃え、選択肢の意味色（タイプ色）で選択状態を塗り分けない — タイプ色を使うのはカードそのもの（タイルの面・選択枠）だけ（2026-09-01 タイプセグメントの淡色地+下線を却下）。
- スキルの発動状態はテキストバッジ（「反映中」「条件未達」等）ではなく、発動=通常表示/不発動=行のグレーアウトで表す。「未反映（未構造化）」という状態は UI に設けない — データ側を 100% 構造化して状態自体をなくす（dataset のテストが 100% を強制）。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同一の角丸+影、装飾絵文字。地・罫線は無彩色に保ち、色は意味（タイプ・状態）にだけ使う。
- 機能的な意味を持たない装飾・記号を付けない（例: 選択済みカードのチェックマーク、所属チップの選択✓、しぼりこみチップの ✓ — 濃色地で選択は伝わる。2026-08-31 / 09-01 / 09-05 で同種 3 回）。状態を表す記号（並び順の ▼/▲）は可。グラフは表で表現できている情報に重ねて置かない（意味のないグラフ禁止）。
- ゲーム内で色の名前を持つもの（赤・青・黄・緑のホロメンボード）は、その色のトークン（`--board-*`）で描く（解放マス・接続線。黄だけは文字を濃色に）。選択コントロール自体は濃色地の規則のまま。用意できていない種類はタブとして先に置き disabled で見せる（Step 0 の「ユニット」と同種 — 2026-09-07。ボードの色は 2026-09-08 に赤も入り 4 色そろった） 切替の既定（シートを開いたときの色）も実装順でなくゲーム内の並びの先頭にする（青で実装を始めたが「ボードのデフォルトは青じゃなく赤」— 2026-09-08）。
- デザイントークンの正は `src/style.css` の `:root`。根拠と定石の出典は docs/human/tmp/20260831-design-research.md。

## 文言と情報量

- 注記に当然の否定を書かない（「メンバー 5 人に効き（リーダー自身には効かない）」の括弧は「不要」— 2026-09-08）。
- 冗長な文字情報を置かない: 背景色や見出しで伝わることをテキストで繰り返さない（枠名「リーダー」、タイプ名「ピュア」、不要な合計値）。空プレースホルダは中央の 1 行値のみにする。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない（2026-09-01）。件数はコントロール内の右寄せ値として置き、任意項目は「未入力+でも OK」でなく既定値「おまかせ」を実値として表示する（結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は可）。既定値が文脈で決まるなら、その実値まで具体化して見せる — ただし決まった時点で出し、先回りして出さない（おかゆモードの最後のメンバー枠は、4 枚選んでもおかゆんがいないときだけ「おかゆん（おまかせ）」。最初からは出さず、おかゆんを選んだ時点で出ない — 2026-09-02）。「おまかせ」はツールが実際に最良を選ぶ枠（リーダー・メンバー）にだけ使い、選ばなくても計算が成り立つ枠（曲）は「指定なし」と書く（2026-09-05「一曲選ぶのではなく平均にしてるんだよね？」）。指定なしのときに代表値の実値（2:09 / 全曲の中央値）を並べていたのは曲長を試算に使っていた時期の名残なので 2026-09-09 に削除した — **試算に効かない値を実値のように見せない**（行の高さだけ充填時に合わせる）。
- 手順の説明文で UI を補わない — UI 自体に情報を語らせ、本文コピーは最小にする。補足の注記（単価・確率の説明、★別集計などの統計文、選択対象の再掲）も置かない — コスト・件数はボタンや見出しのラベル内に含める（例:「10回 2,500」「結果（n回）」）。新機能にも例外なく適用する（仮想ガチャで 3 回指摘 — 2026-08-31）。操作方法の説明文（「タップで◯◯」等）も置かない。件数はメイン画面の行ボタン内の値としてだけ示し、ピッカーのヘッダには出さない（2026-09-05「ヘッダの枚数表示いらん」。旧「モーダルヘッダ等の値として示す」を置き換え）。免責・試算値の注記はフッタに集約する。シート内の注記（試算の前提・未確認の断り）は本文の途中に置かず、末尾の脚注（`.footnotes`、※n）にまとめ、本文側は見出しや値の直後の上付き `※n`（`.fn`）で参照する — 表の下の 1 行注記は「途中にあると読みにくい」（2026-09-07）。脚注は番号列（`.fn-num`、固定幅）と本文の 2 列にして、2 行目以降の左端を本文の左端に揃える（「左端が揃ってない」— 2026-09-07）。
- タップ可能の手掛かりに誘導テキスト・記号（「詳細 ›」等）を置かない（2026-09-01）。大きな行（結果一覧の 1 件）の押下で面を暗くしない — 「タップする時暗くなってタップアクションが見えるのは不要」（2026-09-08。2026-09-01 の「行全体の :active の背景変化で示す」を置き換え）。
- 押下の視覚効果は付けない — OS のタップハイライトは全要素で無効化済み（src/style.css）で、`:active` の暗転・減光も 2026-09-08 に全部削除した。iOS Safari はタッチ / pointer のリスナーがある要素にしか `:active` を当てないため、それまで実機では一度も見えておらず、カルーセルのリスナーで初めて見えた結果一覧の行が「不要」だった（2026-09-01 の「意味のある操作の :active にのみ付ける」を置き換え）。
- 選択モーダルのタイトルは、対応するメイン画面の見出しと同じ名詞ラベルにする（本体の文言を変えたら派生画面も同じターンで追随させる — 2026-09-01）。
- 同じ対象を見せる画面同士（選択モーダルと詳細など）で情報の粒度を揃え、片方にだけ細かい数値を出さない（2026-09-01 詳細のメンバー個別パラメータを削除）。
- 表示件数などプレゼンテーション都合の設定を実行前のフォーム入力で聞かない — 常に十分な件数を計算し、結果側で見せる。2026-09-01 は上位 100 件を 10 件+全幅の「さらに10件」の逐次表示、2026-09-08 からは上位 10 件を 1 件ずつの横スクロール（下の「n / 10」が上限を伝える。「100件じゃなくて10件をデフォにしていい」）。同じ形の大きな部品（メンバー枠 5 つ・結果 100 件）は縦に並べず、`PageCarousel.vue`（自前のページ送り: 指に追従 → 離した瞬間にページ確定 → transform 300ms。ブラウザの scroll-snap は「止まるまでが遅い」、180ms は「早すぎ」で却下。下に「n / N」と左右の三角、端の三角は disabled で隠さない、パネル全体の左右スワイプと PC のマウスドラッグでも送る。送り中も分子は揺らさず、収まりを待たずにタップできる）で 1 つずつ見せる（「縦に 5 個長い」— 2026-09-08）。動きの原則: アニメーションは短く残す（180ms は「早すぎ」、300ms）が、表示値（分子）はアニメーション途中の位置から計算せず、送った瞬間に確定値を出す。ジェスチャ直後の操作を待たせない — OS の惰性スクロールのような「収まるまで触れない時間」を UI に入れない（scroll-snap を却下、2026-09-08 に 4 往復）。 アニメーションはユーザーが起こした操作（三角・スワイプ）にだけ付け、状態変化に伴う自動遷移（カードを入れたあとの「次の枠へ」）は瞬時に切り替える（`PageCarousel.jumpTo`。送ると入れたカードの面が最後にチラ見えして「嫌」— 2026-09-08）。
- ヘッダには識別情報（タイトル・機能アイコン）以外のテキスト（手順リスト・キャッチコピー）を置かない（2026-08-31、同種 2 回目）。メイン画面のフッタは免責の 1 段落だけ（データ確認日・GitHub リンクは 2026-09-07 に削除し、リンクはサイドメニューへ）。
- 数値に対する操作（追加・リセット等）は説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる（例: 課金額の隣の課金 +、リセット ↺ — 2026-08-31）。
- 並ぶ選択肢のラベルは主語と構文を揃える（さがすステップのオプション 5 チップはすべて「ツールが主語の他動詞文」— 「所持カードから探す / ボード状況を考慮する / 開花状況を考慮する / 衣装スキル発動に限る / パッシブ全員発動に限る」。「衣装スキルが発動する」はスキルが主語の自動詞で不揃いだった — 2026-09-06「自動詞と他動詞とか文体の統一も」）。ラベルは短く — 「持っているカードのみからさがす」は「所持カードから探す」に（2026-09-08）。
- 同名の別種があるものは種類を明示する。種類の切り替えが見込まれるなら見出しに入れず、切替コントロールで示す（ホロメンボードは見出し「ホロメンボード（青）」（2026-09-06）→ 見出し「ホロメンボード」+ 赤・青・黄・緑のセグメント。用意できていない種類は disabled で置く — 2026-09-07）。
- セクション見出しは短い名詞 1 語にし、括弧の補足を付けない（「リーダースキル（衣装）」→「衣装スキル」、「リーダー（衣装スキル）」→「リーダー」— 2026-09-07）。
- 回数は「n回」と表記する（「n連」などの言い回しを使わない — 2026-08-31）。
- カード表示は名前を大きく左上、カード名（サブタイトル）をその下に小さく。スキルの表記順は常に SP → アクティブ → パッシブ（リーダー文脈では衣装スキル）。
- 同種の操作（カード選択）は見た目も操作も同形に揃える（リーダーとメンバーで別 UI にしない）。
- モーダルの出口はヘッダ右上の ✕ 1 つ（共通部品 `CloseButton.vue`: 44px の正円に 18px × 2px の線 2 本。ハンバーガーが開いたときに変わる ✕ と同じ形・大きさ — 文字の ✕ は「サイズが違う」で 2026-09-07 に置き換え）。複数選択（除外・所持）も切り替えが即時反映なので下の「完了」は置かない — 同じ動作の出口が 2 つあると「✕ は取り消しか」と迷わせる。ヘッダを無くして下に「完了」だけ置く案はユーザー提案で試した後に「戻す」となった（モーダルには明示的な脱出手段が要る — 2026-09-05）。
- 所属の並び（フィルタのチップ・一覧の順 — `src/ui/labels.ts` の `AFFILIATION_ORDER`）はゲーム内のデビュー順: 0・1・2期生 → ゲーマーズ → 3・4・5期生 → holoX → Myth・Promise・Advent → AREA15・holoro・holoh3ro → ReGLOSS。ゲーマーズは 2期生と 3期生の間（1期生の後に置いて「ゲマズが 2期生の前にあるけどあと。3期生の前」— 2026-09-08）。
- 名前を列挙する区切りは読点「、」にし、名前自体に含まれうる記号（中点「・」）を使わない（曲の歌唱者を「・」で繋いで「フワワ・アビスガード・モココ・アビスガード」となり「分かれ目が不明になる。読点にしよう」— 2026-09-08。`artistsLabel`）。
- カード一覧（リーダー・メンバー・除外・所持）はホロメン名の読み → カード名の読みであいうえお順に並べる（文字コード順は英字→カナ→かな→漢字の部首順になり不可 — 2026-09-05）。読みは `holomen.json` / `cards.json` の `reading`（約束事は `src/data/README.md`）、比較は `src/ui/labels.ts` の `readingSortKey`（長音を直前の母音に正規化）。検索も読みに一致する。

## 数値の表

- 1 つの列に絶対値と % を混在させない。% は絶対値の括弧補足に落とす（2026-09-01）。
- 内訳は足すと合計に一致する形（検算できる形）で見せる。表示上の丸め誤差は 1 行に寄せてでも一致させる。
- 表同士の親子関係（どの数字の内訳か）は見出しと合計行で明示する — 合計行の値が親の数字と一致して環が閉じるように置く。
- 結果詳細の表はゲーム画面と同じ項目・同じ名前で、メンバー別（素の P/T/S と総合力）→ 総合力の 6 項目 → スコアボーナスの 4 項目の順に置く。ゲーム画面にない中間量の表（旧「総合力」の連鎖乗算の表、総合期待スコアの内訳表）は置かない（2026-09-08「既存の総合力の一番上の表はもはや不要」「ホロメンごとの表は一番上に」）。
- 前段から変化していない値は淡色にして、効いた列だけ目立たせる。
- 表のセルは 1 行に収める — 値セルと行見出しは折り返さず（`white-space: nowrap`）、収まらなければ文字を小さくする前に文言を削る（効果名は「歌唱者条件のパフォーマンス」、結果詳細の列見出しは「〜後」を外して「素の合計 / 赤ボード / パッシブ / 衣装スキル」— 2026-09-08「全員のセンスが 2 行になってる」「後があるせいで 2 行になるので後削除」）。
- ボード効果の割合はゲーム内どおり小数第 1 位まで（+4.0%、+20.0%、+0.5%）で全色そろえ、整数の「+4%」を混在させない（`formatBoardPercent` / `formatBoardPermil`、`src/data/boardGraph.ts`。青の発動率・黄のホロワーク報酬が整数表記だった — 2026-09-08「小数第一位で .0% までつけること。他の色のボード効果も表記揺れしてるので直す」）。

## 実装ノート

- iOS Safari は数字列を電話番号と誤検出して青いリンクにするため、index.html に `<meta name="format-detection" content="telephone=no">` を必ず置く（「計算結果の文字色が青」の原因だった）。保険として `src/style.css` の `a[href^="tel:"], a[x-apple-data-detectors]` でリンク化された数字の見た目も打ち消す。ただし 2026-09-07 の「結果一覧のスコアの数字が青色（iPhone の Chrome）」の原因は電話番号検出ではなく、**iOS の `<button>` の既定文字色がシステムの青**であること — 色を指定していない `<button>`（結果一覧の行）がそのまま青くなった。`src/style.css` で `button { color: inherit }` を全体に当てて解決。Linux の Chromium では黒く描かれるので playwright-cli では再現しない — `<button>` を文字の器に使うときは色を明示するか継承に任せ、既定色に頼らない。新しいシートを作るときはヘッダを共通寸法（padding 16px・h3 24px/900・77px）にし、boundingBox で実測する（結果詳細が 12px/18px のまま残っていた — 2026-09-07）。
- iOS Safari は、要素かその親にタッチ / pointer のイベントリスナーがないと `:active` を適用しない — このアプリでは長く「押下で暗くなる」CSS が実機で一度も見えておらず、カルーセルが pointer リスナーを付けた途端に結果行だけ暗くなって「不要」となった（2026-09-08）。Linux の Chromium ではマウスで再現するので、実機の見え方を playwright-cli の結果から断定しない。
- transform で送る部品（PageCarousel）は、全ページを 1 枚の帯にせず現在ページの前後だけを個別に transform し、`will-change: transform` で常時レイヤーに載せる — 100 件で横 35,000px 超の帯や、送りの開始・終了でのレイヤーの作り直しは iOS で一瞬白く抜ける（2026-09-08。この対策で実機のちらつきは消えた）。
- 連打・トグル操作にブラウザ既定のジェスチャ（ダブルタップズーム・文字選択）が割り込むのは不具合として扱う。`button, [role="button"]` には `touch-action: manipulation`（src/style.css、全体に適用済み）、連打する記号には `user-select: none`（開花 ± の連打で iPhone がズームした — 2026-09-05）。
- モーダルの背景スクロールロック（`useModalChrome.ts`、body を position:fixed）中に検索欄でキーボードが出ると、iOS Safari がレイアウトビューポートを押し上げて閉じた後にページ最下部へ空白を残すことがある。html/body の overflow hidden・入力欄の focusout でスクロール 0・解除時に blur してから復元、の対策を入れてある（実機未検証 — pending 9）。
- 脚注の番号（※1・※2…）は画面の上から出てくる順に振る。表の並べ替えで順序が崩れたまま出したら「上から 1・3・2 になってるのきもすぎ」（2026-09-08）。並べ替えたら脚注も振り直す。
- 結果の主数値は「最終的なユニットスコア（試算）」1 つで、説明文（「総合期待スコア（試算値）」）は添えず、同じ値を表の行として繰り返さない（2026-09-08）。免責は脚注 ※1 で持つ。
