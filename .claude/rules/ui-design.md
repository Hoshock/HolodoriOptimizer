# UI デザインの制約（2026-08-31〜09-01 ユーザーフィードバック由来）

機能追加でも新しいデザインを持ち込まない — 既存のコンポーネント・トークン・デザイン言語（例: 状態選択はピッカーのセグメンテッドコントロールと同形）を踏襲する（「見た目に関しては既存を尊重すること」）。遊び機能（仮想ガチャ等）はゲーム仕様の忠実な再現より操作の単純さを優先する（通貨 2 種・割引枠・天井などは要求されるまで再現しない — 2026-08-31）。お遊び機能の入口は本線のフローに混ぜず、説明文も付けない（おかゆモードはフッター最下部の一番右のアイコンのみ。URL パラメータは作らず、状態も保存しないので再読み込みで解除 — 2026-09-02）。詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01）。モード全体に効くグローバルな詳細設定を増やさない — 既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダル内で設定する（2026-09-01 一律開花セグメントの却下）。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法が 1px も変わってはならない（レイアウトシフト禁止）。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測確認する。
- ヘッダなどの常時表示領域も同様に、タブ・モード切替で寸法（高さ）が変わってはならない。この不変則は画面遷移（フルスクリーンモーダル）にも適用する — 画面のヘッダはページヘッダと同寸法・同文字サイズにする（2026-08-31）。切替内容に依存するもの（手順リスト等）をヘッダに置かない。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする（2026-09-01 タブ統合）。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない（選択肢がなくなったら畳む）。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない（2026-09-01。モーダル内全グレーアウト実装を訂正された）。前提が満たされず操作を止めるときも、赤いエラーメッセージでなく「方針」をボタンのラベルで示す（例: おかゆモードで所持ピッカーのボタンを「おかゆんを選んでください」にし、リーダー・メンバー・実行を disabled — 2026-09-02）。
- モーダルを開いたときにテキスト入力へ自動フォーカスしない（モバイルでキーボードが勝手に開く）。フォーカスはシート自体（`tabindex="-1"` の dialog 要素、`outline: none`）へ移し、キーボードはユーザーが入力欄をタップしたときだけ出す（2026-09-01）。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置（ページ先頭）へ視点を移す（おかゆモードの ON / OFF どちらでも先頭へスクロール — 2026-09-02）。
- 同種の連続スロット（メンバー枠等）は先頭の空き枠だけ有効にし、順序に意味がない入力に飛び石の自由度を与えない。解除時は上へ詰める（2026-09-01）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色/白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする（2026-09-01）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す（2026-09-01）。
- スキル行は常に 2 行ぶんの固定高を占有する。本文には固定高を持たせず、行コンテナの `align-items: center` で本文が 1 行でも 2 行でも実高の真ん中に自動整列させる（2026-09-01。旧「1 行なら下を 1 行空ける」を置き換え）。スロット・ピッカーは 2 行クランプ+省略記号、詳細モーダルは min-height で全文表示。
- 並ぶ要素は縦・横の線を揃える。同種のアイコンは全行で同じ列（縦の線）に置き、常に出るもの（開花）を最右の固定列、条件つきのもの（固定ピン等）をその左の列に置く。アイコンの有無で行の高さを揺らさない（min-height で担保 — 2026-09-01）。
- カード類の高さは文字列長で揺らさない（行数固定+省略）。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all`（「55%UP(」等の英数字トークン手前で早折れする不自然な改行の防止）。
- モバイルファーストで設計する。iPhone 実寸（390px 級）での崩れ・不自然な改行は出荷前に playwright-cli で確認する（確認手順は `.claude/rules/ui-verification.md` — このパス群を読むと自動で読み込まれる）。

## アイコンとラベル

- 静的なメタ情報ラベル（スキル種別・役割）に矩形の枠つきバッジ（チップ）を使わない — 「AI デザインの典型」であり、押せる/押せないのアフォーダンスも壊す（2026-09-01、サンプル画像 3 往復で確定）。
- 自明なメタファーがあるものは図のアイコン（衣装=Tシャツ / 固定=ピン / おかゆモード=おにぎり）、ないものは文字アイコン（SP / A / P）にし、すべて 26px の正円細線で囲んで統一する。制約で入ったカードの印（おにぎり）はピンと同じ列に出す（2026-09-02）。開花（凸）は花びらの輪郭+段階の数字で、花の輪郭が正円の枠を兼ねる。実装は `src/components/SkillIcon.vue`（自作 SVG のみ。公式アセット禁止 — ADR-002）。
- 計算の前提になっている値（開花段階など）は既定値でも省略せず常に表示する（0凸も出す — 2026-09-01）。逆に、計算に関係しない値のアイコンをその枠に出さない（リーダー行に開花アイコンは出さず最右列は衣装アイコン。詳細モーダルにピンは出さない — 2026-09-01）。
- 役割の違い（リーダー枠）はアイコンの付加でなく構造で示す — 結果一覧はリーダー行とメンバーの境をセパレータ（罫線）で区切る（無彩色の面バンド案は「不要」で却下 — 2026-09-01）。王冠アイコンは使わない。
- アイコンのテキストラベルは画面に出さず aria-label に退避する（「アクティブ」「パッシブ」「固定」等）。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行/2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- 同じ属性の表現方法を 1 つの画面の中で混在させない — タレント名の文字色でタイプを示す一覧に、タイプ淡色の面を混ぜない（2026-09-01 リーダー行のタイプ色バンドを却下）。
- タイプ色の正はキュート=ピンク/ハッピー=黄/ピュア=緑（docs/human/game-spec.md）。カードのタイプはタイプ淡色の面（背景）で表し、タイプ名のテキストバッジを置かない。タイルでない場所（結果一覧）ではタレント名の文字色（タイプ濃色）で判別する。黄は淡地+濃文字でのみ使う（白抜き禁止）。
- 等価な選択肢（回数違いの同一操作など）には primary/secondary の階層をつけず、同じ配色のボタンにする（例: ガチャの 1回/10回 — 2026-08-31）。
- タイプ色パネルに枠線を付けない。例外は空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠（複数選択では該当する全カード）のみ。選択強調はそのカードのタイプ色を使い、無関係な固定色を当てない。
- コントロール（セグメント・チップ）の選択スタイルは全画面で 1 種類（濃色地+白文字）に揃え、選択肢の意味色（タイプ色）で選択状態を塗り分けない — タイプ色を使うのはカードそのもの（タイルの面・選択枠）だけ（2026-09-01 タイプセグメントの淡色地+下線を却下）。
- スキルの発動状態はテキストバッジ（「反映中」「条件未達」等）ではなく、発動=通常表示/不発動=行のグレーアウトで表す。「未反映（未構造化）」という状態は UI に設けない — データ側を 100% 構造化して状態自体をなくす（dataset のテストが 100% を強制）。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同一の角丸+影、装飾絵文字。地・罫線は無彩色に保ち、色は意味（タイプ・状態）にだけ使う。
- 機能的な意味を持たない装飾・記号を付けない（例: 選択済みカードのチェックマーク、所属チップの選択✓ — 濃色地で選択は伝わる。2026-08-31 / 09-01 で同種 2 回）。グラフは表で表現できている情報に重ねて置かない（意味のないグラフ禁止）。
- デザイントークンの正は `src/style.css` の `:root`。根拠と定石の出典は docs/human/tmp/20260831-design-research.md。

## 文言と情報量

- 冗長な文字情報を置かない: 背景色や見出しで伝わることをテキストで繰り返さない（枠名「リーダー」、タイプ名「ピュア」、不要な合計値）。空プレースホルダは中央の 1 行値のみにする。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない（2026-09-01）。件数はコントロール内の右寄せ値として置き、任意項目は「未入力+でも OK」でなく既定値「おまかせ」を実値として表示する（結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は可）。既定値が文脈で決まるなら、その実値まで具体化して見せる — ただし決まった時点で出し、先回りして出さない（おかゆモードの最後のメンバー枠は、4 枚選んでもおかゆんがいないときだけ「おかゆん（おまかせ）」。最初からは出さず、おかゆんを選んだ時点で出ない — 2026-09-02）。
- 手順の説明文で UI を補わない — UI 自体に情報を語らせ、本文コピーは最小にする。補足の注記（単価・確率の説明、★別集計などの統計文、選択対象の再掲）も置かない — コスト・件数はボタンや見出しのラベル内に含める（例:「10回 2,500」「結果（n回）」）。新機能にも例外なく適用する（仮想ガチャで 3 回指摘 — 2026-08-31）。操作方法の説明文（「タップで◯◯」等）も置かない — 件数はモーダルヘッダ等の値として示す（2026-09-01）。免責・試算値の注記はフッタ（詳細モーダルでは末尾の注記）に集約する。
- タップ可能の手掛かりに誘導テキスト・記号（「詳細 ›」等）を置かない — 行全体の押下フィードバック（:active の背景変化）で示す（2026-09-01）。
- 押下の視覚効果は操作が意味を持つときだけ出す — OS のタップハイライトは全要素で無効化済み（src/style.css）で、フィードバックは意味のある操作の :active にのみ付ける。無効化した操作や選択済みの再タップで何も光らせない（2026-09-01）。
- 選択モーダルのタイトルは、対応するメイン画面の見出しと同じ名詞ラベルにする（本体の文言を変えたら派生画面も同じターンで追随させる — 2026-09-01）。
- 同じ対象を見せる画面同士（選択モーダルと詳細など）で情報の粒度を揃え、片方にだけ細かい数値を出さない（2026-09-01 詳細のメンバー個別パラメータを削除）。
- 表示件数などプレゼンテーション都合の設定を実行前のフォーム入力で聞かない — 常に十分な件数（上位 100）を計算し、結果側の逐次表示（10 件+全幅の「さらに10件」）で見せる。上限は注記テキストでなく、出しきるとボタンが消える構造で伝える（2026-09-01）。
- ヘッダには識別情報（タイトル・機能アイコン）以外のテキスト（手順リスト・キャッチコピー）を置かない（2026-08-31、同種 2 回目）。
- 数値に対する操作（追加・リセット等）は説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる（例: 課金額の隣の課金 +、リセット ↺ — 2026-08-31）。
- 回数は「n回」と表記する（「n連」などの言い回しを使わない — 2026-08-31）。
- カード表示は名前を大きく左上、カード名（サブタイトル）をその下に小さく。スキルの表記順は常に SP → アクティブ → パッシブ（リーダー文脈では衣装スキル）。
- 同種の操作（カード選択）は見た目も操作も同形に揃える（リーダーとメンバーで別 UI にしない）。
- 一覧は識別に必要な最小限にとどめ、詳細はタップ→モーダルの先に置く。ただし結果一覧は条件に関わらず編成全体（リーダー+メンバー 5）を常に同じ形で見せる（2026-09-01）。
- UI に内部用語を出さない（例: 「構造化」「structured」のような実装語彙を画面に出さない。状態表現の冗長な修飾も削る — 「スコアに反映中」ではなく「反映中」）。
- 数値・スキルの前提（レベル最大・設定した開花段階に応じた試算で、未確認の段階は仮定倍率の概算であること）を、値を見せる画面（詳細モーダル等）の注記で明示する。
- 選択 UI は単一選択か複数選択かがぱっと見で分かる形にする。複数選択の状態（除外・所持など）はページには件数のみ出し、内訳の確認・解除はピッカーを開き直して行う — チップ等の一覧をページに並べない（多数選択時に縦へ伸びるため。2026-08-31 訂正: 以前の「何が対象かを一覧で見せる」を置き換え）。長いドロップダウンで選ばせない — 検索+フィルタつきの視覚的な選択 UI にする。複数選択ピッカーには状態フィルター（すべて | 登録済み/除外中）を置き、絞り込み（検索・所属・タイプ・状態）はモーダルを閉じても保持して次回復元する（モーダル種別ごとに独立、ページ再読み込みでリセット）。単一選択ピッカー（カード・曲）は選択中の項目を開いた瞬間に 1 回だけリスト先頭へフィーチャーする（開いている間は並びを動かさない — 2026-09-01）。

## 数値の表

- 1 つの列に絶対値と % を混在させない。% は絶対値の括弧補足に落とす（2026-09-01）。
- 内訳は足すと合計に一致する形（検算できる形）で見せる。表示上の丸め誤差は 1 行に寄せてでも一致させる。
- 表同士の親子関係（どの数字の内訳か）は見出しと合計行で明示する — 合計行の値が親の数字と一致して環が閉じるように置く。
- 前段から変化していない値は淡色にして、効いた列だけ目立たせる。

## 実装ノート

- iOS Safari は数字列を電話番号と誤検出して青いリンクにするため、index.html に `<meta name="format-detection" content="telephone=no">` を必ず置く（「計算結果の文字色が青」の原因だった）。
