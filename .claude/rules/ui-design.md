# UI デザインの制約（全画面共通。2026-08-31〜09-09 ユーザーフィードバック由来）

UI の規則は 2026-09-09 の棚卸し 24 回目で 4 ファイルに分けた（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

機能追加でも新しいデザインを持ち込まない — 既存のコンポーネント・トークン・デザイン言語（例: 状態選択はピッカーのセグメンテッドコントロールと同形）を踏襲する（「見た目に関しては既存を尊重すること」）。遊び機能（仮想ガチャ等）はゲーム仕様の忠実な再現より操作の単純さを優先する（通貨 2 種・割引枠・天井などは要求されるまで再現しない — 2026-08-31）。既存パターンと形が違う UI を入れるときは、提案時にその差の意図（単一選択と複数選択の区別など）を明示する（2026-09-05「意図が知りたい」）。「UI どうする？」のような設計相談には案の提示で止め、明示の着手指示を待ってから実装する — 方針の一言（「欲しいのは獲得ボーナス最大化」）を着手の合図と受け取り、本線の Step 4 に目的セグメントと結果の主数値の差し替えを実装して画像つきで push したところ「微妙だ。一旦戻して別ブランチに退避」となった（2026-09-08。実装はブランチ `claude/event-bonus-objective` に退避、main は revert）。「push までする」運用は指示された変更に適用し、設計相談の回答には適用しない。調整ツール（配色の管理用画面など）は**対象そのものを見ながら触れる形**にする — 全画面のシートに入れて縮小プレビューで代用したら「実画面にしないと意味ないが…」で差し戻された（2026-09-09。実画面の上に固定する操作バーへ）。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法が 1px も変わってはならない（レイアウトシフト禁止）。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測確認する。モード切替で出し入れする要素は同じ高さの枡に置き換え、下の要素を動かさない（ボードの「すべて解放 / 解除」の行が説明モードでは同じ 44px の帯になる — 2026-09-07「他の位置がずれないようにすること」）。
- 表・一覧の行は固定順で全項目を常に出す — 選択順・解放順で行が増減したり並びが変わったりしない。値がないときは +0 などの空値で行を残す（緑ボードの効果表で解放した報酬系だけを解放順に出して「選ぶ順によって上から並ぶ順が変わるのきもい」— 2026-09-07）。番号を持つもの（お気に入りユニットの 1〜10）をページで見せるときも同じで、登録済みだけを詰めずに全数を並べて番号とページ番号を一致させる（2026-09-09）。
- 重ねる装飾・アイコンのために元の部品の寸法を変えない（星の場所を作るために結果のパネルを内側へ寄せた案は「元のパネルのサイズを小さくするな」で差し戻し。はみ出しは親側（カルーセルのトラック）の描画範囲で処理する — 2026-09-09）。
- 可変長の見出し（人名・曲名）と固定幅のコントロールを同じ行に並べない — 見出しは 1 行を占有させ、コントロールは次の行に左右で並べる（ボードの名前と色セグメントを同じ行に置いて「名前が長いと省略されてしまっている」— 2026-09-07）。
- ヘッダなどの常時表示領域も同様に、タブ・モード切替で寸法（高さ）が変わってはならない。この不変則は画面遷移（フルスクリーンモーダル）にも適用する — 画面のヘッダはページヘッダと同寸法（77px）・同文字サイズ（24px/900）・同じ下罫線にし、両画面の boundingBox で実測して確かめる（2026-08-31。2026-09-05 にピッカーが 60px で「開くとヘッダの高さが変わる」と指摘され、規則があっても未実測だった）。切替内容に依存するもの（手順リスト等）をヘッダに置かない。
- はみ出すテキストは動かさない — 1 行は省略記号、複数行は行数固定+省略記号。横スクロール表示は往復・巻き戻し・看板型の 3 形態を試した末「バグってる」で廃止（2026-09-05）。装飾的な動きは実機で確認できない限り入れない。
- 並ぶ要素は縦・横の線を揃える。同種のアイコンは全行で同じ列（縦の線）に置き、常に出るもの（開花）を最右の固定列、条件つきのもの（固定ピン等）をその左の列に置く。アイコンの有無で行の高さを揺らさない（min-height で担保 — 2026-09-01）。
- カード類の高さは文字列長で揺らさない（行数固定+省略）。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all`（「55%UP(」等の英数字トークン手前で早折れする不自然な改行の防止）。
- ゲーム側で決まっている値（ホロメンボードの左右型など）はユーザーに選ばせず、データ（`src/data/holomen.json`）に持って引く（左型 / 右型のセグメントを廃止 — 2026-09-07）。
- モバイルファーストで設計する。iPhone 実寸（390px 級）での崩れ・不自然な改行は出荷前に playwright-cli で確認する（確認手順は `.claude/rules/ui-verification.md` — このパス群を読むと自動で読み込まれる）。

## アイコンとラベル

- 静的なメタ情報ラベル（スキル種別・役割）に矩形の枠つきバッジ（チップ）を使わない — 「AI デザインの典型」であり、押せる/押せないのアフォーダンスも壊す（2026-09-01、サンプル画像 3 往復で確定）。
- 自明なメタファーがあるものは図のアイコン（衣装=Tシャツ / 固定=ピン / おかゆモード=おにぎり）、ないものは文字アイコン（SP / A / P）にし、すべて 26px の正円細線で囲んで統一する。ただし同じ一覧の中では様式を揃える — サイドメニューの項目は丸で囲まない 24px の線画なので、おかゆモードの行もおにぎり単体（丸囲みの `SkillIcon` を混ぜて「他のサブメニューと同じく」と直された — 2026-09-07）。制約で入ったカードの印（おにぎり）はピンと同じ列に出す（2026-09-02）。開花（凸）は花びらの輪郭+段階の数字で、花の輪郭が正円の枠を兼ねる。実装は `src/components/SkillIcon.vue`（自作 SVG のみ。公式アセット禁止 — ADR-002）。
- 計算の前提になっている値（開花段階など）は既定値でも省略せず常に表示する（0凸も出す — 2026-09-01）。逆に、計算に関係しない値のアイコンをその枠に出さない（リーダー行に開花アイコンは出さず最右列は衣装アイコン。詳細モーダルにピンは出さない — 2026-09-01）。値を変更できない画面（メンバーピッカー）では値をアイコンだけで見せ、± などの操作は出さない（開花は Step 0 でのみ変更 — 2026-09-06）。
- アイコンのテキストラベルは画面に出さず aria-label に退避する（「アクティブ」「パッシブ」「固定」等）。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行/2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- 同じ属性の表現方法を 1 つの画面の中で混在させない — タレント名の文字色でタイプを示す一覧に、タイプ淡色の面を混ぜない（2026-09-01 リーダー行のタイプ色バンドを却下）。
- タイプ色の正はキュート=ピンク/ハッピー=黄/ピュア=緑（docs/human/game-spec.md）。カードのタイプはタイプ淡色の面（背景）で表し、タイプ名のテキストバッジを置かない。タイルでない場所（結果一覧）ではタレント名の文字色（タイプ濃色）で判別する。タイプ色の黄は淡地+濃文字でのみ使う（白抜き禁止）。ホロメンボードの黄はこの規則の外で、解放マスの文字は白（2026-09-09 ユーザー指示）。
- 等価な選択肢（回数違いの同一操作など）には primary/secondary の階層をつけず、同じ配色のボタンにする（例: ガチャの 1回/10回 — 2026-08-31）。
- 操作できない表示（キャプション・選んだ対象の説明・状態）は枠線を使わず淡色の地（`var(--bg)`）で示し、枠線つきの角丸はボタンに限る（説明モードの帯を枠線つきにして「ボタンと勘違いすると思う」。空のときも点線にせず、形は同じで中身だけ空 — 2026-09-07）。
- タイプ色パネルに枠線を付けない。例外は空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠（複数選択では該当する全カード）のみ。選択強調はそのカードのタイプ色を使い、無関係な固定色を当てない。
- コントロール（セグメント・チップ・番号バッジ）の選択スタイルは全画面で 1 種類（`--selected` の地 + `--selected-ink` の文字。ライトは濃色地+白文字、ダークモードでは明るい地+暗い文字へ反転する — `--ink` を地に使うとダークで白文字が消える）に揃え、選択肢の意味色（タイプ色）で選択状態を塗り分けない — タイプ色を使うのはカードそのもの（タイルの面・選択枠）だけ（2026-09-01 タイプセグメントの淡色地+下線を却下）。
- スキルの発動状態はテキストバッジ（「反映中」「条件未達」等）ではなく、発動=通常表示/不発動=行のグレーアウトで表す。「未反映（未構造化）」という状態は UI に設けない — データ側を 100% 構造化して状態自体をなくす（dataset のテストが 100% を強制）。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同一の角丸+影、装飾絵文字。地・罫線は無彩色に保ち、色は意味（タイプ・状態）にだけ使う。
- 機能的な意味を持たない装飾・記号を付けない（例: 選択済みカードのチェックマーク、所属チップの選択✓、しぼりこみチップの ✓ — 濃色地で選択は伝わる。2026-08-31 / 09-01 / 09-05 で同種 3 回）。状態を表す記号（並び順の ▼/▲）は可。グラフは表で表現できている情報に重ねて置かない（意味のないグラフ禁止）。
- ヘッダなどの `--chrome` の帯の上に載る 44px の正円（ハンバーガー・✕）は面の色（`--surface`）にして、帯と区別する（2026-09-09）。
- デザイントークンの正は `src/style.css` の `:root`。配色モードは同じトークンを差し替えて表す（`:root.dark-mode` = ダークモード、`:root.okayu-mode` = おかゆモード、併用は `:root.dark-mode.okayu-mode`）。役割の割り当て（面・文字・タイプ 3 色の淡=面 / 濃=文字、ヘッダ・下端の固定エリア・注釈のフッタの `--chrome`）はモードによらず同じにする。`--chrome` は地との差がぎりぎり分かる薄さにとどめ、色みは無彩色寄り（おかゆモードだけ紫系）にする。根拠と定石の出典は docs/human/tmp/20260831-design-research.md。

## 文言と情報量

- 注記に当然の否定を書かない（「メンバー 5 人に効き（リーダー自身には効かない）」の括弧は「不要」— 2026-09-08）。
- 冗長な文字情報を置かない: 背景色や見出しで伝わることをテキストで繰り返さない（枠名「リーダー」、タイプ名「ピュア」、不要な合計値）。空プレースホルダは中央の 1 行値のみにし、字送りもプレースホルダ同士で揃える（14px / 600 の淡色 = `UnitSlot` / `SongRow` の `.empty-msg`。充填時の値の字送り（曲名 15px / 700）を継がない — 2026-09-09「指定なしは中央揃え」「おまかせとフォントサイズが違くない？」の 2 往復）。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない（2026-09-01）。件数はコントロール内の右寄せ値として置き、任意項目は「未入力+でも OK」でなく既定値「おまかせ」を実値として表示する（結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は可）。既定値が文脈で決まるなら、その実値まで具体化して見せる — ただし決まった時点で出し、先回りして出さない（おかゆモードの最後のメンバー枠は、4 枚選んでもおかゆんがいないときだけ「おかゆん（おまかせ）」。最初からは出さず、おかゆんを選んだ時点で出ない — 2026-09-02）。「おまかせ」はツールが実際に最良を選ぶ枠（リーダー・メンバー）にだけ使い、選ばなくても計算が成り立つ枠（曲）は「指定なし」と書く（2026-09-05「一曲選ぶのではなく平均にしてるんだよね？」）。指定なしのときに代表値の実値（2:09 / 全曲の中央値）を並べていたのは曲長を試算に使っていた時期の名残なので 2026-09-09 に削除した — **試算に効かない値を実値のように見せない**（行の高さだけ充填時に合わせる）。
- 手順の説明文で UI を補わない — UI 自体に情報を語らせ、本文コピーは最小にする。補足の注記（単価・確率の説明、★別集計などの統計文、選択対象の再掲）も置かない — コスト・件数はボタンや見出しのラベル内に含める（例:「10回 2,500」「結果（n回）」）。新機能にも例外なく適用する（仮想ガチャで 3 回指摘 — 2026-08-31）。操作方法の説明文（「タップで◯◯」等）も置かない。件数はメイン画面の行ボタン内の値としてだけ示し、ピッカーのヘッダには出さない（2026-09-05「ヘッダの枚数表示いらん」。旧「モーダルヘッダ等の値として示す」を置き換え）。免責・試算値の注記はフッタに集約する。シート内の注記（試算の前提・未確認の断り）は本文の途中に置かず、末尾の脚注（`.footnotes`、※n）にまとめ、本文側は見出しや値の直後の上付き `※n`（`.fn`）で参照する — 表の下の 1 行注記は「途中にあると読みにくい」（2026-09-07）。脚注は番号列（`.fn-num`、固定幅）と本文の 2 列にして、2 行目以降の左端を本文の左端に揃える（「左端が揃ってない」— 2026-09-07）。
- タップ可能の手掛かりに誘導テキスト・記号（「詳細 ›」等）を置かない（2026-09-01）。大きな行（結果一覧の 1 件）の押下で面を暗くしない — 「タップする時暗くなってタップアクションが見えるのは不要」（2026-09-08。2026-09-01 の「行全体の :active の背景変化で示す」を置き換え）。
- 押下の視覚効果は付けない — OS のタップハイライトは全要素で無効化済み（src/style.css）で、`:active` の暗転・減光も 2026-09-08 に全部削除した。iOS Safari はタッチ / pointer のリスナーがある要素にしか `:active` を当てないため、それまで実機では一度も見えておらず、カルーセルのリスナーで初めて見えた結果一覧の行が「不要」だった（2026-09-01 の「意味のある操作の :active にのみ付ける」を置き換え）。
- ヘッダには識別情報（タイトル・機能アイコン）以外のテキスト（手順リスト・キャッチコピー）を置かない（2026-08-31、同種 2 回目）。メイン画面のフッタは免責の 1 段落だけ（データ確認日・GitHub リンクは 2026-09-07 に削除し、リンクはサイドメニューへ）。
- 数値に対する操作（追加・リセット等）は説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる（例: 課金額の隣の課金 +、リセット ↺ — 2026-08-31）。
- 並ぶ選択肢のラベルは主語と構文を揃える（さがすステップのオプション 5 チップはすべて「ツールが主語の他動詞文」— 「所持カードから探す / ボード状況を考慮する / 開花状況を考慮する / 衣装スキル発動に限る / パッシブ全員発動に限る」。「衣装スキルが発動する」はスキルが主語の自動詞で不揃いだった — 2026-09-06「自動詞と他動詞とか文体の統一も」）。ラベルは短く — 「持っているカードのみからさがす」は「所持カードから探す」に（2026-09-08）。
- 同名の別種があるものは種類を明示する。種類の切り替えが見込まれるなら見出しに入れず、切替コントロールで示す（ホロメンボードは見出し「ホロメンボード（青）」（2026-09-06）→ 見出し「ホロメンボード」+ 赤・青・黄・緑のセグメント。用意できていない種類は disabled で置く — 2026-09-07）。
- セクション見出しは短い名詞 1 語にし、括弧の補足を付けない（「リーダースキル（衣装）」→「衣装スキル」、「リーダー（衣装スキル）」→「リーダー」— 2026-09-07）。
- 回数は「n回」と表記する（「n連」などの言い回しを使わない — 2026-08-31）。
- 同種の操作（カード選択）は見た目も操作も同形に揃える（リーダーとメンバーで別 UI にしない）。
- UI に内部用語を出さない（例: 「構造化」「structured」のような実装語彙を画面に出さない。状態表現の冗長な修飾も削る — 「スコアに反映中」ではなく「反映中」）。
- 数値・スキルの前提（レベル最大・設定した開花段階に応じた試算で、未確認の段階は仮定倍率の概算であること）を、値を見せる画面（詳細モーダル等）の注記で明示する。

## 実装ノート（プラットフォーム）

- iOS Safari は数字列を電話番号と誤検出して青いリンクにするため、index.html に `<meta name="format-detection" content="telephone=no">` を必ず置く（「計算結果の文字色が青」の原因だった）。保険として `src/style.css` の `a[href^="tel:"], a[x-apple-data-detectors]` でリンク化された数字の見た目も打ち消す。ただし 2026-09-07 の「結果一覧のスコアの数字が青色（iPhone の Chrome）」の原因は電話番号検出ではなく、**iOS の `<button>` の既定文字色がシステムの青**であること — 色を指定していない `<button>`（結果一覧の行）がそのまま青くなった。`src/style.css` で `button { color: inherit }` を全体に当てて解決。Linux の Chromium では黒く描かれるので playwright-cli では再現しない — `<button>` を文字の器に使うときは色を明示するか継承に任せ、既定色に頼らない。新しいシートを作るときはヘッダを共通寸法（padding 16px・h3 24px/900・77px）にし、boundingBox で実測する（結果詳細が 12px/18px のまま残っていた — 2026-09-07）。
- iOS Safari は、要素かその親にタッチ / pointer のイベントリスナーがないと `:active` を適用しない — このアプリでは長く「押下で暗くなる」CSS が実機で一度も見えておらず、カルーセルが pointer リスナーを付けた途端に結果行だけ暗くなって「不要」となった（2026-09-08）。Linux の Chromium ではマウスで再現するので、実機の見え方を playwright-cli の結果から断定しない。
- 連打・トグル操作にブラウザ既定のジェスチャ（ダブルタップズーム・文字選択）が割り込むのは不具合として扱う。`button, [role="button"]` には `touch-action: manipulation`（src/style.css、全体に適用済み）、連打する記号には `user-select: none`（開花 ± の連打で iPhone がズームした — 2026-09-05）。
