# UI デザインの制約（全画面共通。ユーザーフィードバック由来）

UI の規則は 4 ファイルに分けてある（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## 進め方

- 機能追加でも新しいデザインを持ち込まない — 既存のコンポーネント・トークン・デザイン言語を踏襲する（「見た目に関しては既存を尊重すること」）。既存パターンと形が違う UI を入れるときは、提案時にその差の意図（単一選択と複数選択の区別など）を明示する（「意図が知りたい」）。
- 遊び機能（仮想ガチャ等）はゲーム仕様の忠実な再現より操作の単純さを優先する（通貨 2 種・割引枠・天井などは要求されるまで再現しない）。
- **「UI どうする？」のような設計相談には案の提示で止め、明示の着手指示を待ってから実装する。** 方針の一言を着手の合図と受け取って実装・push したところ「微妙だ。一旦戻して別ブランチに退避」となった（2026-09-08。実装はブランチ `claude/event-bonus-objective`）。「push までする」運用は指示された変更に適用し、設計相談の回答には適用しない。
- **提案は、ユーザーから見て何が変わるか（画面・結果・待ち時間）を先に言い、中身の変更は「いまの手順 → 変えたあとの手順」の具体例で示す。** 内部の言葉（覚えておく・キャッシュ・分担）は、どこに・いつまで・何をもとに、まで言い換える（2026-10-08「A は具体的になにが変わるんだ」「覚えておくというのはどういうこと？」）。
- **モーダルの上にモーダルを重ねない**。1 つの入力の中で段階が進むもの（形 → 倍率 → 持ってくる場所）は、同じモーダルの中身を切り替え、つながりはアニメーションで見せる（選んだ図形がそのまま拡大して移る・選んだ行がその場で広がる）。出方も画面ごとに変えない — ボードのコネクトだけ右から出るサイドバーだったのは「変」で中央のモーダルへ（2026-10-10「モーダルの上にモーダルってキモい」「シームレスにアニメーション入れて」。実装は `ConnectSheet.vue`、規則は `ui-boards.md`）。既存の確認ダイアログ（`ConfirmDialog` をシートの上に出すもの）はまだこの形にしていない。
- 調整ツール（配色の管理用画面など）は**対象そのものを見ながら触れる形**にする — 全画面のシートに縮小プレビューで代用したら「実画面にしないと意味ない」で差し戻された（実画面の上に固定する操作バーへ）。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法が 1px も変わってはならない（レイアウトシフト禁止）。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測確認する。モード切替で出し入れする要素は同じ高さの枡に置き換え、下の要素を動かさない（ボードの「すべて解放 / 解除」の行が説明モードでは同じ 44px の帯になる）。
- 表・一覧の行は固定順で全項目を常に出す — 選択順・解放順で行が増減したり並びが変わったりしない。値がないときは +0 などの空値で行を残す（「選ぶ順によって上から並ぶ順が変わるのきもい」）。
- 重ねる装飾・アイコンのために元の部品の寸法を変えない（「元のパネルのサイズを小さくするな」。はみ出しは親側の描画範囲で処理する）。補助のアイコン（ⓘ など）は主の部品の幅・中央を崩さない場所（見出しの行）に置く — セグメントの横に並べると細くなって中央がずれ、「タブが真ん中からズレるの意味不明」「空間をとりすぎ」（同種 2 回目、2026-10-08）。
- **同じ形の行を縦に何度も繰り返す入力は、まとまり（色など）ごとのカードにして一目で見渡せるようにする**（リソースの画面: 色の見出し + 設定行 × 8 を、色ごとのカード 2 列へ — 2026-10-08「キューブとかの入力ダサいからいい感じの UI にして」）。
- 可変長の見出し（人名・曲名）と固定幅のコントロールを同じ行に並べない — 見出しは 1 行を占有させ、コントロールは次の行に左右で並べる（「名前が長いと省略されてしまっている」）。
- ヘッダなどの常時表示領域も、タブ・モード切替で寸法（高さ）が変わってはならない。画面遷移（フルスクリーンモーダル）にも適用し、画面のヘッダはページヘッダと同寸法（77px）・同文字サイズ（24px/900）・同じ下罫線にして、両画面の boundingBox で実測する（規則があっても未実測で 60px のピッカーが混ざった）。切替内容に依存するもの（手順リスト等）をヘッダに置かない。
- はみ出すテキストは動かさない — 1 行は省略記号、複数行は行数固定 + 省略記号。横スクロール表示（往復・巻き戻し・看板型）は「バグってる」で廃止。装飾的な動きは実機で確認できない限り入れない。
- 並ぶ要素は縦・横の線を揃える。同種のアイコンは全行で同じ列に置き、常に出るもの（開花）を最右の固定列、条件つきのもの（固定ピン等）をその左の列に置く。アイコンの有無で行の高さを揺らさない（min-height で担保）。
- カード類の高さは文字列長で揺らさない（行数固定 + 省略）。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all`（「55%UP」等の英数字トークン手前で早折れする不自然な改行の防止）。
- ゲーム側で決まっている値（ホロメンボードの左右型など）はユーザーに選ばせず、データ（`src/data/holomen.json`）に持って引く。
- モバイルファーストで設計する。iPhone 実寸（390px 級）での崩れ・不自然な改行は出荷前に playwright-cli で確認する（`ui-verification.md`）。

## アイコンとラベル

- 静的なメタ情報ラベル（スキル種別・役割）に矩形の枠つきバッジ（チップ）を使わない — 「AI デザインの典型」で、押せる / 押せないのアフォーダンスも壊す。
- 自明なメタファーがあるものは図のアイコン（衣装 = T シャツ / 固定 = ピン / おかゆモード = おにぎり）、ないものは文字アイコン（SP / A / P）にし、すべて 26px の正円細線で囲んで統一する。ただし同じ一覧の中では様式を揃える — サイドメニューの項目は丸で囲まない 24px の線画なので、おかゆモードの行もおにぎり単体。制約で入ったカードの印（おにぎり）はピンと同じ列に出す。開花（凸）は花びらの輪郭 + 段階の数字で、花の輪郭が正円の枠を兼ねる。実装は `src/components/SkillIcon.vue`（自作 SVG のみ。公式アセット禁止 — ADR-002）。**フォントにある合成済みの記号（①②… などの丸数字）をアイコン代わりに使わない** — 自作の図形にするか、別の表現に置き換える。
- 計算の前提になっている値（開花段階など）は既定値でも省略せず常に表示する（0凸も出す）。逆に、計算に関係しない値のアイコンをその枠に出さない（リーダー行に開花アイコンは出さず最右列は衣装アイコン。詳細モーダルにピンは出さない）。値を変更できない画面（メンバーピッカー）では値をアイコンだけで見せ、± などの操作は出さない。
- アイコンのテキストラベルは画面に出さず aria-label に退避する。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行 / 2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- 同じ属性の表現方法を 1 つの画面の中で混在させない — タレント名の文字色でタイプを示す一覧に、タイプ淡色の面を混ぜない。
- タイプ色の正はキュート = ピンク / ハッピー = 黄 / ピュア = 緑（`docs/human/game-spec.md`）。カードのタイプはタイプ淡色の面（背景）で表し、タイプ名のテキストバッジを置かない。タイルでない場所（結果一覧）ではタレント名の文字色（タイプ濃色）で判別する。タイプ色の黄は淡地 + 濃文字でのみ使う（白抜き禁止）。ホロメンボードの黄はこの規則の外で、解放マスの文字は白。
- 等価な選択肢（回数違いの同一操作など）には primary / secondary の階層をつけず、同じ配色のボタンにする。
- 操作できない表示（キャプション・選んだ対象の説明・状態）は枠線を使わず淡色の地（`var(--bg)`）で示し、枠線つきの角丸はボタンに限る（「ボタンと勘違いすると思う」。空のときも点線にせず、形は同じで中身だけ空）。
- タイプ色パネルに枠線を付けない。例外は空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠のみ。選択強調はそのカードのタイプ色を使い、無関係な固定色を当てない。
- コントロール（セグメント・チップ・番号バッジ・トグル）の選択スタイルは全画面で 1 種類（`--selected` の地 + `--selected-ink` の文字。ライトは濃色地 + 白文字、ダークモードでは明るい地 + 暗い文字へ反転する — `--ink` を地に使うとダークで白文字が消える）に揃え、選択肢の意味色（タイプ色）で選択状態を塗り分けない。
- スキルの発動状態はテキストバッジ（「反映中」「条件未達」等）ではなく、発動 = 通常表示 / 不発動 = 行のグレーアウトで表す。スキルの行を出さない画面では、そのスキルを指すアイコンをグレーアウトする（結果詳細のリーダーの衣装アイコン）。「未反映（未構造化）」という状態は UI に設けない — データ側を 100% 構造化して状態自体をなくす（`dataset` のテストが強制）。
- **エラー・状態・空の表示は 3 種類にそろえる**（2026-10-10 ユーザー指示「書き方を統一したい。警告色など。不必要な文章はなるべく削りたい」「基本は不要な文は書かない。表示位置と余白を考える」）:
  - **エラー**（実行できない・失敗した・止めている）は共通の `.error-text`（`src/style.css`。`--error`・13px・600・行間 1.5。背景・枠・アイコンなし）の 1 文。**置き場は原因になった操作のすぐ下**で間隔 8px（さがす・組み直すとの失敗はボタンの下、おかゆモードはアカウントのボタンの下）、シートでは本文の先頭（組み直しプランはタブの上）、ダイアログでは本文とボタンの間。灰色の箱には入れない。
  - **状態の赤**（超過・不足・マイナス・未登録）は文にせず、数字やラベルだけを `--error` にする（「230 / 9 Pt」「残り -2」「未登録」）。0 は淡い色。選択中の濃い地の上では赤を地の文字色へ寄せる（`color-mix`）。
  - **空**（結果がないだけ）は淡い色の 1 文「〜がありません」。**中身が空になる入口は押せなくして空の画面を作らない**ほうを先に考える（`ui-flow.md`）。
  - 文は**起きている事実の 1 文**で句点なし。直し方は見ても分からないときだけ足し、「〜ため、」の理由・全角括弧の補足・言い直しの二文目は書かない。数字は半角で単位の前にスペース（「ボードPt が 3 Pt 足りません」）。**計算の失敗はどこでも「計算に失敗しました」**（`src/ui/messages.ts` の `CALC_FAILED`。Worker の中の文は画面に出さず、各 composable の `error` に残す）。
  - 知らせのダイアログ（`NoticeDialog`）はボードの操作を断るときだけ（盤面の下に文を出す場所がない）。戻るで戻せる操作には確認を挟まない（ボードの解除・コネクトマスの解除）。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同一の角丸 + 影、装飾絵文字。地・罫線は無彩色に保ち、色は意味（タイプ・状態）にだけ使う。
- 機能的な意味を持たない装飾・記号を付けない（選択済みカードのチェックマーク・所属チップやしぼりこみチップの ✓ — 濃色地で選択は伝わる。同種 3 回）。状態を表す記号（並び順の ▼/▲）は可。グラフは表で表現できている情報に重ねて置かない。
- ヘッダなどの `--chrome` の帯の上に載る 44px の正円（ハンバーガー・✕）は面の色（`--surface`）にして、帯と区別する。
- デザイントークンの正は `src/style.css` の `:root`。配色モードは同じトークンを差し替えて表す（`:root.dark-mode` = ダークモード、`:root.okayu-mode` = おかゆモード、併用は `:root.dark-mode.okayu-mode`）。役割の割り当て（面・文字・タイプ 3 色の淡 = 面 / 濃 = 文字、ヘッダ・下端の固定エリア・注釈のフッタの `--chrome`）はモードによらず同じにする。`--chrome` は地との差がぎりぎり分かる薄さにとどめ、色みは無彩色寄り（おかゆモードだけ紫系）。

## 文言と情報量

- 注記に当然の否定を書かない（「（リーダー自身には効かない）」の括弧は「不要」）。
- **状況を説明する文を UI に足さない** — 数字や構造（「残り -2」・選んだ行が広がる）で伝わるなら文は置かず、読み上げ用の aria-label に回す（2026-10-10「不要な文章はなるべく書かないこと」。コネクトの「〜は 2 枚とも使っています。どこから外して持ってきますか？」を外した。見出しの「範囲内のホロメンボード効果を UP」も自明で外した）。操作の結果は短い言葉で操作の側に付ける（「青ボードから外す」）。
- 冗長な文字情報を置かない: 背景色や見出しで伝わることをテキストで繰り返さない（枠名「リーダー」、タイプ名「ピュア」、不要な合計値）。空プレースホルダは中央の 1 行値のみにし、字送りもプレースホルダ同士で揃える（14px / 600 の淡色 = `UnitSlot` / `SongRow` の `.empty-msg`。充填時の値の字送りを継がない）。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない。件数はコントロール内の右寄せ値として置き、任意項目は既定値「おまかせ」を実値として表示する（結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は可）。既定値が文脈で決まるなら実値まで具体化して見せる — ただし決まった時点で出し、先回りして出さない（おかゆモードの最後のメンバー枠は、4 枚選んでもおかゆんがいないときだけ「おかゆん（おまかせ）」）。「おまかせ」はツールが実際に最良を選ぶ枠（リーダー・メンバー）にだけ使い、選ばなくても計算が成り立つ枠（曲）は「指定なし」と書く。**試算に効かない値を実値のように見せない**（曲の指定なしに代表値の曲長を並べない。行の高さだけ充填時に合わせる）。
- 手順の説明文で UI を補わない — UI 自体に情報を語らせ、本文コピーは最小にする。補足の注記（単価・確率の説明、★別集計などの統計文、選択対象の再掲）も置かない — コスト・件数はボタンや見出しのラベル内に含める（「10回 2,500」「結果（n回）」）。操作方法の説明文（「タップで◯◯」等）も置かない。件数はメイン画面の行ボタン内の値としてだけ示し、ピッカーのヘッダには出さない（「ヘッダの枚数表示いらん」）。免責・試算値の注記はフッタに集約する。例外は 2 つ: **検索から来た人にこの画面が何なのかを示す本線最下部の説明カード**（`AboutSection.vue`。ページ自体の説明なので、この規則を根拠に消さない。置き場と中身は `ui-flow.md`）と、**見出しの行の ⓘ から開く説明**（次の項目）。シート内の注記（試算の前提・未確認の断り）は本文の途中に置かず、末尾の脚注（`.footnotes`、※n）にまとめ、本文側は見出しや値の直後の上付き `※n`（`.fn`）で参照する。脚注は番号列（`.fn-num`、固定幅）と本文の 2 列にして、2 行目以降の左端を本文の左端に揃える。**脚注・注記に観測日や「実機観測に基づく」のような根拠の来歴を書かない** — 利用者には不要で、根拠はコードのコメントとドキュメント側に置く。脚注は実装が変わったら同じターンで追随させる（「全ページの脚注のドリフト、冗長表現がないかを要確認」）。
- **ⓘ から開く説明**（`InfoButton.vue` → `InfoDialog.vue`。置き場は メイン画面の アカウント・リーダー・メンバー・曲・さがす（3 択）・結果（いまのまま / 組み直すと）、絞り込みのダイアログ、組み直しプランの「最適化するもの」「発動頻度の選び方」、リソースとホロメンボードのシート、ティア表（一覧と 1 枚の評価画面の両方 — 評価画面へ進んでも消さない）の 12 か所）— 画面には ⓘ だけを置き、押したときだけ中央のダイアログで出す。**形は中身に合わせる**: 違いがいくつもある 3 択は「列 = 選択肢、行 = 違い」の表、言葉の意味が分かればよいものは名前と段落、名前の要らないもの（シートの使い方）は段落だけ（「意味さえわかればいいので表である必要なくない？ただしわかりやすく」）。表の中の言葉（「登録のまま」「全解放」）は表の前の段落で言う。**ⓘ は見出しの行の右端**（図 20px・押せる範囲 40px を負のマージンで重ね、見出しの行の高さを変えない。右端が閉じるボタンのシートの見出しでは文字のすぐ右）。**表の中の言い方はそろえ**（同じ状態は同じ語 — 「登録の段階 / 登録のマス / 登録のまま」の混在は「表記揺れも気になる」）、**違いだけを置く**（両側が同じ行・細かすぎる行・ほかの画面への案内の行は置かない。思い込みを正す行 — 育てきったらでもコネクトは登録のまま — は残す）。**入力の仕方・選択肢の意味の説明は脚注ではなく ⓘ に置く**（脚注は初期表示で見えず、結果のタブの脚注は実行したあとにしか出ない。試算の前提・近似・実機未確認の断りは脚注のまま）。**ⓘ に書くのは操作で選べることの意味だけで、計算の仕組み（何がスコアに入るか）の解説は置かない**（リーダーの ⓘ の「リーダーのカードからスコアに入るのは衣装スキルと赤ボードだけ」は「不要な文章」）。**ⓘ は短く保ち、長くなる細かい規則（どの場合に何を変えるか・値の求め方）と断り（相対値であること・試算であること）は脚注へ回す**（同種 2 回目 — 2026-10-09「最小限で組み直すの info 多すぎる。こんなに長いなら脚注に移すべき内容ある」「脚注と info の使い分けは以前指摘したことある」。最小限は ⓘ に何を組み直すかだけ・規則は組み直しプランの脚注 ※1、ティア表は ⓘ に段の意味だけ・採用率の求め方と断りは評価画面の脚注 ※1）。中身は `src/ui/infoContent.ts`。
- **画面に出す説明の文（ⓘ・脚注・使い方のページ・説明カード）は初見の人が分かるように書く** — その画面で初めて出る言葉は言い換えるか、先に意味を言う。文ごとに改行せず段落にまとめ、長いときだけ段落を分ける。同じものは画面・ⓘ・脚注・使い方のページで同じ言い方にする（2026-10-08「文ごとの改行だるいかも」「文章は初見の人がわかるように書くこと」「不整合や冗長なのがないか整理して」）。
- タップ可能の手掛かりに誘導テキスト・記号（「詳細 ›」等）を置かない。大きな行（結果一覧の 1 件）の押下で面を暗くしない。
- **スワイプで隠れた操作を出す UI を使わない** — 操作できることが初見で分からない（行の左スワイプ → 削除は「初見でわからない」で撤去）。判断させたいものは見えるボタンかダイアログで聞く。既存の左右スワイプはページ送り（`PageCarousel`）だけで、こちらは三角ボタンという見える代替が同じ画面にある。
- 押下の視覚効果は付けない — OS のタップハイライトは全要素で無効化済み（`src/style.css`）で、`:active` の暗転・減光も全部削除した。iOS Safari はタッチ / pointer のリスナーがある要素にしか `:active` を当てないため、カルーセルのリスナーで初めて見えた結果一覧の行が「不要」だった。
- ヘッダには識別情報（タイトル・機能アイコン）以外のテキスト（手順リスト・キャッチコピー）を置かない。メイン画面のフッタは免責の 1 段落だけ（データ確認日・GitHub リンクは置かず、リンクはサイドメニューへ）。
- 数値に対する操作（追加・リセット等）は説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる（課金額の隣の課金 +、リセット ↺）。
- 並ぶ選択肢のラベルは主語と構文を揃える（「自動詞と他動詞とか文体の統一も」。さがすの 3 択「いまの育成で / 育てきったら / 全カード」も揃えた言い回し。ぶら下がりの短いラベルは主の設定の中身を指す名詞でよい）。ラベルは短く — 「持っているカードのみからさがす」は「所持カードから探す」に。
- 同名の別種があるものは種類を明示する。種類の切り替えが見込まれるなら見出しに入れず、切替コントロールで示す（見出し「ホロメンボード」+ 赤・青・黄・緑のセグメント。用意できていない種類は disabled で置く）。
- セクション見出しは短い名詞 1 語にし、括弧の補足を付けない（「衣装スキル」「リーダー」）。
- 回数は「n回」と表記する（「n連」などの言い回しを使わない）。
- 同種の操作（カード選択）は見た目も操作も同形に揃える（リーダーとメンバーで別 UI にしない）。
- UI に内部用語を出さない（「構造化」「structured」のような実装語彙。状態表現の冗長な修飾も削る — 「スコアに反映中」ではなく「反映中」）。
- 数値・スキルの前提（レベル最大・設定した開花段階に応じた試算で、実機で確認できていない段階は文言を「未確認」と出し、試算にはいちばん近い段階の内容をそのまま使っていること）を、値を見せる画面（詳細モーダル等）の注記で明示する。

## 実装ノート（プラットフォーム）

- iOS Safari は数字列を電話番号と誤検出して青いリンクにするため、`index.html` に `<meta name="format-detection" content="telephone=no">` を必ず置く。保険として `src/style.css` の `a[href^="tel:"], a[x-apple-data-detectors]` でリンク化された数字の見た目も打ち消す。ただし「結果一覧のスコアの数字が青色（iPhone の Chrome）」の原因は電話番号検出ではなく、**iOS の `<button>` の既定文字色がシステムの青**であること（`src/style.css` で `button { color: inherit }` を全体に当てて解決）。Linux の Chromium では黒く描かれるので playwright-cli では再現しない — `<button>` を文字の器に使うときは色を明示するか継承に任せ、既定色に頼らない。新しいシートを作るときはヘッダを共通寸法（padding 16px・h3 24px/900・77px）にし、boundingBox で実測する。
- iOS Safari は、要素かその親にタッチ / pointer のイベントリスナーがないと `:active` を適用しない。Linux の Chromium ではマウスで再現するので、実機の見え方を playwright-cli の結果から断定しない。
- モバイルでキーボードを出させる入力は、代替のワンボタンを用意する（貼り付けは `navigator.clipboard.readText()` の「ペースト」ボタン）。**数値の入力は `<input>` を置かず自前のダイアログ**にする（桁を打たせる値は自前のテンキー `NumberPad.vue`。刻みで動かせる値 — ホロメンランク・イベントメモリー・メンバー強化ボーナス — は +/- の `StepperDialog.vue`。詳細は `ui-parts.md`）。**`readText()` は環境によって解決も失敗もしない**（headless の Chromium で確認。iOS Safari は純正の確認ダイアログを出すので待ちは正常）— 押しても無反応に見える状態を避けるため、数秒後に手貼りの案内を出す保険を入れる。書き込み（`writeText`）は素直に成功するので、結果はボタンのラベルで示す。
- 連打・トグル操作にブラウザ既定のジェスチャ（ダブルタップズーム・文字選択）が割り込むのは不具合として扱う。`button, [role="button"]` には `touch-action: manipulation`（`src/style.css`、全体に適用済み）、連打する記号には `user-select: none`。
- **iOS Safari は、文字を打てる入力欄（`<input>` / `<textarea>`）の `font-size` が 16px 未満だとフォーカスで勝手に拡大し、閉じても戻らない。** 本線で打たせる欄は例外なく 16px 以上（開発用の `BloomTextSheet` も 16px）。密度を優先したい貼り付け欄（`ImportSheet` の JSON）だけ小さいまま（`pending.md` 11）。`maximum-scale` / `user-scalable=no` で塞がない（アクセシビリティ上よくないうえ、iOS は無視することがある）。
- **`touch-action` でピンチ（拡大の戻し）を塞がない。** `pan-y` や `none` だけを指定するとその範囲でピンチが効かず、一度拡大されると戻せなくなる。横送りを拾う範囲は `pan-y pinch-zoom`（`PageCarousel` の `.swipe-area`）、背景のスクロールだけ止めたい中央ダイアログのオーバーレイは `pinch-zoom`。例外は自前で 2 本指を扱う画面（`BoardSheet` のボードのピンチ）。**自前のジェスチャも 2 本目の指が触れたら捨ててブラウザへ譲る** — 2 本目の `pointerdown` で横ドラッグが始まり直すと、ピンチが横送りと競合して縮小できない（`PageCarousel` の `pointers`。`PageCarousel.test.ts` で固定）。
- **`touch-action` で縦パンを許した範囲は、JS で横と決めてもブラウザが縦へ動かす。** 横のジェスチャと決めたら、そのあいだの `touchmove` を `preventDefault` して縦スクロールを止める（`addEventListener("touchmove", ..., { passive: false })` — 既定の passive では効かない）。向きは小さめの距離（6px）で 1 度だけ決めて途中で変えず、縦と決めたジェスチャでは止めない。
- **`<button>` の中に `position: absolute` + % の幅で重ねた要素は、iOS Safari ではボタンの左右の余白を除いた幅を基準に計算されることがある**（さがすのゲージが件数の割合より短く、満ちても右端が残った — 2026-10-09 ユーザー指摘。Linux の Chromium では再現しない）。ボタンの中の割合の表示はボタン自身の背景（`linear-gradient` + CSS 変数）で描き、文字は絶対配置にせず grid の同じ枡に重ねる。
- iOS Safari の**文字サイズ自動調整（text inflation）**は、`html` に `text-size-adjust: 100%` を置かないと勝手に効く。指定した px を無視して「12px の `.card-name` が 14px の `.member-name` より大きく描かれる」「`text-overflow: ellipsis` が効かない」という形で出て、レイアウトの再構成（`useModalChrome` の body `position: fixed` の付け外しなど）をまたぐと出たり消えたりする（`src/style.css` の `html` で全体に当てて解決）。Linux の Chromium では再現しない。
