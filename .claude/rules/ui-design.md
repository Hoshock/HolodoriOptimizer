# UI デザインの制約（2026-08-31〜09-01 ユーザーフィードバック由来）

機能追加でも新しいデザインを持ち込まない — 既存のコンポーネント・トークン・デザイン言語（例: 状態選択はピッカーのセグメンテッドコントロールと同形）を踏襲する（「見た目に関しては既存を尊重すること」）。遊び機能（仮想ガチャ等）はゲーム仕様の忠実な再現より操作の単純さを優先する（通貨 2 種・割引枠・天井などは要求されるまで再現しない — 2026-08-31）。詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01）。

## レイアウトの規律

- 選択枠・プレースホルダは、空・充填・選択解除のどの状態でも枠の寸法が 1px も変わってはならない（レイアウトシフト禁止）。固定高と透明ボーダーで担保し、playwright-cli の boundingBox で実測確認する。
- ヘッダなどの常時表示領域も同様に、タブ・モード切替で寸法（高さ）が変わってはならない。この不変則は画面遷移（フルスクリーンモーダル）にも適用する — 画面のヘッダはページヘッダと同寸法・同文字サイズにする（2026-08-31）。切替内容に依存するもの（手順リスト等）をヘッダに置かない。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする（2026-09-01 タブ統合）。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない（選択肢がなくなったら畳む）。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない（2026-09-01。モーダル内全グレーアウト実装を訂正された）。
- 同種の連続スロット（メンバー枠等）は先頭の空き枠だけ有効にし、順序に意味がない入力に飛び石の自由度を与えない。解除時は上へ詰める（2026-09-01）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色/白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする（2026-09-01）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す（2026-09-01）。
- スキル行は常に 2 行ぶんの固定高を占有する。本文には固定高を持たせず、行コンテナの `align-items: center` で本文が 1 行でも 2 行でも実高の真ん中に自動整列させる（2026-09-01。旧「1 行なら下を 1 行空ける」を置き換え）。スロット・ピッカーは 2 行クランプ+省略記号、詳細モーダルは min-height で全文表示。
- 並ぶ要素は縦・横の線を揃える。役割アイコンは右端の固定位置に置き、アイコンの有無で行の高さを揺らさない（min-height で担保 — 2026-09-01）。
- カード類の高さは文字列長で揺らさない（行数固定+省略）。数値は `tabular-nums`。日英混在のスキル本文は `word-break: break-all`（「55%UP(」等の英数字トークン手前で早折れする不自然な改行の防止）。
- モバイルファーストで設計する。iPhone 実寸（390px 級）での崩れ・不自然な改行は出荷前に playwright-cli で確認する（確認手順は `.claude/rules/ui-verification.md` — このパス群を読むと自動で読み込まれる）。

## アイコンとラベル

- 静的なメタ情報ラベル（スキル種別・役割）に矩形の枠つきバッジ（チップ）を使わない — 「AI デザインの典型」であり、押せる/押せないのアフォーダンスも壊す（2026-09-01、サンプル画像 3 往復で確定）。
- 自明なメタファーがあるものは図のアイコン（衣装=Tシャツ / リーダー=王冠 / 固定=ピン）、ないものは文字アイコン（SP / A / P）にし、すべて 26px の正円細線で囲んで統一する。実装は `src/components/SkillIcon.vue`（自作 SVG のみ。公式アセット禁止 — ADR-002）。
- アイコンのテキストラベルは画面に出さず aria-label に退避する（「アクティブ」「パッシブ」「固定」等）。
- アイコンの縦位置は行コンテナの中央揃えに任せ、本文 1 行/2 行の実高の真ん中に自動で揃える。

## 色と情報の表現

- タイプ色の正はキュート=ピンク/ハッピー=黄/ピュア=緑（docs/human/game-spec.md）。カードのタイプはタイプ淡色の面（背景）で表し、タイプ名のテキストバッジを置かない。タイルでない場所（結果一覧）ではタレント名の文字色（タイプ濃色）で判別する。黄は淡地+濃文字でのみ使う（白抜き禁止）。
- 等価な選択肢（回数違いの同一操作など）には primary/secondary の階層をつけず、同じ配色のボタンにする（例: ガチャの 1回/10回 — 2026-08-31）。
- タイプ色パネルに枠線を付けない。例外は空プレースホルダの点線と、ピッカーで選択中のカードに出すタイプ基準色の太枠（複数選択では該当する全カード）のみ。選択強調はそのカードのタイプ色を使い、無関係な固定色を当てない。
- スキルの発動状態はテキストバッジ（「反映中」「条件未達」等）ではなく、発動=通常表示/不発動=行のグレーアウトで表す。「未反映（未構造化）」という状態は UI に設けない — データ側を 100% 構造化して状態自体をなくす（dataset のテストが 100% を強制）。
- 「AI デザインの典型」を使わない: カード片側の細い色ストライプ、意味のないグラデーション、全要素同一の角丸+影、装飾絵文字。地・罫線は無彩色に保ち、色は意味（タイプ・状態）にだけ使う。
- 機能的な意味を持たない装飾・記号（例: 選択済みカードのチェックマーク）を付けない。グラフは表で表現できている情報に重ねて置かない（意味のないグラフ禁止）。
- デザイントークンの正は `src/style.css` の `:root`。根拠と定石の出典は docs/human/tmp/20260831-design-research.md。

## 文言と情報量

- 冗長な文字情報を置かない: 背景色や見出しで伝わることをテキストで繰り返さない（枠名「リーダー」、タイプ名「ピュア」、不要な合計値）。空プレースホルダは中央の 1 行値のみにする。
- ステップの見出しは名詞ラベルだけにし、括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない（2026-09-01）。件数はコントロール内の右寄せ値として置き、任意項目は「未入力+でも OK」でなく既定値「おまかせ」を実値として表示する（結果見出しの「（n回）」「X 通りから上位 n 件」のような、その見出し自身の集計は可）。
- 手順の説明文で UI を補わない — UI 自体に情報を語らせ、本文コピーは最小にする。補足の注記（単価・確率の説明、★別集計などの統計文、選択対象の再掲）も置かない — コスト・件数はボタンや見出しのラベル内に含める（例:「10回 2,500」「結果（n回）」）。新機能にも例外なく適用する（仮想ガチャで 3 回指摘 — 2026-08-31）。免責・試算値の注記はフッタ（詳細モーダルでは末尾の注記）に集約する。
- ヘッダには識別情報（タイトル・機能アイコン）以外のテキスト（手順リスト・キャッチコピー）を置かない（2026-08-31、同種 2 回目）。
- 数値に対する操作（追加・リセット等）は説明文つきのボタンでなく、その数値の隣のアイコンボタンにし、説明は aria-label に寄せる（例: 課金額の隣の課金 +、リセット ↺ — 2026-08-31）。
- 回数は「n回」と表記する（「n連」などの言い回しを使わない — 2026-08-31）。
- カード表示は名前を大きく左上、カード名（サブタイトル）をその下に小さく。スキルの表記順は常に SP → アクティブ → パッシブ（リーダー文脈では衣装スキル）。
- 同種の操作（カード選択）は見た目も操作も同形に揃える（リーダーとメンバーで別 UI にしない）。
- 一覧は識別に必要な最小限にとどめ、詳細はタップ→モーダルの先に置く。ただし結果一覧は条件に関わらず編成全体（リーダー+メンバー 5）を常に同じ形で見せる（2026-09-01）。
- UI に内部用語を出さない（例: 「構造化」「structured」のような実装語彙を画面に出さない。状態表現の冗長な修飾も削る — 「スコアに反映中」ではなく「反映中」）。
- 数値・スキルが最大強化（レベル・開花最大）時の値である前提を、値を見せる画面（詳細モーダル等）で明示する。
- 選択 UI は単一選択か複数選択かがぱっと見で分かる形にする。複数選択の状態（除外・所持など）はページには件数のみ出し、内訳の確認・解除はピッカーを開き直して行う — チップ等の一覧をページに並べない（多数選択時に縦へ伸びるため。2026-08-31 訂正: 以前の「何が対象かを一覧で見せる」を置き換え）。長いドロップダウンで選ばせない — 検索+フィルタつきの視覚的な選択 UI にする。

## 数値の表

- 1 つの列に絶対値と % を混在させない。% は絶対値の括弧補足に落とす（2026-09-01）。
- 内訳は足すと合計に一致する形（検算できる形）で見せる。表示上の丸め誤差は 1 行に寄せてでも一致させる。
- 表同士の親子関係（どの数字の内訳か）は見出しと合計行で明示する — 合計行の値が親の数字と一致して環が閉じるように置く。
- 前段から変化していない値は淡色にして、効いた列だけ目立たせる。

## 実装ノート

- iOS Safari は数字列を電話番号と誤検出して青いリンクにするため、index.html に `<meta name="format-detection" content="telephone=no">` を必ず置く（「計算結果の文字色が青」の原因だった）。
