# 一覧・ピッカー・詳細シート・結果表示の部品（UI 規則）

UI の規則は 4 ファイルに分けてある（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## 部品と一覧の構成

- 一覧 → 詳細の導線は既存のピッカー部品（`CardPicker` / `SongPicker`）をそのまま一覧として開き、選んだら詳細シートを上に重ねる。
- 同じ対象（カード・曲）はメイン画面とピッカーで同じ部品（`CardTile` / `SongRow`）を使い、見た目と固定高を一致させる — 別部品で似せない（二重実装は片方だけ直して齟齬が出た）。幅はそれぞれの置き場に従ってよい（メイン = パネル内 324px / ピッカー = シート 358px @390px）。メイン画面は白いパネル（ページ左右 16px + 内余白 16px）が基準で、ピッカーは白い 1 枚のシート（ヘッダ → 絞り込み → 一覧）。幅まで揃えるための全幅の白い帯・角丸ブロック・罫線 + 接続線のステッパー・ピッカー内のカード入れ子 + 内側スクロールはすべて却下（「キモすぎるしわかりにくすぎる」）。画面の構造は単純に保ち、部品の一致より入れ子の少なさを優先する。
- モーダルを開いたときにテキスト入力へ自動フォーカスしない（モバイルでキーボードが勝手に開く）。フォーカスはシート自体（`tabindex="-1"` の dialog 要素、`outline: none`）へ移し、キーボードはユーザーが入力欄をタップしたときだけ出す。**例外は、打つことが決まっている操作から開くダイアログ**（お気に入りのユニット名の鉛筆 → `UnitNameDialog`。「ここは自動フォーカスすべき」）。この場合はカーソルを末尾に置き、既存の値を消さずに続きから打てるようにする。
- キーと向きを持つ選択（並び順）は、キーのセグメント 1 つにまとめ、選択中のセグメントの再タップで向きを反転する — 4 択の全列挙や向きの別ボタンにしない。ラベルは現在の向きを言葉で示し（「Lv 高い順」「Lv 低い順」）、選択中には ▼（降順）/ ▲（昇順）の片方を添える（⇅ のような抽象記号は「微妙」）。ホロメンのピッカーも同じ形（`ui-boards.md`）。**曲ピッカーの並び順は 左 = Lv・右 = 五十音順 で、既定は五十音順**（曲長の並びは外した）。五十音順は曲名の読み（`src/data/songReadings.ts`）で並べ、曲を足したら読みも足す（`songReadings.test.ts` が全曲を固定）。
- **曲ピッカーの絞り込みの 2 段目（セグメント）は すべて / オリジナル / カバー / イベント の 4 択**。「イベント」は**開催中のイベントの課題曲だけ**（`activeEventSongIds` — 本体の課題曲 + 進行中のチャプターの課題曲）。開催期間は `events.json` の `startAt` / `endAt`（日本時間、終了は表示の分まで）。**開催中でなければ「イベント」は disabled**（枠は消さず薄くするだけ）。開いたままでも時刻を見直さず、開いた時点の時刻で決める。イベントのスコアボーナスそのものは探索に未接続（`pending.md` 21）で、この絞り込みは選びやすさだけのもの。
- スキル行は常に 2 行ぶんの固定高を占有する。本文には固定高を持たせず、行コンテナの `align-items: center` で本文が 1 行でも 2 行でも実高の真ん中に自動整列させる。スロット・ピッカーは 2 行クランプ + 省略記号（3 行に伸ばす・3 行固定・縦に送るはいずれも却下）、詳細モーダルは min-height で全文表示。行同士の隙間は 2px、名前ブロックと効果の間隔はタイルの上下 padding と同じ 9px にして縦の余白を対称にする。
- 結果一覧の順位の円は全順位を無色のフラット（白地 + 罫線 + `--ink-2`）にする。1〜3 位のメダル色は廃止（`--silver` / `--bronze` トークンも削除）。
- 既存の要素に重ねるアイコンは、既存の縦の列・行に合わせる。お気に入りの星は結果の 1 件の右上、**右端のアイコン列（リーダー行の衣装・メンバー行の開花）の真上**で、見出しの行（順位の円とスコア）と同じ高さに置き、中心は 390px の実測で合わせる（パネルの外へはみ出す案・角に中心を重ねる案は差し戻し）。大きな数字の隣に置くアイコンは行の中央に揃えるだけでなく、数字の中心線に見える位置まで少し持ち上げる（42px の星を `translateY(-4px)`）。
- **お気に入りは 登録済み = 金の星 / 未登録 = 輪郭だけの星（`UnitStar`）で、番号は出さない**。押すと 登録済み = 解除の確認 / 未登録 = 番号選び。番号が見えるのは登録画面（`UnitSaveModal` の 1〜10）だけで、解除で番号が詰まっても画面の表示は動かない。ゴミ箱のアイコンは「わかりにくい」で星へ戻した — 作り直さない（役割は画面で分けたまま: 結果側は登録と解除、ユニット詳細は解除だけで常に金の星）。寸法は 結果一覧 28px / 結果詳細・ユニット詳細 42px。
- **登録も解除もできない候補では、星の枠ごと出さない**（減光した星を置く案は差し戻し）。結果詳細では左隣の共有ボタンが右端へ詰まる。出す条件は「**所持カードから探した結果**（`ranSearchAll` が false）で、かつ 6 枚とも**いまの所持リストにある**」— お気に入りにできるのは所持カードで組んだ編成だけという仕様（`ui-flow.md`）の入口側の表現。判定は**実行したときのモード**で持つ（オプションを切り替えただけで、表示したままの前回の結果のアイコンが入れ替わらないように）。既に登録してあるユニットの金の星はこの条件と無関係に出す。
- **ページごとに変わるアイコン・値は、開いている順位ではなくそのページの添字で決める**（`PageCarousel` の `#page` スロットが渡す `index`）。送りの途中は隣のページも見えるので、開いている順位の値を全ページに描くとスワイプ中に隣が違う見た目で出る。
- 結果一覧はホロメン名とサブタイトル（カード名）を隣接させ（カード名 line-height 14px・margin-top -3px）、メンバー同士の間隔 6px・パネル上下 10px と密にする。詳細モーダルも同じ隣接。
- 詳細シート（カード詳細・曲詳細）の見出しは入口の一覧名と同じ（「カード一覧」）にし、対象の名前は本文の色つきカード（タレント名 + サブタイトルだけ）で示す。所属のような分類はカードの中に文字で書かず、カードの直下に表示専用の小さなピル（24px・12px、ピッカーの所属チップの縮小形）を左から並べる — 静的ラベルにチップを使わない規則のユーザー指示による例外。データにない項目（作詞・作曲・編曲など）は行ごと消さず「未確認」で残して将来入る場所を見せる。**カード詳細の並びは パラメータ → 衣装スキル → スキル → コネクト**（「開花」のセクションは置かない。「コネクト」は 2026-10-09 に戻した: 範囲の形の図（`ConnectFigure`）と Lv1（0〜4凸）/ Lv2（5凸）の ％ を横に並べ、外部解析で実機未確認なことは脚注 ※3）。パラメータの脚注 ※1 はレベル上限（★5 Lv80 / ★4 Lv70）を出す。**スキルの見出しの右端に 0〜5凸 のトグル**（`.segment` + 開花アイコン。ボードシートと同形）を置き、SP / アクティブ / パッシブの文言をその段階のものへ切り替える（衣装スキルは開花で変わらないので切り替えない）。**最初に選んでおく段階は入口が決める**（`CardDetail` の `bloom` prop）— 既定と一覧系の入口は 5凸、**結果詳細・ユニット詳細のメンバーのタイルからはその試算に使った段階**（タイルの開花アイコンと一致する）。**リーダーのパネルからは常に 5凸** — リーダーカードの開花段階は試算に一切効かない（`game-facts.md`）ので、登録値を出すと効いているように見える。**実機で確認できていない段階は文言を「未確認」と出す**（`cardAtBloomWithProvenance`）。一覧を経由しない入口（結果詳細・ユニット詳細のタイル）から開くときは見出しを「カード」にする（`CardDetail` の `title` prop。一覧名を騙らない）。
- **ティア表**（`TierSheet.vue`。サイドメニューのカード一覧の上。2026-10-09 ユーザー指示）は ★5 だけを **リーダー / メンバーの 2 つの表**に分け（排他なので上の 40px のセグメント。**リーダーが左で既定**）、**段（SS / S / A / B / C / D）ごとの見出し（大きな段の文字 + 枚数。本文のスクロールの上端に貼り付く）の下に、採用率の高い順**にカードを並べる（段の根拠は仮想アカウントでの採用率 — ADR-024 Update）。カードは**結果詳細のメンバー 5 人と同じ細いタイル**（5 列・タイプ淡色の面・中央揃え・2 行クランプ。下の行は左に比 `99.1%`・右に星）で、説明文は一覧に置かない（「文が長すぎると意味不明」）。**押すと評価画面 `TierCardSheet.vue`**（見出し「ティア表」。並びは カード（タイプ淡色の面。押すとカード詳細（見出し「カード」））→ 役割・段の大きな文字・右端に採用率（段の根拠）→ **総評**（1〜2 文）→ **最高スコアの編成**（結果詳細と同じ リーダーのパネル + メンバー 5 人の細いタイル。このカードはタイプ色の太枠（ピッカーの選択中と同じ表し方）。押すとカード詳細）→ **評価軸の表**「項目 / 内容 / 順位」（メンバー: メンバー採用率 / リーダー採用率 / 最高ユニットスコア / 全体の最高との差（点と %）/ 0凸のまま / 素のパラメータ / パッシブ / アクティブ / SP、リーダー: リーダー採用率 / メンバー採用率 / 最高ユニットスコア / 全体の最高との差 / 衣装スキル（同じ衣装スキルのカードの枚数つき）。順位は ★5 全枚の中で、差・パッシブ・衣装スキルには付けない。文言は `src/ui/tier.ts`）→ 脚注 ※1〜※3）。**「比」という言い方は画面に出さない** — 点数と全体の最高との差で言う（2026-10-09 ユーザー指示「最良の比というのがわかりにくい」「名前だけだとわからんだろ。もろもろわかりやすく、かつ定量性も大事」）。細いタイルに数字（%）は書かない。空の段は出さない。段の意味（採用率で分けること・段の下限）は一覧と評価画面の見出しの ⓘ（`TIER_INFO`）、採用率の求め方と断り（相対値・ユニットスコアの試算）は評価画面の脚注 ※1。評価はデータ `src/data/tierList.json` から導くだけで、開いても計算しない（ADR-024。段の下限は `src/engine/tier.ts` の `TIER_THRESHOLDS`）。役割のセグメントの下に**タイプの絞り込み（すべて / キュート / ハッピー / ピュア。ピッカーと同じ 4 列のセグメント、既定はすべて）**だけを置く（2026-10-09 ユーザー指示。所属・レアリティ・検索は置かない）。構造は `TierSheet.test.ts` で固定。
- **カード一覧では、実機確認（開花文言フォーム）をまだ通していないカードのスキル文言を淡色（`--ink-2`）で出す**（`CardPicker` / `CardDetail` の `dimUnverified`）。衣装スキルも含めて 4 種すべて淡くし、確認を通したカードは区間が「未確認」でも淡くしない（淡いかどうかはカード単位の状態）。立てるのはカード一覧の入口だけで、本線のピッカーや結果詳細から開いたカード詳細では立てない（本線の操作で多数が淡くなると読みにくい）。
- **ピッカーのタイルが出すスキル文言の開花段階は、その画面が開花を扱うかで決める**（`CardPicker` の `blooms`。構造は `CardPicker.test.ts` で固定）。`blooms` を渡さない入口（カード一覧・ガチャのピックアップ・開花文言）は**5凸**で出す — 0凸として解決すると記録のない段階が「未確認」ばかりになる。メンバーピッカーは**「いまの育成で」のときだけ所持カードの段階**で、育てきったら・全カードは全カード 5凸（`OptimizerPanel` の `currentBlooms`）。
- **ピッカー（カード・曲・ホロメン）は、絞り込み・並び替えを切り替えたら一覧を先頭へ戻す**（`useScrollTopOnChange`。「0期生の次に1期生を選んだらスクロール位置が保存されてるの使いづらい」）。絞り込みごとに位置を覚える案は採らない。戻す契機は絞り込み・並び替えの値だけで、タイルのタップによる選択の切り替えでは動かさない。新しいピッカーを作るときも同じ部品を使う。
- **リーダーのピッカーだけ、タイプ（すべて / C / H / P — 左半分）と「すべて / ホロメン」（右半分）の 2 つを 1 行に置く**（`CardPicker` の `holomenOption`）。「ホロメン」は同じホロメンのカードを区別せず 1 人 1 行で並べる（行はホロメンボードのピッカーと同じで、解放マスのアイコンだけない。所属の絞り込みは効く）。**「ホロメン」のあいだタイプとレアリティは効かず disabled（値は保ったまま薄くする。レアリティは 2026-10-09 ユーザー指示「ホロメンフィルタえらんだとき、レアリティのフィルタは disable にすべき」— ホロメンを選ぶと ★4 も含む全カードから探すので、レアリティで行を絞ると選べるホロメンが隠れる）。タイプを選んでいても「ホロメン」は押せる**（2026-10-09 ユーザー指示「キュートとか選ぶとホロメン選べない」。それまでの「片方を選ぶともう片方を『すべて』へ戻す」はやめた）。選ぶとそのホロメンの**全カード（★4 も）からリーダーをおまかせ**で探す（`OptimizerPanel` の `leaderHolomenId` → `leaderCandidateIds`。カード指定とは同時に持たず、片方を選ぶともう片方は外す）。リーダー枠には「ホロメン名（おまかせ）」と ✕ を出す。選べるカードがそのホロメンに 1 枚もないとき（おかゆモードのおかゆん以外）は行を無効にし、除外中のカードも（リーダー・メンバーのピッカーでは）選べる。選択中のホロメンがあれば「ホロメン」の表示で開く。
- **カードのピッカーの絞り込みの 1 行目は レアリティ（すべて / ★5 / ★4）の 3 択のセグメント**（`CardPicker` の `rarities`。既定は ★5。★ は星のアイコン。2026-10-09 ユーザー指示 — ADR-022）。**カード名・ホロメン名の検索欄はこれに置き換えて廃止した**（ホロメンボードのピッカー `HolomenPicker` の検索はそのまま）。`rarities` を立てるのは ★4 を選べる入口（リーダー・メンバーの固定・所持の登録・カード一覧）だけで、立てない入口（除外・候補の選択・ガチャのピックアップ・開花文言）は切り替えを出さず ★5 だけを並べる。「ホロメン」の表示のあいだはレアリティを効かせず disabled にする（上の項目）。**状態（固定中 / 登録済み / 除外中 / 所持）に絞っているあいだは、レアリティ・所属・タイプの絞り込みを効かせず disabled にする**（その状態のカードを ★4 も含めて全部見せる。値は保ったまま薄くし、「すべて」へ戻すと効き直す。タイプや所属を選んでいても状態は選べる — 2026-10-09 ユーザー指示）。構造は `CardPicker.test.ts` で固定。
- **レアリティはカードを見せる場所すべてで星のアイコン（`SkillIcon` の `rarity`。星の輪郭 + ★の数。26px）で示す**（2026-10-09 ユーザー指示）: **星は常に右端**で、開花の有無で位置が動かない（2026-10-09 ユーザー指示「選択すると星の位置が動くのは嫌」）: `CardTile` は右上の角に 開花（ステッパー / アイコン。入口が開花を扱うときだけ）→ 星 の順。**5 列の細いメンバータイル（メイン画面の固定枠・結果詳細・ユニット詳細・ティア表）は下の行に 開花 → 星 の順で、両端に離さず中央に寄せて 2px の間隔（「もうちょっと真ん中の隙間小さい方がいい」）**（両端だと真ん中の隙間が目立つ — 2026-10-09 ユーザー指摘。ティア表は前提の最大 = 5凸 を出す）。**リーダーのパネル（結果詳細・ユニット詳細）は開花を出さず、名前の行の右端に 衣装 → 星 の順**。カード詳細は見出しの色つきカードの名前の右端。「★4」の文字は書かない（仮想ガチャの結果タイルの ★n の文字は従来のまま）。
- **1 枚選ぶピッカーは既定ではタイプの 4 択だけ**で、`CardPicker` の `ownedIds` を渡したときだけ「すべて / `selectedLabel`」の状態フィルタが付く（複数選択・除外のピッカーと同じ 1 行の左右半分。開発用の開花文言の「所持」だけが使う）。
- 縦に長い本文をページ送りする詳細シート（結果詳細・ユニット詳細）は、操作を**本文の外・シート下端の固定エリア**（`UnitActionFoot`、地は `--chrome-foot`）に置く。**前後へ送る三角は置かない** — 順位・番号の送りは**左右のスワイプだけ**（順位・番号は見出しの「n位の編成」「ユニットn」が示す）。縦スクロールとの誤爆は `PageCarousel` 側が縦優先で判定する。トラックは `touch-action: pan-y pinch-zoom` で、2 本目の指が触れたらジェスチャを捨ててピンチをブラウザへ譲る（`ui-design.md` の実装ノート）。一覧側（結果パネル）は元からスワイプで送る。**詳細で送った順位は一覧のカルーセルにも反映する**（`ResultList` の `index` を親と v-model で共有し、詳細の `rank` の更新で一緒に動かす）。
- 同じ操作は、その対象が出てくる画面すべてから同じ形でできるようにする（お気に入りの登録・解除は結果一覧の 1 件・結果詳細・ユニット詳細のどこからでも星で行う）。詳細シートでは主数値の行の反対の端（右上）に置き、大きさは一覧の 1.5 倍にする。
- **お気に入りのユニットは名前を付けられる**（最大 10 文字。`UnitNameDialog.vue`）。鉛筆のアイコン（自作 20px）を**ユニット名のすぐ隣**、シートのヘッダに置き、押すと中央ダイアログ（`ConfirmDialog` と同形 + 1 行の入力欄・キャンセル / 決定）が出る。**ここは自動フォーカスする**（カーソルは末尾。`UnitNameDialog.test.ts` で固定）。上限は `maxlength` で入力の時点で止めてエラーは出さない。空で決定すると名前なしへ戻り、表示は「ユニット{番号}」になる。未登録の番号では鉛筆を出さない。
- **取り消しのきかない一括操作（データの取り込み）は「貼る → 質問 → 確認 → 実行」にし、確認を見てからでないと保存しない**（`ImportSheet.vue`）。操作は下端の固定エリアに置き（1 段目は「内容を確認」、2 段目は「貼り直す」+「n 件を取り込む」）、**実行したらシートを閉じて元の画面へ戻す — 結果報告の画面は置かない**（取り込んだ内容は実行前の確認で見せ終わっている）。一覧そのものが最終確認なので `ConfirmDialog` は重ねない。
- **人が決めることは実行前に「はい / いいえ」で 1 問ずつ聞く**（`QuestionDialog.vue`。「内容を確認」を押した時点で貼り付け画面の上に中央ダイアログを出し、先頭に「確認 1 / 3」・対象・問い・下に「いいえ / はい」。答えるとダイアログのまま次の問いに差し替わり、**全部答えるまで画面は遷移しない**。外側タップ / Escape は質問の取り消しで前の画面へ）。問いの文言は「〜しますか？」にし、言い訳の括弧を足さない。**1 つの対象に確認が 2 つ以上あっても 1 つの問いに連結しない** — 片方だけ「いいえ」がありうるので別の問いに分け、その対象は自分の問い全部に「はい」と答えられたときだけ取り込む。**人が決められないものは件数だけ**「取り込みエラー n 件」として出し、内容は明かさない。
- **確認の画面は説明文を置かず、件数は見出しの右端の値**で示す。区分は上から **取り込みエラー（赤）→ 登録済み → 取り込むカード** の順で、**0 件の区分は行そのものを出さない**。取り込む行は 1 つのリスト（並びは JSON の順）にまとめ、開花段階は開花アイコン（`SkillIcon` の bloom）を**取り込んだ後の 1 つだけ**置く（前 → 後 の矢印も「新規」のラベルも不要）。行ごとに外す操作は置かない。
- **外部の AI に渡す手順は説明文で書かず、コピーできるプロンプトを画面に置く**（`src/ui/importPrompt.ts` を読み取り専用の枠 + 右上のコピーボタンで出す）。**枠のヘッダのコピーボタンは文字でなく 32px 正方形のアイコンボタン**（`CopyButton.vue`。コピーのアイコン → できたらチェックのアイコンに 2 秒だけ替えて戻す。ラベルは aria-label）にし、隣のヘッダのラベルは 1 行に収めて省略する（文字の「コピー / コピーしました」は幅が変わってヘッダが 2 行になる）。**プロンプトはスキルへのポインタ 2 行だけ**にし、実行手順・出力の作法・失敗時の振る舞いはスキル側に書く（`ui-design.md`）。**渡すものと受け取るものは同じ枠で対に並べる**（「AI に渡すプロンプト」+「コピー」/「AI が出力した JSON」+「ペースト」）。**貼り付けはボタン 1 つで済ませ**（`clipboard.readText()`。キーボードを出させない）、**ペーストと確認は分ける**（貼っただけでは進まず、確認は下端の主ボタン）。貼り付け欄は自動フォーカスせず、プレースホルダの JSON は 1 キー 1 行に整形して置く。冒頭の説明文は置かない。
- **下端の固定エリアは「組み直しプラン」の 1 つのボタン**（`UnitActionFoot`。全幅の secondary）。押すと組み直しプランのシート（`OptimizePlanSheet`。中身は `ui-flow.md`）が開く。開ける編成がないとき — お気に入りが 0 件 — は隠さず disabled。**下端の固定エリアのボタンは全シート 48px（エリアは 65px）にそろえる**（文字は primary 15px/700・secondary 14px/600）。**お気に入り（ユニット詳細）と結果詳細の両方に置く**。重ねるシートは `z-index` を 1 段上げる（結果詳細 10 → 12。その中で開く曲ピッカーは、このオーバーレイの子として出せばピッカー自身の `z-index: 10` が上に載る）。
- **頻度の表**（組み直しプランのシートの「発動頻度」のタブ）: **見るだけ**。**表は ホロメン / 現在 / 推奨 の 3 列**（列見出しはこの 3 語だけ。推奨は文字だけで、押せる枠にしない）、その下に選んだ案の見込み 3 つ（スコアUP・期待カバレッジ・最大空白。等幅で横並び・項目名の下に数値）。スコアUP は理論値重視なら理論値、ほかは期待値の %。**どの頻度マスにも届かないメンバー**（Pt が足りず、外して空けることもできない）は推奨の欄を「届かない」の淡色の文字にする。選び方（期待値重視 / 理論値重視 / ユニットスコア重視。**既定は理論値重視**。エンジン側の名前 `perfect-score` は変えていない）とメンバーごとの頻度マスの数の固定は条件のタブに置く（`ui-flow.md`）。**「いまのボード状況がすでに最良です」の類の文は置かない**。説明文・ヒントは置かない。脚注には当然の前提（ボードを外すと素材が返る・同時発動は最大だけ有効など）と「おすすめの決定には使わない」の類の注記を書かない。
- **1 つの行の中で揃え方を混ぜない**: 見出しと見込みは左揃え、数値は右揃えで通す（各列に「発動頻度(現在)」と 2 行で書く・見込みを左・中央・右寄せにする・2 列にまたがる 2 段の見出し、はいずれも「バランス悪い」で却下）。**上付きの脚注マーク（`.fn`）は行の高さに数えない**（`line-height: 0`）。**推奨に色は付けない**（達成 = 緑 / 不足 = 青 / 過剰 = 赤 は「色も戻す」で撤去。現在と推奨が並んでいれば差は読める。復活させるなら `src/ui/frequencyTone.ts` と `--state-*` を消した commit を見る）。
- 指標を 3〜4 個並べて選ばせない。**結論に使わない情報は画面に出さない** — 冒頭の説明文・現在の設定・ほかの案・案ごとの差分（+n pt）・内部の単位（マス数・追加解放数）は置かない。値の意味も含めて用語の説明は末尾の脚注へ回す（「不明な用語は脚注」）。
- **数値の入力に `<input>` を使わない（モバイルで OS のキーボードが出る）** — 自前のテンキー `NumberPad.vue`（中央ダイアログ。`ConfirmDialog` と同じ地・寸法）を出し、押せるのは **0〜9 と小数点、1 文字消す（⌫）だけ**にする。ダイアログの上部は 見出し（ボタンのラベルと同じ文字）→ 入力中の値（右寄せの大きな数字 + 小さな単位）→ キー → 「キャンセル / 決定」。**決定するまで呼び出し側の値は変えない**。0 のときは空欄と同じに見せてそのまま打てるようにし、先頭の 0 は次の数字で打ち消す。**範囲の検査は入力の時点で行い、外れるキーは黙って無視する — エラーは出さない**（上限 50%。小数の桁数は props `decimals` — イベントメモリーは小数第 1 位・メンバー強化ボーナスは小数第 2 位）。呼び出し側のボタンの値は同じ桁数まで常に出す（0 でも `0.0%` / `0.00%`、`toFixed`。ゲーム画面の表記と同じ桁）。打ち途中の「50.」は通し、確定値だけを見る。範囲外の値が保存されていたときは空から入れ直してもらう。**小数点のキーを ∞ のキーにできる**（`infinity-key`。リソースの未登録 = ∞ — 押すと表示が ∞ になり、決定で `clear` を出す。数字を打てば ∞ は外れる）。**刻みで動かせる値は +/- ボタンの `StepperDialog.vue`**（同じ中央ダイアログ。左から 粗く減らす / 細かく減らす / 細かく増やす / 粗く増やす。範囲の端では押せない。現在値（未登録は既定値）から始め、「決定」まで呼び出し側の値は変えない。計算は整数で誤差を出さない）: ホロメンランク（1〜50・1 と 10 刻み・未登録は 30 から・「未登録に戻す」あり）/ イベントメモリー（0.0〜50.0%・0.1 と 1.0 刻み・既定 3.0）/ メンバー強化ボーナス（0.00〜50.00%・0.01 と 0.1 刻み・既定 2.00）。`NumberPad` はリソースの個数（整数・∞ キー）など、桁を直接入れたい値だけが使う。
- 数値そのものを打たせるより、既存のピッカーで選ばせる — 評価区間は秒数入力ではなく曲ピッカー（`SongRow` + `SongPicker`、開いた時点のメイン画面の曲で始まる）。見出しと入力欄で同じラベルを 2 回出さない。見出しは選ぶものの名前にする（「曲」。区間の長さの話は脚注だけ）。
- 結果詳細・ユニット詳細（`UnitBreakdown`）の並びは **ユニットスコア（行内に「詳細 ▼」と、共有・星）→〔詳細を開いたときだけ〕総合力 → スコアボーナス → リーダー（タイプ淡色の全幅パネル。名前 + カード名だけで、右端に衣装アイコン）→ メンバー 5 人（仮想ガチャの結果タイルと同じ 5 列の横並び。ホロメン名・カード名の 2 行クランプ + 開花アイコン）→ メンバー別の表 → 下端のボタン → 脚注**。「リーダー」「メンバー」という見出しは置かない（役割は構造で伝える）。**リーダーのパネル・メンバーのタイルはどれも押すとそのカードの詳細（`CardDetail`）が開く**。見た目は押せる印を足さずタイルのままにし、詳細は最上位の `App` が重ねる（ページを `transform` で送る `PageCarousel` の中では `position: fixed` が効かないので、イベントを上へ渡して外で開く）。スキルの原文は出さず、衣装スキルは右端のアイコンだけで示す（発動していなければグレーアウト）。主数値の行の右端に置く共有は**箱から上へ出る矢印**（`ShareButton.vue`。3 点を線でつないだ形は「違う」）。箱は正方形に近い縦長で、大きさは隣の星（42px）に近づける（40px）。矢印の縦棒は箱の中から上へ抜けさせ、矢じりは上辺から離す（上辺に近いと「橋が架かって見える」）。**共有は結果詳細とお気に入りのユニット詳細の両方に置く**（中身は `useUnitShare`）。
- **総合力・スコアボーナスの内訳は 2 列で、項目名の下に数値を置く**。並びは左から右・上から下で、総合力 = メンバーパラメータ / 衣装スキル / ホロメンボード効果 / パッシブスキル / メモリー効果 / メンバー強化ボーナス、スコアボーナス = 衣装スキル / アクティブスキル / ホロメンボード効果 / パッシブスキル / スペシャルスキル に固定する。**効いていない項目も 0 として必ず出す**（淡色にするだけで、0 の欄を省略しない）。1 列の表（`.param-table`）へ戻さない。この形（項目名は小さく淡色・その下に数値）は頻度の見込みでも使う。
- **数字の内訳は既定で畳む** — 総合力・スコアボーナスの表は主数値の行の「詳細 ▼」（▼ / ▲ の開閉記号つきの行内の文字ボタン、12px）で開閉し、既定は閉じる。**開いたときは主数値のすぐ下**に出す（下の方で開くと、開いたことが画面外で起きて分からない）。畳んでいるあいだはその区分を参照する脚注も出さない。
- 主数値の行に脚注番号と操作を同居させるときは、**脚注番号は数字の右上（上付き）、操作は右下（ベースライン）**に置く。`.fn` の `vertical-align: super` はフレックスの子だと効かないので、番号は数字と同じ `span` の中に入れる。
- **同じ見た目の表を続けて置かない** — 列見出しのある表の直後に同形の表を並べると、下の表の値までその列の値に見える。形そのものを変えて分ける（左右 2 列 + 右は表ではなく 1 列の内訳、など）。主数値も、単位の違う表の直後では大きな数字で置かず、その表の 1 行目として名前つきで出す。
- **脚注は初期表示では画面に出さない** — 脚注ブロックの区切り線が画面の下端（下端の固定エリアがあればその上端）にちょうど来る高さを、**脚注より上だけを包む要素**の `min-height` で確保し、スクロールして初めて脚注が現れるようにする。`.breakdown-main`（結果詳細・ユニット詳細）は `calc(100dvh - 174px - env(safe-area-inset-bottom))` = ヘッダ 77 + 固定エリア 65 + 本文の上余白 16 + 区分の間隔 16、`.sheet-main`（組み直しプラン）はスクロールしない上部の高さも引く（`ui-flow.md`）。**脚注を含む要素に `min-height` を掛けても効かない**（脚注自身の高さで埋まってしまう）。広い画面のシートは 100dvh ではないので `min-height: 0` に戻す。本文が画面より長いときは自然に流す。脚注を持つシートを増やしたら同じ扱いにする。
- 取り消しのきかない登録操作（上書き・解除）は確認を挟む（`ConfirmDialog.vue`: 中央の小さなカード + 「キャンセル」白 / 実行は `--action`。全画面シートは 2 択の確認には重い）。
- **お気に入りの一覧（ユニット詳細）は登録しているぶんだけをページにし、空のページは出さない**。番号が 1 から連続するので「ページ番号 = ユニットの番号」は保たれる。**1 件も登録がないときだけ**「未登録」の 1 枚を出し、送りは `1 / 1`、シートの見出しは番号を名乗らず「お気に入り」にする（0 件でも入口は押せる）。
- **番号を選ばせる画面（`UnitSaveModal` の 1〜10）は枠を全部並べたまま、使えない番号を disabled にする**（減光のみ。並びと寸法は変えない）。使えるのは「登録済みの番号（上書き）」と「先頭の空き 1 つ」だけ（判定は `canUseSlot`、構造は `UnitSaveModal.test.ts` で固定）。
- 役割の違い（リーダー枠）はアイコンの付加でなく構造で示す — 結果一覧はリーダー行とメンバーの境をセパレータ（罫線）で区切る。王冠アイコンは使わない。

## 結果の表示

- **結果は「いまのまま / 組み直すと」のタブ**（見出し「結果」の下の 44px のセグメント。見出し右端の「最適化順」のチップ + 進み具合のモーダルの形は、初めての人に優しくないという指摘で替えた — 復活させない。タブの名前は「育成すると」だと さがすの「育てきったら」と「なにがちがうんだ」となるので「組み直すと」— 育てきったら = 全部開けた理想、組み直すと = 今のランクの Pt と持っているキューブの範囲で開け直す）。**タブを切り替えても結果の高さを変えない**（「結果エリアの高さかわるのいや」）: 一覧と進み具合を同じ枠に重ね（`.result-body`）、進み具合を出しているあいだも一覧は見えないまま高さを決める。行の「いま n」の行は「いまのまま」でも取っておく（見えないだけ）。
- 「組み直すと」は結果が届くと自動で裏の計算を始める（`useTrueRanking` → `rankingWorker.ts` → `trueRanking.ts`。中身は ADR-016。最適化は組み直しプランの既定と同じ — ボード → コネクト → 発動頻度・ユニットスコア重視・最小限で組み直す・所持リソースを考慮する・コネクトはシートで実行できるときだけ）。**止めて始め直すのは探し直したときだけ**で、計算中・計算後に登録（ボード・コネクト・ランク・リソース・開花・アカウント補正）が変わっても始めたときの登録のまま続け、計算し直さない（見込みの計算が重い）。
- **計算中はタブのラベルの右に小さなリング（北を始点に時計回り）と全体の %**、タブを開くと**中身に進み具合**（`TrueRankingProgress.vue`: リング（中に全体の % と「残り 約 n 分」。1 分を切ったら「残り 約 n 秒」（5 秒刻み・10 秒未満は「数秒」— 2026-10-09 ユーザー指示。さがすのボタンと同じ）。残り時間はページが裏に回って止まっていた時間を除いて補正する — iPhone は別のアプリへ切り替えると計算ごと止まる）→ 3 段（見込みのボード / 候補の絞り込み / 最適化。済 = チェック、いま = その段の済んだ割合の小さなリング、まだ = 空の円、右に「済んだ数 / 全体」）。**経過時間・ここまでの最高値・「目安」の文字・「中止」は置かない**。始める前（探したあとでボードを登録したとき）は見積もりの分と「開始」、失敗は文言と「やり直す」）。
- **そろうと一覧になり、組み直した後（最適化後）のユニットスコアの順に並ぶ**。行の数字は組み直した後の値で、**その下に小さく「いま n」**（いま登録している状態のユニットスコア — `ResultList` の `baseScores`）。**並べた一覧は上位 30 件で、探索の結果にない編成も出る**。結果詳細の内訳は登録の盤面のまま。結果詳細から「組み直しプラン」を開くと計算済みの結果をそのまま出す（`OptimizePlanSheet` の `preset`。シートの曲が探索した曲と同じで、始めたときから登録が変わっていないときだけ）。
- **「いまの育成で」探した結果で、ボードを登録しているときだけ計算する** — 育てきったら・全カードの結果ではタブを disabled（隠さない）、ボードが未登録ならタブの 2 行目に「ボード未登録」。**育てきったら・全カードの結果では結果詳細の「組み直しプラン」も disabled**（一覧の数字は全解放とみなした値、シートの「現在」は登録の値で食い違う。`ResultDetail` の `optimizeDisabled`。お気に入りのユニット詳細は登録の値で出すので押せる）。探し直したらタブは「いまのまま」へ戻る。
- **結果の見出しの行の右端に ⓘ**（結果があるときだけ）を置き、押すと 2 つのタブの名前と意味を段落で（いまのまま = さがしたときの条件のまま計算したスコアの順 / 組み直すと = 編成ごとに開けるマス・置くコネクト・発動頻度マスの数をいちばん強くなるように付け替えたときのスコアの順で、使えるのはいまのホロメンランクのボードPt と持っているキューブ・コアキューブ・コネクトだけ。「いまの育成で」でさがしボードを登録しているときに使える）を中央のダイアログで出す（表ではなく文 — `ui-design.md`）。

## 文言と情報量

- 選択モーダルのタイトルは、対応するメイン画面の見出しと同じ名詞ラベルにする（本体の文言を変えたら派生画面も同じターンで追随させる）。
- 同じ対象を見せる画面同士（選択モーダルと詳細など）で情報の粒度を揃え、片方にだけ細かい数値を出さない。
- 表示件数などプレゼンテーション都合の設定を実行前のフォーム入力で聞かない — 常に十分な件数を計算し、結果側で見せる。結果は上位 30 件を 1 件ずつの横スクロール（下の「n / 30」が上限を伝える。「組み直すと」が 30 件を最適化するので 30 件）。同じ形の大きな部品は縦に並べず、`PageCarousel.vue`（自前のページ送り: 指に追従 → 離した瞬間にページ確定 → transform 300ms）で 1 つずつ見せる。**向きは 6px 動いた時点で 1 度だけ決めて、途中で変えない**（横と決めたらそのジェスチャの `touchmove` を `preventDefault` してブラウザの縦スクロールを止める）。**縦へ譲るのは縦の動きが横の 1.3 倍を超えたときだけ**（1:1 だと横に払ったつもりの弧を描く指が縦に取られる）。**送るかどうかは「ゆっくりなら距離（40px）、速ければ速さ（0.3px/ms のフリック）」の 2 本立て**（距離だけだと「さっとスワイプするとページがめくれない」）。速く払うとブラウザが `pointercancel` を送ってくることがあるので、**横のドラッグとして成立していれば取り消しでも送る**（最後に動いた位置で測る）。判定は `PageCarousel.test.ts` で固定。ブラウザの scroll-snap は「止まるまでが遅い」、180ms は「早すぎ」で却下。下に「n / N」と左右の三角（操作部は `PageNav.vue` に切り出してあり、`navPosition="none"` で別の場所へ置ける）、端の三角は disabled で隠さない、パネル全体の左右スワイプと PC のマウスドラッグでも送る。送り中も分子は揺らさず、収まりを待たずにタップできる。動きの原則: アニメーションは短く残す（300ms）が、表示値（分子）はアニメーション途中の位置から計算せず、送った瞬間に確定値を出す。ジェスチャ直後の操作を待たせない — 「収まるまで触れない時間」を UI に入れない。アニメーションはユーザーが起こした操作（三角・スワイプ）にだけ付け、状態変化に伴う自動遷移は瞬時に切り替える。
- カード表示は名前を大きく左上、カード名（サブタイトル）をその下に小さく。スキルの表記順は常に SP → アクティブ → パッシブ（リーダー文脈では衣装スキル）。
- モーダルの出口はヘッダ右上の ✕ 1 つ（共通部品 `CloseButton.vue`: 44px の正円に 18px × 2px の線 2 本。地は面の色 —`--chrome` のヘッダの上で押せることを示す。ハンバーガーが開いたときに変わる ✕ と同じ形・大きさ）。複数選択（所持・固定・除外）のピッカーは、✕ に加えて**下端の固定エリアに「確認」**（`--action` の全幅ボタン。押すと閉じる）を置く。一覧の領域が狭くなるぶん、**タイプ（すべて / C / H / P）と状態（すべて / 登録中・固定中・除外中）の絞り込みを 1 行の左右半分に収める**（1 枚選ぶピッカーはタイプの 4 択のみで、フルネームのまま）。**中央の小さなダイアログ**（`ConfirmDialog` / `UnitSaveModal`）はヘッダを持たないので、脱出手段は下の「キャンセル」1 つにする。
- 所属の並び（フィルタのチップ・一覧の順 — `src/ui/labels.ts` の `AFFILIATION_ORDER`）はゲーム内のデビュー順: 0・1・2期生 → ゲーマーズ → 3・4・5期生 → holoX → AREA15・holoro・holoh3ro → Myth・Promise・Advent → ReGLOSS。
- 名前を列挙する区切りは読点「、」にし、名前自体に含まれうる記号（中点「・」）を使わない（`artistsLabel`）。
- カード一覧（リーダー・メンバー・除外・所持）はホロメン名の読み → カード名の読みであいうえお順に並べる（文字コード順は不可）。読みは `holomen.json` / `cards.json` の `reading`（約束事は `src/data/README.md`）、比較は `src/ui/labels.ts` の `readingSortKey`（長音を直前の母音に正規化）。ホロメンボードのピッカーの検索も読みに一致する（カードのピッカーに検索はない）。
- 一覧は識別に必要な最小限にとどめ、詳細はタップ → モーダルの先に置く。所持の登録のピッカーは ★4 も登録できる（★4 を持っていればそのコネクトも持っていることになる）。ただし結果一覧は条件に関わらず編成全体（リーダー + メンバー 5）を常に同じ形で見せる。
- 選択 UI は単一選択か複数選択かがぱっと見で分かる形にする（排他は境界線でつながったセグメント、独立した ON/OFF は離したピル形チップ）。複数選択の状態（除外・所持など）はページには件数のみ出し、内訳の確認・解除はピッカーを開き直して行う — チップ等の一覧をページに並べない。長いドロップダウンで選ばせない — フィルタつきの視覚的な選択 UI にする。複数選択ピッカーには状態フィルター（すべて | 登録中 / 除外中 / 固定中）を置き、絞り込み（レアリティ・所属・タイプ・状態。ホロメンボードは検索も）と並び順（キーと向き）はモーダルを閉じても保持して次回復元する（モーダル種別ごとに独立、ページ再読み込みでリセット）。単一選択ピッカー（カード・曲）は選択中の項目を開いた瞬間に 1 回だけリスト先頭へフィーチャーする（開いている間は並びを動かさない）。
- メイン画面のメンバー 5 枠は**仮想ガチャ・結果詳細と同じ 5 列のタイル**（タイプ淡色の面・中央揃え・2 行クランプ・開花アイコン）で横並びにする。どのタイルも同じピッカーを開く入口で、枠ごとの ✕ は置かず**解除はピッカーの中でタップして外す**。**空き枠はまとめて 1 つの大きな「おまかせ」**にし、その中に残り枠数ぶんの点線の枡を敷いて枠数だけ見せる（タップ判定はまとめて 1 つ）。行の高さは空・充填でもさがすの条件でも変えない（`min-height` は 1 通り）。開花アイコンは常に 1 行ぶん取り、登録値を見ない前提（育てきったら / 全カード）では探索が使っている段階 = 5 を出す。
- **選んだらシートを閉じるのは 1 つだけ選ぶピッカー（リーダー・曲）だけ。複数入れるピッカー（所持・除外・メンバーの固定）は選んでも閉じない** — タップでトグルし、続けて選べるようにする（固定は探索へ集合として渡るので枠ごとに開く必要がない）。枠数が決まっている選択（メンバー 5 枠）は**何人目かをタイルの背景に敷く大きな透かしの数字**で示す — ヘッダに「n / 5」・丸数字（①）の文字・アイコンはいずれも却下。枠が埋まったら残りは理由つきで選択不可にし、固定中のカードは常に押せる（タップで外して入れ替える）。閉じたときは次の空き枠を見せる。

## 数値の表

- 内訳表で和を見出しの値と一致させるための丸め誤差は、常に大きい値の行へ寄せる。0 のはずの行も 0 として出し、帳尻合わせを 0 や小さい値の行に見せない（曲未選択の楽曲スコアボーナス行に -1 が出て「これはなんだ」）。
- 1 つの列に絶対値と % を混在させない。% は絶対値の括弧補足に落とす。ただし環（内訳の和 = 見出しの値）に入らない補足の括弧は置かない — メモリー効果・メンバー強化ボーナスの入力値（%）、ホロメンボード効果の内訳（赤 +n）はどちらも「不要」。
- 内訳は足すと合計に一致する形（検算できる形）で見せる。表示上の丸め誤差は 1 行に寄せてでも一致させる。
- 表同士の親子関係（どの数字の内訳か）は、区分の見出し（総合力・スコアボーナス）の直下にその区分の値を主数値として置いて示し、表は内訳の行だけにする — 同じ値の合計行を表の最後に置かない。区分の主数値は結果の主数値（ユニットスコア 28px）より一段小さい 22px / 700 で、区分同士は同寸法にそろえる。内訳の行に + を付けず、値だけを並べる。
- 結果詳細の表はゲーム画面と同じ項目・同じ名前で、メンバー別（素の P/T/S と総合力）→ 総合力の 6 項目 → スコアボーナスの項目の順に置く。ゲーム画面にない中間量の表（連鎖乗算の表、総合期待スコアの内訳表）は置かない。
- 前段から変化していない値は淡色にして、効いた列だけ目立たせる。
- 表のセルは 1 行に収める — 値セルと行見出しは折り返さず（`white-space: nowrap`）、削れない固有名詞（カード名）は省略記号にし（`text-overflow: ellipsis` + `min-width: 0` の flex 行）、それ以外は文字を小さくする前に文言を削る（効果名は「歌唱者条件のパフォーマンス」、列見出しは「〜後」を外して「素の合計 / 赤ボード / パッシブ / 衣装スキル」）。

## 実装ノート

- transform で送る部品（`PageCarousel`）は、全ページを 1 枚の帯にせず現在ページの前後だけを個別に transform し、`will-change: transform` で常時レイヤーに載せる — 横 35,000px 超の帯や、送りの開始・終了でのレイヤーの作り直しは iOS で一瞬白く抜ける。
- モーダルの背景スクロールロック（`useModalChrome.ts`、body を position:fixed）中に検索欄でキーボードが出ると、iOS Safari がレイアウトビューポートを押し上げて閉じた後にページ最下部へ空白を残すことがある。html/body の overflow hidden・入力欄の focusout でスクロール 0・解除時に blur してから復元、の対策を入れてある（実機未検証）。
- `boolean` の prop は**渡さないと `false`** になる（Vue のブーリアンキャスト）。「省略時は有効」にしたい真偽値は否定形の名前にする（`PageCarousel` に `swipe?: boolean` で作ったら全カルーセルのスワイプが死んだ）。
- **子の部品のルート要素には親の scoped なスタイルも当たる**（Vue は子のルートに親のスコープを付ける）。ほかのダイアログ・シートの中に重ねる部品のルートに `.overlay` のような親と同じクラス名を付けると、親の余白などが効いてしまう（`InfoDialog` を絞り込みのダイアログの上に重ねたら左右の余白が親の 24px になった）。ルートのクラスは部品固有の名前にする（`.info-overlay`）。
- 背景が見えるダイアログでスクロールロック（`useModalChrome` の body `position: fixed`）をかけると、文書全体の再レイアウトで背後のカルーセル（常時レイヤー）が作り直されて一瞬ちらつく。この手のダイアログは `lockScroll: false` で開き、オーバーレイの `touch-action` + `overscroll-behavior: contain` で背景のスクロールを止める。
- 脚注の番号（※1・※2…）は画面の上から出てくる順に振る。並べ替えたら脚注も振り直す。
- 結果の主数値は「最終的なユニットスコア（試算）」1 つで、説明文は添えず、同じ値を表の行として繰り返さない。免責は脚注 ※1 で持つ。
