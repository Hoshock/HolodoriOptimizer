# 一覧・ピッカー・詳細シート・結果表示の部品（UI 規則）

UI の規則は 2026-09-09 の棚卸し 24 回目で 4 ファイルに分けた（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## 部品と一覧の構成

- 一覧 → 詳細の導線は既存のピッカー部品（`CardPicker` / `SongPicker`）をそのまま一覧として開き、選んだら詳細シートを上に重ねる。
- 同じ対象（カード・曲）はメイン画面とピッカーで同じ部品（`CardTile` / `SongRow`）を使い、見た目と固定高を一致させる — 別部品で似せない（UnitSlot と CardTile の二重実装は片方だけ直して齟齬が出た）。幅はそれぞれの置き場に従ってよい（メイン=パネル内 324px / ピッカー=シート 358px @390px）。メイン画面は白いパネル（ページ左右 16px + 内余白 16px）が基準で、ピッカーは白い 1 枚のシート（ヘッダ → 絞り込み → 一覧）— 幅まで揃えるための全幅の白い帯・左右 8px の角丸ブロック・罫線+接続線のステッパー・ピッカー内のカード入れ子+内側スクロールはすべて却下（「びみょう」「キモすぎるしわかりにくすぎる」— 2026-09-05、6 往復）。画面の構造は単純に保ち、部品の一致より入れ子の少なさを優先する。
- モーダルを開いたときにテキスト入力へ自動フォーカスしない（モバイルでキーボードが勝手に開く）。フォーカスはシート自体（`tabindex="-1"` の dialog 要素、`outline: none`）へ移し、キーボードはユーザーが入力欄をタップしたときだけ出す（2026-09-01）。
- キーと向きを持つ選択（並び順）は、キーのセグメント 1 つにまとめ、選択中のセグメントの再タップで向きを反転する — 4 択の全列挙や向きの別ボタンにしない（「同じボタンでトグル」）。ラベルは現在の向きを言葉で示し（「長い順」「短い順」）、選択中には現在の向きを ▼（降順）/ ▲（昇順）の片方で添える — ラベルの変化だけでは反転できることが伝わらないが、⇅ のような「反転できる」抽象記号は「微妙」（2026-09-05 曲ピッカーの並び順、3 往復で確定）。
- スキル行は常に 2 行ぶんの固定高を占有する。本文には固定高を持たせず、行コンテナの `align-items: center` で本文が 1 行でも 2 行でも実高の真ん中に自動整列させる（2026-09-01。旧「1 行なら下を 1 行空ける」を置き換え）。スロット・ピッカーは 2 行クランプ+省略記号（原文は基本 2 行に収まる。3 行に伸ばす・3 行固定にする・縦に送るはいずれも却下 — 2026-09-05）、詳細モーダルは min-height で全文表示。行同士の隙間は 2px、名前ブロックと効果の間隔はタイルの上下 padding と同じ 9px にして縦の余白を対称にする（「サブタイトルと効果の余白と一番下の余白が対称じゃない」）。
- 結果一覧の順位の円は全順位を無色のフラット（白地 + 罫線 + `--ink-2`）にする。1〜3 位のメダル色（金銀銅）は 2026-08-31 のデザイン調査由来で入れていたが「やめて4番目以降と同じくフラット無色にして」で廃止（`--silver` / `--bronze` トークンも削除 — 2026-09-09）。
- 既存の要素に重ねるアイコンは、既存の縦の列・行に合わせる。お気に入りの星は結果の 1 件の右上、**右端のアイコン列（リーダー行の衣装・メンバー行の開花）の真上**で、見出しの行（順位の円とスコア）と同じ高さに置き、中心は 390px の実測で合わせる（「角ではなく衣装アイコンの列の上にバランスよく」— パネルの外へはみ出す案・角に中心を重ねる案はいずれも差し戻された。2026-09-09、4 往復）。大きな数字の隣に置くアイコンは行の中央に揃えるだけでなく、数字の中心線に見える位置まで少し持ち上げる（42px の星を `translateY(-4px)`）。
- 結果一覧はホロメン名とサブタイトル（カード名）を隣接させ（カード名 line-height 14px・margin-top -3px）、メンバー同士の間隔 6px・パネル上下 10px と密にする（2026-09-05）。詳細モーダルも同じ隣接。
- 詳細シート（カード詳細・曲詳細）の見出しは入口の一覧名と同じ（「カード一覧」）にし、対象の名前は本文の色つきカード（タレント名+サブタイトルだけ）で示す。所属のような分類はカードの中に文字で書かず、カードの直下に表示専用の小さなピル（24px・12px、ピッカーの所属チップの縮小形）を左から並べる — 静的ラベルにチップを使わない規則のユーザー指示による例外。データにない項目（コネクト効果の内容、作詞・作曲・編曲、開花途中の文言）は行ごと消さず「未確認」で残して将来入る場所を見せる。並び順はパラメータ → 衣装スキル → スキル → 開花 → コネクト効果（2026-09-07、2 往復で確定）。
- 縦に長い本文をページ送りする詳細シート（結果詳細・ユニット詳細）は、送りの操作を**本文の外・シート下端の固定エリア**（`.sheet-foot` + `PageNav`、地は `--chrome-foot`）に置き、**左右スワイプでは送らない**（`PageCarousel` の `noSwipe`）— スクロールしても操作が残り、縦スクロールと誤爆しない（「一番下に固定エリアを用意しそこにおく」「スワイプを許さない。ボタンだけ」— 2026-09-09）。一覧側（結果パネル・メンバー枠）はスワイプのまま。
- 同じ操作は、その対象が出てくる画面すべてから同じ形でできるようにする（お気に入りの登録・解除は結果一覧の 1 件・結果詳細・ユニット詳細のどこからでも星で行う — 「結果詳細画面でもできるように」「ユニット画面でも解除に関してはできるように」2026-09-09）。詳細シートでは主数値の行の反対の端（右上）に置き、大きさは一覧の 1.5 倍にする。
- 別モデルの計算（表示ユニットスコアではないもの）を見せる画面は、内訳シートの中に混ぜず**別のシートに分けて**、入口を内訳の末尾の全幅ボタンに置く（`UnitBreakdown` の「発動頻度のおすすめ」→ `FrequencyPlanSheet`。結果詳細とユニット詳細の両方から同じ形で開ける）。重ねるシートは `z-index` を 1 段上げる（結果詳細 10 → 12。その中で開く曲ピッカーは、このオーバーレイの子として出せばピッカー自身の `z-index: 10` が上に載る）。主指標は 2 つまでに絞り、**2 つの案を縦に並べず排他のセグメンテッドコントロールで切り替える**（`FrequencyPlanSheet` の「期待値重視 / 理論最大重視」。既定は期待値重視 — 2026-09-10）。指標を 3〜4 個並べて選ばせない（2026-09-09 ユーザー指示）。**結論に使わない情報は画面に出さない** — 冒頭の説明文・現在の設定・ほかの案・案ごとの差分（+n pt）・内部の単位（マス数・追加解放数）は 2026-09-10 に全部外し、残したのは「おすすめ 2 つ × メンバーごとの発動頻度」と補助 2 行だけ。値の意味も含めて用語の説明は末尾の脚注へ回す（「％の数字の意味がわからない」「不明な用語は脚注」— 2026-09-10）。
- 数値そのものを打たせるより、既存のピッカーで選ばせる — 評価区間は秒数入力をやめて曲ピッカー（`SongRow` + `SongPicker`、既定は編成をさがしたときの曲）にした（2026-09-10）。見出しと入力欄で同じラベルを 2 回出さない（「評価区間」の重複を削除）。
- 結果詳細・ユニット詳細（`UnitBreakdown`）の並びは **ユニットスコア（行内に「詳細 ▼」と星）→ リーダー（タイプ淡色の全幅パネル。名前 + カード名だけで、右端に衣装アイコン）→ メンバー 5 人（仮想ガチャの結果タイルと同じ 5 列の横並び。ホロメン名・カード名の 2 行クランプ + 開花アイコン）→ メンバー別の表 →〔詳細を開いたときだけ〕総合力 → スコアボーナス → 「発動頻度のおすすめ」ボタン → 脚注**（2026-09-10 ユーザー指示、3 往復）。「リーダー」「メンバー」という見出しは置かない（役割は構造 — 全幅パネルか 5 列タイルか — で伝える）。スキルの原文は出さず、衣装スキルは右端のアイコンだけで示す（発動していなければグレーアウト）。
- **数字の内訳は既定で畳む** — 総合力・スコアボーナスの表は主数値（ユニットスコア）の行に置いた「詳細 ▼」（さがすステップの「オプション ▼」と同じ形の行内版、12px）で開閉し、既定は閉じる。**開いたときは主数値のすぐ下**に出す（下の方で開くと、開いたことが画面外で起きて分からない — 2026-09-10）。「発動頻度のおすすめ」はどちらの状態でもメンバー別の表の直下。畳んでいるあいだはその区分を参照する脚注（※2・※3）も出さない。
- 主数値の行に脚注番号と操作を同居させるときは、**脚注番号は数字の右上（上付き）、操作は右下（ベースライン）**に置く（2026-09-10）。`.fn` の `vertical-align: super` はフレックスの子だと効かないので、番号は数字と同じ `span` の中に入れる。
- **同じ見た目の表を続けて置かない** — 列見出しのある表（メンバー / 発動頻度）の直後に同形の表を並べると、下の表の値までその列の値（発動頻度）に見える。区分（`.block`）と見出しを分ける（「見込み」に アクティブ期待値 / 期待カバレッジ / 最大空白 — 2026-09-10 ユーザー指摘）。主数値も、単位の違う表の直後では大きな数字で置かず、その表の 1 行目として名前つきで出す。
- **脚注は初期表示では画面に出さない** — 脚注ブロックの区切り線が画面の下端（下端の固定エリアがあればその上端）にちょうど来る高さを、**脚注より上だけを包む要素**の `min-height` で確保し、スクロールして初めて脚注が現れるようにする。`.breakdown-main`（結果詳細・ユニット詳細）は `calc(100dvh - 166px - env(safe-area-inset-bottom))` = ヘッダ 77 + 固定エリア 57 + 本文の上余白 16 + 区分の間隔 16、`.sheet-main`（発動頻度のおすすめ。固定エリアなし）は `calc(100dvh - 109px)` = ヘッダ 77 + 16 + 16。**脚注を含む要素に `min-height` を掛けても効かない**（脚注自身の高さで埋まってしまう）。広い画面のシートは 100dvh ではないので `min-height: 0` に戻す。本文が画面より長いときは自然に流す（2026-09-10 ユーザー指示「デフォルトは長い脚注を見たくない」。脚注を持つシートを増やしたら同じ扱いにする）。
- 取り消しのきかない登録操作（上書き・解除）は確認を挟む（`ConfirmDialog.vue`: 中央の小さなカード + 「キャンセル」白 / 実行は `--action`。全画面シートは 2 択の確認には重い — 2026-09-09 お気に入りユニット）。
- 番号で保存するものを一覧するときは、登録済みだけを詰めずに**番号の全数**を並べる（ページ番号 = ユニットの番号。空き番号は「未登録」の 1 行 — 「ユニット3なのに2ページしかないのはどういうことだ？」2026-09-09）。
- 役割の違い（リーダー枠）はアイコンの付加でなく構造で示す — 結果一覧はリーダー行とメンバーの境をセパレータ（罫線）で区切る（無彩色の面バンド案は「不要」で却下 — 2026-09-01）。王冠アイコンは使わない。

## 文言と情報量

- 選択モーダルのタイトルは、対応するメイン画面の見出しと同じ名詞ラベルにする（本体の文言を変えたら派生画面も同じターンで追随させる — 2026-09-01）。
- 同じ対象を見せる画面同士（選択モーダルと詳細など）で情報の粒度を揃え、片方にだけ細かい数値を出さない（2026-09-01 詳細のメンバー個別パラメータを削除）。
- 表示件数などプレゼンテーション都合の設定を実行前のフォーム入力で聞かない — 常に十分な件数を計算し、結果側で見せる。2026-09-01 は上位 100 件を 10 件+全幅の「さらに10件」の逐次表示、2026-09-08 からは上位 10 件を 1 件ずつの横スクロール（下の「n / 10」が上限を伝える。「100件じゃなくて10件をデフォにしていい」）。同じ形の大きな部品（メンバー枠 5 つ・結果 100 件）は縦に並べず、`PageCarousel.vue`（自前のページ送り: 指に追従 → 離した瞬間にページ確定 → transform 300ms。ブラウザの scroll-snap は「止まるまでが遅い」、180ms は「早すぎ」で却下。下に「n / N」と左右の三角（操作部は `PageNav.vue` に切り出してあり、`navPosition="none"` で別の場所へ置ける）、端の三角は disabled で隠さない、パネル全体の左右スワイプと PC のマウスドラッグでも送る。送り中も分子は揺らさず、収まりを待たずにタップできる）で 1 つずつ見せる（「縦に 5 個長い」— 2026-09-08）。動きの原則: アニメーションは短く残す（180ms は「早すぎ」、300ms）が、表示値（分子）はアニメーション途中の位置から計算せず、送った瞬間に確定値を出す。ジェスチャ直後の操作を待たせない — OS の惰性スクロールのような「収まるまで触れない時間」を UI に入れない（scroll-snap を却下、2026-09-08 に 4 往復）。 アニメーションはユーザーが起こした操作（三角・スワイプ）にだけ付け、状態変化に伴う自動遷移（カードを入れたあとの「次の枠へ」）は瞬時に切り替える（`PageCarousel.jumpTo`。送ると入れたカードの面が最後にチラ見えして「嫌」— 2026-09-08）。
- カード表示は名前を大きく左上、カード名（サブタイトル）をその下に小さく。スキルの表記順は常に SP → アクティブ → パッシブ（リーダー文脈では衣装スキル）。
- モーダルの出口はヘッダ右上の ✕ 1 つ（共通部品 `CloseButton.vue`: 44px の正円に 18px × 2px の線 2 本。地は面の色 —`--chrome` のヘッダの上で押せることを示す。ハンバーガーが開いたときに変わる ✕ と同じ形・大きさ — 文字の ✕ は「サイズが違う」で 2026-09-07 に置き換え）。複数選択（除外・所持）も切り替えが即時反映なので下の「完了」は置かない — 同じ動作の出口が 2 つあると「✕ は取り消しか」と迷わせる。ヘッダを無くして下に「完了」だけ置く案はユーザー提案で試した後に「戻す」となった（モーダルには明示的な脱出手段が要る — 2026-09-05）。**中央の小さなダイアログ**（`ConfirmDialog` / `UnitSaveModal`）はヘッダを持たないので、脱出手段は下の「キャンセル」1 つにする（44px の ✕ は小さなダイアログには重い — 2026-09-09）。実画面の上に固定する操作バー（`AdminPanel`）は 32px に縮めた同形の ✕ を右上に置く。
- 所属の並び（フィルタのチップ・一覧の順 — `src/ui/labels.ts` の `AFFILIATION_ORDER`）はゲーム内のデビュー順: 0・1・2期生 → ゲーマーズ → 3・4・5期生 → holoX → Myth・Promise・Advent → AREA15・holoro・holoh3ro → ReGLOSS。ゲーマーズは 2期生と 3期生の間（1期生の後に置いて「ゲマズが 2期生の前にあるけどあと。3期生の前」— 2026-09-08）。
- 名前を列挙する区切りは読点「、」にし、名前自体に含まれうる記号（中点「・」）を使わない（曲の歌唱者を「・」で繋いで「フワワ・アビスガード・モココ・アビスガード」となり「分かれ目が不明になる。読点にしよう」— 2026-09-08。`artistsLabel`）。
- カード一覧（リーダー・メンバー・除外・所持）はホロメン名の読み → カード名の読みであいうえお順に並べる（文字コード順は英字→カナ→かな→漢字の部首順になり不可 — 2026-09-05）。読みは `holomen.json` / `cards.json` の `reading`（約束事は `src/data/README.md`）、比較は `src/ui/labels.ts` の `readingSortKey`（長音を直前の母音に正規化）。検索も読みに一致する。
- 一覧は識別に必要な最小限にとどめ、詳細はタップ→モーダルの先に置く。ただし結果一覧は条件に関わらず編成全体（リーダー+メンバー 5）を常に同じ形で見せる（2026-09-01）。
- 選択 UI は単一選択か複数選択かがぱっと見で分かる形にする（排他 2 択は境界線でつながったセグメント、独立した ON/OFF は離したピル形チップ — 旧 Step 1 のセグメントと Step 5 のチップの差はこの意図。2026-09-05。さがす対象は 2026-09-08 にオプションのチップ「所持カードから探す」になった）。複数選択の状態（除外・所持など）はページには件数のみ出し、内訳の確認・解除はピッカーを開き直して行う — チップ等の一覧をページに並べない（多数選択時に縦へ伸びるため。2026-08-31 訂正: 以前の「何が対象かを一覧で見せる」を置き換え）。長いドロップダウンで選ばせない — 検索+フィルタつきの視覚的な選択 UI にする。複数選択ピッカーには状態フィルター（すべて | 登録済み/除外中）を置き、絞り込み（検索・所属・タイプ・状態）と並び順（キーと向き）はモーダルを閉じても保持して次回復元する（モーダル種別ごとに独立、ページ再読み込みでリセット。並び順の localStorage 保存は「画面更新したときはリセットでいい」で却下 — 2026-09-06）。単一選択ピッカー（カード・曲）は選択中の項目を開いた瞬間に 1 回だけリスト先頭へフィーチャーする（開いている間は並びを動かさない — 2026-09-01）。

## 数値の表

- 内訳表で和を見出しの値と一致させるための丸め誤差は、常に大きい値の行へ寄せる。0 のはずの行も 0 として出し、帳尻合わせを 0 や小さい値の行に見せない（曲未選択の楽曲スコアボーナス行に -1 が出て「+-1 となるのがあったがこれはなんだ」— 2026-09-08）。
- 1 つの列に絶対値と % を混在させない。% は絶対値の括弧補足に落とす（2026-09-01）。ただし環（内訳の和 = 見出しの値）に入らない補足の括弧は置かない — メモリー効果・メンバー強化ボーナスの入力値（%）、ホロメンボード効果の内訳（赤 +n）はどちらも「不要」（2026-09-09）。
- 内訳は足すと合計に一致する形（検算できる形）で見せる。表示上の丸め誤差は 1 行に寄せてでも一致させる。
- 表同士の親子関係（どの数字の内訳か）は、区分の見出し（総合力・スコアボーナス）の直下にその区分の値を主数値として置いて示し、表は内訳の行だけにする — 同じ値の合計行を表の最後に置かない（2026-09-09「最後の総合力の1行はいらない」。区分の主数値は結果の主数値（ユニットスコア 28px）より一段小さい 22px / 700 で、区分同士は同寸法にそろえる）。内訳の行に + を付けず、値だけを並べる。
- 結果詳細の表はゲーム画面と同じ項目・同じ名前で、メンバー別（素の P/T/S と総合力）→ 総合力の 6 項目 → スコアボーナスの 4 項目の順に置く。ゲーム画面にない中間量の表（旧「総合力」の連鎖乗算の表、総合期待スコアの内訳表）は置かない（2026-09-08「既存の総合力の一番上の表はもはや不要」「ホロメンごとの表は一番上に」）。
- 前段から変化していない値は淡色にして、効いた列だけ目立たせる。
- 表のセルは 1 行に収める — 値セルと行見出しは折り返さず（`white-space: nowrap`）、収まらなければ文字を小さくする前に文言を削る（効果名は「歌唱者条件のパフォーマンス」、結果詳細の列見出しは「〜後」を外して「素の合計 / 赤ボード / パッシブ / 衣装スキル」— 2026-09-08「全員のセンスが 2 行になってる」「後があるせいで 2 行になるので後削除」）。

## 実装ノート

- transform で送る部品（PageCarousel）は、全ページを 1 枚の帯にせず現在ページの前後だけを個別に transform し、`will-change: transform` で常時レイヤーに載せる — 100 件で横 35,000px 超の帯や、送りの開始・終了でのレイヤーの作り直しは iOS で一瞬白く抜ける（2026-09-08。この対策で実機のちらつきは消えた）。
- モーダルの背景スクロールロック（`useModalChrome.ts`、body を position:fixed）中に検索欄でキーボードが出ると、iOS Safari がレイアウトビューポートを押し上げて閉じた後にページ最下部へ空白を残すことがある。html/body の overflow hidden・入力欄の focusout でスクロール 0・解除時に blur してから復元、の対策を入れてある（実機未検証 — pending 9）。
- `boolean` の prop は**渡さないと `false`** になる（Vue のブーリアンキャスト）。「省略時は有効」にしたい真偽値は否定形の名前にする — `swipe?: boolean` で作ったら全カルーセルのスワイプが死んだ（`.swipe-area` がどこにも付かないのを実測で発見。`noSwipe` に反転して解決 — 2026-09-09）。
- 背景が見えるダイアログでスクロールロック（`useModalChrome` の body `position: fixed`）をかけると、文書全体の再レイアウトで背後のカルーセル（常時レイヤー）が作り直されて一瞬ちらつく（「お気に入りボタン押すと後ろの画面がチラつく」— 2026-09-09）。この手のダイアログは `lockScroll: false` で開き、オーバーレイの `touch-action: none` + `overscroll-behavior: contain` で背景のスクロールを止める。
- 脚注の番号（※1・※2…）は画面の上から出てくる順に振る。表の並べ替えで順序が崩れたまま出したら「上から 1・3・2 になってるのきもすぎ」（2026-09-08）。並べ替えたら脚注も振り直す。
- 結果の主数値は「最終的なユニットスコア（試算）」1 つで、説明文（「総合期待スコア（試算値）」）は添えず、同じ値を表の行として繰り返さない（2026-09-08）。免責は脚注 ※1 で持つ。
