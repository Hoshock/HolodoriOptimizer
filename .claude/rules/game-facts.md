# ゲーム仕様・逆解析のルール

## 必読

証拠状態とprovenanceは `docs/human/evidence-policy.md` が正典。カードDBは `docs/human/card-data-provenance.md` も読む。

## 権威順位

実機表示を最優先する。ただし転記にはヒューマンエラーがあるため、単発報告 `reported` と再確認 `rechecked` を区別する。算術一致 `cross-checked` は入力条件の再確認とは別。

## 実験

- 位置・効果・接続線は別々に検証する。
- 到達可能なボード解放集合だけを条件にする。
- 同時に複数要因が変わった観測を単独差分と呼ばない。
- 観測時点のアカウント状態を現在値で上書きしない。
- **青 / 赤 / 黄 / 緑の「実効値」を解析 fixture へ手入力するときは、マスの表記値ではなくコネクト増幅込みの値を入れる。** 増幅は production の `connectFactorMapOf` → 各色の `*BoardEffects` を、アカウントスナップショットの保存値（解放マス + コネクトの配置）に通して確かめる。コネクトの図形はホロメンの左右型で反転せず物理座標の絶対方向なので（ADR-008、2026-09-11）、青が右のホロメンでも「左へ 3」は左へ 3。2026-09-13 の K7 は 水着フブキ の 発動率を マスの表記値 6% で入れて解析結果を誤らせた（正しくは 1500‰ 増幅込みの 15%）。
- Goldenをモデルへ合わせない。
- ケース別magic constantを禁止する。
- 1つの確定から隣接する未確定項目まで確定に広げない。
- カード仕様はID / role / bloom / provenanceを確認してから因果説明へ使う。

## 横断事実

- リーダー1 + メンバー5は別枠。赤はリーダーホロメンからメンバー5へ効く。
- 総合力は6項目の加算モデル。
- count人を選ぶ確認済み効果は対象候補の素値P+T+S上位を選ぶ。
- 表示unit scoreの外側は `ceil(totalPower × (1 + bonus/100) × 2.03734)`。
- Activeは200秒共通タイムラインのモデルが既存Goldenに高精度で一致する。
- 青ボードの反映は **発動率 = 乗算型 `min(1, p0 × (1 + r/100))` / 発動頻度 = `周期 ÷ (1 + f/100)`**。頻度側の非単調な実機系列（4.6 → 4.7 → 4.4 → 5.0）は、同時候補の正規化 `max(1, Σp)` と projective 配分を合わせると自由係数なしで再現できる（2026-09-13 に「この式では再現できない」という記述を撤回）。
- 黄10%の直接対照は `Y × (100 + Costume + Active + Passive + Special)` のBoard増分を支持する。
- 赤スコアサポートの旧候補秒率式は一般式として棄却済み（2026-09-13 に実装からも削除）。
- スコアサポート（赤・リーダー衣装）の表示合計への総増分は `支援/100 × E_blue(乗算)` が強い推定。リーダー衣装・赤・パッシブの支援は加算合成（乗算ではない）。パッシブのスコアサポートは**静的**（供給側の発動確率で割り引かない。gated 型は K6 で棄却）。
- 青がなければリーダー支援の増分はパッシブ支援の有無によらず全量衣装欄（K5 / K6）。カテゴリ再配賦の起点は青。
- **表示 5 欄のうち 衣装 / ボード / パッシブ は「source ごとの増分の和 `T`」を「source ごとの raw weight `W`」で按分する**（`(C,B,P) = T × W/ΣW`、2026-09-13 に production 実装）。`W` は全体を定数倍しても同じ表示になるので、**raw `W` をデッキ間で比べる議論は gauge を固定した比較**であり、そのままでは候補族の構造的棄却にならない。gauge 非依存の比（`B/C`・`P/C`・同一編成での 4 状態一定）で判定する。
- **`W_blue` の「編成全体の評価値どうしの差」型は棄却済み**（2026-09-13 の発動頻度 ownership 系列 F0〜F3。ΣR・ΣF を固定したまま所有者だけを移した 4 状態で、要求は 0.2208〜0.2215 に一定なのに候補族は 0.175〜0.277 とばらつく）。採用中は member-local 型で、F2 だけ 0.023 低い。

## 実装との距離

コードコメントやテストに古い仮説が残っていても、`docs/human/` の正典に反する説明をゲーム事実として再利用しない。反証を見つけたら正典・再現資料・コメント・テストの順に整合させる。
