# ゲーム仕様・逆解析のルール

## 必読

証拠状態とprovenanceは `docs/human/evidence-policy.md` が正典。カードDBは `docs/human/card-data-provenance.md` も読む。

## 権威順位

実機表示を最優先する。ただし転記にはヒューマンエラーがあるため、単発報告 `reported` と再確認 `rechecked` を区別する。算術一致 `cross-checked` は入力条件の再確認とは別。

## 実験

- 位置・効果・接続線は別々に検証する。
- 到達可能なボード解放集合だけを条件にする。
- **解放済みのマスは外して振り直せる**（2026-09-13、フワワの 黄 16 → 0 / 青 0 → 14 をユーザーが現在のボードとして確認）。素材が戻るかどうかは未確認なので、探索のコストは「新しく開けるマス」だけを数える現行方針を変えない（`.claude/rules/engine-structure.md`）。振り直しの前後を同じ観測系列として扱わない。
- 同時に複数要因が変わった観測を単独差分と呼ばない。
- 観測時点のアカウント状態を現在値で上書きしない。
- **青 / 赤 / 黄 / 緑の「実効値」を解析 fixture へ手入力するときは、マスの表記値ではなくコネクト増幅込みの値を入れる。** 増幅は production の `connectFactorMapOf` → 各色の `*BoardEffects` を、アカウントスナップショットの保存値（解放マス + コネクトの配置）に通して確かめる。コネクトの図形はホロメンの左右型で反転せず物理座標の絶対方向なので（ADR-008、2026-09-11）、青が右のホロメンでも「左へ 3」は左へ 3。2026-09-13 の K7 は 水着フブキ の 発動率を マスの表記値 6% で入れて解析結果を誤らせた（正しくは 1500‰ 増幅込みの 15%）。
- Goldenをモデルへ合わせない。
- ケース別magic constantを禁止する。
- 1つの確定から隣接する未確定項目まで確定に広げない。
- カード仕様はID / role / bloom / provenanceを確認してから因果説明へ使う。

## 横断事実

- リーダー1 + メンバー5は別枠。赤はリーダーホロメンからメンバー5へ効く。
- 総合力は6項目の加算モデル。
- count人を選ぶ確認済み効果は対象候補の素値P+T+S上位を選ぶ。
- 表示unit scoreの外側は `ceil(totalPower × (1 + bonus/100) × 2.03734)`。
- Activeは200秒共通タイムラインのモデルが既存Goldenに高精度で一致する。
- 青ボードの反映は **発動率 = 乗算型 `min(1, p0 × (1 + r/100))` / 発動頻度 = `周期 ÷ (1 + f/100)`**。頻度側の非単調な実機系列（4.6 → 4.7 → 4.4 → 5.0）は、同時候補の正規化 `max(1, Σp)` と projective 配分を合わせると自由係数なしで再現できる（2026-09-13 に「この式では再現できない」という記述を撤回）。
- 黄10%の直接対照は `Y × (100 + Costume + Active + Passive + Special)` のBoard増分を支持する。
- **SP 欄は `表示アクティブ欄 × Σ_i (効果時間_i/120) × (支援_i/100) × (1 + 発動率 UP_i/200)` の 0.1% 切り上げ**（2026-09-13 確定。カードデータに記録のある実機 23 編成で誤差 0 — 2026-09-15 に恒常 0凸 の実機値が入って K5 / K6 / K7 も加わった）。SP スキルごとの独立な加法項で、発動率 UP はタイムラインを動かさず自分の支援項を定数倍するだけ。条件は SP ごとに評価する。基準は raw ではなく**表示**アクティブ欄。旧「効果時間 / 100 × タイムライン再評価の差分」型は棄却済み（2026-09-13 に実装からも削除）。
- 赤スコアサポートの旧候補秒率式は一般式として棄却済み（2026-09-13 に実装からも削除）。
- スコアサポート（赤・リーダー衣装）の表示合計への総増分は `支援/100 × E_blue(乗算)` が強い推定。リーダー衣装・赤・パッシブの支援は加算合成（乗算ではない）。パッシブのスコアサポートは**静的**（供給側の発動確率で割り引かない。gated 型は K6 で棄却）。
- 青がなければリーダー支援の増分はパッシブ支援の有無によらず全量衣装欄（K5 / K6）。カテゴリ再配賦の起点は青。
- **表示 5 欄のうち 衣装 / ボード / パッシブ は「source ごとの増分の和 `T`」を「source ごとの raw weight `W`」で按分する**（`(C,B,P) = T × W/ΣW`、2026-09-13 に production 実装）。**表示 0.1 刻みから raw の区間へ戻すときは量子化規則の仮定が入る** — 3 欄の規則は未確定なので、切り上げ `(d − 0.1, d]` と 四捨五入 `[d − 0.05, d + 0.05)` を分けて評価する（対称な ±0.05 は四捨五入を仮定したもの）。**2026-09-15**: 衣装欄は**アクティブ欄との差** `ceil(A + C) − ceil(A)` で量子化される（現行の独立切り上げは棄却。パッシブ欄の位相は分かれない）。総量 `T` と対象選抜は正しく、**`W_C` はリーダーのスコアサポート % に比例する**ので、表示の重みは `W = Σ (支援%/100) × w_i` に絞れた。**残る不定性は `w_i` だけ**で、production の「競合で正規化した取り分」は 12 編成中 9 で外れる（一様でもない）。**`A` の量子化ぶれを入れずに区間を出さないこと** — モデルの `A` は表示値を 16/16 で再現するが 1 quantum のぶれが残り、それは要求区間の幅と同じ桁（これを忘れて「位相は 1 通り」「S2 → S3 で向きが逆」と書き、どちらも取り下げた）。**production はまだ現行のまま**（`docs/human/display-score.md`「量子化」）。`W` は全体を定数倍しても同じ表示になるので、**raw `W` をデッキ間で比べる議論は gauge を固定した比較**であり、そのままでは候補族の構造的棄却にならない。gauge 非依存の比（`B/C`・`P/C`・同一編成での 4 状態一定）で判定する。
- **`W_blue`（青ボードの配分の重み）は「青を実効スコアサポート % に直す」形が現時点の最有力**（2026-09-13。**確定ではない**）。`W_blue = (青の実効支援%/100) × H_C` で、実効支援 % は各メンバーの発動率 / 発動頻度 % を**単独寄与**（`スコア UP_i × p0_i × 発動候補秒_i / T`。同時候補の正規化を入れない量）で重みづけした加重平均。リーダー衣装の `W_C = (L/100) × H_C` と同じ形。実装は `displayScore.ts` の `blueSupportPercentOf`、式の全体・要求区間の作り方・候補の比較・49 組の頑健性は `docs/human/display-score.md`「9. `W_blue` の決定式」が正典（ここで再導出しない）。使うときに効く 2 点だけ挙げる: **青の % は直接効き、青の窓・青の確率は入らない**（発動頻度 +4% は発動候補秒を 1 秒も増やさないのに配分は一定量だけ動く）。**メンバーの重みは青の状態に依存しないが、所有者には依存する**（「所有者に依存しない」という 2026-09-13 の記述は撤回 — F0〜F3 で要求区間が重なるのは差が量子化の区間幅より小さいから）。棄却済みの族（「編成全体の評価値どうしの差」型 / member-local 型 / 2 つの分母をそろえる形）を作り直さない。残る未解決は `docs/ai/tmp/pending.md`。
