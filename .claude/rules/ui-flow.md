# 本線フローと入口の構成（UI 規則）

UI の規則は 4 ファイルに分けてある（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## サイドメニューと入口

- 本線の外の入口（取り込み・一覧・遊び機能・外部リンク・管理用・モード切替）はヘッダ右上のハンバーガー → 右のサイドメニューに集約する: **1 本のリストにし、セパレータは置かない。折り畳みの行でグループを作る**（「境目の感覚が一定じゃない」）。並び:
  - トップレベル（折り畳みなし）= **使い方 / お気に入り / ティア表 / カード一覧 / 曲一覧 / 仮想ガチャ**。「使い方」は一番上で、行き先はアプリの外の解説ページ `guides/simulator/`（通常のリンクで遷移）。「お気に入り」= 登録ユニットの詳細シート `UnitSheet.vue`。「ティア表」= ★5 の評価のシート `TierSheet.vue`（カード一覧の上。2026-10-09 ユーザー指示。タイルを押すと評価画面 `TierCardSheet.vue`。中身は `ui-parts.md`、評価は ADR-024）。
  - 折り畳み「**設定**」（歯車）= **データの取り込み / データの出力 / オプションの保持 / ダークモード / 絶対おかゆんモード**。「データの出力」= 登録しているホロメンの 4 色ボードとコネクト・所持メンバーと開花・イベントメモリー・メンバー強化ボーナスを 1 つの JSON `holodori-optimizer/account` でコピーする `ExportSheet.vue`（取り込みと同じ枠 + 右上の「コピー」だけの画面。JSON は読み取り専用の欄にして枠を本文いっぱいに広げ、枠の中だけをスクロールする）。
  - 折り畳み「**開発用**」（コードの括弧。設定の下）= **GitHub / 開花文言**。ホロメンボード・ペルソナ風 UI・「カラー確認」「文言・配置」の入口は廃止した — 復活させない。
  - 「おまけ機能」というグループは廃止した。作り直さない。
- **モードの 2 つ（ダークモード・絶対おかゆんモード）は遷移ボタンではなく設定項目**。ラベルは状態で変えず、現在値は行の右端のトグルと `aria-checked` で示す。**行そのものを `role="switch"` のボタン 1 つにして、トグルは `aria-hidden` の見た目だけにする**（別々の押せる要素にすると二重に発火しうる）。トグルの ON はほかのコントロールと同じ `--selected` の地（`--selected-ink` のつまみ）。**切り替えてもメニューは閉じず、スクロールもしない**（配色の変化はメニュー自身に出る）。
- **折り畳みは最初は畳み**、押すと右端の山形が回り、行の下に**一段（24px）インデントした項目（アイコン + 内容）**が開いて、その位置より下の行が下へ動く（下端に貼り付けない。メニューを閉じたら畳み直す。片方を開いてももう片方は閉じない。項目は 1 段小さい 15px / 600・48px、アイコンは親と同じ 24px）。リストの最下部は安全領域ぶんの余白を持つ。
- サイドメニューは常時表示領域（ヘッダ）に掛けず、開く瞬間のヘッダ下端から出す。**ヘッダがスクロールで画面の外に出ているあいだは、同じハンバーガーを右上に浮かせて出す**（`App.vue` の `.menu-float`。`IntersectionObserver` でヘッダの可視を見る。開いている間は ✕ として残り、メニューは画面の上端から出る）。位置はヘッダのハンバーガー・各シートの ✕ と同じ 右 16px・上 16px、出入りは 0.22 秒のフェード + わずかな沈み込み（`prefers-reduced-motion` では無効）。開閉の操作は同じ場所で形を変える（ハンバーガー ⇄ ✕）。閉じる手段は ✕・外側タップ・Escape の 3 つで、開けるのはメイン画面だけ。サイドメニューの地は不透過で、背後は scrim で少し暗くする（透過 + ぼかしは「やっぱ透過しないように」）。
- **解説ページへ出ていくときは、そのときの縦位置を覚えて戻ってきたら復元する**（`src/storage/returnScroll.ts`、入口は `src/ui/guideReturn.ts` の `rememberGuideReturn()`。通常のリンクでの遷移なのでブラウザのスクロール復元は効かない。メニューを開いている間はスクロールロック中で `window.scrollY` が 0 なので、`currentScrollY()`（`useModalChrome`）が返すロック前の位置を使う）。**解説ページへ行くリンクは全部 `rememberGuideReturn` を通す**（サイドメニューの「使い方」と説明カード）— 一部だけ覚える形にすると、覚えた値が使われないまま残り、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ。**位置へ戻すのは解説ページのヘッダの「←」だけ**で、本文の「編成シミュレーターを開く」（`guides/**` の `.guide-cta`）からは先頭へ出す — CTA は遷移の前に覚えた値を捨てる（各解説ページ末尾の小さな `<script>` が `sessionStorage` のキーを消す。`src/seo.test.ts` で固定）。**復元はマウントの途中（最初の描画より前）に同期で当てる**（`App.vue` の `restoreScroll`）— `requestAnimationFrame` に入れると先頭に描かれたフレームが 1 枚見えてから飛ぶ（「チラついて戻る」）。高さがまだ足りないときだけ届くまで数フレーム追いかける。
- **検索から来た人向けの説明は、本線の一番下の 1 枚（`AboutSection.vue`）だけに置く**。入力の導線より上へは出さず、ファーストビューを押し下げない。中身は `src/ui/siteCopy.ts`。できることの箇条書きは重要度順を優先し、同じくらいのものは画面の操作順（試算値であることはフッタの免責に書いてあるので重ねない）。検索用の隠しテキストは使わない。
- アカウント情報の取り込み（スクショ → ローカル LLM → 構造化データ）の入口は**折り畳み「設定」の一番上の 1 行**「データの取り込み」で、種別（所持メンバー・将来のボード等）ごとに入口を増やさない — 貼られた JSON の `kind` で何を取り込むか決める。
- 開発用の「開花文言」（`BloomTextSheet.vue`。「開発用」の GitHub の下）は、カードごとに開花段階ごとのスキル文言を実機を見ながら入れ直すための入力フォーム。**実画面の上に固定せず全画面のシート**（量のある入力をする道具だから）。中身は 3 つだけで説明文は置かない: 「カードを選ぶ」（`CardPicker`）→ 開いたカードの切り替えチップ → スキル 4 種（衣装 → スペシャル → アクティブ → パッシブ）× **文言が変わらない区間**の欄 →（末尾に）共有用データ + コピーボタン（区間ごとの欄にもコピーボタン。入力欄は 16px）。**欄は開花段階ごとに出さない** — どのスキルがどの段階で強くなるかは決まっている（`BLOOM_UPGRADE_STAGE`。衣装は変わらない / アクティブ 1凸 / SP 3凸 / パッシブ 4凸）ので、区間ごとに 1 つ（衣装 1・ほか各 2 の計 7 欄）。欄の既定値はいまのカードデータから出した文言（`cardAtBloomWithProvenance` の raw を区間の先頭の段階で引く）で、区間ごとに出所の印を添える。見出しはホロメン名が主で、カード名は下に小さく添える。**上書きは既定値と違う文字列だけを持ち**、既定値に戻すと上書きも消える。開いたカードはチップで行き来でき、共有用データ（`kind: "holodori-optimizer/bloom-text"`）には開いた順に全部入る — 直していないカードも「この内容で合っている」の記録として出す。入力は localStorage にだけ残り、カードデータは書き換えない。**ピッカーに出すのは対応がまだのカードだけ**（`bloomTextPickerPool`: 実機確認を通したカード（`BLOOM_TEXT_VERIFIED_CARD_IDS`）と、このフォームで開いて記録したカードを外す）。「外す」で記録を捨てるとピッカーへ戻る。未入力のカードが残っていないときは「カードを選ぶ」を無効にして「未入力のカードはありません」。ピッカーには「すべて / 所持」の絞り込みが付く（部品側は `ui-parts.md`）。

## さがすの条件

- **再読み込みで残すのはさがすの「オプション」だけで、枠の選択（リーダー・固定メンバー・曲）は毎回まっさらから始める**（2026-09-16 ユーザー指示「リーダー、メンバー、曲はページ更新されても保持するのやめよう。探すオプションだけはデフォルト維持」— 復活させない）。オプション側（育成の前提の 3 択 / 役割別の除外・選択）は既定で保存し、**「設定」の「データの出力」の下のトグル「オプションの保持」で OFF にできる**（`useKeepOptions`。ダークモードと同じ 1 行の `role="switch"`。仕組みは `storage-compat.md`）。
- 詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する。モード全体に効くグローバルな詳細設定を増やさない — 既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダル内で設定する。
- **さがすステップは「育成の前提」の 3 択 → 「絞り込み」の 1 行 → 実行ボタン**（2026-10-08 ユーザー指示。初めての人に優しくないという指摘からモック 3 案を比べ、モードを分けず全員が同じ画面を使う形に決めた — ADR-017。「シンプル / 詳細」の切り替えは置かない。旧「オプション ▼」の開閉と中のチップ「所持カードから探す」「ボード状況を考慮する」「開花状況を考慮する」、色ごとのボードのサブオプション、コネクトのチップはすべて撤去 — 復活させない）。3 択は**いまの育成で / 育てきったら / 全カード**（排他なので 40px のセグメント。`src/ui/searchPremise.ts`）: いまの育成で = 所持カード・登録している開花とボード、育てきったら = 所持カード・開花最大とボード全解放、全カード = 未所持を含む全カード（開花最大・全解放）。**ボードと開花の片方だけを考慮する組み合わせは持たない**（「ボードオンで開花オフで調べることない」）。ボードを考慮しないは全解放であって 0 ではない — 育てきった前提で比べたい。保存の形は変えない（`storage-compat.md`）。**コネクトは前提によらず登録している（ボードで置いた）コネクトで常に計算する**（全解放として試算するときも、登録したコネクトの範囲が全解放のマスに掛かる。「OFF なら最適な形で試算」「OFF なら増幅なし」はどちらも撤去 — 復活させない）。メモリー・メンバー強化ボーナスも登録値をそのまま使う。
- 「絞り込み」は押すと中央のダイアログ（`PoolFilterDialog.vue`。除外 / 選択のセグメント → 「リーダー n枚」「メンバー n枚」→「閉じる」）を開き、行の右に今の状態（除外は合計の枚数か「なし」、選択は合計の枚数か「すべて」）を出す。ダイアログからピッカーを開くあいだはダイアログを隠し、ピッカーを閉じると戻る。見出しの行の右端の ⓘ で除外 / 選択の意味を出す。
- **さがすの見出しの行の右端に ⓘ** を置き、押すと 3 択の違いの表（カード・開花・ボード・頻度マス・コネクト × 3 択。いま選んでいる列の見出しは選択の色）を中央のダイアログで出す（部品と置き方は `ui-design.md`）。
- **リーダー・メンバーの絞り込み**: 「除外 / 選択」のセグメント（既定は除外）の下に「リーダー n枚」「メンバー n枚」の 2 ボタン。除外は選んだカードを候補から外し、**選択は選んだカードの中だけからおまかせで探す**（ピッカーは「リーダー候補」「メンバー候補」の複数選択）。リストは種類ごとに別々に持ち、効くのは現在の種類のほうだけ。選択が 0 枚のときは絞らず、件数の欄は「すべて」（0 件になる設定を作らない）。エンジンは役割別の除外しか持たないので、選択は補集合として渡す（`src/ui/poolRestriction.ts`）。
- **★4 は自分で枠に置いたときだけ編成に入る**（ADR-022）: リーダーのピッカー・メンバーの固定のピッカー（と所持の登録・カード一覧）は すべて / ★5 / ★4 の切り替え（既定 ★5）を持ち、おまかせの候補は ★5 だけ（固定していない ★4 はエンジンの除外に足す — `star4Pool.ts`）。除外・候補の選択のピッカーは ★5 だけを出す（★4 はおまかせに入らないので絞る意味がない）。**リーダーをホロメンで指定したとき（おかゆモードのおかゆんも）は、そのホロメンの ★4 もリーダーの候補に入れる**（2026-10-09 ユーザー指示。メンバーの枠には入らない）。**★5 を 1 枚も持っていないホロメンの ★4 も、リーダーのおまかせの候補に入れる**（同日ユーザー指示「星5のないタレントは星4もリーダーの探索に入れる」。「持っていない」は所持カードから探すときの除外で決め、「全カード」ではどのホロメンにも ★5 があるので入らない。★5 のあるホロメンの ★4 は入れない — 衣装スキルは基本 ★5 が強く、全部入れると さがす が 3〜4 割遅くなるうえ、計測では上位 30 件に ★4 のリーダーは入らなかった）。この決まりはリーダーとメンバーの見出しの ⓘ に書く（選べることの意味なので脚注ではない）。
- **枠での指定は除外・選択より優先する**（「除外のカードも選べて良い」）。自分で指定したリーダー・固定したメンバーにエンジンは除外を適用しない。リーダー・メンバーのピッカーでは選択の外のカードも除外中のカードも選べる。ホロメンで指定したリーダー・おかゆモードのおかゆんのカードは除外・選択のどちらでも候補に残す。除外のピッカーでも、指定中のリーダー・固定中のメンバーを除外にも解除にもできる。おかゆモードのおかゆんだけは新たに除外できない（すでに入っているものは外せる）。
- 絞り込み系オプションの既定は保守的な OFF ではなく実用上おすすめの状態にする — 既定のまま実行すれば一番よい結果が出る（育成の前提は「いまの育成で」）。**候補を減らすだけのしぼりこみ（衣装スキル発動に限る / パッシブ全員発動に限る）は撤去済み — 復活させない**（常に全探索して不発の編成も並べ、発動しているかどうかは結果側で見せる。プールが小さいと条件 1 つで 0 件になる事故もこれで無くなった）。**登録がないと必ず 0 件になる設定は、定数ではなく登録状態から既定を決める**（所持カードが 1 枚もなければ既定は「全カード」。`storage-compat.md`）。
- 順位に影響の薄い要素（課題曲のイベントスコアボーナス +10%）は UI に出さない（「あんまいらんかも」）。
- **まとまりのある設定を枠で囲む形（`.option-group`）は、いまは使う画面がない**（さがすは 3 択へ、組み直しプランは小見出しの区分へ組み替えた）。主とぶら下がりの関係を示す必要がまた出たらこの形で作る: 地を一段落とした角丸の枠 + 主の設定を上の行・ぶら下がりを下の行の左右半分ずつ（ぶら下がりのチップは文字だけ一回り小さく）。枠の中に区切り線は引かない。枠どうしは同じ高さ（上下とも 32px の行で 84px）。親が OFF のあいだ、ぶら下がりは白 + disabled。

## ステップと操作の構成

- ステップは意味単位で切る — 同じ意味に属する設定を別ステップに分けない。同じ操作を役割で分けるときは、1 つの入口の中に状態を重ねるより、目的別の入口を名前で分ける平たい構造にする（「リーダーから除外、メンバーから除外の二つのタイルを用意しよう」）。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない。ただし**開いた先に「何が空いているか」の情報があるなら開けてよい**（お気に入りは登録 0 件でも押せる）。前提が満たされず操作を止めるときも、赤いエラーメッセージでなく「方針」をボタンのラベルで示す（おかゆモードでリーダー・メンバー・実行を disabled）。例外: Step 0 の入口はラベルを変えると収まらないので、おかゆモードで未登録のときだけボタンの下に 1 行「おかゆんを持っているカードに指定してください」を出し、出ていないときは余白も取らない。ある条件で効かなくなる設定は、その条件のあいだ disabled にするが見た目は 2 通り: 一時的に効かないだけの設定は保持している設定値の見た目（選択中の濃色地）を変えず減光だけ / そのモードでは意味を持たない設定は未選択（白）+ disabled（例: ボードもコネクトも選んでいないときの組み直しプランの「最小限で組み直す」）。どちらも保存値は保持し、条件が外れれば復帰する。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置（ページ先頭）へ視点を移す。例外はサイドメニューの中のトグル（メニューを開いたまま切り替えるので閉じもスクロールもしない）。
- 同種の連続スロット（メンバー枠等）は順序に意味がない入力なので、飛び石の自由度を与えない: 追加は常に先頭の空き枠へ入れ、解除時は上へ詰める。枠自体はどれもピッカーの入口として押せてよい（固定は複数選択ピッカーで入れる）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色 / 白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする。数値を入力する設定（Step 0 の「イベントメモリー」「メンバー強化ボーナス」）は**同じパネルのボタンと同じ器**にし、ボタンの中でラベルを左端・値（%）を右端に寄せる（押すと +/- の `StepperDialog`。イベントメモリーは既定 3.0 で 0.1 と 1.0 刻み、メンバー強化ボーナスは既定 2.00 で 0.01 と 0.1 刻み。上限 50% — `ui-parts.md`）。**ラベルと値が重なるなら 1 行に押し込まず 1 行 1 つの縦積みにし、名前も略さない**。ラベルの文字サイズはパネルのボタン内と揃える（小さく淡くしない）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す。選択コントロールを実行ボタンに隣接させるときは形・高さ・幅・色で役割を分ける — 選択は内容幅・32px のピル形チップ（ピッカーの所属チップと同形）で濃色地（`--ink`）、アクションは全幅・48px の角丸矩形で実行専用の緑（`--action`。おかゆモードは紫のまま）。
- 処理の進行は、押した実行ボタンの中だけで示す（ボタンの寸法は保ち、中止ボタンは置かない）。**「ベスト編成をさがす」はボタン全体をゲージにする**（2026-10-09 ユーザー指示「スピナーやめて左からゲージが満たされつつ、今何分の何かの数字を出して欲しい。それと終わりの見込み時間」— モック 3 案から A。全カードだと長い）: 地を淡い緑（`--action` と面の色の混色）にして済んだぶんを左から `--action` で満たし（**ゲージはボタン自身の背景のグラデーション `--gauge` で描く** — ボタンの子に % の幅で重ねると iOS Safari はボタンの左右の余白を除いた幅を基準にするので、件数の割合より短く、満ちても右端が残った。文字も絶対配置にせず、隠したラベルと同じ枡に重ねる。2026-10-09 ユーザー指摘）、左に「済んだ組合せの数 / 全体」（万・億で 3 けたほど。`src/ui/searchProgress.ts`）、右に「残り 約 n 分 n 秒」。**残り時間は「計算中」とは出さず**、最初の進み具合が届いたときから出して届くたびに直し、そのあいだは 1 秒ごとに減らす（同日ユーザー指示）。数え終えたら右は「仕上げ中」（上位を正確に計算し直す。全カードでは上位 20 万件を全部計算し直すので 10 秒ほど）。**全体の数は探索が実際に数える組合せの数**（同じホロメンを 2 人入れない — `optimize.ts` の `total`。2026-10-09 まで同一ホロメンの排他を数えない概算で、全カードではゲージが 91% で止まっていた）。組み直しプランの「最適化を実行」も同じゲージで、中央に残り時間だけ（下の項目）。**再実行のあいだは前回の結果を消さず、薄く（opacity 0.5・触れない・`aria-busy`）残して結果が届いたら置き換える** — 結果セクションをアンマウントするとフッタが繰り上がってチラつく。非同期の更新で領域を空にしてレイアウトを動かさない。結果の描画に使うスナップショット（開花・ボード・リーダー指定など）も開始時でなく結果が届いたときに差し替える（前回の候補を今回の設定で描かない）。
- 並ぶ選択肢は指定された順を保ったまま 2 列 × n 行の等幅グリッドに収める（縦 1 列は却下）。ラベルが収まらなければ文言を短くし、文字サイズを落とすのはそのグリッド内だけにとどめる（375px 幅でも収まることを実測する）。性質の違う要素（ON/OFF のチップと、ピッカーを開くボタン）を同じグリッドに並べるときは 1 行を全幅にせず左右に置き、形で区別する（チップはピル、ボタンは角丸矩形。高さ 32px と文字はチップに揃え、ラベル左・件数右で件数はボタンの中）。

## Step 0「アカウント」

- アカウントの状態（持っているカードと開花段階・ホロメンボード・リソース）は Step 0「アカウント」にまとめ、そこでだけ変更する（お気に入りユニットの登録・解除は結果側の星から行い、登録ぶんを見る入口はサイドメニューの「お気に入り」）。入口は **2 列 × 2 段の 4 ボタン「ボード / カード / コネクト / リソース」**（1 段目 ボード・カード、2 段目 コネクト・リソース。コネクトは見るだけの画面）。**見出し「アカウント」の行の右端の ⓘ** で 4 つの入口が何で、どこで使うかを出す（`ACCOUNT_INFO`）。同じ形で **Step 1「リーダー」**（リーダーのカードから入るのは衣装スキルと赤ボードだけ・指定しないときはおまかせ）と **Step 3「曲」**（曲で変わるもの・指定なしのとき）の見出しの行にも ⓘ を置く。
- 入口のボタンに件数・値は出さない（「枚数表示とかいらん」）。**ただし登録がまだのものだけ、ボタンの右端に注意色の小さな「未登録」を出す**（ラベルは中央のまま動かさず、右上の角に重ねる。ボード = 4 色のどれかのマスかホロメンランク、カード = 所持カード、コネクト = 所持カードから導いた所持が 1 枚でもある、リソース = どれか 1 つの個数）。探索の条件（枠・曲・オプション）と混ぜない。
- ホロメンボードはカードでなくホロメンに属するので入口もホロメン一覧から（カードタイル上の入口は却下）。
- **持っているコネクトは登録しない** — 所持カードと開花段階から導く（カード 1 枚 = コネクト 1 枚、％ はカード固有の効果の Lv1 / Lv2。★4 のカードのコネクトも入り、コネクトの最適化はその全部の範囲で置く。ADR-023）。**「コネクト」は見るだけの画面**（`ConnectInventorySheet.vue`。範囲の形 17 種を図形のタイルで 1 行 4 列に並べ、置いているか持っている形に**「使用 / 所持」**（ボードに置いている数 / 持っている枚数。％ を合わせた合計 — 2026-10-10 ユーザー指示「今何個使われているかもそこから見たい」）を右上に出し、どれかの ％ で所持を超えて置いていれば赤の地。**タイルを押すとその形の ％ ごとの 使用 / 所持 を見るダイアログ**（`ConnectInventoryDialog.vue`。取りうる ％ を全部並べ、行の下に使っているホロメン、両方 0 の ％ は淡色、超えている行は赤の数字。数え方は `connectInventory.ts` の `connectUsage`）。2026-10-02〜09 の ＋ / － で枚数を入れる操作は外した — 復活させない）。カード 1 枚のコネクトはカード詳細の「コネクト」（`ui-parts.md`）で見せる。形の名前の文字（「右へ 3」など）は画面に出さず、図形で示す。
- **リソース**（`ResourceSheet.vue`）は、ボードを開けた上で余っているキューブ・コアキューブの個数を色ごと（赤・青・黄・緑）に登録する画面で、**色ごとのカードを 2 列（広い画面は 4 列）に並べ**、カードの中に「キューブ」「コアキューブ」のボタン（その色のキューブのアイコン + 小さな名前の下に大きな値。押すと自前のテンキー `NumberPad` で整数を入れる。上限 999,999）を置く。カードの地はその色の淡い面 `color-mix`、コアキューブのアイコンは半透明のキューブの中の核。値は 360px で 999,999・−99,999 が省略されない寸法。**未登録は ∞（制限なし。0 は別の値）、マイナスは不足（最適化の推奨を反映したときだけ入る。注意色で「−74」のように出す）で、テンキーの小数点のキーを ∞ のキーにしてあり**（`NumberPad` の `infinity-key`。押すと表示が ∞ になり、決定すると未登録に戻る。数字を打てば ∞ は外れる）、値のボタンにも未登録は ∞ と出す（絵文字ではなく文字の ∞）。**使い方（余りを入れる・どこで使うか・未登録は ∞・マイナスは不足）は見出しのすぐ右の ⓘ から開く**（脚注は置かない。中身は `RESOURCE_INFO`）。ゲームではボードを開けるのにボードPt に加えてこの 2 つが要るが、**このツールで手動でボードを開ける操作は個数に左右されない**（手動の編集でこの登録値を自動で増減もしない）。使うのは組み直しプランと結果の「組み直すと」（ボードの段）だけで、いまのボードへ投入済みの資材 + 登録した余りを総量として全ホロメンで共有して配り直す。推奨を反映するとこの余りも新しい盤面に合わせて置き換わる。保存は `board-resources`（`storage-compat.md`）。
- **「お気に入り」で見せる値は、ゲームのユニット編成画面と同じ入力（曲なし・登録している開花と 4 色ボード・コネクト・アカウント補正そのもの）で出し、メイン画面の曲も「さがす」のオプションも渡さない** — 曲を変えるたびに登録ユニットの値が変わるのは「気持ち悪い」、オプションで変わるのも「きもい。実ゲームのユニットと同じように自分のボードやカード状況を加味された値であるべき」。曲の反映（黄のボード欄・赤の歌唱者条件・イベント）は「さがす」の結果側だけ。登録している開花・ボードを変えれば反映される（`registeredBlooms` / `boardMap` / `greenMap` / `yellowMap` / `redMap` / `connectMap` を直接渡す。`current*` は育てきったら・全カードで最大状態に切り替わる探索専用の値）。ゲーム内の画面に対応する表示は、その画面と同じ入力だけで出す。
- **お気に入りに登録できるのは所持カードで組んだ編成だけ**（6 枚すべてが所持リストにあること。開花段階は問わない）。全カードから探した結果は登録できない（入口の見せ方は `ui-parts.md`）。**効かせるのは登録の時点だけ**で、登録済みのユニットはあとで所持から外れても消さず・隠さず、お気に入り画面に出して自分で外せるようにする（`storage-compat.md`）。

## 組み直しプラン（`OptimizePlanSheet.vue`）

結果詳細・ユニット詳細の下端の 1 つのボタンから開く（`ui-parts.md`）。名前は「最適化」→「育成プラン」→「組み直しプラン」と改め、「育成」は さがすの「育てきったら」と紛らわしいので使わない。

- **この編成のまま**、選んだものを **ボード → コネクト → 頻度** の順に最適化する。**ボード**はホロメンごとのボードPt の予算（ホロメンランク。未登録は制限なし）と共有の資材の範囲で、**コネクト**は所持カードから導いた持っているコネクトの範囲で、いま置いている配置から、その編成の表示ユニットスコアが上がる変更だけを出す。**頻度**はその盤面から、メンバーごとに発動頻度マスを選ぶ（目的関数・守る制約・近似は `engine-structure.md` と ADR-012〜016。**変更量を最小にするのが方針** — 置いても置かなくても結果が変わらない場所は、いま置いているものをそのまま残す）。基準は**いま登録している状態**（ボード 4 色・コネクトの解放と配置・ホロメンランク・開花・アカウント補正。探索の前提の 3 択に関わらない）と、シートの曲。
- **頻度を選んだときは、ボードは青の発動頻度マスをすべて OFF にして選び、その盤面から頻度マスを選び直して反映する**（選び直しは登録の頻度マスに足す・減らすだけで、数が同じなら場所を変えない）（ADR-014 / 015。キューブ・コアキューブはボードの段も頻度の段も 余り + この編成に効かないマスの分の範囲 — ADR-016）。**頻度を選ばないときは、登録している頻度マスとそこまでの経路を残したまま**ボードとコネクトを選ぶ（「頻度を最適化するオプション外すと何でユニットスコアの現在変わるんだ」）。コネクトの評価は、頻度を選んだときは頻度マスを外した世界、選ばないときは登録の頻度マスを残した世界で行う。**現在のユニットスコアはいつも登録そのまま**（結果一覧と同じ。設定で変わらない。脚注 ※1）。
- **キューブ・コアキューブが足りなくなるぶんは、ほかのホロメンのこの編成に効かないマスを外す変更として推奨に入る**（2026-10-10 ユーザー指示。ボードのタブの区分に出て、反映の確認で行ごとに外せる。それまでは盤面を変えず「外して回します」と添えて余りを負にしていた）。**余りが負になる推奨**（所持リソースを考慮しなかった色・外せるマスが足りないとき・効かないマスを外すホロメンの行を外したとき・前から負の余り）は画面には出さず、**反映の確認に一言を添える**: 「赤のキューブが 10 不足します。余りはマイナスで登録されます。」（複数は「、」でつなぐ。不足がなければ何も添えない）。余りは負のまま登録し、リソースの画面で注意色のマイナスで見せる。
- **開いただけでは計算しない — 条件のページ**（「最適化ボタンを押したら最適化を走らせるのではなく、最適化設定ページに飛ばすだけ」）。計算は下端の「最適化を実行」を押したときだけ。
- **シートの上から順に**（**タブまでは固定**で、スクロールするのはタブの中身と脚注だけ。表の列見出しは本文のスクロールの上端に貼り付く。**スクロールする場所は本文の 1 か所だけ** — 上部に開閉行を置くと 2 か所がスクロールして境目が白く見切れた）: 現在 / 推奨のユニットスコア（伸びの % は出さない。実行する前は現在だけ。編成 1 つの評価なので UI スレッドで出す）→ 注意（コネクトの登録が足りない・実行の失敗。資材の不足は出さない）→ **タブ「ボード / コネクト / 発動頻度」+ その右に離した「条件」のボタン**（2026-10-09 ユーザー指示。条件は入力で、ほかの 3 つは 1 回の結果の見方なので同じ列の 4 択にしない — モック 3 案（条件と結果を別ページ / 条件をシートで重ねる / タブの横に離して置く）から 3 つめを選んだ。結果の 3 つは排他のセグメント、条件はピル形のボタンで、開いているときは選択の色。**開いた直後は条件**（いまの条件の結果を覚えていれば・結果の「組み直すと」から計算済みの結果を渡されたときは、最初の結果のタブ）。**結果のタブは実行するまで disabled**、実行したあとは表示中の結果で対象にしなかったものが disabled。**結果が届くと最初の結果のタブへ移る**。条件へ戻って変えても推奨は上部に見えたまま薄くなる）→ タブの中身 → 脚注（※1 は推奨の欄、※2 からは開いているタブの中身のぶんだけ出す。条件のタブは ※1 だけ）。
