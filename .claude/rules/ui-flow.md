# 本線フローと入口の構成（UI 規則）

UI の規則は 2026-09-09 の棚卸し 24 回目で 4 ファイルに分けた（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## 方針

- 本線の外の入口（取り込み・一覧・遊び機能・外部リンク・管理用・モード切替）はヘッダ右上のハンバーガー → 右のサイドメニューに集約する: **1 本のリストにし、セパレータは置かない。折り畳みの行でグループを作る**（2026-09-11 ユーザー指定「境目の感覚が一定じゃない。セパレータをやめて折り畳みをグループごとに作ろう」）。**並びは 2026-09-14 のユーザー指示で組み替えた**（それ以前の「1 つめ = お気に入り / カード一覧 / 曲一覧 / データの取り込み / データの出力 / ダークモード、2 つめ = 折り畳み『おまけ機能』= 仮想ガチャ / 絶対おかゆんモード、3 つめ = 折り畳み『開発用』」を置き換える）:
  - トップレベル（折り畳みなし）= **使い方 / お気に入り / カード一覧 / 曲一覧 / 仮想ガチャ**（「使い方」は一番上で、行き先はアプリの外の解説ページ `guides/simulator/` — 通常のリンクで遷移する。2026-09-14 追加。「お気に入り」= 登録ユニットの詳細シート `UnitSheet.vue`。2026-09-11 に Step 0 の「ユニット」から移して改名。「仮想ガチャ」は 2026-09-14 に折り畳みの中からここへ移しただけで、機能と状態管理は変えていない）。**解説ページへ出ていくときは、そのときの縦位置を覚えて戻ってきたら復元する**（`src/storage/returnScroll.ts` に置き、`src/ui/guideReturn.ts` の `rememberGuideReturn()` が入口。通常のリンクでの遷移なのでブラウザのスクロール復元は効かない。メニューを開いている間はスクロールロック中で `window.scrollY` が 0 なので、`currentScrollY()`（`useModalChrome`）が返すロック前の位置を使う — 2026-09-14 ユーザー指示「ヘッダで戻った時、前のページの位置は記憶しておいてそこに戻ろう」）。**解説ページへ行くリンクは全部 `rememberGuideReturn` を通す**（サイドメニューの「使い方」と説明カードの 2 本）— 一部だけ覚える形にすると、覚えた値が使われないまま残り、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ。**位置へ戻すのは解説ページのヘッダの「←」だけ**で、本文の「編成シミュレーターを開く」（`guides/**` の `.guide-cta`、2 ページで計 4 本）からは先頭へ出す（2026-09-15 ユーザー指示）。そのため CTA は遷移の前に覚えた値を捨てる（各解説ページ末尾の小さな `<script>` が `sessionStorage` のキーを消す。覚えたまま残すと、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ — `src/seo.test.ts` で固定）。**復元はマウントの途中（最初の描画より前）に同期で当てる**（`App.vue` の `restoreScroll`）— `requestAnimationFrame` に入れていたときは中身が先頭に描かれたフレームが 1 枚見えてから飛んでいた（2026-09-14 ユーザー報告「使い方から戻る時画面がなんかチラついて戻る」。フレームごとに測ると `[高さ 844・scrollY 0] → [高さ 1795・scrollY 0] → [scrollY 900]` で、2 枚目が先頭の描画だった）。高さがまだ足りないときだけ届くまで数フレーム追いかける。
  - 折り畳み「**設定**」（歯車のアイコン）= **データの取り込み / データの出力 / オプションの保持 / ダークモード / 絶対おかゆんモード**（「オプションの保持」は 2026-09-16 追加のトグル。「データの出力」= 登録しているホロメンの 4 色ボードとコネクト・所持メンバーと開花・イベントメモリー・メンバー強化ボーナスを 1 つの JSON `holodori-optimizer/account` でコピーする `ExportSheet.vue`。取り込みと同じ枠 + 右上の「コピー」だけの画面で、JSON は読み取り専用の欄にして枠を本文いっぱいに広げ、枠の中だけをスクロールする — 2026-09-11）。
  - 折り畳み「**開発用**」（コードの括弧のアイコン。設定の下）= **GitHub / カラー確認 / 文言・配置 / 開花文言**（2026-09-13 にホロメンボードとペルソナ風UIの入口を削除。復活させない。「文言・配置」は 2026-09-14、「開花文言」は 2026-09-15 追加）。**「開花文言」のカードピッカーは実機確認を通したカード（`BLOOM_TEXT_VERIFIED_CARD_IDS`）を外して出す** — 残っているカードがそのまま「文言は入っているが本確認がまだ」の集合になる（2026-09-15 ユーザー指示「対応し終わったカードは非表示にして」）。
  - 「おまけ機能」というグループは 2026-09-14 に廃止した。作り直さない。
  - **モードの 2 つ（ダークモード・絶対おかゆんモード）は遷移ボタンではなく設定項目**にする（2026-09-14 ユーザー指示）。ラベルは状態で変えず（「ダークモード」「絶対おかゆんモード」で固定。2026-09-09 の「ラベルは切り替え先の名前」は撤回）、現在値は行の右端のトグルと `aria-checked` で示す。**行そのものを `role="switch"` のボタン 1 つにして、トグルは `aria-hidden` の見た目だけにする** — 行とトグルを別々の押せる要素にすると二重に発火しうるし、キーボード操作とフォーカスリングもボタン 1 つに任せたほうが素直。トグルの ON はほかのコントロールの選択状態と同じ `--selected` の地（`--selected-ink` のつまみ）にして、選択スタイルを全画面で 1 種類に保つ。**切り替えてもメニューは閉じない**（配色の変化はメニュー自身に出るのでその場で見比べられる）。おかゆモードで 2026-09-02 から入れていた「閉じてページ先頭へスクロール」も、メニューが開いたままでは意味がないので同時に撤回した。
  - **折り畳みは最初は畳み**、押すと右端の山形が回り、行の下に**一段（24px）インデントした項目（アイコン + 内容）**が開いて、**その位置より下の行が下へ動く**（下端に貼り付けない。メニューを閉じたら両方とも畳み直す。片方を開いてももう片方は閉じない。項目は 1 段小さい 15px / 600・48px、アイコンは親と同じ 24px — 2026-09-11「開くと一段下げてアイコンと内容が出る感じ」「折りたたみの中身はインデント一段入れること」「アイコンもちゃんとつけること」）。リストの最下部が安全領域ぶんの余白を持つ。
  - サイドメニューは常時表示領域（ヘッダ）に掛けず、開く瞬間のヘッダ下端から出す。**ヘッダがスクロールで画面の外に出ているあいだは、同じハンバーガーを右上に浮かせて出す**（`App.vue` の `.menu-float`。`IntersectionObserver` でヘッダの可視を見る。開いている間は ✕ として残り、メニューは画面の上端から出る — 2026-09-12 ユーザー指示「ヘッダ見えなくなったら出せないので、隠れたら右上に浮いてて欲しい」）。位置は**ヘッダのハンバーガー・各シートの ✕ と同じ 右 16px・上 16px**、出入りは 0.22 秒のフェード + わずかな沈み込み（`Transition name="float"`。`prefers-reduced-motion` では無効）。開閉の操作は同じ場所で形を変える（ハンバーガー ⇄ ✕、CSS トランジション）。閉じる手段は ✕・外側タップ・Escape の 3 つで、開けるのはメイン画面だけ（モーダルの右上は従来どおり閉じるボタン。2026-09-07、4 往復で確定）。サイドメニューの地は不透過で、背後は scrim で少し暗くする（透過+ぼかしは試して「やっぱ透過しないように」— 2026-09-07）。

- **検索から来た人向けの説明は、本線の一番下の 1 枚（`AboutSection.vue`）だけに置く**（2026-09-14 ユーザー指示）。入力の導線より上へは出さず、ファーストビューを押し下げない。中身（見出し・説明文・できること・解説ページへのリンク名）と位置の既定値は `src/ui/copyTuning.ts` にあり、開発用の「文言・配置」で実機のまま試せる。できることの箇条書きは**重要度順を優先し、同じくらいのものは画面の操作順**にする（試算値であることはフッタの免責に書いてあるので、ここへ重ねない）。検索用の隠しテキスト（`display:none`・画面外・透明文字）は使わない。
- **再読み込みで残すのはさがすの「オプション」だけで、枠の選択（リーダー・固定メンバー・曲）は毎回まっさらから始める**（2026-09-16 ユーザー指示「やっぱりリーダー、メンバー、曲はページ更新されても保持するのやめよう。探すオプションだけはデフォルト維持」。2026-09-14 に入れた枠の保存はここで撤回 — 復活させない）。オプション側（所持カードから探す / ボード・開花の反映 / ボードの色とコネクト / 役割別の除外）は既定で保存し、**サイドメニューの折り畳み「設定」の「データの出力」の下のトグル「オプションの保持」で OFF にできる**（`useKeepOptions`。ダークモードと同じ 1 行の `role="switch"`。OFF にした時点で保存済みのオプションのキーを消し、以後は書かない — 消すのはオプションだけで、所持カード・ボード・お気に入りのような登録データには触らない。仕組みは `storage-compat.md`）。
- お遊び機能の入口は本線のフローに混ぜず、説明文も付けない（おかゆモードは 2026-09-02 にフッター最下部の一番右のアイコン、2026-09-07 からサイドメニューの 1 行、2026-09-14 から折り畳み「設定」の中のトグル「絶対おかゆんモード」。URL パラメータは作らず、状態も保存しないので再読み込みで解除）。**表示の設定（ダークモード）は逆に保存する**（`holodori-optimizer:theme`、既定はライト。「更新しても記憶する」— 2026-09-09）。切り替えでメニューは閉じない（配色の変化はメニュー自身に出るのでその場で見比べられる）。
- 開発用の「開花文言」（`BloomTextSheet.vue`。サイドメニューの折り畳み「開発用」の文言・配置の下）は、**カードごとに開花段階ごとのスキル文言を実機を見ながら入れ直す**ための入力フォーム（2026-09-15 ユーザー指示「カードごとに開花ごとの文言を更新するための入力フォームが欲しい。その上でそれを構造化してペーストする部分もほしい。不必要な文章はいらない。複数のホロメンを連続して入れられるように工夫して。また既にDBに入っているやつをデフォルトで入力しておくこと。間違ってる場合もあるので上書きできるようにしておくこと」）。ほかの 2 つと違い**実画面の上に固定せず全画面のシート**にする — 直した結果を実画面で見る道具ではなく、量のある入力をする道具だから。中身は 3 つだけで説明文は置かない: 「カードを選ぶ」（`CardPicker`）→ 開いたカードの切り替えチップ → スキル 4 種（並びは 衣装 → スペシャル → アクティブ → パッシブ — 2026-09-15 ユーザー指示）× **文言が変わらない区間**の欄 →（末尾に）共有用データ + コピーボタン。**欄は開花段階ごとに出さない** — どのスキルがどの段階で強くなるかは決まっているので（`BLOOM_UPGRADE_STAGE`。衣装は変わらない / アクティブ 1凸 / SP 3凸 / パッシブ 4凸）、区間ごとに 1 つだけ出す（衣装 1・ほか各 2 の計 7 欄。「開花でどのスキルが強くなるかは決まってるので、こんなにフォームいらないはずでは」— 2026-09-15、24 欄から直した）。**欄の既定値はいまのカードデータから出した文言**（`cardAtBloomWithProvenance` の raw を区間の先頭の段階で引く）で、区間ごとに出所の印（実機 / master / 推定 など）を添える。開いているカードの見出しは**ホロメン名が主で、カード名は下に小さく添える**（一覧・結果詳細と同じ隣接の形。1 行に連結しない — 2026-09-15）。**上書きは既定値と違う文字列だけを持ち**、既定値に戻すと上書きも消える（共有用データの `edited` を信用できるようにするため）。複数のホロメンを続けて入れられるよう、開いたカードはチップで行き来でき、共有用データ（`kind: "holodori-optimizer/bloom-text"`）には開いた順に全部入る — 直していないカードも「この内容で合っている」の記録として出す。入力は localStorage（`holodori-optimizer:bloom-text`）にだけ残り、**カードデータ（`src/data/cards.json`）は書き換えない** — データへの反映は根拠を確かめてからコミットで行う（`docs/human/evidence-policy.md`）。**ピッカーに出すのは対応がまだのカードだけ**（`bloomTextPickerPool`）: 実機確認を通したカード（`BLOOM_TEXT_VERIFIED_CARD_IDS`）に加えて、このフォームで開いて記録したカードも外す（2026-09-30 ユーザー指示「終わってるやつはカード一覧に出したくない」）。開いたカードは上のチップ行から行き来でき、「外す」で記録を捨てるとピッカーへ戻る。未入力のカードが残っていないときは「カードを選ぶ」ボタンを無効にして「未入力のカードはありません」と出す。ピッカーには「すべて / 所持」の絞り込みが付く（実機で確かめられるのは持っているカードなので — 2026-09-30 ユーザー指示「所持カードかどうかのフィルタも追加で入れたい」。部品側の規則は `ui-parts.md`）。所持は登録済みの所持カードだけを指し、未所持側だけに絞る選択肢は置いていない。
- 管理用画面の「カラー確認」（`AdminPanel.vue`。サイドメニューの折り畳み「開発用」の GitHub の下）はヘッダ・フッタ・背景の色をモードごとに試すための操作バーで、**実画面の上に固定して出す**（scrim もスクロールロックも置かず背後を触れる）。上書きは `:root` のインライン変数 + localStorage（`holodori-optimizer:palette`）で、既定色（`src/style.css`）は書き換えない。**ID / PW 認証は置かない** — サーバなしの静的サイト（パブリックリポジトリ）では資格情報を隠せず、この画面が触るのも自分のブラウザの表示だけで守るものがない。入口を隠すなら URL のフラグメントで出す・ビルドを dev 限定にする、が現実的（どちらも未実施）。
- 開発用の「文言・配置」（`CopyTunePanel.vue`。サイドメニューの折り畳み「開発用」のカラー確認の下）は、画面の文言と説明セクションの位置を実機のまま差し替えて見るための操作パネルで、カラー確認と同じく**実画面の上に固定して出す**（scrim もスクロールロックも置かず背後を触れる。狭い画面では「たたむ」で見出しの帯だけにできる）。同時に出すと重なるので、どちらかを開いたらもう片方は閉じる（`App.vue`）。**既定値＝本番の文言は `src/ui/copyTuning.ts`** にあり、上書きは localStorage（`holodori-optimizer:copy-tuning`）にだけ残る — 決まった文言は既定値へ反映してコミットする。パネルの一番下に**調整結果を渡すための構造化データ**（`kind: "holodori-optimizer/ui-copy"`、読み取り専用の欄 + コピーボタン）を出す。入るのは編集した文言・位置・自由記述のメモと、見ていた画面の条件（表示領域とモード）だけで、所持カードや保存内容は入れない（2026-09-14 ユーザー指示「実機で確認したいのと調整したいので、文言や配置をいじれる開発用サブメニューを追加して。さらにその結果をあなたに共有するための構造化データを共有するコピーフォームも」）。
- アカウント情報の取り込み（スクショ → ローカル LLM → 構造化データ）の入口は**サイドメニューの折り畳み「設定」の一番上の 1 行**「データの取り込み」で（2026-09-14 までは折り畳みなしのトップレベル）、種別（所持メンバー・将来のボード等）ごとに入口を増やさない — 貼られた JSON の `kind` で何を取り込むか決める（2026-09-10 ユーザー決定。案 A = サイドメニュー / 案 B = 各ピッカーの中 / 案 C = Step 0 の 4 つめのボタン から選択）。
- 詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01）。
- さがすステップのオプションは「オプション ▼」の 1 行で既定は畳む（2026-09-06 に「今は少ないし全部見せておこう」で常時表示にしたが、2026-09-08 に旧 Step 1「さがす対象」を統合して 5 件になった時点で「デフォルトたたむ」に戻した）。中身は**1 行 + 枠 2 つ + 1 行**（2026-09-30 に組み替え）: 所持カードから探す（1 行全幅のチップ。グルーピングしない）、リーダー・メンバーの絞り込みの枠（上の行 = 除外 / 選択のセグメント・下の行 = 左「リーダー n枚」・右「メンバー n枚」）、ボードの反映の枠（上の行 = ボード状況を考慮する・下の行 = 左コネクト・右に 赤・青・黄・緑）、開花状況を考慮する。
- **まとまりのある設定は 1 つの枠で囲み、主の設定を上の行・ぶら下がりを下の行の左右半分ずつに置く**（`.option-group`。地を一段落とした角丸の枠 + ぶら下がりのチップは**文字だけ**一回り小さく。**枠の中に区切り線（セパレータ）は引かない** — 2026-09-30 ユーザー指示「グループ内のセパレータは不要」）。**枠どうしは同じ高さにそろえる**（上下とも 32px の行で、枠の高さは 84px。2026-09-16「所持カードから探すグループの高さ下のグループの高さよりでかいので統一して」— ぶら下がりの高さを縮めて背を変えない）。2026-09-16 ユーザー指示「赤青とかのボタンがボード状況を考慮するのサブボタンであることがわかるようなUIにすること」。2026-09-30 ユーザー指示で、左に主・右にぶら下がりだった形を、主を上・ぶら下がりを下（ボードはコネクトが左半分・4 色が右半分）へ組み替え、「所持カードから探す」はグルーピングをやめて 1 行全幅にした。**親が OFF のあいだ、ぶら下がりは白 + disabled**（親を OFF にしたのと同じ結果になる設定を、効いているように見せない）。
- 絞り込み系オプションの既定は保守的な OFF ではなく実用上おすすめの状態にする — 既定のまま実行すれば一番よい結果が出る（育成の反映は全部 ON が既定）。**候補を減らすだけのしぼりこみ（衣装スキル発動に限る / パッシブ全員発動に限る）は 2026-09-16 に撤去した** — 常に全探索して不発の編成も並べ、発動しているかどうかは結果側で見せる（ユーザー指示「衣装スキル発動とパッシブのボタンは削除する。内部的にはそれらを考慮せず全探索する」。プールが小さいと条件 1 つで 0 件になる事故もこれで無くなった）。**復活させない。** **ただし登録がないと必ず 0 件になる設定は、定数ではなく登録状態から既定を決める**（「所持カードから探す」の既定は所持カードの枚数から — 初めて来た人は 0 枚で必ず 0 件になる。仕組みと保存の扱いは `storage-compat.md`。2026-09-14）。
- 機能は「ゲーム内で何を最大化したいか」から決め、順位に影響の薄い要素（課題曲のイベントスコアボーナス +10% は一律の倍率で対象カードの有無以外で順位が変わらない）は UI に出さない（「イベントスコアボーナスはあんまいらんかも」— 2026-09-08）。
- モード全体に効くグローバルな詳細設定を増やさない — 既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダル内で設定する（2026-09-01 一律開花セグメントの却下）。
- 探索には「いま組める最強」と「将来に向けて育てる目標」の 2 つの用途がある — 全カードは将来向けなので現在の育成状態（開花・ボード）を混ぜず、持っているカードでは「ボード状況を考慮する / 開花状況を考慮する」をさがすステップのオプションで選べる（既定は両方 ON。2026-09-06 ユーザー判断）。育成状態を考慮しないときは素の値（0凸・ボードなし）ではなくマックスの状態（開花最大・4 色ボード全解放）として試算する — 育てきった前提で比べたい（2026-09-08 ユーザー指示）。**全カードから探すあいだは、その 2 つのオプションの ON / OFF に関わらず必ず最大の状態で試算する**（`useBloom` / `useBoard` が `!searchAll` を含む。チップも disabled）。**コネクトは最大の状態にしない** — ボード状況を考慮するかどうかに関わらず、**登録している（ボードで置いた）コネクトマスで常に計算する**（次の項目）。メモリー・メンバー強化ボーナスはモードによらず登録値をそのまま使う。
- **ボードの反映は色ごとに外せる**（赤・青・黄・緑。2026-09-16 ユーザー指示「緑全開放ってめっちゃ大変なので、ボード状況を考慮するのサブオプションで赤、青、黄、緑を個別につけ外ししたい」）。外した色はそこだけ**全解放**として試算する（親を OFF にしたときと同じ扱いで、0 にはしない）。**コネクトのチップは 2026-10-02 に撤去した**（ユーザー指示「探すオプションからコネクトを削除しよう。コネクトはボード状況を考慮するモードならボードのコネクトで探し、それがオフでも関係なく今のコネクトマスで常に計算する」）。ボードを全解放として試算するときも、登録したコネクトの範囲が全解放のマスに掛かる。同日に入れた「OFF なら最適な形と倍率で試算する」（探索のあとに配置を選び直す近似）と、その前の「OFF なら増幅なし」は、どちらもこれで置き換えた — 復活させない。保存済みの旧項目 `connect` は読み飛ばす（`storage-compat.md`）。**4 色を全部 OFF にはできない**（最後の 1 色のボタンは disabled。親 OFF と同じ状態への道を 2 つ作らない）。効いている色を disabled にするときは減光しない — 「緑だけ反映」は実際によく使う状態なので、薄い緑だと効いていないように見える。

## ステップと操作の構成

- ステップは意味単位で切る — 同じ意味に属する設定を別ステップに分けない（探索プールを狭める操作は、さがすステップのオプションにまとめる）。同じ操作を役割で分けるときは、1 つの入口の中に状態を重ねる（除外したタイル上で役割ピルを切り替える案）より、目的別の入口を名前で分ける平たい構造にする（2026-09-08「リーダーから除外、メンバーから除外の二つのタイルを用意しよう」）。
- **リーダー・メンバーの絞り込み（2026-09-30 ユーザー指示）**: 「除外 / 選択」のセグメント（既定は除外）の下に「リーダー n枚」「メンバー n枚」の 2 ボタンを並べ、それぞれのピッカーを開く。除外は選んだカードを候補から外し、**選択は選んだカードの中だけからおまかせで探す**（選ぶピッカーは「リーダー候補」「メンバー候補」の複数選択）。リストは種類ごとに別々に持ち、効くのは現在の種類のほうだけ。選択が 0 枚（所持外・未知のカードだけも同じ）のときは絞らず、件数の欄は「すべて」と出す（0 件になる設定を作らない）。エンジンは役割別の除外しか持たないので、選択は補集合として渡す（`src/ui/poolRestriction.ts`）。
- **枠での指定は除外・選択より優先する**（2026-09-30 ユーザー指示「選べないのは意味不明」「除外のカードも選べて良い」）。自分で指定したリーダー・固定したメンバーにエンジンは除外を適用しない。リーダーピッカー・メンバーピッカーでは、選択の外のカードも除外中のカードも選べる。ホロメンで指定したリーダー・おかゆモードのおかゆんのカードは、除外・選択のどちらでも候補に残す。**除外のピッカーでも、指定中のリーダー・固定中のメンバーを除外にも解除にもできる**（指定してから除外を外せなくなる不具合の報告）。おかゆモードのおかゆんだけは新たに除外できない（すでに入っているものは外せる）。
- **コネクトの最適化**（2026-10-02 ユーザー指示。結果詳細・ユニット詳細の下端の 1 行 3 つのうち**中央**。左はボードの最適化、右は頻度の最適化 — `ui-parts.md`）: アカウントの「コネクト」に登録した**持っているコネクト（形 × ％ × 枚数）の範囲で、いま置いている配置から、その編成のユニットスコアが上がる変更だけ**を出す（`ConnectPlanSheet.vue` / `src/engine/connectOptimize.ts`）。**変更量を最小にするのが方針**（ユーザー指示「変更量を最小にしたい」）: 置いても置かなくても結果が変わらない場所は、いま置いているものをそのまま残す（外さない・置き換えない）。出発点が現在の配置なので推奨は現在を下回らない。基準は発動頻度の最適化と同じく**いま登録している状態**（ボード 4 色・開花・アカウント補正。探索のオプションの「考慮する / しない」に関わらない）と、シートの曲（下記）。**シートの一番上に「曲」の見出しつきの曲の行**を置き（発動頻度の最適化と同じ `SongRow` / `SongPicker`。開いた直後の曲はメイン画面の曲（さがした曲）で、ここで選び直す・解除できる。**選び直した曲は閉じても覚え、発動頻度の最適化と共有する**（`OptimizerPanel` の `planSongChoice`。開き直すたびにメイン画面の曲へ戻っていた — 2026-10-03 ユーザー報告）。メイン画面で曲を変えたら覚えた曲は捨ててメイン画面の曲に従う。保存はしない。メイン画面の曲そのものは変えない — 2026-10-03 ユーザー指示）、曲を変えると結果は(曲, 範囲)ごとに計算し直す。1 枚は 1 か所のコネクトマスにだけ置ける。
  - **開く前の確認**: ボードに置いているコネクトが所持の登録に収まっていない（所持にない形・％、または持っている枚数を超えて置いている）ときは、シートを開かず中央のダイアログ（`NoticeDialog.vue`）に「所持しているコネクトにないものがボードに置かれています。所持コネクトを正しく登録してください。」を出す（`placementShortage`）。所持の登録もボードに置いたものもないときだけ、下端のボタンを disabled にする（置いたものがあれば押せて、エラーで所持の登録を促す）。
  - **一番上のトグル 2 つ**（左右半分ずつ。既定は左）: 「**ユニットのみ変更**」= リーダーとメンバーの置き方だけを変える（ユニット外が使っているコネクトが必要で枚数が足りないときだけ、ユニット外から外す変更を含む）/「**全て変更**」= 全ホロメンを変えてよい（緑・黄はアカウント全体に効く）。選んだ範囲ごとに 1 回だけ計算して覚える（切り替えは 2 回目から即時）。
  - **スクロールするのは表から下だけ**（2026-10-02 ユーザー指示「ユニットスコアのところまでは固定。表からできるように」「表のヘッダも脚注が出てくるまでは固定」）: ヘッダの下の**トグルと現在 / 推奨のユニットスコアは固定**（`.fixed-top`。計算中もスコア欄の枠は同じ高さで残し、`--summary-h` が脚注の `min-height` の計算にも入る）、表の列見出し（ホロメン / 現在 / 推奨）は `position: sticky` で表が終わって脚注が現れるまでスクロールの上端に留まる。
  - トグルの下に**現在 / 推奨のユニットスコア**（伸びの % は出さない — ユーザー指示）、その下に **ホロメン / 現在 / 推奨** の表（違う置き場所だけ。形の図 + ％。どのコネクトマスかは名前の下に小さく）。**並びは リーダー → メンバー（その結果のメンバーの順）→ それ以外のホロメン（五十音順）、同じホロメンの中は 中心 → 赤 → 青 → 黄**。「それ以外」は、ユニットのみ変更では「ユニットが必要とするため外す必要のあるホロメン」、全て変更では「置き方が変わるそれ以外のホロメン」。**「なし」は、外す（回す）か、新しく置く場所を示す** — 所持にないものを欲しがる推奨ではない。
  - **下端の固定エリアに緑（`--action`）の「ホロメンボードに反映」を 1 つ置く（ラベルはユーザー指示）**（2026-10-02 ユーザー指示「ホロメンボードに反映ボタン(緑)を画面の一番下に固定して。押したときには確認モーダルを出すこと」）。押すと `ConfirmDialog`（「推奨の配置をホロメンボードに反映しますか？」/「反映する」）を挟み、OK で**確認した時点の推奨**（その時選んでいた範囲の結果）を全ホロメンの `connect-placements` と置き換えて（`replaceConnectPlacements`。推奨に含まれない配置は外れる）シートを閉じる。推奨が現在と変わらないとき・計算中は disabled（隠さない）。確認ダイアログはシートのオーバーレイの子として出す（ダイアログ自身の `z-index` がシート 12 の上に載る）。固定エリアは結果詳細・発動頻度の最適化と同じ寸法（65px・ボタン 48px・15px/700）で、脚注の初期非表示の `min-height` もこの高さ（174px）で計算する。計算は Web Worker（`connectWorker.ts`）で、終わるまではシートの中で回転表示を出す。置き方の選び方は近似（遅延評価の貪欲法）で、脚注にそう書く。
  - **ホロメンボードの最適化**（2026-10-04 ユーザー指示。下端の固定エリアに**1 行 3 つ**で並べる（左から「ボードの最適化」「コネクトの最適化」「頻度の最適化」。文字は `clamp(10px, 3.1vw, 13px)` で幅に合わせて縮め、360px でも「コネクトの最適化」が収まる — 2026-10-04 ユーザー指示）。3 つを 1 段に並べると 1 つ 114px で文字が収まらないので 2 段にした — `UnitActionFoot.vue`）: **この編成のまま**、ホロメンごとのボードPt の予算（ホロメンランク。未登録は制限なし）の範囲で、表示ユニットスコアが高くなる解放マスを選ぶ（`BoardPlanSheet.vue`。目的関数・守る制約・近似は `boardOptimize.ts` と ADR-012）。シートの形はコネクトの最適化と同じ（曲 → 「ユニットのみ変更 / 全て変更」→ 現在 / 推奨のユニットスコア → 表 → 緑の「ホロメンボードに反映」。反映は確認を挟み、解放マスとコネクトの解放を置き換える。**コネクトの配置は変わらない**）。表は変更のあるホロメンだけで、**列は「ホロメン」と「推奨」の 2 つだけ**（現在の列・Pt・Rank・予算・増減の数字は出さない）。**各行の推奨の欄に「ボードを開く」ボタンを置き**（名前の横の矢印は置かない — 2026-10-04 ユーザー指示）、押すとそのホロメンの推奨のボードを図で開く（`BoardSheet` の見るだけの表示 `preview`。**追加するマスはそのマスの色が点滅、解除するマスは丸の右上から左下への斜線(斜線も点滅)**。注釈・凡例は出さない。タップは説明だけ。承認するかをこの図で決める）。**3 つの最適化（ボード・コネクト・発動頻度）の結果は、結果詳細・お気に入りのユニット詳細に戻るまでキャッシュして再計算しない**（`usePlanCache.ts`。キーは編成・開花・曲・範囲 / 固定した頻度。両方の詳細を閉じたとき、と結果を反映したときに捨てる — 2026-10-04 ユーザー指示）。必須のコネクトがランクの予算に収まらず変更できなかったホロメンは警告文で出す。反映は「スコアが上がるとき」でなく**変更があるとき**に押せる（予算超過を直す場合があるため）。
  - **「検索画面に入力」は同日にボタンを外した**（ロジック — `load` のイベントと `loadIntoSearch` — は残してある）。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする（2026-09-01 タブ統合）。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない（選択肢がなくなったら畳む）。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない（2026-09-01。モーダル内全グレーアウト実装を訂正された）。ただし**開いた先に「何が空いているか」の情報があるなら開けてよい** — Step 0 の「ユニット」は登録 0 件でも押せ、1〜10 の番号が「未登録」で並ぶ（2026-09-09「ユニット登録してなくてもボタン押せるように」で disabled を撤回）。前提が満たされず操作を止めるときも、赤いエラーメッセージでなく「方針」をボタンのラベルで示す（例: おかゆモードでリーダー・メンバー・実行を disabled — 2026-09-02）。例外: Step 0 の 3 ボタンはラベルを変えると 3 列に収まらないので、おかゆモードで未登録のときだけボタンの下に 1 行「おかゆんを持っているカードに指定してください」を出し、出ていないときは余白も取らない（2026-09-06 ユーザー指示「これは例外的処理」）。ある条件で効かなくなる設定は、その条件のあいだ disabled にして効いていないことを示すが、見た目は 2 通りに使い分ける: 一時的に効かないだけの設定は保持している設定値の見た目（選択中の濃色地）を変えず減光だけにする（白地化は「設定保持のままでいい」で却下 — 2026-09-05。例に使っていた「6 枠すべて固定のときの発動条件チップ」は 2026-09-16 にチップごと撤去した）。そのモードでは意味を持たない設定（全カードでの「ボード状況を考慮する / 開花状況を考慮する」）は未選択（白）+disabled に見せる（「選択が外れた状態で disabled にしろ」— 2026-09-06）。どちらも保存値は保持し、条件が外れれば保存した状態で復帰する。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置（ページ先頭）へ視点を移す（2026-09-02）。ただし**サイドメニューの中のトグル（ダークモード・絶対おかゆんモード）は例外**で、メニューを開いたまま切り替えるので閉じもスクロールもしない（2026-09-14 ユーザー指示。配色の変化はメニュー自身に出る）。
- 同種の連続スロット（メンバー枠等）は順序に意味がない入力なので、飛び石の自由度を与えない: 追加は常に先頭の空き枠へ入れ、解除時は上へ詰める（2026-09-01）。枠自体はどれもピッカーの入口として押せてよい（2026-09-10 に「先頭の空き枠だけ押せる」から変更 — 固定は 1 枚ずつでなく複数選択ピッカーで入れる形になったため）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色/白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする（2026-09-01）。数値を入力する設定（Step 0 の「イベントメモリー」「メンバー強化ボーナス」）は**同じパネルのボタンと同じ器**にし、ボタンの中でラベルを左端・値（%）を右端に寄せる（2026-09-10 ユーザー指示。押すと自前のテンキー `NumberPad` が開く — `ui-parts.md`）。**ラベルと値が重なるなら 1 行に押し込まず 1 行 1 つの縦積みにし、名前も略さない**（左半分・右半分に 2 つ置く形から変更 — 同日「オーバーラップするならボタンは無理に 1 行にせず 2 行にする。そのときはイベントメモリー、メンバー強化ボーナスという文にする」）。1 項目 1 行の設定行 + 数値欄だった形（2026-09-08。2 列横並びの小さなラベル + 数値欄は「ださい」）を置き換えたもので、ラベルの文字サイズをパネルのボタン内と揃える点は変わらない（小さく淡くしない）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す（2026-09-01）。選択コントロールを実行ボタンに隣接させるときは形・高さ・幅・色で役割を分ける — 選択は内容幅・32px のピル形チップ（ピッカーの所属チップと同形）で濃色地（`--ink`）、アクションは全幅・48px の角丸矩形で実行専用の緑（`--action`。おかゆモードは紫のまま）（2026-09-05 しぼりこみチップで形を分け、2026-09-06「色が同じで分かりにくいから緑っぽい色に」で色も分けた）。
- 数秒で終わる処理の進行は、押した実行ボタンの中だけで示す — ラベルを白い細線のリング（22px・2.5px、`.spinner`）に置き換え、ボタンの寸法・色は保つ。進捗バー・評価件数のテキスト・中止ボタンは置かない（「バーの近くの文字は不要。ステータスバーも中止も不要。ボタンにスピナー」— 2026-09-07）。**再実行のあいだは前回の結果を消さず、薄く（opacity 0.5・触れない・`aria-busy`）残して結果が届いたら置き換える** — 候補を null にして結果セクションをアンマウントすると、下のフッタが繰り上がって「結果のところがチラつく。後ろに脚注が一瞬見えてしまう」（2026-09-11）。非同期の更新で領域を空にしてレイアウトを動かさない。結果の描画に使うスナップショット（開花・ボード・リーダー指定など）も開始時でなく結果が届いたときに差し替える（前回の候補を今回の設定で描かない）。
- 並ぶ選択肢は指定された順を保ったまま 2 列 × n 行の等幅グリッドに収める（縦 1 列は「2 行に収められない？」で却下 — 2026-09-06）。ラベルが収まらなければ文言を短くし、文字サイズを落とすのはそのグリッド内だけにとどめる（375px 幅でも収まることを実測する）。性質の違う要素（ON/OFF のチップと、ピッカーを開くボタン）を同じグリッドに並べるときは 1 行を全幅にせず左右に置き、形で区別する（チップはピル、ボタンは角丸矩形。高さ 32px と文字はチップに揃え、ラベル左・件数右で件数はボタンの中に入れる）。枠（`.option-group`）の中は、上の行に主の 1 つ（セグメントまたはチップ）、下の行に左右半分ずつの 2 つを置く（さがすのオプション: 除外 / 選択 と リーダー・メンバー、ボード状況 と コネクト・4 色）。
- アカウントの状態（持っているカードと開花段階・ホロメンボード・お気に入りユニット）は Step 0「アカウント」にまとめ、そこでだけ変更する（お気に入りユニットの**登録・解除は結果側の星**から行い、登録ぶんを見る入口はサイドメニューの「お気に入り」— 2026-09-09 に Step 0 の「ユニット」として置き、2026-09-11 に「ユニットはお気に入りとリネームしてサイドバーに移す」でメニューへ）。Step 0 の入口は横並びの 3 ボタン「ボード / カード / コネクト」（2026-10-02 ユーザー指示「ボード、カード、コネクトという文言にすればおさまる」。それまでは「ホロメンボード / 所持カード」の 2 つで、2026-09-11 に「ホロメン / メンバー」から改名した。3 つめの**コネクト**は、自分が持っているコネクトの **形 × ％ × 枚数** を登録する画面（`ConnectInventorySheet.vue`。**コネクトの最適化だけが使い**、ボードの上で置いているコネクトとは別管理）。形の名前の文字（「右へ 3」など）は画面に出さず、図形で示す）で件数は出さない（ヘッダの件数削除と同種 2 回目 — 2026-09-06「枚数表示とかいらん」）。探索の条件（枠・曲・オプション）と混ぜない。**「お気に入り」で見せる値は、ゲームのユニット編成画面と同じ入力（曲なし・登録している開花と 4 色ボード・コネクト・アカウント補正そのもの）で出し、メイン画面の曲も「さがす」のオプション（所持カードから探す / ボード状況・開花状況を考慮する）も渡さない** — 曲を変えるたびに登録ユニットのユニットスコアが変わるのは「気持ち悪い」（2026-09-11）、オプションで変わるのも「きもい。実ゲームのユニットと同じように自分のボードやカード状況を加味された値であるべき。オプションとは独立に」（2026-09-12。曲の反映 — 黄のボード欄・赤の歌唱者条件・イベント — は「さがす」の結果側だけ）。登録している開花・ボードを変えれば反映される（`registeredBlooms` / `boardMap` / `greenMap` / `yellowMap` / `redMap` / `connectMap` を直接渡す。`current*` はオプション OFF や全カードで最大状態に切り替わる探索専用の値）。ゲーム内の画面に対応する表示は、その画面と同じ入力だけで出す。ホロメンボードはカードでなくホロメンに属するので入口もホロメン一覧から（カードタイル上の入口は却下 — 2026-09-06）。**お気に入りに登録できるのは所持カードで組んだ編成だけ**（リーダー + メンバー 5 の 6 枚すべてが所持リストにあること。開花段階は問わない — 2026-09-16 ユーザー指示「自分の所持カードしかお気に入りにできない仕様にしたい」）。全カードから探した結果は登録できない（入口の見せ方は `ui-parts.md`）。**効かせるのは登録の時点だけ**で、登録済みのユニットはあとで所持から外れても消さず・隠さず、お気に入り画面に出して自分で外せるようにする（`storage-compat.md`）。
