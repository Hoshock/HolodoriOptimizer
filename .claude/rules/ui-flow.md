# 本線フローと入口の構成（UI 規則）

UI の規則は 2026-09-09 の棚卸し 24 回目で 4 ファイルに分けた（触るファイルに応じて読み込まれる）: `ui-design.md` = 全画面に効く原則 / `ui-flow.md` = 本線フローと入口の構成（`OptimizerPanel` / `App` / サイドメニュー）/ `ui-parts.md` = 一覧・ピッカー・詳細シート・結果表示の部品 / `ui-boards.md` = ホロメンボードの描画と操作。実機での確認手順は `ui-verification.md`。分けた先に規則が見つからないときは 4 ファイルを横断して探す。

## 方針

- 本線の外の入口（取り込み・一覧・遊び機能・外部リンク・管理用・モード切替）はヘッダ右上のハンバーガー → 右のサイドメニューに集約する: **1 本のリストにし、セパレータは置かない。折り畳みの行でグループを作る**（2026-09-11 ユーザー指定「境目の感覚が一定じゃない。セパレータをやめて折り畳みをグループごとに作ろう」）。**並びは 2026-09-14 のユーザー指示で組み替えた**（それ以前の「1 つめ = お気に入り / カード一覧 / 曲一覧 / データの取り込み / データの出力 / ダークモード、2 つめ = 折り畳み『おまけ機能』= 仮想ガチャ / 絶対おかゆんモード、3 つめ = 折り畳み『開発用』」を置き換える）:
  - トップレベル（折り畳みなし）= **使い方 / お気に入り / カード一覧 / 曲一覧 / 仮想ガチャ**（「使い方」は一番上で、行き先はアプリの外の解説ページ `guides/simulator/` — 通常のリンクで遷移する。2026-09-14 追加。「お気に入り」= 登録ユニットの詳細シート `UnitSheet.vue`。2026-09-11 に Step 0 の「ユニット」から移して改名。「仮想ガチャ」は 2026-09-14 に折り畳みの中からここへ移しただけで、機能と状態管理は変えていない）。**解説ページへ出ていくときは、そのときの縦位置を覚えて戻ってきたら復元する**（`src/storage/returnScroll.ts` に置き、`src/ui/guideReturn.ts` の `rememberGuideReturn()` が入口。通常のリンクでの遷移なのでブラウザのスクロール復元は効かない。メニューを開いている間はスクロールロック中で `window.scrollY` が 0 なので、`currentScrollY()`（`useModalChrome`）が返すロック前の位置を使う — 2026-09-14 ユーザー指示「ヘッダで戻った時、前のページの位置は記憶しておいてそこに戻ろう」）。**解説ページへ行くリンクは全部 `rememberGuideReturn` を通す**（サイドメニューの「使い方」と説明カードの 2 本）— 一部だけ覚える形にすると、覚えた値が使われないまま残り、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ。**位置へ戻すのは解説ページのヘッダの「←」だけ**で、本文の「編成シミュレーターを開く」（`guides/**` の `.guide-cta`、2 ページで計 4 本）からは先頭へ出す（2026-09-15 ユーザー指示）。そのため CTA は遷移の前に覚えた値を捨てる（各解説ページ末尾の小さな `<script>` が `sessionStorage` のキーを消す。覚えたまま残すと、あとの関係ない読み込みで消費されて思わぬ位置へ飛ぶ — `src/seo.test.ts` で固定）。**復元はマウントの途中（最初の描画より前）に同期で当てる**（`App.vue` の `restoreScroll`）— `requestAnimationFrame` に入れていたときは中身が先頭に描かれたフレームが 1 枚見えてから飛んでいた（2026-09-14 ユーザー報告「使い方から戻る時画面がなんかチラついて戻る」。フレームごとに測ると `[高さ 844・scrollY 0] → [高さ 1795・scrollY 0] → [scrollY 900]` で、2 枚目が先頭の描画だった）。高さがまだ足りないときだけ届くまで数フレーム追いかける。
  - 折り畳み「**設定**」（歯車のアイコン）= **データの取り込み / データの出力 / ダークモード / 絶対おかゆんモード**（「データの出力」= 登録しているホロメンの 4 色ボードとコネクト・所持メンバーと開花・イベントメモリー・メンバー強化ボーナスを 1 つの JSON `holodori-optimizer/account` でコピーする `ExportSheet.vue`。取り込みと同じ枠 + 右上の「コピー」だけの画面で、JSON は読み取り専用の欄にして枠を本文いっぱいに広げ、枠の中だけをスクロールする — 2026-09-11）。
  - 折り畳み「**開発用**」（コードの括弧のアイコン。設定の下）= **GitHub / カラー確認 / 文言・配置 / 開花文言**（2026-09-13 にホロメンボードとペルソナ風UIの入口を削除。復活させない。「文言・配置」は 2026-09-14、「開花文言」は 2026-09-15 追加）。**「開花文言」のカードピッカーは実機確認を通したカード（`BLOOM_TEXT_VERIFIED_CARD_IDS`）を外して出す** — 残っているカードがそのまま「文言は入っているが本確認がまだ」の集合になる（2026-09-15 ユーザー指示「対応し終わったカードは非表示にして」）。
  - 「おまけ機能」というグループは 2026-09-14 に廃止した。作り直さない。
  - **モードの 2 つ（ダークモード・絶対おかゆんモード）は遷移ボタンではなく設定項目**にする（2026-09-14 ユーザー指示）。ラベルは状態で変えず（「ダークモード」「絶対おかゆんモード」で固定。2026-09-09 の「ラベルは切り替え先の名前」は撤回）、現在値は行の右端のトグルと `aria-checked` で示す。**行そのものを `role="switch"` のボタン 1 つにして、トグルは `aria-hidden` の見た目だけにする** — 行とトグルを別々の押せる要素にすると二重に発火しうるし、キーボード操作とフォーカスリングもボタン 1 つに任せたほうが素直。トグルの ON はほかのコントロールの選択状態と同じ `--selected` の地（`--selected-ink` のつまみ）にして、選択スタイルを全画面で 1 種類に保つ。**切り替えてもメニューは閉じない**（配色の変化はメニュー自身に出るのでその場で見比べられる）。おかゆモードで 2026-09-02 から入れていた「閉じてページ先頭へスクロール」も、メニューが開いたままでは意味がないので同時に撤回した。
  - **折り畳みは最初は畳み**、押すと右端の山形が回り、行の下に**一段（24px）インデントした項目（アイコン + 内容）**が開いて、**その位置より下の行が下へ動く**（下端に貼り付けない。メニューを閉じたら両方とも畳み直す。片方を開いてももう片方は閉じない。項目は 1 段小さい 15px / 600・48px、アイコンは親と同じ 24px — 2026-09-11「開くと一段下げてアイコンと内容が出る感じ」「折りたたみの中身はインデント一段入れること」「アイコンもちゃんとつけること」）。リストの最下部が安全領域ぶんの余白を持つ。
  - サイドメニューは常時表示領域（ヘッダ）に掛けず、開く瞬間のヘッダ下端から出す。**ヘッダがスクロールで画面の外に出ているあいだは、同じハンバーガーを右上に浮かせて出す**（`App.vue` の `.menu-float`。`IntersectionObserver` でヘッダの可視を見る。開いている間は ✕ として残り、メニューは画面の上端から出る — 2026-09-12 ユーザー指示「ヘッダ見えなくなったら出せないので、隠れたら右上に浮いてて欲しい」）。位置は**ヘッダのハンバーガー・各シートの ✕ と同じ 右 16px・上 16px**、出入りは 0.22 秒のフェード + わずかな沈み込み（`Transition name="float"`。`prefers-reduced-motion` では無効）。開閉の操作は同じ場所で形を変える（ハンバーガー ⇄ ✕、CSS トランジション）。閉じる手段は ✕・外側タップ・Escape の 3 つで、開けるのはメイン画面だけ（モーダルの右上は従来どおり閉じるボタン。2026-09-07、4 往復で確定）。サイドメニューの地は不透過で、背後は scrim で少し暗くする（透過+ぼかしは試して「やっぱ透過しないように」— 2026-09-07）。

- **検索から来た人向けの説明は、本線の一番下の 1 枚（`AboutSection.vue`）だけに置く**（2026-09-14 ユーザー指示）。入力の導線より上へは出さず、ファーストビューを押し下げない。中身（見出し・説明文・できること・解説ページへのリンク名）と位置の既定値は `src/ui/copyTuning.ts` にあり、開発用の「文言・配置」で実機のまま試せる。できることの箇条書きは**重要度順を優先し、同じくらいのものは画面の操作順**にする（試算値であることはフッタの免責に書いてあるので、ここへ重ねない）。検索用の隠しテキスト（`display:none`・画面外・透明文字）は使わない。
- お遊び機能の入口は本線のフローに混ぜず、説明文も付けない（おかゆモードは 2026-09-02 にフッター最下部の一番右のアイコン、2026-09-07 からサイドメニューの 1 行、2026-09-14 から折り畳み「設定」の中のトグル「絶対おかゆんモード」。URL パラメータは作らず、状態も保存しないので再読み込みで解除）。**表示の設定（ダークモード）は逆に保存する**（`holodori-optimizer:theme`、既定はライト。「更新しても記憶する」— 2026-09-09）。切り替えでメニューは閉じない（配色の変化はメニュー自身に出るのでその場で見比べられる）。
- 開発用の「開花文言」（`BloomTextSheet.vue`。サイドメニューの折り畳み「開発用」の文言・配置の下）は、**カードごとに開花段階ごとのスキル文言を実機を見ながら入れ直す**ための入力フォーム（2026-09-15 ユーザー指示「カードごとに開花ごとの文言を更新するための入力フォームが欲しい。その上でそれを構造化してペーストする部分もほしい。不必要な文章はいらない。複数のホロメンを連続して入れられるように工夫して。また既にDBに入っているやつをデフォルトで入力しておくこと。間違ってる場合もあるので上書きできるようにしておくこと」）。ほかの 2 つと違い**実画面の上に固定せず全画面のシート**にする — 直した結果を実画面で見る道具ではなく、量のある入力をする道具だから。中身は 3 つだけで説明文は置かない: 「カードを選ぶ」（`CardPicker`）→ 開いたカードの切り替えチップ → スキル 4 種（並びは 衣装 → スペシャル → アクティブ → パッシブ — 2026-09-15 ユーザー指示）× **文言が変わらない区間**の欄 →（末尾に）共有用データ + コピーボタン。**欄は開花段階ごとに出さない** — どのスキルがどの段階で強くなるかは決まっているので（`BLOOM_UPGRADE_STAGE`。衣装は変わらない / アクティブ 1凸 / SP 3凸 / パッシブ 4凸）、区間ごとに 1 つだけ出す（衣装 1・ほか各 2 の計 7 欄。「開花でどのスキルが強くなるかは決まってるので、こんなにフォームいらないはずでは」— 2026-09-15、24 欄から直した）。**欄の既定値はいまのカードデータから出した文言**（`cardAtBloomWithProvenance` の raw を区間の先頭の段階で引く）で、区間ごとに出所の印（実機 / master / 推定 など）を添える。開いているカードの見出しは**ホロメン名が主で、カード名は下に小さく添える**（一覧・結果詳細と同じ隣接の形。1 行に連結しない — 2026-09-15）。**上書きは既定値と違う文字列だけを持ち**、既定値に戻すと上書きも消える（共有用データの `edited` を信用できるようにするため）。複数のホロメンを続けて入れられるよう、開いたカードはチップで行き来でき、共有用データ（`kind: "holodori-optimizer/bloom-text"`）には開いた順に全部入る — 直していないカードも「この内容で合っている」の記録として出す。入力は localStorage（`holodori-optimizer:bloom-text`）にだけ残り、**カードデータ（`src/data/cards.json`）は書き換えない** — データへの反映は根拠を確かめてからコミットで行う（`docs/human/evidence-policy.md`）。
- 管理用画面の「カラー確認」（`AdminPanel.vue`。サイドメニューの折り畳み「開発用」の GitHub の下）はヘッダ・フッタ・背景の色をモードごとに試すための操作バーで、**実画面の上に固定して出す**（scrim もスクロールロックも置かず背後を触れる）。上書きは `:root` のインライン変数 + localStorage（`holodori-optimizer:palette`）で、既定色（`src/style.css`）は書き換えない。**ID / PW 認証は置かない** — サーバなしの静的サイト（パブリックリポジトリ）では資格情報を隠せず、この画面が触るのも自分のブラウザの表示だけで守るものがない。入口を隠すなら URL のフラグメントで出す・ビルドを dev 限定にする、が現実的（どちらも未実施）。
- 開発用の「文言・配置」（`CopyTunePanel.vue`。サイドメニューの折り畳み「開発用」のカラー確認の下）は、画面の文言と説明セクションの位置を実機のまま差し替えて見るための操作パネルで、カラー確認と同じく**実画面の上に固定して出す**（scrim もスクロールロックも置かず背後を触れる。狭い画面では「たたむ」で見出しの帯だけにできる）。同時に出すと重なるので、どちらかを開いたらもう片方は閉じる（`App.vue`）。**既定値＝本番の文言は `src/ui/copyTuning.ts`** にあり、上書きは localStorage（`holodori-optimizer:copy-tuning`）にだけ残る — 決まった文言は既定値へ反映してコミットする。パネルの一番下に**調整結果を渡すための構造化データ**（`kind: "holodori-optimizer/ui-copy"`、読み取り専用の欄 + コピーボタン）を出す。入るのは編集した文言・位置・自由記述のメモと、見ていた画面の条件（表示領域とモード）だけで、所持カードや保存内容は入れない（2026-09-14 ユーザー指示「実機で確認したいのと調整したいので、文言や配置をいじれる開発用サブメニューを追加して。さらにその結果をあなたに共有するための構造化データを共有するコピーフォームも」）。
- アカウント情報の取り込み（スクショ → ローカル LLM → 構造化データ）の入口は**サイドメニューの折り畳み「設定」の一番上の 1 行**「データの取り込み」で（2026-09-14 までは折り畳みなしのトップレベル）、種別（所持メンバー・将来のボード等）ごとに入口を増やさない — 貼られた JSON の `kind` で何を取り込むか決める（2026-09-10 ユーザー決定。案 A = サイドメニュー / 案 B = 各ピッカーの中 / 案 C = Step 0 の 4 つめのボタン から選択）。
- 詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01）。
- さがすステップのオプション（所持カードから探す / ボード / 開花 / 衣装 / パッシブの 5 チップ）は「オプション ▼」の 1 行で既定は畳む（2026-09-06 に「今は少ないし全部見せておこう」で常時表示にしたが、2026-09-08 に旧 Step 1「さがす対象」を統合して 5 件になった時点で「デフォルトたたむ」に戻した）。
- 絞り込み系オプションの既定は保守的な OFF ではなく実用上おすすめの状態にする — 既定のまま実行すれば一番よい結果が出る（スキル発動のしぼりこみは両方 ON が既定 — 2026-09-05）。**ただし登録がないと必ず 0 件になる設定は、定数ではなく登録状態から既定を決める**（「所持カードから探す」の既定は所持カードの枚数から — 初めて来た人は 0 枚で必ず 0 件になる。仕組みと保存の扱いは `storage-compat.md`。2026-09-14）。
- 機能は「ゲーム内で何を最大化したいか」から決め、順位に影響の薄い要素（課題曲のイベントスコアボーナス +10% は一律の倍率で対象カードの有無以外で順位が変わらない）は UI に出さない（「イベントスコアボーナスはあんまいらんかも」— 2026-09-08）。
- モード全体に効くグローバルな詳細設定を増やさない — 既定値固定でよいものは UI を置かず、カード個別の値はそのカードを扱うモーダル内で設定する（2026-09-01 一律開花セグメントの却下）。
- 探索には「いま組める最強」と「将来に向けて育てる目標」の 2 つの用途がある — 全カードは将来向けなので現在の育成状態（開花・ボード）を混ぜず、持っているカードでは「ボード状況を考慮する / 開花状況を考慮する」を Step 5 で選べる（既定は両方 ON。2026-09-06 ユーザー判断）。育成状態を考慮しないときは素の値（0凸・ボードなし）ではなくマックスの状態（開花最大・4 色ボード全解放）として試算する — 育てきった前提で比べたい（2026-09-08 ユーザー指示）。

## ステップと操作の構成

- ステップは意味単位で切る — 同じ意味に属する設定を別ステップに分けない（除外は探索プールを狭める操作なので「さがす対象」のセグメントの下に行ボタンとして置き、旧 Step 2 を統合 — 2026-09-06。2026-09-08 に「さがす対象」自体をさがすステップのオプション「所持カードから探す」へ移し、除外の入口は一度外したのち同日に戻して「リーダーから除外 n枚」「メンバーから除外 n枚」の 2 ボタンにした）。同じ操作を役割で分けるときは、1 つの入口の中に状態を重ねる（除外したタイル上で役割ピルを切り替える案）より、目的別の入口を名前で分ける平たい構造にする（「リーダーから除外、メンバーから除外の二つのタイルを用意しよう」— 2026-09-08）。
- モードの二者択一は画面全体のタブ複製でなく、1 フロー内の状態選択（セグメンテッドコントロール）にする（2026-09-01 タブ統合）。機能・状態の切替で操作ボタンの構成・位置を変えない — 使えない操作は隠さず disabled で示す。選択肢が 1 つしかない切替 UI は置かない（選択肢がなくなったら畳む）。
- 使えない操作の disabled は入口（ボタン）の段階で行い、開けるのに何もできないモーダルを作らない（2026-09-01。モーダル内全グレーアウト実装を訂正された）。ただし**開いた先に「何が空いているか」の情報があるなら開けてよい** — Step 0 の「ユニット」は登録 0 件でも押せ、1〜10 の番号が「未登録」で並ぶ（2026-09-09「ユニット登録してなくてもボタン押せるように」で disabled を撤回）。前提が満たされず操作を止めるときも、赤いエラーメッセージでなく「方針」をボタンのラベルで示す（例: おかゆモードでリーダー・メンバー・実行を disabled — 2026-09-02）。例外: Step 0 の 3 ボタンはラベルを変えると 3 列に収まらないので、おかゆモードで未登録のときだけボタンの下に 1 行「おかゆんを持っているカードに指定してください」を出し、出ていないときは余白も取らない（2026-09-06 ユーザー指示「これは例外的処理」）。ある条件で効かなくなる設定は、その条件のあいだ disabled にして効いていないことを示すが、見た目は 2 通りに使い分ける: 一時的に効かないだけの設定（6 枠すべて固定のときの発動条件チップ）は保持している設定値の見た目（選択中の濃色地）を変えず減光だけにする（白地化は「設定保持のままでいい」で却下 — 2026-09-05）。そのモードでは意味を持たない設定（全カードでの「ボード状況を考慮する / 開花状況を考慮する」）は未選択（白）+disabled に見せる（「選択が外れた状態で disabled にしろ」— 2026-09-06）。どちらも保存値は保持し、条件が外れれば保存した状態で復帰する。
- モード切替のように画面全体の状態が変わる操作の後は、変化が見える位置（ページ先頭）へ視点を移す（2026-09-02）。ただし**サイドメニューの中のトグル（ダークモード・絶対おかゆんモード）は例外**で、メニューを開いたまま切り替えるので閉じもスクロールもしない（2026-09-14 ユーザー指示。配色の変化はメニュー自身に出る）。
- 同種の連続スロット（メンバー枠等）は順序に意味がない入力なので、飛び石の自由度を与えない: 追加は常に先頭の空き枠へ入れ、解除時は上へ詰める（2026-09-01）。枠自体はどれもピッカーの入口として押せてよい（2026-09-10 に「先頭の空き枠だけ押せる」から変更 — 固定は 1 枚ずつでなく複数選択ピッカーで入れる形になったため）。
- パネル内の主要操作ボタンは secondary（白背景）も含めて全幅にする。primary との階層は背景色（濃色/白）で分ける。選択モーダルを開く行ボタンはラベル左・現在値（件数）右の設定行パターンにする（2026-09-01）。数値を入力する設定（Step 0 の「イベントメモリー」「メンバー強化ボーナス」）は**同じパネルのボタンと同じ器**にし、ボタンの中でラベルを左端・値（%）を右端に寄せる（2026-09-10 ユーザー指示。押すと自前のテンキー `NumberPad` が開く — `ui-parts.md`）。**ラベルと値が重なるなら 1 行に押し込まず 1 行 1 つの縦積みにし、名前も略さない**（左半分・右半分に 2 つ置く形から変更 — 同日「オーバーラップするならボタンは無理に 1 行にせず 2 行にする。そのときはイベントメモリー、メンバー強化ボーナスという文にする」）。1 項目 1 行の設定行 + 数値欄だった形（2026-09-08。2 列横並びの小さなラベル + 数値欄は「ださい」）を置き換えたもので、ラベルの文字サイズをパネルのボタン内と揃える点は変わらない（小さく淡くしない）。
- 押すと何かが起きる動作ボタンと、状態を切り替えるトグルを同じ見た目で並べない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す（2026-09-01）。選択コントロールを実行ボタンに隣接させるときは形・高さ・幅・色で役割を分ける — 選択は内容幅・32px のピル形チップ（ピッカーの所属チップと同形）で濃色地（`--ink`）、アクションは全幅・48px の角丸矩形で実行専用の緑（`--action`。おかゆモードは紫のまま）（2026-09-05 しぼりこみチップで形を分け、2026-09-06「色が同じで分かりにくいから緑っぽい色に」で色も分けた）。
- 数秒で終わる処理の進行は、押した実行ボタンの中だけで示す — ラベルを白い細線のリング（22px・2.5px、`.spinner`）に置き換え、ボタンの寸法・色は保つ。進捗バー・評価件数のテキスト・中止ボタンは置かない（「バーの近くの文字は不要。ステータスバーも中止も不要。ボタンにスピナー」— 2026-09-07）。**再実行のあいだは前回の結果を消さず、薄く（opacity 0.5・触れない・`aria-busy`）残して結果が届いたら置き換える** — 候補を null にして結果セクションをアンマウントすると、下のフッタが繰り上がって「結果のところがチラつく。後ろに脚注が一瞬見えてしまう」（2026-09-11）。非同期の更新で領域を空にしてレイアウトを動かさない。結果の描画に使うスナップショット（開花・ボード・リーダー指定など）も開始時でなく結果が届いたときに差し替える（前回の候補を今回の設定で描かない）。
- 並ぶ選択肢は指定された順を保ったまま 2 列 × n 行の等幅グリッドに収める（縦 1 列は「2 行に収められない？」で却下 — 2026-09-06）。ラベルが収まらなければ文言を短くし、文字サイズを落とすのはそのグリッド内だけにとどめる（375px 幅でも収まることを実測する）。性質の違う要素（ON/OFF のチップと、ピッカーを開くボタン）を同じグリッドに並べるときは 1 行を全幅にせず左右に置き、形で区別する（チップはピル、ボタンは角丸矩形。高さ 32px と文字はチップに揃え、ラベル左・件数右で件数はボタンの中に入れる）。左の 1 つを 2 行分（`grid-row: span 2`）にして右の 2 つと高さを揃えてよい（さがすのオプション 1〜2 行目: 「所持カードから探す」+「リーダーから除外 / メンバーから除外」— 2026-09-08、2 往復）。
