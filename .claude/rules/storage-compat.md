# ブラウザ保存データの後方互換（2026-09-02 ユーザー指示）

ユーザーがブラウザ（localStorage）に登録したデータ（所持カード・開花段階・ホロメンボード・仮想ガチャの状態・さがすときのオプションと除外）は、機能追加・データ更新で読めなくならないようにする。

- 保存形式を変えるときは、過去の全形式を読む移行を書き、旧形式の読み込みをテストで固定する（所持カードは `src/storage/owned.ts` + `owned.test.ts`。v0 = ID の文字列配列 / v1 = `{id, bloom}` の配列 / v2 = 版番号つき封筒）。書き出しは常に最新形式。
- 現在のデータに存在しない ID を読み込み時に捨てない。配列に残したまま書き戻し、UI で使うときに既知の ID だけを選ぶ（一時的な不整合やデータ側のミスで登録が永久に消えないように）。
- 公開済みのカード・ホロメン ID は改名・削除しない。全 ID は `src/data/published-ids.json` に凍結され、`dataset.test.ts` が「消えた ID」と「追記漏れ」を検知する。新規追加時はここにも追記する。表記を直したい ID があっても改名せず、必要なら保存層で別名対応する。
- **保存するのは入力だけで、そこから計算できる数値は保存しない** — 表示するときに最新の登録状態で計算し直す（2026-09-09 ユーザー指示「数値は登録した時点ではなく表示した時点で最新の情報で計算した値にする」）。お気に入りユニットはカード ID の組み合わせだけを持ち（`src/storage/units.ts`、番号 1〜10 の版番号つき封筒）、開いたときに現在の開花・ボード・メモリー・強化ボーナス・曲で `runOptimize`（`src/engine/request.ts`）して評価する。
- **外から貼り付けて取り込むデータ（インポート用 JSON。`src/storage/import.ts`）も入力として扱う**: 解釈は純関数（文字列 → プラン）にとどめて保存はせず、画面が差分を見せて確定してから既存の配列へ当てる（`ImportSheet.vue`）。**取り込みで登録が減ってはいけない** — データに無いカードの登録はそのまま残し、全消しは別操作にする（スクショが全件そろっている保証がない）。読み取れなかった値（`bloom: null`）は推測で埋めず、新規は既定の 0凸、登録済みは現在の段階を保つ。形式の定義とローカル LLM 向けの作り方は `.claude/skills/structure-import/`（保存形式の版 `owned` v2 とは別に、封筒の版 `format` / `version` を持つ）。
- **さがすのオプションを保存するかどうかはユーザーが切り替えられる**（`keep-options`、`src/composables/useKeepOptions.ts`。サイドメニューの折り畳み「設定」の「オプションの保持」。既定は ON で、`"false"` のときだけ OFF）。OFF にした時点で対象の 3 キー（`search-all` / `search-options` / `selection`）を消し、以後は書かない — 次の読み込みは既定から始まる（2026-09-16 ユーザー指示）。**消してよいのはこの 3 キーだけ**で、登録したデータ（所持カード・ボード・コネクト・お気に入り・アカウント補正・仮想ガチャ）には触らない。
- 保存キーは `holodori-optimizer:` 名前空間。新しいキーを足すときも上の 3 点を満たす読み込みにする（真偽値だけの設定キー `search-all` / `search-options`（`src/storage/searchOptions.ts` + `searchOptions.test.ts`）は壊れていれば既定値に戻す読み込みで足りる — 2026-09-05。`search-all` は 2026-09-14 に「未保存」と「false」を区別する読み込み（`src/storage/searchAll.ts` の `parseSearchAll` は未保存・壊れた値・真偽値でない値を `null` にする）へ変えた。`search-options` の中身は 2026-09-16 に入れ替わった: 衣装・パッシブのしぼりこみ 2 件を落とし、ボードの色 4 つ（`boardColors`）とコネクト（`connect`）を足した。**旧項目 `costume` / `passives` と旧キー `skill-filters` は読み飛ばす**（未知の項目と同じ扱い。封筒の版は持たない）。4 色は明示的に `false` のときだけ OFF で、**4 色すべて OFF で保存されていたら既定のすべて ON へ戻す**（UI で作れない状態なので `searchOptions.test.ts` で固定）。ピッカーの絞り込み・並び順は保存しない（閉じても保持・再読み込みでリセット — 2026-09-06 ユーザー判断）。**保存するのはさがすの「オプション」だけで、枠の選択（リーダー・固定メンバー・曲）は保存しない**（2026-09-16 ユーザー指示「やっぱりリーダー、メンバー、曲はページ更新されても保持するのやめよう。探すオプションだけはデフォルト維持」。2026-09-14 の「リーダー、メンバー、曲も保存する」方針はここで撤回した — 復活させない）。保存するのは `search-all` / `search-options` と、除外（リーダーから除外 / メンバーから除外。`selection`、版番号つき封筒 v1）の 3 キー。2026-09-14〜16 に保存された `selection` の `leaderId` / `memberIds` / `songId` は**読み込みで読み飛ばす**（未知のフィールドと同じ扱い。封筒の版は上げない — `selection.test.ts` で固定）。
- コネクトマスの入力は `connect-placements`（`src/storage/connect.ts`、版番号つき封筒 v3。ホロメン ID → アンカー（center / leader / card / content）→ `{ extent, permil }`）。**v2（2026-09-11 の数時間）は範囲の形を青 / 黄のコネクトでは青が右のホロメン、赤ではライフ系が右のホロメンで dx を反転して当てていた** — v3 で反転をやめたので、v2 の形は読み込み時にそのアンカーだけ左右反転した形へ写し（`unmirrorPlacements`。`mirrorExtent` は 17 種すべてに幾何で相手がある）、同じマスに掛かるようにする（「既存の localStorage 壊れないように注意」— 2026-09-11）。4 色の解放マスのキーには混ぜず、キーがない旧データは「どこにも置いていない」として読む。v1（数時間だけ公開。値がカード ID）は形が分からないので読み飛ばす。知らないアンカー・知らない形・0 以下の ‰ は読み飛ばし、データにないホロメンは捨てない（`connect.test.ts` — 2026-09-11）。
- ボードは色ごとに別キーで同じ封筒（`red-boards` / `blue-boards` / `yellow-boards` / `green-boards`、`src/storage/boards.ts` の `BoardColor`）。既知のマス ID の絞り込みも色ごと（R-xxx / B-xxx / Y-xxx / G-xxx）— 2026-09-07、黄・赤は 2026-09-08。
- UI の入口を外しても保存済みの状態は消さない（除外するカードは 2026-09-08 に入口を一度外したが状態と探索への反映は保持 — ユーザー指示「内部的には保持しつつ UI からは削除」。同日に「リーダーから除外 / メンバーから除外」の 2 入口で戻し、状態は `excludedLeaderIds` / `excludedMemberIds`。2026-09-14 から `selection` に保存する — それまでは再読み込みで消えていた。2026-09-16 からは「オプションの保持」が ON のあいだだけ）。設定キーの既定値を変えるときは保存済みの値を尊重する（`search-all` の既定を「持っているカードのみ」に変えたが保存値はそのまま読む）。**既定値を「他の保存済みデータから導ける値」にしてよい** — 定数を切り替えると、まだ選んでいない既存ユーザーの見え方まで変わる。`search-all` の既定は所持カードの枚数から決める（`resolveSearchAll(stored, ownedCount)`: 選んでいれば保存値、選んでいなければ所持カードが 0 枚のときだけ全カード）— 初めて来た人は所持カードが無く、所持カードから探しても 0 件にしかならない。既に登録がある人はこれまでどおり所持カードから探す（2026-09-14 ユーザー指示「初めて訪れるユーザは所持カードないので所持カードから探すはデフォルトオフにしたい。ただ既に使ってるユーザのオプションは変えないで」）。導出は保存せず、ユーザーが自分で切り替えたときだけ書く。
- ゲーム側で決まっている値をユーザー入力からデータへ移したときは、保存済みの旧フィールドを読み飛ばすだけにし、封筒の版は上げない（`blue-boards` の `mirrored`（左右型）は 2026-09-07 に `holomen.json` の `board` へ移し、読み込みで無視・書き出しに含めない — `boards.test.ts` で固定）。
- さがすときの除外は `selection`（`src/storage/selection.ts` + `selection.test.ts`。役割別の除外リストだけ）。壊れた値・文字列でない ID・重複は落とすが、**現在のカードデータにない ID は落とさず持ち回る**（候補から外すだけなので未知の ID が残っても害がなく、データの入れ替えで登録が消えないほうを採る — `owned` と同じ約束）。枠の選択（リーダー・固定メンバー・曲）は保存しないので毎回まっさらから始まり、所持カードから探すモードでは所持外のカードを枠から外す（`pool` の watch が `immediate`）。お気に入りユニットは `units`（`src/storage/units.ts` + `units.test.ts`。版番号つき封筒。番号は 1〜10 で範囲外・メンバー数が 5 でない項目は落とし、現在のカードデータにない ID は残して UI 側で解決できるものだけ出す）。**番号は 1 から連続していなければならない**（2026-09-16 ユーザー指示）— `compactUnits` が読み込み・登録・解除・書き出しのすべてで詰め直すので、歯抜けで保存されていた過去のデータ（1, 3, 7）は**読み込んだ時点で 1, 2, 3 になる**。動くのは番号だけで、編成も名前もそのまま移り**登録は 1 件も消えない**。登録できる番号は「登録済み」と「先頭の空き 1 つ」だけで（`canUseSlot`）、飛ぶ番号への `putUnit` は何もしない。**所持カードの登録と `units` は独立**で、お気に入りに登録できるのは所持カードで組んだ編成だけだが（UI 側の判定）、**あとで所持から外しても登録は消さない**（取り込みで 1 枚欠けた JSON を貼っただけでお気に入りが消えるのを避ける。そのカードは開花段階の登録も無くなるので 0凸 として計算し直される）。**名前（`name`、最大 10 文字）は後から足した任意の項目**で、版番号は上げていない — ない保存もそのまま読め、付けていなければ書き出しにも入れない（表示は `unitDisplayName` が「ユニット{番号}」へ落とす。2026-09-15 ユーザー指示）。上書き登録すると別の編成になるので名前は残さない。仮想ガチャの状態は `gacha`（`src/composables/useGacha.ts`。ダイヤ・課金額・排出の累計・ピックアップのカード ID。版番号は持たず、数値でない値・負の値・現在のデータにないカード ID は既定へ戻す読み込み）。表示の設定は `theme`（`"dark"` / `"light"`、既定はライト）と `palette`（管理用画面の配色の上書き。モードごとの 16 進 6 桁だけを受け付け、壊れた値は捨てる）— どちらも真偽値・列挙だけなので壊れていれば既定に戻す読み込みで足りる（2026-09-09）。
- 解説ページから戻ってきたときに戻す縦位置は `return-scroll`（`src/storage/returnScroll.ts`）。**localStorage ではなく sessionStorage** に置き、トップページの起動時に 1 度読んで消す（タブを閉じれば消える一時的な値で、ユーザーが登録したデータではない）— 2026-09-14。解説ページ本文の「編成シミュレーターを開く」は遷移の前にこのキーを消す（先頭から始める。戻すのはヘッダの「←」だけ — 2026-09-15）。
- 開発用の「文言・配置」の上書きは `copy-tuning`（`src/composables/useCopyTuning.ts`）。既定値は `src/ui/copyTuning.ts` にあり、保存値はその上書きなので、知らない項目・型の違う値・知らない位置は既定へ戻して読む（`normalizeCopyTuning`。開発用の調整値なので過去形式の移行は持たない — `copyTuning.test.ts` で固定）。ユーザーが登録したデータではないので、消えても失われるものはない — 2026-09-14。開発用の「開花文言」で入れた文言は `bloom-text`（`src/composables/useBloomText.ts` + `src/ui/bloomText.ts` の `normalizeBloomTextState`）。同じく開発用の入力なので過去形式の移行は持たず、知らないスキル・段階の範囲外・文字列でない値は読み飛ばして残りを読む（入力の途中で再読み込みしても続けられるように保存するだけ。カードデータは書き換えない）— 2026-09-15。
- アカウント共通の補正（メモリー % ・メンバー強化ボーナス %）は `account-bonus`（`src/storage/account.ts`、版番号つき封筒）。数値でない・負・NaN は 0 に戻し、未知のフィールドは読み飛ばす（`account.test.ts`）— 2026-09-08。
