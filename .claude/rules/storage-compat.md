# ブラウザ保存データの後方互換（2026-09-02 ユーザー指示）

ユーザーがブラウザ（localStorage）に登録したデータ（所持カード・開花段階・ホロメンボード・仮想ガチャの状態・さがすときの入力 — オプションと枠の選択・除外）は、機能追加・データ更新で読めなくならないようにする。

- 保存形式を変えるときは、過去の全形式を読む移行を書き、旧形式の読み込みをテストで固定する（所持カードは `src/storage/owned.ts` + `owned.test.ts`。v0 = ID の文字列配列 / v1 = `{id, bloom}` の配列 / v2 = 版番号つき封筒）。書き出しは常に最新形式。
- 現在のデータに存在しない ID を読み込み時に捨てない。配列に残したまま書き戻し、UI で使うときに既知の ID だけを選ぶ（一時的な不整合やデータ側のミスで登録が永久に消えないように）。
- 公開済みのカード・ホロメン ID は改名・削除しない。全 ID は `src/data/published-ids.json` に凍結され、`dataset.test.ts` が「消えた ID」と「追記漏れ」を検知する。新規追加時はここにも追記する。表記を直したい ID があっても改名せず、必要なら保存層で別名対応する。
- **保存するのは入力だけで、そこから計算できる数値は保存しない** — 表示するときに最新の登録状態で計算し直す（2026-09-09 ユーザー指示「数値は登録した時点ではなく表示した時点で最新の情報で計算した値にする」）。お気に入りユニットはカード ID の組み合わせだけを持ち（`src/storage/units.ts`、番号 1〜10 の版番号つき封筒）、開いたときに現在の開花・ボード・メモリー・強化ボーナス・曲で `runOptimize`（`src/engine/request.ts`）して評価する。
- **外から貼り付けて取り込むデータ（インポート用 JSON。`src/storage/import.ts`）も入力として扱う**: 解釈は純関数（文字列 → プラン）にとどめて保存はせず、画面が差分を見せて確定してから既存の配列へ当てる（`ImportSheet.vue`）。**取り込みで登録が減ってはいけない** — データに無いカードの登録はそのまま残し、全消しは別操作にする（スクショが全件そろっている保証がない）。読み取れなかった値（`bloom: null`）は推測で埋めず、新規は既定の 0凸、登録済みは現在の段階を保つ。形式の定義とローカル LLM 向けの作り方は `.claude/skills/structure-import/`（保存形式の版 `owned` v2 とは別に、封筒の版 `format` / `version` を持つ）。
- 保存キーは `holodori-optimizer:` 名前空間。新しいキーを足すときも上の 3 点を満たす読み込みにする（真偽値だけの設定キー `search-all` / `search-options` は壊れていれば既定値に戻す読み込みで足りる — 2026-09-05。`search-all` は 2026-09-14 に「未保存」と「false」を区別する読み込み（`src/storage/searchAll.ts` の `parseSearchAll` は未保存・壊れた値・真偽値でない値を `null` にする）へ変えた。`search-options` がないときは旧キー `skill-filters` の衣装・パッシブを引き継ぐ — 2026-09-06）。ピッカーの絞り込み・並び順は保存しない（閉じても保持・再読み込みでリセット — 2026-09-06 ユーザー判断）。**さがすときの入力は保存する方針**（2026-09-14 ユーザー指示「さがすオプションはローカルストレージに保存する方針ね。リーダー、メンバー、曲も」）— オプション（`search-all` / `search-options`）に加えて、枠の選択（リーダー・固定メンバー・曲）と除外（リーダーから除外 / メンバーから除外）も `selection`（`src/storage/selection.ts`、版番号つき封筒 v1）に保存し、次回は続きから始める。
- コネクトマスの入力は `connect-placements`（`src/storage/connect.ts`、版番号つき封筒 v3。ホロメン ID → アンカー（center / leader / card / content）→ `{ extent, permil }`）。**v2（2026-09-11 の数時間）は範囲の形を青 / 黄のコネクトでは青が右のホロメン、赤ではライフ系が右のホロメンで dx を反転して当てていた** — v3 で反転をやめたので、v2 の形は読み込み時にそのアンカーだけ左右反転した形へ写し（`unmirrorPlacements`。`mirrorExtent` は 17 種すべてに幾何で相手がある）、同じマスに掛かるようにする（「既存の localStorage 壊れないように注意」— 2026-09-11）。4 色の解放マスのキーには混ぜず、キーがない旧データは「どこにも置いていない」として読む。v1（数時間だけ公開。値がカード ID）は形が分からないので読み飛ばす。知らないアンカー・知らない形・0 以下の ‰ は読み飛ばし、データにないホロメンは捨てない（`connect.test.ts` — 2026-09-11）。
- ボードは色ごとに別キーで同じ封筒（`red-boards` / `blue-boards` / `yellow-boards` / `green-boards`、`src/storage/boards.ts` の `BoardColor`）。既知のマス ID の絞り込みも色ごと（R-xxx / B-xxx / Y-xxx / G-xxx）— 2026-09-07、黄・赤は 2026-09-08。
- UI の入口を外しても保存済みの状態は消さない（除外するカードは 2026-09-08 に入口を一度外したが状態と探索への反映は保持 — ユーザー指示「内部的には保持しつつ UI からは削除」。同日に「リーダーから除外 / メンバーから除外」の 2 入口で戻し、状態は `excludedLeaderIds` / `excludedMemberIds`。2026-09-14 から `selection` に保存する — それまでは再読み込みで消えていた）。設定キーの既定値を変えるときは保存済みの値を尊重する（`search-all` の既定を「持っているカードのみ」に変えたが保存値はそのまま読む）。**既定値を「他の保存済みデータから導ける値」にしてよい** — 定数を切り替えると、まだ選んでいない既存ユーザーの見え方まで変わる。`search-all` の既定は所持カードの枚数から決める（`resolveSearchAll(stored, ownedCount)`: 選んでいれば保存値、選んでいなければ所持カードが 0 枚のときだけ全カード）— 初めて来た人は所持カードが無く、所持カードから探しても 0 件にしかならない。既に登録がある人はこれまでどおり所持カードから探す（2026-09-14 ユーザー指示「初めて訪れるユーザは所持カードないので所持カードから探すはデフォルトオフにしたい。ただ既に使ってるユーザのオプションは変えないで」）。導出は保存せず、ユーザーが自分で切り替えたときだけ書く。
- ゲーム側で決まっている値をユーザー入力からデータへ移したときは、保存済みの旧フィールドを読み飛ばすだけにし、封筒の版は上げない（`blue-boards` の `mirrored`（左右型）は 2026-09-07 に `holomen.json` の `board` へ移し、読み込みで無視・書き出しに含めない — `boards.test.ts` で固定）。
- さがすときの入力は `selection`（`src/storage/selection.ts` + `selection.test.ts`。リーダー・メンバー枠・曲の ID と、役割別の除外リスト）。壊れた値・文字列でない ID は未選択に戻し、メンバーは前から詰めて枠数ぶんにそろえ、除外は重複を 1 つにする。**枠の選択は現在のカード・曲データにない ID を UI 側で落とすが、除外のリストは落とさず持ち回る**（候補から外すだけなので未知の ID が残っても害がなく、データの入れ替えで登録が消えないほうを採る — `owned` と同じ約束）。所持カードから探すモードでは所持外のカードを枠から外す（`pool` の watch が `immediate`）。お気に入りユニットは `units`（`src/storage/units.ts` + `units.test.ts`。版番号つき封筒。番号は 1〜10 で範囲外・メンバー数が 5 でない項目は落とし、現在のカードデータにない ID は残して UI 側で解決できるものだけ出す）。仮想ガチャの状態は `gacha`（`src/composables/useGacha.ts`。ダイヤ・課金額・排出の累計・ピックアップのカード ID。版番号は持たず、数値でない値・負の値・現在のデータにないカード ID は既定へ戻す読み込み）。表示の設定は `theme`（`"dark"` / `"light"`、既定はライト）と `palette`（管理用画面の配色の上書き。モードごとの 16 進 6 桁だけを受け付け、壊れた値は捨てる）— どちらも真偽値・列挙だけなので壊れていれば既定に戻す読み込みで足りる（2026-09-09）。
- 解説ページから戻ってきたときに戻す縦位置は `return-scroll`（`src/storage/returnScroll.ts`）。**localStorage ではなく sessionStorage** に置き、トップページの起動時に 1 度読んで消す（タブを閉じれば消える一時的な値で、ユーザーが登録したデータではない）— 2026-09-14。解説ページ本文の「編成シミュレーターを開く」は遷移の前にこのキーを消す（先頭から始める。戻すのはヘッダの「←」だけ — 2026-09-15）。
- 開発用の「文言・配置」の上書きは `copy-tuning`（`src/composables/useCopyTuning.ts`）。既定値は `src/ui/copyTuning.ts` にあり、保存値はその上書きなので、知らない項目・型の違う値・知らない位置は既定へ戻して読む（`normalizeCopyTuning`。開発用の調整値なので過去形式の移行は持たない — `copyTuning.test.ts` で固定）。ユーザーが登録したデータではないので、消えても失われるものはない — 2026-09-14。
- アカウント共通の補正（メモリー % ・メンバー強化ボーナス %）は `account-bonus`（`src/storage/account.ts`、版番号つき封筒）。数値でない・負・NaN は 0 に戻し、未知のフィールドは読み飛ばす（`account.test.ts`）— 2026-09-08。
