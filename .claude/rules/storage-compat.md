# ブラウザ保存データの後方互換（2026-09-02 ユーザー指示）

ユーザーがブラウザ（localStorage）に登録したデータ（所持カード・開花段階・ホロメンボード・仮想ガチャの状態・さがすときのオプションと除外）は、機能追加・データ更新で読めなくならないようにする。

- 保存形式を変えるときは、過去の全形式を読む移行を書き、旧形式の読み込みをテストで固定する（所持カードは `src/storage/owned.ts` + `owned.test.ts`。v0 = ID の文字列配列 / v1 = `{id, bloom}` の配列 / v2 = 版番号つき封筒）。書き出しは常に最新形式。
- 現在のデータに存在しない ID を読み込み時に捨てない。配列に残したまま書き戻し、UI で使うときに既知の ID だけを選ぶ（一時的な不整合やデータ側のミスで登録が永久に消えないように）。
- 公開済みのカード・ホロメン ID は改名・削除しない。全 ID は `src/data/published-ids.json` に凍結され、`dataset.test.ts` が「消えた ID」と「追記漏れ」を検知する。新規追加時はここにも追記する。表記を直したい ID があっても改名せず、必要なら保存層で別名対応する。
- **保存するのは入力だけで、そこから計算できる数値は保存しない** — 表示するときに最新の登録状態で計算し直す（2026-09-09 ユーザー指示「数値は登録した時点ではなく表示した時点で最新の情報で計算した値にする」）。お気に入りユニットはカード ID の組み合わせだけを持ち（`src/storage/units.ts`、番号 1〜10 の版番号つき封筒）、開いたときに現在の開花・ボード・メモリー・強化ボーナス・曲で `runOptimize`（`src/engine/request.ts`）して評価する。
- **外から貼り付けて取り込むデータ（インポート用 JSON。`src/storage/import.ts`）も入力として扱う**: 解釈は純関数（文字列 → プラン）にとどめて保存はせず、画面が差分を見せて確定してから既存の配列へ当てる（`ImportSheet.vue`）。**取り込みで登録が減ってはいけない** — データに無いカードの登録はそのまま残し、全消しは別操作にする（スクショが全件そろっている保証がない）。読み取れなかった値（`bloom: null`）は推測で埋めず、新規は既定の 0凸、登録済みは現在の段階を保つ。形式の定義とローカル LLM 向けの作り方は `.claude/skills/structure-import/`（保存形式の版 `owned` v2 とは別に、封筒の版 `format` / `version` を持つ）。
- **さがすのオプションを保存するかどうかはユーザーが切り替えられる**（`keep-options`、`src/composables/useKeepOptions.ts`。サイドメニューの折り畳み「設定」の「オプションの保持」。既定は ON で、`"false"` のときだけ OFF）。OFF にした時点で対象の 3 キー（`search-all` / `search-options` / `selection`）を消し、以後は書かない — 次の読み込みは既定から始まる（2026-09-16 ユーザー指示）。**消してよいのはこの 3 キーだけ**で、登録したデータ（所持カード・ボード・コネクト・お気に入り・アカウント補正・仮想ガチャ）には触らない。
