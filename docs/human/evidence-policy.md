# 証拠・観測・推定の扱い

この文書は、ゲーム仕様・実機観測・データセット・逆解析を混同しないための正典。

## 基本原則

情報の権威順位は **実機表示 > 公式・公開情報 > 外部解析 > 仮説** とする。ただし、ユーザーが実機から読み取った値にも入力ミス・読み違い・編成取り違えは起こり得る。したがって「権威が高い」と「無誤謬」は同義ではない。

観測値はモデルへ合わせて書き換えない。矛盾が出たら、観測を消すのではなく状態を下げて再確認する。

## 状態ラベル

| ラベル                      | 意味                                                                                     |
| :-------------------------- | :--------------------------------------------------------------------------------------- |
| `reported`                  | 実機から1回報告された値。最優先の一次観測だが再読未実施                                  |
| `rechecked`                 | 同じ条件を再度確認し、値・編成・画面項目を再読した観測                                   |
| `cross-checked`             | 合計や既知式など独立な算術整合が取れた観測。再読の代わりにはならない                     |
| `source-transcribed`        | 公開データ・既存一覧等から転記した値。実機確認とは別                                     |
| `reconstructed-observation` | 実機で数値・効果は確認したが、`raw` 文言は別段階の文を基に数値だけ置換して再構成したもの |
| `derived`                   | 確定規則から計算した値。実機に表示された値ではない                                       |
| `estimated`                 | 仮定倍率・未確定モデル等から推定した値                                                   |
| `hypothesis`                | 一般式・因果関係の候補                                                                   |
| `rejected`                  | 反例があり一般式として棄却したもの                                                       |

`cross-checked` は `reported` に追加できる属性であり、`rechecked` への自動昇格ではない。

## 実機 Golden

- Golden の実機列をモデルに合わせて変更しない。
- ユーザーが「さっきの値は誤記」と明示した場合は訂正してよい。元値と訂正理由は Git 履歴に残す。
- 後から編成順・Lv・開花・曲などが不明になった観測は、値を捨てず「入力条件の一部不明」と明記する。
- 式から逆算した Power 等を実測欄へ入れない。
- カテゴリ和やユニットスコア式が一致しても、カード・編成の取り違えまでは検出できない。

## カードデータの3層

1. `src/data/cards.json` は**取り込み元レコード**。トップレベルの `stats` / `raw` / `structured` は開花最大側のレコードとして扱うが、全件が実機確認済みという意味ではない。
2. `src/data/cardCorrections.ts` は、後から実機で訂正された確定事項を適用する**権威付き補正層**。ランタイムの正典は `src/data/index.ts` が export する `cards`。
3. `cardAtBloomWithProvenance()` は、所持開花へ解決した値と、その値が最大レコード・実測variant・再構成観測・最大値からの推定のどれかを返す。

`cards.json` の検索スニペットだけをカード事実の根拠にしてはいけない。

## 開花段階

- トップレベルは最大開花側のレコード。
- `bloomVariants` は途中段階について追加で得た情報。
- variant の `raw` が必ずしもゲーム内文言そのものとは限らない。`src/data/bloomEvidence.ts` の分類を確認する。
- 2凸のパラメータ +10% は確認済み。ただし最大値から pre-2凸値を整数へ戻す際には丸め由来の不確実性があるため `derived` とする。
- スキルの未確認途中値を最大値から `÷1.1` する処理は `estimated`。確定値として引用しない。

## カード事実を引用する前の必須手順

1. カード ID とカード名、ホロメン ID を同じオブジェクトで確認する。
2. リーダーかメンバーかを確認する。衣装スキルはリーダー側、パッシブはメンバー側として扱う。
3. 実際の開花段階を確認する。
4. `cardAtBloomWithProvenance()` 相当で解決し、各スキルの provenance を確認する。
5. `raw` を引用する場合は `observed-text` か、最大レコードの転記か、再構成文かを明記する。
6. 検索結果の隣接オブジェクトをカード本人の情報として読まない。

## 仮説を昇格する条件

- 同時に複数条件が変わる比較から単独因果を主張しない。
- 1編成だけに合う係数は一般式ではない。
- 新しい反例が出たら、旧仮説に例外を足す前に一般式として棄却する。
- 「次の本命仮説」は正典に固定しない。十分な対照がない候補は `pending.md` に検証課題としてのみ残す。
