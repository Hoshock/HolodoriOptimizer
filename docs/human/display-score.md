# 表示ユニットスコアの逆解析

ユニット編成画面に表示される「スコアボーナス」と「ユニットスコア」の現在の知識をまとめる。実測値そのものは [repro/display-score-20260912.md](./repro/display-score-20260912.md)、証拠の扱いは [evidence-policy.md](./evidence-policy.md) を正典とする。

`src/engine/displayScore.ts` は現在の試算実装であり、反証済みの近似が残る。コードが存在することをゲーム仕様の証拠にしない。

## 確定・強く支持されること

### ユニットスコアの外側

```txt
unitScore = ceil(totalPower × (1 + scoreBonus / 100) × 2.03734)
```

多数の実機報告で1点単位まで一致する。新しい観測もこの式で cross-check する。ただし式が一致しても、編成・Lv・カードの読み違いまでは検出できない。

### 5カテゴリ

現在の実機では次の5カテゴリを観測できる。

1. 衣装（Costume / Leader）
2. アクティブ（Active）
3. ホロメンボード（Board / SkillTree）
4. パッシブ（Passive）
5. SP（Special）

0のカテゴリは表示上省略されることがある。【外部情報】サーバー応答にも Active / Leader / Passive / SkillTree / Special の独立カテゴリがあるとされる。現在実装のタイムライン差分配賦をゲーム内部式とみなさない。

### 黄ボード

同一編成・同一赤状態の「曲なし Y=0」と「Gamers Y=10%」の直接比較では、Boardだけが `40.7 → 64.8`（+24.1）となった。他4カテゴリは `Costume 14.1 / Active 77.7 / Passive 1.9 / SP 47.0` で同じ。

表示値でも、

```txt
0.1 × (100 + 14.1 + 77.7 + 1.9 + 47.0) = 24.07
```

となる。したがって現在の最も強いモデルは、量子化前rawを用いる

```txt
YellowBoardIncrement
= Y × (100 + Costume + Active + Passive + Special)
```

である。Costumeを除く旧4カテゴリ式はこの直接対照に合わない。

実装（`songBoardRaw`）は2026-09-12にこの5カテゴリ式へ更新した。`DisplayScoreBreakdown` も `costume` を含む5カテゴリで、合計は5欄の表示値の和。Costume欄の現在値は「衣装スコアサポートを静的に (1 + X/100) 倍した増分」という既知の近似で、実機（13〜17pt台）より大きい。Costumeの一般式は未解明のまま。

### 赤のパラメータ効果と赤スコアサポートは分ける

赤の P/T/S 固定値・割合を変えて総合力が変化しても、スコアカテゴリが変わらなかった対照がある。赤のパラメータ計算を、赤「全員のスコアサポート効果」の表示換算へ混ぜない。

## 強い推定

### Active

200秒の共通仮想タイムラインを使う現在モデルが既存Goldenに非常によく一致する。

- 発動候補: `k × interval <= s < k × interval + duration`、`k >= 1`
- 基礎発動確率: 高55% / 中46% / 低37%【外部情報を含む】
- 同時候補時は確率和で正規化する現在モデル
- Activeの0.1%単位化は切り上げで既存観測と一致

発動確率の実数値自体はゲーム内表示から直接確認できない。

**既知の不一致（2026-09-12）**: 条件つきアクティブ 3 枚（ライフ 600 / 40 コンボ / ハッピー 2 人）を含む恒常そら / アキ / スバル / フレア / ぼたん 0凸の 5 人（K5）では、抽出マスター Lv1 の入力でも現行評価器は 59.6 で、実機アクティブ欄 63.3 を再現しない（下の「リーダー衣装のスコアサポート」）。既存 Golden 20 ケースと水着フワワリーダー 9 編成・K1〜K4 のアクティブ欄は 0.1 以内で一致するので、条件つきアクティブの表示評価方式（ライフ・コンボ条件の扱い）が未解明として残る。

### パッシブ欄（既知の近似）

production のパッシブ欄（供給側の発動確率で重みづけした支援行列）は、恒常マリン 1凸のパッシブ「3期生が2人以上で3期生2人のスコアサポート効果」を 2026-09-12 に抽出マスター Lv1 = 9%（旧仮定倍率 12 ÷ 1.1 ≈ 10.9）へ訂正した後、恒常ぺこらとの 2 人で条件が成立する Golden 9.8〜9.11 で実機 2.4〜3.5 に対し 1.7〜2.1（不足 0.7〜1.8）になった。正しい入力ほど不足が大きく、モデルの既知の近似として上限だけ更新した（`displayScore.test.ts`。Golden は不変）。

### SP

現在モデルは多くのケースで近いが、発動率UPを含むケースなどに残差がある。Activeほど確度は高くない。

## 赤「全員のスコアサポート効果」

### 観測から安全に言えること

- 表示への効きは編成依存。赤+24の報告差は現在 `+16.4〜+20.9pt` まで広がっている。
- 赤+24の曲比較ではActive / SPが変わらず、Boardを中心にCostume / Passiveも動く例がある。
- R-061（+3）だけを開いた対照ではPower不変、Bonus `178.7 → 181.4`（+2.7）。
- 同じ白上フブキのホロメンボード状態でも、水着フブキ0凸と恒常フブキ1凸で赤+24の差が異なる報告がある。これは「青ボード量だけ」では説明できないが、カード変更に伴いActive / Passive等も同時に変わるため原因は特定できない。
- 水着ミオ + 恒常マリンでは、青補正なし候補秒149/200に対して赤+24の実測差が+20.9で、旧候補秒率式の17.88を大きく外す。

### 棄却済み

一般式として使わない。

- `固定係数 × X`（0.88、0.85等）
- `X × 基準候補秒 / 200`
- `X × 表示Active / 90`
- Costume表示値だけで決める単純倍率
- 青込み候補秒・発動確率込み占有率だけで決める単純式

現行 `redScoreSupportDisplayGain` は旧候補秒率式を残した**既知の近似**で、一般式として反証済み。実装を根拠にGoldenや正典を書き換えない。

### 現在最有力の一般則候補（強い推定。確定ではない）

```txt
ΔRed(X) = X / 100 × E_blue
```

`E_blue` は production のアクティブ欄と同じ評価器（200秒の共通仮想タイムライン、条件解決済みスコアUP、同時候補は確率和 `Σ up × p / max(1, Σ p)` で正規化）に、青ボードを次のように入れたアクティブ期待値。

- 発動確率: `p_i = min(1, p0_i × (1 + 発動率UP_i / 100))`（**乗算型**）
- 発動周期: `interval_i / (1 + 発動頻度UP_i / 100)`
- 候補窓: `k × interval_i' <= s < k × interval_i' + duration_i`（`k >= 1`、200秒）

実機13対照（[repro](./repro/display-score-20260912.md) の赤+24 × 9、R-061 +3、旧R-002 +10 × 3）に対する raw 予測は RMSE ≈ 0.09 pt、最大絶対誤差 ≈ 0.13 pt（2026-09-12、各対照はその観測時点の青実効値を使用）。旧候補秒率式は同じ13対照で RMSE ≈ 1.0 pt（+24の9件だけなら ≈ 1.2 pt、水着ミオ+恒常マリンで 3 pt 外す）で、大幅に改善する。発動率UPを production の青と同じ加算型 `p0 + r` にすると RMSE ≈ 0.85 pt になり、乗算型が明確に良い。

解析コードは `src/engine/displayScoreExperimental.ts`、回帰評価は `displayScoreExperimental.test.ts`（仕様のGoldenではなく仮説の回帰ガード: RMSE < 0.15 / 最大 0.25）。

**production には採用しない。** 総増分は説明できても、実機ではその増分が Costume / Board / Passive のカテゴリへ分かれて動き（赤+24で Costume +0.5 / Board +20.4 / Passive 0 など）、その配賦式が未解明のため。総量だけ合わせて全部 Board に入れると5カテゴリ表示が誤り、黄が Costume / Passive を基底に使うぶん黄込みの結果にも波及する。また乗算型が赤の内部基準量として強いことは、production の青 Board 換算を乗算型へ変える根拠ではない（青の一般仕様として `p0 × (1 + r)` が確定したわけではなく、raw の server permil も未取得）。

### カテゴリ配賦（Costume / Board / Passive）は未解明 — 既存評価器上の逐次 marginal は全順序で反証

総増分 `X/100 × E_blue` を、production と同じ評価器 F の上で「スキルツリー赤（S）・リーダー衣装（L）・パッシブ支援（P）」の 3 供給源を順に足したときの限界寄与として配賦する仮説を、2026-09-12 に 6 順序 × 供給側確率 2 種（`p0` / 青乗算型）× 量子化 2 種（round / ceil）の 24 組で評価した（`src/engine/displayScoreAttributionExperimental.ts` / `.test.ts`、production 未採用）。コーパスは赤だけを変えた直接比較 15 行（水着フワワリーダー +24 × 9、R-061 +3、衣装なし R-002 +10 × 3、水着ミオリーダー +24 の黄 0 / 10%）で、各行に赤変更前後の 5 欄の絶対値を持つ。黄の交差項は raw 5 欄 → `songBoardRaw` → 量子化の順で分離し、量子化は全ケース同一とした。

**結果: どの組も 衣装 ΔC ≤ 0.25 / パッシブ ΔP ≤ 0.25 / ボード ΔB ≤ 0.5 pt を同時に満たさない。**

| 順序（先 → 後）                 | ΔC RMSE / 最大   | ΔP RMSE / 最大   | ΔB RMSE / 最大   | 主な破綻                                                                                           |
| :------------------------------ | :--------------- | :--------------- | :--------------- | :------------------------------------------------------------------------------------------------- |
| S → P → L, S → L → P            | 3.65〜3.70 / 5.3 | 0.19〜0.31 / 0.5 | 0.73〜0.75 / 1.2 | 衣装欄が赤で ×(1+X/100) され、+24 で ΔC ≈ +5.2（実機 −0.1〜+0.5）                                  |
| P → S → L                       | 3.68〜3.70 / 5.3 | 0.20 / 0.5       | 0.89〜0.98 / 1.5 | 同上。パッシブを先に取るとボードも悪化                                                             |
| L → S → P, L → P → S, P → L → S | 0.30 / 0.5       | 0.20〜0.31 / 0.5 | 4.23〜4.47 / 6.2 | 衣装は動かないが、赤の総増分が衣装で 1.25 倍されボードが +24 で ≈ +5 過大、R-061 +3 でも +0.7 過大 |

round と ceil の差は ΔP で最大 0.1、ΔB で最大 0.1 程度で、破綻の大きさ（数 pt）に比べ無視できる。供給側確率を `p0` から青乗算型へ変えても同様（差 ≤ 0.1）。2026-09-12 に恒常ころね 3凸のパッシブ「ハッピータイプ2人のスコアサポート効果」を仮定倍率 10 → 抽出マスター Lv1 = 8% に訂正しても（恒常フブキ1 / 恒常ころね3 の ΔP モデル値 0.3 → 0.2、ΔB 21.2 → 21.1）、この反証は変わらない。9 編成の主要アクティブ入力は訂正の対象外（水着みこ1 / ミオ1 / ころね2、恒常マリン1 / フブキ1 / ころね3 は Lv2、水着フワワ0 / フブキ0 / ノエル0 は実機 variant）なので、衣装欄・ボード欄の配賦問題は入力の推定ミスでは説明できない。

**衣装欄は一様倍率ではない（構造的な下限による棄却）。** 衣装スキル「ピュア 2 人以上で全員のスコアサポート 25%」を、どの配賦法であれ全員のスコアに掛かる一様な ×1.25 として表すなら、衣装欄の値はどの順序でも `0.25 × E_base`（青・赤なしのアクティブ期待値。L を先頭に取った限界寄与がちょうどこの値）以上になる。水着フワワリーダー 9 編成でこの下限は 17.7〜19.9 pt だが、実機の衣装欄は 13.4〜17.4 pt で全編成が下限を下回る（比 0.72〜0.97）。したがって衣装欄の算出は「一様倍率 × 何らかの配賦」の形ではなく、配賦順序を変えても救えない。また衣装欄は同じ X でもメンバーで大きく変わり（水着ミオ1 + 水着ころね2 で 14.1、水着ミオ1 + 恒常マリン1 で 17.4）、X 26 → 50 で −0.1 になった編成もある。22 個の衣装欄観測に対する単一特徴量の探索では、どの候補も編成間の差を 22% 以内に収められなかった。

**パッシブ欄の増分は既存の支援モデルと大小関係が逆。** 衣装なしの対照で、実機は R-002 +10 でパッシブ +0.4 / +0.5 / +0.3、水着ミオ +24 で +0.2 だが、既存の支援行列（供給側 `p0`）を S の後に取った限界寄与は +0.2 / +0.1 / +0.1 と +0.5 で、+10 の方が +24 より大きい実機の関係を再現しない。パッシブのスコアサポートが赤とどう合成されるかは未解明のまま。

**青の provenance 衝突（総量モデルの感度）。** 水着フワワの青は 2026-09-09 の実機報告で発動率 +45% / 頻度 0 だが、2026-09-12 の構造化データ（アカウント状態）にはフワワの青マスがなく、みこも 36（09-09）と 42（構造化データ）で食い違う。総量モデルの水着フワワリーダー 10 対照は、0 / 0 & みこ 42 で RMSE 0.086 / 最大 0.128、45 / 0 & 42 で 0.201 / 0.392（系統的に +0.1〜+0.4）。モデルの当てはまりを provenance の裁定に使わず、カード画面の再確認待ちとする。exploratory 行（水着みこ → 恒常みこ、Lv「約 20」）は総量モデルが +17.4 を返し実機 +16.4 と約 1.0 ずれる。入力条件（Lv・スキル Lv）が未確認なので fit に入れず、不一致として記録する。

公開情報の探索（`LiveDeckEvaluationScoreUpPermilUp`、`by_live_leader_skill`、`score_up_permil_up_by_skill_tree` 等）では、これらのキーの算出コードや式は見つからなかった。

**次の実験。** 現在の優先は下の「リーダー衣装のスコアサポート」末尾の 1 件（青なし・パッシブ支援ありの clean 対照）。赤側の 1 要因実験（水着ミオ1 / 恒常マリン1 で FUWAMOCO のまま赤マス 1 つだけを開閉し dC/dX の符号を見る）はその後。

### 現在は原因仮説を固定しない

以前は「水着フブキ0凸を含むケースだけ低い」ことから、水着フブキのパッシブ・スコアサポートとの相互作用を本命仮説としていた。しかしカード仕様の参照ミスが発生し、さらに水着みこ→恒常みこへ変更した新観測では、同時にActive / Passive / SP / Costume成立など複数条件が変化して赤+24差が+16.4まで下がった。

このため、**水着フブキのパッシブを原因とする仮説は正典から撤回する**。数値相関は観測として残すが、対照実験が成立するまで特定カード・特定スキルを原因扱いしない。

次の実験は、カードID・開花・Lv・リーダー/メンバー役割・衣装条件・各スキルprovenanceを事前に監査し、変更要因を1つに近づけられるものだけ採用する。

## リーダー衣装のスコアサポート: 総量とカテゴリ配賦（2026-09-12 典獄クロニー 60%）

材料は [repro](./repro/display-score-20260912.md) の「Leader-only matched pairs」K1〜K5: 同じメンバー 5 人・赤 0・黄 0・曲指定なしで、リーダーだけを 恒常みこ 0凸（支援 0%）→ 典獄クロニー 0凸（衣装「全員のスコアサポート効果60%」、条件なし）に替えた 5 欄の差。解析コードは `src/engine/displayScoreLeaderSupportExperimental.ts` / `.test.ts`（production 未採用）。K1〜K4 のアクティブ欄は評価器の `E_base` と 0.1 以内で一致し、クロニー側 4 件はユニットスコア式に 1 点単位で一致する。

### 総量: `Δ衣装 + Δボード + Δパッシブ = S/100 × E_blue(乗算)`（強い推定）

S = 60 で、赤の総量モデル（上の `X/100 × E_blue`）と**同じ評価器・同じ E_blue** を使う。

| ケース（A / B 枠）                                 | 実測 Δ衣装 / Δボード / Δパッシブ | 実測合計 | 0.60 × E_base                         | 0.60 × E_blue(加算) | 0.60 × E_blue(乗算) |
| :------------------------------------------------- | :------------------------------- | -------: | :------------------------------------ | ------------------: | ------------------: |
| K1 水着ミオ1 / 水着ころね2                         | 38.6 / 12.6 / 1.1                |     52.3 | 46.6                                  |                54.9 |                52.3 |
| K2 水着ミオ1 / 恒常マリン1                         | 46.2 / 6.3 / 0                   |     52.5 | 43.2                                  |                54.6 |                52.4 |
| K3 水着フブキ0 / 恒常マリン1                       | 38.4 / 7.4 / 0.4                 |     46.2 | 42.5                                  |                49.3 |                46.2 |
| K4 水着フブキ0 / 水着ころね2                       | 37.0 / 9.5 / 1.4                 |     47.9 | 43.0                                  |                50.7 |                47.7 |
| K5 clean（恒常そら/アキ/スバル/フレア/ぼたん 0凸） | 37.9 / 0 / 0                     |     37.9 | （表示アクティブ 63.3 × 0.6 = 37.98） |                同左 |                同左 |

K1〜K4 で乗算型は RMSE 0.11 / 最大 0.18、加算型は RMSE 2.7（+2.1〜+3.1 過大）、`E_base` は RMSE 6.2（−3.7〜−9.3 不足）。したがって、**リーダー衣装のスコアサポートと赤のスコアサポートは「総増分」としては同じ基礎量 `E_blue(乗算)` に比例する**。過去の同じ 5 人での 水着フワワ 25% + 赤 26%（黄 10% を表示値で除く）とクロニー 60% + 赤 0 の合計差も、4 組とも `(60 − 25 − 26)/100 × E_blue` に ±0.2 で一致する（K1 7.67 vs 7.84、K2 7.81 vs 7.86、K3 6.89 vs 6.94、K4 7.14 vs 7.16）。

K5（青 0・パッシブ支援なし）は clean control: ボード・パッシブは動かず、衣装欄 37.9 = 0.60 × 表示アクティブ 63.3（37.98）。表示アクティブは切り上げなので raw は (63.2, 63.3]、`0.6 × raw` は (37.92, 37.98] で、衣装欄の 37.9 は切り上げでは出ない（切り捨てなら区間全体、四捨五入なら raw < 63.25 のとき）。これだけで量子化規則は決めない。**K5 の 5 枚の 0凸アクティブは 2026-09-12 に抽出マスター Lv1（`extracted-master-variant`。外部解析であり実機目視ではない — [card-data-provenance.md](./card-data-provenance.md)）へ確定した: そら 85 / アキ 50（ライフ 600 以上で 95）/ スバル 95 / フレア 50（40 コンボ以上で 100）/ ぼたん 50（ハッピー 2 人以上で 105。この 5 人では不成立）。それでも現行評価器はアクティブ欄 63.3 を再現しない**: ライフ・コンボ条件を production と同じ成立扱いにして 59.58（表示 59.6、−3.7）、旧仮定倍率の入力では 67.9（+4.6）、全条件を基準値にすると 46.6、ぼたんの条件まで成立扱いにすると 66.9 で、どの扱いでも 63.3 にならない。条件つきアクティブの表示評価方式は未解明として残し、63.3 に合わせる条件判定や定数は入れない。K5 の評価は表示アクティブを E の代理にしている（0.60 × 63.3 = 37.98 vs 衣装欄 37.9。評価器の 0.60 × 59.58 = 35.7 は −2.2）。

### カテゴリ配賦は総量と別問題（衣装 = 0.60 × E_blue ではない）

K1〜K4 では同じ 60% が 衣装 38.6 / ボード 12.6 / パッシブ 1.1（K1）〜 衣装 46.2 / ボード 6.3 / 0（K2）へ分かれ、K5 では全量が衣装。つまりリーダーのスコアサポートが本質的にボード・パッシブへ分割されるのではなく、**青ボード・パッシブ支援との相互作用があるときだけ配賦が動く**。衣装欄を `0.60 × E` にした値の観測 `E_C = Δ衣装 / 0.6` は K1 64.3 / K2 77.0 / K3 64.0 / K4 61.7 / K5 63.2 で、K2 だけ `E_base`（72.0）より大きく、他は下回る。

衣装欄の候補（自由係数なし。値は 0.60 × E の K1 / K2 / K3 / K4 の誤差 pt）:

| 衣装候補の E                                                      |    K1 |   K2 |   K3 |    K4 | RMSE | 判定                      |
| :---------------------------------------------------------------- | ----: | ---: | ---: | ----: | ---: | :------------------------ |
| `E_base`（一様倍率）                                              |  +8.0 | −3.0 | +4.1 |  +6.0 |  5.7 | 棄却（両符号）            |
| `E_blue(乗算)`（総量そのもの）                                    | +13.7 | +6.2 | +7.8 | +10.7 | 10.0 | 棄却（K1〜K4 が直接否定） |
| 主仮説: 編成条件を未解決にした基準 up × 基準タイムライン × p0     |  −1.5 | −7.0 | +0.4 |  −3.0 |  3.9 | 棄却（K2）                |
| C*: 編成条件を未解決にした基準 up × 青の頻度込みタイムライン × p0 |  +1.5 | −0.3 | +1.4 |  −1.5 |  1.3 | 最良だが式ではない        |

「編成条件を未解決」は、タイプ人数・所属人数の条件つきスコア UP（水着フワワ 120 → 60、水着ころね 120 → 60）を基準値で評価し、ライフ・コンボ条件は production と同じく成立扱いにするもの（前回の swap 方向 9/10 の手掛かりの再検証）。主仮説は K2 を 7 pt 外す: K2 の観測 `E_C = 77.0` は `E_base` 72.0 より大きく、水着ミオ 1凸の発動頻度 8% で恒常マリン 1凸との同一窓（周期 23 秒 / 効果 8 秒）がずれる効果（基準 65.4 → 頻度込み 76.6）を入れないと届かない。C* はその頻度を入れたものだが、K1 / K3 を +1.4〜1.5 過大、K4 を −1.5 過小にし、誤差の符号はパッシブ支援の有無（K2 だけなし）と対応しない。青の発動率 UP（乗算型 p）まで衣装欄に入れると K1 で +4.4 過大になる。

残差 `R = 0.60 × E_blue(乗算) − C*` は Δボード + Δパッシブ を ±1.5 で追う（総量が合う以上、衣装の誤差の鏡像）。パッシブ欄の増分は、既存のパッシブ支援 marginal（供給側 `p0`、青乗算型）を `S/100` 倍した値の 1.6〜2.0 倍（K1 1.1 vs 0.58、K3 0.4 vs 0.23、K4 1.4 vs 0.82）で、自由係数なしには分離できない。ボード = 総量 − C* − パッシブ候補 の conservation は ±2 pt（K4 で +1.9）。

**リーダーなし（恒常みこ、支援 0）のボード欄**にも新しい観測がある: パッシブ支援のない K2 ではボード欄 15.3 が `E_blue(乗算) − E_base` = 15.28 に一致し（production の加算型は 18.9）、パッシブ支援のある K1 / K3 / K4 では同じ差より 1.6 / 0.5 / 1.8 高い。青の発動率 UP のボード換算（未解明）に対し、乗算型を支持する 1 点と、パッシブ支援との交差項の存在を示す 3 点として残す。production の青は変えない（既存 Golden 20 ケース側の再評価が先）。

**過去の水着フワワ 25% との接続。** 総量は上のとおり整合するが、衣装欄は C*（S=25）より 7〜18% 低い（同じ 5 人でクロニー 60% の `E_C` に対し 0.82〜0.93）。リーダーと同じホロメン（水着フワワ 0凸メンバー）を支援対象から外す構造仮説では 9 編成 RMSE 0.8 / 偏り +0.5（恒常フブキ1 / 恒常ころね3 で +1.6）で、前回の候補族の最良（1.00）より良いが式ではない。1 データセットの手掛かりとして記録し、採用しない。

**次の実機観測（1 つ）。** クロニーリーダー（と対照の恒常みこリーダー）で、メンバー 恒常そら0 / 恒常アキ0 / 恒常スバル0 / 恒常フレア0 / **恒常マリン1**（この 5 人は青 0。マリンのパッシブ「3期生2人以上で3期生2人のスコアサポート12%」がフレアとの 2 人で成立）の 5 欄を読む。青がないので「パッシブ支援の存在だけで衣装欄が 0.6 × アクティブを下回るか」を単独で判定できる。C*（青の頻度が原因）は 衣装 = 0.60 × 表示アクティブ（±0.1）、Δボード = 0、Δパッシブ ≈ 0.6 × パッシブ marginal（マリン 1凸は抽出マスター Lv1 = 9% で marginal ≈ 1.0 → ≈ 0.6。上の 1.6〜2 倍なら ≈ 1.0〜1.2）を予測する。「パッシブ支援との相互作用が衣装欄を減らす」側（K3 で −6.8 相当）は 衣装が 0.60 × アクティブ を数 pt 下回り、その分がボード / パッシブ欄に現れると予測する。両者の差は衣装欄で数 pt あり、評価器が K5 のアクティブ欄を再現しなくても（表示アクティブ基準の比較なので）判別に影響しない。この 5 人のアクティブ欄の実機値は、条件つきアクティブの表示評価方式の 2 点目の材料にもなる。

観測から言える構造（式ではない）:

- **一様な倍率ではない。** `0.25 × E_base` / `0.25 × E_blue` / `0.25 × 線形和` はどれも +3.9 pt 以上の系統的過大で、上限 `0.25 × E_base` を 9 編成すべてが下回る。`C = k × Active` 型も否定（Active 77.7 → 72.1 と下がる入替で衣装は 14.1 → 17.4 と上がる）。
- **入替効果は加法ではなく相手枠に強く依存する。** 水着ころね2 → 恒常マリン1 の入替は、水着ミオ1 と組むと +3.3、水着フブキ0 と組むと +0.8、恒常フブキ1 と組むと +2.0。水着ミオ1 と恒常マリン1 は周期 23 秒・効果 8 秒が同一で候補窓が完全に重なり、その組が最大（17.4）。production の正規化（重なりを割り引く）とは逆向きの相互作用で、アクティブ評価器由来の量では説明できない。
- **条件つきスコア UP の扱い。** 条件解決済み up（水着ころね2 60 → 120、水着フワワ 50 → 100）で評価すると 10 組の 1 枚差の方向を 7 組以下しか当てないが、条件を無視した基準値で評価すると 9 組以上当てる。ただし絶対値は RMSE 1.4 で合わず、条件つきメンバーを衣装の対象外にする「効果 UP が重複しない」型も RMSE 1.6 以上。方向の観測として残す。
- **赤 X との交差は小さい。** 評価器の up を `×(1 + X/100)` すると +24 の衣装増分が 2 pt 以上過大になる（実機 −0.1〜+0.5、R-061 +3 で +0.1）。赤を入れなければ増分 0 で、実機の小さな増分（同一編成で 14.0 / 14.1 / 14.6）は未説明のまま。X=23 の値は水着フブキ0 13.6 / 水着ノエル0 13.3 / 恒常マリン1 15.5 とも報告されており（会話由来、X=23 は推定）、X 26 の値からいずれも −0.1。
- **量子化では救えない。** round / ceil / floor の差は RMSE で 0.1 以下。
- **水着フワワの青 45/0 と 0/0 の差**は、青を使う候補でも RMSE 差 0.5 以下で、どちらでも衣装欄を説明しない（provenance の裁定には使わない）。
- **negative control**: ピュア 1 人（恒常みこ入替）では衣装欄は非表示で、候補評価器も条件不成立で 0 を返す。
- 素値（P+T+S）で重み付けした評価器も試したが、9 編成の素値は 23.5k〜25.9k で差が小さく結果は変わらない（Lv 70 の 2 枚は最大 Lv の値で代用）。

公開情報: `by_live_leader_skill` / `LiveDeckEvaluation` / `liveDeckEvaluationCoefficientPermilMultiply` / `LiveDeckEvaluationScoreUpPermilUp` の算出コードや式は見つからなかった。攻略サイトの検索要約には「スコアサポートはスコア UP スキルの効果を上げる効果で、スコア自体を直接は上げない」「スコアボーナスはアクティブスキルと乗算で、アクティブが発動しているときだけ効く」という記述があった（外部解析・要約のみ。本文は本環境から取得できず未確認）。これは「アクティブのスコア UP を一様に ×1.25」の解釈と整合するが、その解釈は表示欄の絶対値では上の下限で反証されているので、表示評価器は実スコアの意味とは別の量を出していると考える。

この候補族の探索はここで打ち切る。その後の典獄クロニー 60% の観測で、衣装欄は青・パッシブ支援がないときだけ `S/100 × アクティブ` に一致し、あるときの配賦が問題だと分かった（上の「リーダー衣装のスコアサポート」）。次の観測もそちらの 1 件に統合する。

## 実験・実装時のルール

- Golden観測値をモデルに合わせない。
- 実機報告は最優先だが、単発報告を無誤謬と扱わない。`reported / rechecked / cross-checked` を分ける。
- 1ケースだけに合う定数を一般化しない。
- 同時に複数要因が変わった比較から単独因果を主張しない。
- カード事実はID・開花・role・provenanceを確認してから使う。
- モデル変更前に既存コーパスで反証を探す。
- 実ライブのスコア式と表示ユニットスコアを混同しない。
