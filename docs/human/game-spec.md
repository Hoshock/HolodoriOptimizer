# ホロドリ ゲーム仕様メモ

実機観測などで裏付けられた変わりにくい仕様の概観。証拠状態は [evidence-policy.md](./evidence-policy.md)、カード出所は [card-data-provenance.md](./card-data-provenance.md)、表示スコア詳細は [display-score.md](./display-score.md)。

## ユニット

- リーダー1人とメンバー5人は別枠。
- **リーダーカードから試算に入るのは衣装スキルと、そのホロメンの赤ホロメンボードだけ**。リーダーカードのP/T/S・開花段階・パッシブ・アクティブ・SPはどこにも入らない（2026-09-16 ユーザー指示で明文化）。衣装スキルの内容は開花段階で変わらないので、リーダーの開花段階は値を動かさない。
- 赤ホロメンボードはリーダーにしたホロメンのものがメンバー5人へ効く。歌唱者条件などの発動判定もそのホロメン基準で、カードではなくホロメンの状態で決まる。
- 総合力はメンバー5人から作る。衣装スキルの発動条件もメンバー5人だけを数える（リーダー自身は数えない）。
- count人を選ぶ確認済み効果は、対象集合の素値P+T+Sが高い順から選ぶ。
- スキル文の「〜が2人以上で」は**発動条件**、「〜2人の」は**効果の対象人数**で、別のもの。カードデータも前者だけを `condition` として構造化する（アーニャ・メルフィッサのパッシブ「holoroが2人以上で自身の全パラメータが33%UP」は `condition: affiliationCount min 2` で holoro が1人なら不発。アイラニ・イオフィフティーンの「ピュアタイプ2人のテクニックが41%UP」は `condition: always` + 対象 `type: pure, count: 2` なので、ピュアの人数によらず発動する — 変わるのは効果の当たる人数）。発動の可否を数えるときに対象人数を条件と読み替えない。

## カードと開花

★5の確認済み強化段階:

| 段階 | 主な強化    |
| :--- | :---------- |
| 1凸  | Active      |
| 2凸  | 全パラ+10%  |
| 3凸  | SP          |
| 4凸  | Passive     |
| 5凸  | Connect関連 |

`cards.json` トップレベルは最大開花側として扱う取り込みレコードで、全件実機確認済みという意味ではない。途中開花は `cardAtBloomWithProvenance()` で出所を区別する。記録のない段階は「未確認」で、計算には最近傍の凸の内容をそのまま流用する（2026-09-15。÷1.1 の推定は廃止）。抽出マスターから入れていた途中値 4 件は 2026-09-15 の実機確認で実機と一致したので `observed-text` へ上げた（どのマスターから入れた値かは `bloomEvidence.ts` に残している）。実データに `extracted-master-variant` は残っていないが、新しく転記するときは実機目視と区別する。マスターのスキル level 番号と凸段階はカード共通で一律対応させない — 支持する証拠がない。

衣装スキルはリーダーカード、パッシブはメンバーカードの効果として扱う。カード仕様を議論するときはroleを混同しない。開花段階が意味を持つのはメンバーとして使うときだけで、リーダーに置いたカードの開花段階は試算に効かない。

## カード詳細P/T/S

カード本体Lv・開花、青・緑、所属向けパラメータ等が反映される。赤、メモリーのユニットパラメータ、メンバー強化、編成条件衣装/パッシブはカード詳細P/T/Sに直接入らない。

## ホロメンボード

- 青: メンバー本人のP/T/S、Active発動率/頻度
- 緑: アカウント全体のP/T/S・所属効果
- 黄: 楽曲スコアボーナス・ホロワーク報酬。曲ボーナス上限10%
- 赤: リーダー時にメンバー5人へP/T/S、歌唱者条件、スコアサポート等

解放済みのマスは**外して振り直せる。外すと素材も返ってくる**（2026-09-13 に振り直しを実機で確認、素材が返ることは 2026-09-16 ユーザー報告）。返還の単位（1 マスずつか・全額か）は未確認。

赤パラメータ効果と赤スコアサポート表示換算は別問題。

## 総合力

ユニット編成画面は6項目の加算として扱う。

1. メンバーパラメータ
2. 衣装スキル
3. ホロメンボード
4. パッシブ
5. メモリー
6. メンバー強化

各項目は素値基準で独立算出し、連鎖乗算しない。

## 表示ユニットスコア

```txt
unitScore = ceil(totalPower × (1 + scoreBonus / 100) × 2.03734)
```

カテゴリは現在 `Costume / Active / Board / Passive / SP` を観測。内部式は [display-score.md](./display-score.md)。

## 個別の実機訂正

水着フワワ `fuwawa-abyssgard-02` の衣装は2026-09-12再確認で、

```txt
ピュアタイプ2人以上で全員の全パラメータ30%UP
ピュアタイプ2人以上で全員のスコアサポート25%
```

の2行。両効果とも条件付き。旧「後半25%は無条件」解釈は誤り。

## 楽曲・イベント

所属名だけで歌唱者を解けない曲は `songSingers.ts` の明示データを使う。イベントのメンバー対象とホロメン対象は別。イベントスコアボーナスの表示ユニットスコア内での適用位置は未確認。

**曲の長さは表示ユニットスコアに入らない**（2026-09-16 ユーザー報告「散々検証したので実機でも入ってないことは確認済み」。個別の観測記録は残っていないので `reported`）。曲を選んで変わるのは 黄ボードの楽曲スコアボーナス（曲ごとの固定 %。ボード欄へ）・赤ボードの歌唱者条件・イベントスコアボーナスの 3 つだけで、アクティブ欄 / SP 欄の評価区間は曲によらない（[display-score.md](./display-score.md) の共通仮想タイムライン 200 秒はこれと整合する）。曲長が効くのはライブ側の試算（発動頻度の最適化）だけ。
