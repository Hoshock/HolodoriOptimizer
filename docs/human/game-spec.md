# ゲーム仕様まとめ(hololive Dreams)

本ツールのデータスキーマとスコアモデルの根拠となる、『hololive Dreams』のゲーム仕様の整理。公式がスコア計算式を公開していないため、一部はコミュニティの解析・攻略サイトに基づく。**「未確認」と付した項目は実装時にゲーム内実測で裏取りすること。**

## 基本情報

- 正式名称: 『hololive Dreams』(公式略称「ホロドリ」)。開発・運営はカバー株式会社 × 株式会社 QualiArts。
- 2026-07-23 全世界同時リリース。iOS / Android / PC (Steam)。リズムゲーム + パーク経営・育成。
- 登場タレント 50 名以上、楽曲はリリース時 150 曲以上(2026-09-08 時点で 197 曲。ツールにも全曲登録済み。週に数曲ペースで追加)。

## カード(メンバーカード)

- レアリティ★1〜★5。★5 は 2026-09-08 時点で 73 枚(2026-08 末の 70 枚に水着 3 枚が追加)、月数枚〜十数枚ペースで増加中。1 ホロメンに複数枚(通常・水着等)が存在し始めている。
- パラメータ 3 種: **パフォーマンス / テクニック / センス**(合計が「トータル」)。★5 のトータル最大値はほぼ横並び(約 25,800〜26,000)で、P/T/S の配分がカード個性。
- タイプ 3 種: **キュート(ピンク) / ハッピー(黄色) / ピュア(緑)**(色は 2026-08-31 ユーザー確認)。加えて**所属**(0期生・1期生・ゲーマーズ等。複数所属あり)がスキル発動条件に使われる。
- カード 1 枚が持つスキルは 4 系統:
  | スキル系統       | 発動条件                     | 例                                                                     |
  | :--------------- | :--------------------------- | :--------------------------------------------------------------------- |
  | 衣装スキル       | リーダー設定時のみ、常時     | 「0期生が2人以上で全員の全パラメータ 50% UP」「全員のセンス 120% UP」  |
  | パッシブスキル   | メンバー時、常時             | 「1期生2人のセンス 43% UP」「ピュアタイプ2人のスコアサポート効果 11%」 |
  | アクティブスキル | ライブ中に時間経過で確率発動 | 「24秒毎に中確率で10秒間スコア 100% UP」(ライフ条件つきもあり)         |
  | スペシャル (SP)  | SP ゲージ                    | 「10秒間スコアサポート効果 160%」+ SP 追加効果                         |
- スキル効果の分類: スコア UP / スコアサポート / 判定強化 / ライフ回復 / スキル発動率 UP / パラメータ UP の 6 種。
- ★4 以上のカードには「ライブ衣装」(リーダー時に装備、衣装スキル発動)と「パーク衣装」が付く。
- 育成: レベルと開花(いわゆる凸)。開花は最大 5 段階で、1 段階ごとにメンバー開花Pt を 1 消費する(開花Pt はガチャの重複入手。★5 はショップの「ブルームストーン」でも開花可)。段階ごとに「**1凸=アクティブスキル / 2凸=パラメータ / 3凸=スペシャルスキル / 4凸=パッシブスキル / 5凸=★3はパラメータ追加・★4以上はコネクト効果**」が 1 項目ずつ強化される(検索要約: Game8 801157 / AppMedia 80242753 / Gamerch 999671。**2026-09-01 ユーザーが仕様として正しいと確認**)。衣装スキルは強化対象外。**2凸のパラメータ上昇は ★5 で全パラメータ +10%**（2026-09-06 ユーザー実機確認。先行ツール holodori-sim の概算 +5% は誤り）。スキルの強化実数値はカード固有で非公開。段階別のスキル文言も**未確認**で、所持カードの実機確認で `bloomVariants` に埋める(それまでは `src/data/bloom.ts` の仮定倍率で割り戻して試算)。

## ユニット編成

- **リーダー 1 人 + メンバー 5 人の計 6 枠**。リーダー枠は衣装スキルの供給元で、メンバーとは別枠。**リーダーはメンバーと同一ホロメン・同一カードでも編成できる**(リーダーとメンバーの重複可)。メンバー 5 人同士は同一ホロメンの重複不可(2026-08-31 ユーザー確認)。
- **総合力（ユニット編成画面の表示値）の構造**（2026-09-08 ユーザー実機観測: 同じメンバー 5 枚でリーダー 2 通り、内訳 6 項目とメンバー別の表示値。ツールのモデルは ADR-004、実装は `src/engine/power.ts`）:

  総合力 = メンバーパラメータ + 衣装スキル + ホロメンボード効果 + パッシブスキル + メモリー効果 + メンバー強化ボーナス

  1. **メンバーパラメータ** = メンバー 5 人の**素のパラメータ**（開花後・ホロメンボード前の本体値）の合計。リーダー自身のパラメータは入らない（確定）。カード詳細画面の P/T/S（青・緑ボード込み）の合計とは一致しない。
  2. 各項目は**別々に**求めて最後に加算する。「前の補正後の値に次の倍率を掛ける」連鎖乗算ではない（確定）。衣装スキル・パッシブ・赤ボードの割合・メモリーの基準は素のパラメータ（確定に近い。衣装 +50% = 素値合計のほぼ 50%）。
  3. **ホロメンボード効果** = 青・緑による増分（カード詳細値 − 素値）+ リーダーの赤ボード（固定値 × 5 人 + 割合分。割合は同じパラメータの % を合算して素値合計に掛ける — 41190 と一致した強い推定）。曲を選ばないこの画面では「このホロメンが楽曲歌唱者に含まれる時」の効果は発動しない。曲を選んでリーダーが歌唱者に含まれると、歌唱者条件の P/T/S +10% も**このホロメンボード効果に入り、メンバー強化ボーナスの基準にも入る**（2026-09-11 実機: OFF → ON でボード効果 +12,251・強化 +367、他 4 項目は不変。ツールの切り上げ単位では増分が +12,253 と 2 点多く、単位は未確定のまま）。
  4. **パッシブスキル**のパラメータ UP は対象メンバー × 対象パラメータごとに ceil(素値 × %)（20340 と完全一致）。「◯◯2人の」は条件に合うメンバーのうち**対象パラメータが高い順に 2 人**にだけ効く（強い推定。全員に効くのではない）。
  5. **メモリー効果** = メンバー × パラメータごとに ceil(素値 × メモリー%)（7359 と完全一致）。**メンバー強化ボーナス** = メンバーごとに ceil((素値 + ボード + 衣装 + パッシブ) × 強化%) で、**メモリーは基準に含まない**（8709 / 7161 と一致）。
  6. 端数は各項目とも切り上げが合う（どの単位で切り上げるかは最も合う仮説を採用 — `src/engine/power.test.ts` のゴールデンケース）。0/1凸カードの素値は 2凸値 ÷ 1.1 の推定で ±1 の誤差があり、5 人合計で 2 点ずれる。
  7. 条件の人数カウントはメンバー 5 人に対して判定（リーダー枠は数えない）。スコアサポート・アクティブ・SP は総合力に入らない。

### 表示ユニットスコア（ユニット編成画面）— ツールのランキングの本体

ツールの順位づけはこの**表示ユニットスコア**で行う（総合力 = `src/engine/power.ts`、スコアボーナスとユニットスコア = `src/engine/displayScore.ts`。実ライブのスコアではない — 下の節）。

- **確定**（2026-09-08 の実機 20 ケース）: **ユニットスコア = ceil(総合力 × (1 + スコアボーナス / 100) × 2.03734)**（20 ケース全一致。係数の意味は未確定）。**スコアボーナス** = アクティブスキル + ホロメンボード効果 + パッシブスキル + スペシャルスキル の 4 項目（各 小数 1 桁）の加算。アクティブスキル欄は**青ボードの発動率・発動頻度を含まない**基準値（青を変えても 77.0% のまま）、スペシャルスキル欄はメンバー順・青ボード・リーダーを変えても不変。青の発動頻度の効果は単調でない（頻度 0 → 4 → 8 → 12% でボード欄 4.6 → 4.7 → 4.4 → 5.0 — 9.13〜9.15 と 2026-09-09 追加の 12%）。
- **確定**（2026-09-09）: 各欄の値は **0.1%（permil）単位の切り上げ**で整数化される。アクティブ欄は四捨五入だと 20 ケース中 15 しか一致しないのに、切り上げなら **20 ケースすべて実機と完全一致**する（SP 欄も 10 → 15 件に増える）。サーバー応答が各カテゴリを permil の整数で返すこと（外部情報）と整合する。仮想タイムラインの長さ **200 秒**もこの一致で裏づけられた（120 / 180 / 220 / 240 / 300 秒ではアクティブ欄の一致が 0〜1 件）。
- **強い推定**: アクティブ欄 = 5 人共通の 200 秒タイムライン（各秒の発動候補のスコア UP を発動確率 高 55 / 中 46 / 低 37 で重みづけし、確率の合計で正規化）。SP 欄 = アクティブ欄 × スコアサポート% × 効果時間 / 12000 + 発動率 UP の増分。
- **外部情報**（ゲーム内に数値表示がなく実機確認はできない。2026-09-09 共有）: 発動確率の 3 段階の実数値はコミュニティが公開しているマスターデータでも 低 37 / 中 46 / 高 55%（‰ の整数）で、上の推定値と一致する。青ボードの 2 種の効果も「発動確率 UP（‰ 加算）」「クールタイム短縮（‰）」という別々の効果種別として持たれている。**確定するのは効果の種別と値だけで、スコアボーナス欄がその値をどう換算するかは別問題**。またサーバー応答ではスコアボーナスが **アクティブ / リーダー（衣装）/ パッシブ / スキルツリー（ホロメンボード）/ スペシャル の 5 カテゴリの独立した値**として返る。表示が 4 欄なのは実機 20 ケースで衣装（リーダー）由来が 0 だったからで、源が 4 種類しかないわけではない。
- **未解決**: 青ボードの反映（発動率は確率に加算・頻度は周期を割る、という仮説）と、スコアサポートのボード欄 / パッシブ欄への配賦 — この配賦はサーバー側のカテゴリ別算出の再現ではなく**算出式が不明なあいだの近似**。リーダーの赤「全員のスコアサポート効果 +28.1%」はボード欄・パッシブ欄を大きく増やす（13.2 → 36.7、2.2 → 3.1）がアクティブ欄は変えない（合計への換算は下の 2026-09-11 の確定を参照）。
- **現在の精度**（実機 20 ケース。モデル − 実機。`src/engine/displayScore.test.ts` に全ケースの表）:

  | 項目           |                 誤差 |
  | :------------- | -------------------: |
  | アクティブ欄   | 0（20 ケース全一致） |
  | SP 欄          |        −0.4〜+0.6 pt |
  | ボード欄       |        −1.5〜+2.9 pt |
  | パッシブ欄     |        −1.6〜+0.8 pt |
  | 合計           |        −0.8〜+2.3 pt |
  | ユニットスコア |         −0.4%〜+1.0% |

  （2026-09-09 に青ボードの実効発動率を実機値へ訂正した後の数字 — フブキ水着 39.0%・ぺこら恒常 30.0%・みこ水着 36.0%・フワワ水着 45.0%。ボード欄の幅が広がったのは入力の実機値が変わったためで、モデルは変えていない。訂正でボード欄が実機と完全一致するケースも出た（9.12 / 9.16））

- **確定**（2026-09-11 の実機 8 点）: 曲を選ぶと**黄ボードの楽曲スコアボーナスはスコアボーナスのホロメンボード効果欄に入る**。総合力は変わらず（258,144 のまま）、アクティブ / パッシブ / SP 欄も変わらず、ボード欄だけが 黄 0% の 14.2 から 黄 10% で 36.8 に増えた（ユニットスコア 1,259,596 → 1,378,455。黄 0 / 2 / 3 / 5 / 5.4 / 7.4 / 9.86 / 10% の 8 点は `docs/ai/tmp/status.md`「黄ボードの適用位置」）。**強い推定**: 増分は 黄 × (100 + アクティブ + パッシブ + SP) を表示に丸める前の値でボード欄に足したもの（8 点すべてと整合。表示済みの値から計算すると 9.86% で丸め境界が合わない）。曲を選ばない画面では黄は入らない。
- **確定**（2026-09-11 の実機 4 象限。同じ編成で赤の歌唱者条件 OFF / ON × 黄 0 / 10%）: リーダーの赤「全員のスコアサポート効果」（歌唱者条件で 28.1 → 52.1%）は アクティブ / SP 欄を変えず、**ボード欄 +20.9・パッシブ欄 +0.2・合計 +21.1**。黄 10% は赤 OFF / ON の両方で ボード +22.7・合計 +22.7 で、黄と赤の表示上の効果は 0.1% の精度で加法分離する（交差する倍率はない）。ユニットスコアの式は 4 点とも 1 点単位で一致。合計の増分は 0.88 × 24 = 21.12（下の確定）。**未解明**: ボード / パッシブへの配賦（`docs/ai/tmp/status.md`「赤の歌唱者条件」、pending 12）。
- **確定（実機再現則。2026-09-11 の水着おかゆリーダーの 3 点）**: リーダーの赤「全員のスコアサポート効果 +X%」は**表示スコアボーナスの合計を 0.88 × X pt 増やす**。同一条件で赤 R-002（歌唱者条件 +10%）だけを ON / OFF した単独差分が 合計 +8.8（ボード +8.4・パッシブ +0.4、アクティブ / SP / 総合力は不変）で、上の +24 → +21.1 と、リーダー・ボード状態をまたぐ補助証拠（0 → 28.1 で +24.8、0 → 52.1 で +45.9）もすべて 0.88 × X に表示の量子化の範囲で一致する。ツールはこの換算（`src/engine/displayScore.ts` の `RED_SCORE_SUPPORT_DISPLAY_FACTOR`）を使う（旧「(1 + X/100) 倍」= 0.924 pt / X は廃止）。確定したのは表示合計への実効換算で、ゲーム内部が文字どおり 0.88 を掛けているとは断定しない（候補秒の時間率などから結果的に出ている可能性が残る）。**未解明**: ボード欄 / パッシブ欄への配賦（パッシブ側の増分は +10 で +0.4、+24 で +0.2 と X に比例せず頭打ち。ツールは合計を全部ボード欄に入れる近似で、内訳 2 欄が ±0.4 程度ずれる）。同じ 3 点で、曲なし → おかゆソロ曲（黄 3.0%）の増分は ボード +6.8・合計 +6.8 で他 3 欄は不変、139.5 + 黄 6.8 + 赤 8.8 = 155.1 と黄・赤は加算分離する（`docs/ai/tmp/status.md`「赤スコアサポートの 0.88 換算」）。
- ツールの順位づけの値は **曲条件つきの表示ユニットスコア（試算。曲を選んでいれば黄をボード欄に含む） × (1 + イベントスコアボーナス)**。黄は候補ごとの アクティブ + パッシブ + SP に比例して効くので、曲を選ぶと候補の順位が変わりうる（以前の「ユニットスコアに (1 + 黄) を後掛けする」実装は実機と一致せず 2026-09-11 に廃止）。イベントの掛け方は未確認の仮定のまま。**曲の長さ・譜面はこの計算に入らない**（2026-09-09。それ以前は曲長に基づくアクティブ・SP の期待値モデルを内訳として持っていたが、順位づけには使っておらず削除した — ADR-006）。

### 実ライブスコア（曲をプレイしたときのスコア）— 未実装

- ライブスコアは総合力を土台に、コンボ・判定・アクティブ発動・スコアサポート・強化ボーナスで積み上がる。「1 ノーツスコア ≒ ユニットスコアの約 2.59 倍」という考察報告あり（**未確認**）。
- **ツールは実装していない**（2026-09-09 時点）。表示ユニットスコアの再現とは別問題（譜面のノーツ列、メンバー順、SP の発動位置と順序、アクティブの周期と重なり、スコアサポートの重なり、RNG の期待値）なので、将来**別エンジン**として設計する（ADR-006。旧 `src/engine/live.ts` の曲長で按分する簡易期待値は精度未検証のまま順位づけにも使われていなかったため削除した）。
- 実ライブスコアが解明されるまで、曲別の最適化で意味を持つのは黄ボードの楽曲スコアボーナス（ボード欄に入り、候補ごとの効き方が違う）とイベントスコアボーナス（編成に依存しない倍率の仮定）だけ。曲の長さ・コンボ数とアクティブスキルの発動周期の噛み合わせは、実ライブエンジンができてから扱う。

## 楽曲

- 各曲は Original / Cover の別、難易度 4 段階(easy / normal / hard / expert、Lv 1〜30 程度)、演奏時間、難易度別コンボ数、歌唱アーティスト(ホロメンまたはユニット名)を持つ。
- **曲にタイプ(キュート等)属性はなく、「曲との属性一致ボーナス」は存在しない模様**(既存ツールの楽曲データにも属性フィールドなし。隠し補正の有無は**未確認**)。
- 曲別最適化が意味を持つのは主に、曲の長さ・コンボ数とアクティブスキルの発動周期の噛み合わせ（**実ライブスコアのエンジンは未実装**なので、現在のツールで曲を指定して変わるのは黄ボードの楽曲スコアボーナス（ボード欄）とイベントのスコアボーナスだけ — 上の「実ライブスコア」）。

## ガチャと課金(2026-08-31 調べ、仮想ガチャシミュレーションの根拠)

攻略サイト本体(Game8 / AppMedia / Gamerch / horodori.com)は開発環境のネットワーク制約で直接閲覧できず、検索エンジンの要約経由で確認した。**ゲーム内実測での裏取りは未実施。**

- **通貨**: ダイヤ 2 種。**レッドダイヤ**(配布などで入手する無償)と**ブルーダイヤ**(購入する有償、所持上限 1,000,000)。両方所持時は**レッドダイヤが優先消費**される。ほかにガチャチケットあり。
- **ガチャのコスト**: 通常のガチャは **1 回 250 個・10 連 2,500 個**(どちらのダイヤでも可)。**1 日 1 回 90 個の割引単発**と**スタートダッシュガチャ(10 連で★5 が 1 枚確定)はブルーダイヤ専用**。
- **提供割合(通常)**: **★5 = 5% / ★4 = 10% / ★3 = 85%**。**10 連の 10 枚目は★4 以上確定**(内訳 ★5 5% / ★4 95%)。
- **ピックアップ**: 新カードピックアップは対象 1 枚 **1.0000%**(例: その他★5 は各 0.0508%)。選択式イベントガチャの例では本命 1.0000% + 残り 4 人各 0.2500%。**初心者応援ガチャ**(開始 7 日間)は好きな★5 を 3 人選んで各 **0.6666%**(対象はいつでも変更可)。
- **天井**: ガチャ Pt **200 回ぶん(ダイヤ 50,000 個)** でピックアップ対象と交換。**Pt はガチャごとで引き継ぎ不可**、開催終了で未使用 Pt はホロステッカーに変換される。
- **ショップ価格**: 確認できた通常価格パックは「**ブルーダイヤ×8,200 = 9,800 円**」(1 個あたり約 1.19 円。大きいパックほど単価が安い)。ほかに回数限定の「リリース記念!お得なダイヤ」(480 円のパックが単価最安)があるが、**全パックの個数・価格の一覧は未確認**。月額は**ホロパスポート 480 円**(報酬 2 倍・ブースト上限 2 倍・ブルーダイヤ 360 付与)、ホロメン別**メンバーシップ 290 円/月**。
- **★3・★4 カード**: 一覧は Game8 / AppMedia に存在するが直接閲覧できず、**カード名・種類数・タイプは未確認**。チュートリアルガチャの固定排出が「★5×1・★4×1・★3×3」であることから★3/★4 の存在は確実。仮想ガチャでは「1 ホロメン 1 枚」と**仮定**しホロメン名のみで表示している(最適化ツールの対象は★5 のみで不変)。
- リリース記念ログインボーナスの配布はダイヤ合計 2,500 個(仮想ウォレットの初期値の根拠)。

## ホロメンボード

- ホロメンごとのマス解放型育成ボード(リリース済み)。マスは発動条件で 3 分類: リーダー時のみ / メンバー時 / 編成外でも発動(色との正確な対応は**未確認**。**青 = メンバー編成時にそのホロメン自身へ適用**は 2026-09-06 ユーザー確認)。青ボードのノード構成は全ホロメン共通(31 マス、左右 2 型) — `.claude/skills/parameter-calculation/references/blue-board.md`。緑ボードも全ホロメン共通(24 マス、下側、反転なし)で、効果は編成の有無にかかわらずアカウント全体に効く(全員向けの P/T/S UP・所属向けの全パラメータ UP・報酬系) — 同 `references/green-board.md`(2026-09-07 ユーザー実機確認)。黄ボードも全ホロメン共通(31 マス、青の反対側で形は青の左右反転)で、効果はパラメータでなく楽曲のスコアボーナス(本人のソロ / 本人を含むユニット / 全体楽曲)とホロワークの報酬(レッスン Pt / キューブ / 特訓アイテム)。フワワ・モココのソロ系は「歌唱者が FUWAMOCO のみの楽曲」が対象。楽曲スコアボーナスは合計 10.0% が上限。楽曲の区分はホロメン 1 人の曲がソロ・複数人の曲がユニット・hololive IDOL PROJECT の曲が全体楽曲(`src/data/songSingers.ts`)。アカウント全体に効く(編成外でも乗る)。スコア式の位置は 2026-09-11 に実機で確定(曲選択時のスコアボーナスのホロメンボード効果欄に入る — 上の「表示ユニットスコア」)— 同 `references/yellow-board.md`(2026-09-08 ユーザー確認)。赤ボードも全ホロメン共通(63 マス、上側。中心から 7 マス目のコネクトマスから上エリア 22 / ライフ系 20 / ステータス系 21 の 3 エリアに分かれ、ライフ系が左か右かはホロメンごとに固定 — `holomen.json` の `board.lifeSide`)で、効果は**リーダー用**: そのホロメンをリーダーにしたライブでメンバー 5 人(リーダーは含まない)の全パラ / P・T・S の固定値と割合、歌唱者条件(「このホロメンが楽曲歌唱者に含まれる時」)の P・T・S +10.0%、スコアサポート効果、ライフ、判定強化 / ライフ回復のホロメンスキル、ライブ報酬(メンバー Exp・ホロゴールド) — 同 `references/red-board.md`(2026-09-08 ユーザー実機確認 4 回)。
- 強化にはマス対応色のキューブと対象ホロメンのボードポイントが必要。マスは初期地点から隣接連結でのみ解放。
- **青マスにはスキル発動頻度を上げる効果があり、SP・アクティブスキルの期待値に影響する**（2026-09-01 ユーザー情報）。1 マスあたりの効果量・ホロメンあたりのマス数・解放コスト、頻度が「発動率を上げる」のか「周期を縮める」のかは**未確認**。
- 同じカードでもボード進捗でユニットスコアが変わるため、最適化ではボード補正を入力パラメータとして扱う(Step 0 のホロメン → ボードで 4 色とも入力できる。2026-09-08 に 4 色そろった)。
- **カード詳細画面の P/T/S への反映**（2026-09-06 ユーザー実機確認）: 青・緑ボードは反映され（コネクトマスの増幅も込みの値）、赤ボードは反映されない。青ボードにはパラメータのほかアクティブスキルの発動率 UP と発動頻度 UP がある。計算モデルの詳細は `.claude/skills/parameter-calculation/SKILL.md`、アカウントの現在値は `docs/ai/tmp/status.md`。
