### 編成 2 は再読でも 40.6（`衣装欄 = 0.60 × アクティブ欄` の棄却）

再読で 総合力の内訳と ユニットスコアも取った。

```txt
ユニットスコア 555096
総合力 106264（メンバーパラ 75066 / ホロメンボード 20265 / パッシブ 3380 / メモリー 4510 / 強化ボーナス 3043）
スコアボーナス 156.4（衣装 40.6 / アクティブ 67.3 / ボード 0 / パッシブ 8.6 / SP 39.9）
```

`ceil(106264 × (1 + 156.4/100) × 2.03734) = 555096` で**外側の式が 1 点単位で一致**するので、合計 156.4 は `cross-checked`。

アクティブ欄 67.3 から `0.60 × A ≤ 0.60 × 67.3 = 40.38`。**切り上げ・四捨五入・切り捨てのどれで落としても 40.4 以下**にしかならず、実機 40.6 と両立しない。3 欄の配分は projective で `W_P = ΔP` が約分されるため、パッシブの対象をどう選んでも衣装欄は `0.60 × A` のまま動かない。**「衣装欄 raw = 0.60 × アクティブ欄 raw」はこの 1 件で棄却される。**

### カードの Lv はスキルの数値を変えない

メンバーパラメータ 75066 は 5 人で平均 15,013 で、`cards.json`（上限側）の素値合計 約 23,600 の **64% 程度**しかない。**それでもアクティブ欄は 8 編成すべて実機と一致した**（SP 欄も 3 件一致）。したがって**スキルの数値（スコア UP % ・効果時間・発動周期・スコアサポート %）は Lv に依存しない**と扱ってよい。Lv が効くのは パラメータと、それを介した「N人」の対象選抜だけ。

### パッシブの対象選抜では説明できない（2026-09-15 に取り下げ）

編成 1 の ハッピータイプ 3 人のカード詳細 P/T/S は マリン 8672 / 11775 / 9498（合計 29945）、レイネ 5197 / 6386 / 5619（17202）、ロボ子 7006 / 5030 / 5081（17117）。**順位は マリン > レイネ > ロボ子 で、モデルが選ぶ マリン + レイネ と同じ**。緑ボードの解放も レイネ と ロボ子 は同じ 4 マスなので素値でも順位は変わらない。

したがって「実機は マリン + ロボ子 を選んでいる（対象を強制すると パッシブ raw 2.4374 で要求区間に入る）」という読みは**成り立たない**。編成 1 の 0.1 も、配分か量子化の位相の側にある。

## 読み取れること

1. **パッシブ支援がない 4 件（K5 / 6 / 7 / 8）は全会一致**。独立に切り上げる現行の規則は 4/4 外し（すべて実機より 0.1 高い）、「アクティブ欄との差として量子化する」形が 4/4 当てる。**現行の位相は棄却**。
2. **1 と 3 は判定に使えない。** 判定は `ceil(1.6 × A)` がどちら側に落ちるかで決まるが、この 2 件は `1.6A` が 0.1 の境界から 0.0005 / 0.0008 しか離れていない（編成を選ぶときに `A` と `0.6A` の境界距離しか見ていなかった設計ミス）。raw が 0.001 動けば答えが反転するので、1 と 3 が逆を向いたことは矛盾ではない。
3. **残る食い違いはパッシブ支援がある編成に限られ、衣装欄とパッシブ欄のあいだの移動になっている。** 総量 `T`・アクティブ欄・ボード欄・SP 欄・合計はすべて合う。必要な raw の移動は 編成 1 が `(−0.05, +0.05)`、編成 2 が `(+0.16, −0.16)`、編成 3 が 0。**符号が逆なので、`W_P` を定数倍する形（`W_P = k × ΔP`）では両立しない** — 編成 1 は `k ≥ 1.022`、編成 2 は `k ≤ 0.979` を要求する。
4. **次に要るのは 編成 1 と 2 を、リーダーだけ 恒常みこ 0凸（スコアサポート 0）に替えた baseline。** 支援 0 ならパッシブ欄がそのまま `ΔP` になるので、配分を経由せずに `T` の内訳が読める。モデルの予測は 編成 1 が パッシブ 2.4、編成 2 が パッシブ 8.8。ここが実機とずれていればパッシブ支援の評価そのもの、合っていれば配分だけの問題に絞れる。

## 支援なしリーダーの baseline（2026-09-15）

同じメンバーで**リーダーだけ 恒常みこ 0凸（スコアサポート 0）**に替えた。支援 0 ならパッシブ欄がそのまま `ΔP` になる。

|   # | リーダー     | 衣装 | アクティブ | ボード | パッシブ |   SP |
| --: | :----------- | ---: | ---------: | -----: | -------: | ---: |
|   1 | 恒常みこ0    |    0 |       69.3 |      0 |  **2.4** | 40.3 |
|   1 | 典獄クロニー | 41.5 |       69.3 |      0 |  **2.5** | 40.3 |
|   2 | 恒常みこ0    |    0 |       67.3 |      0 |  **8.8** | 39.9 |
|   2 | 典獄クロニー | 40.6 |       67.3 |      0 |  **8.6** | 39.9 |

**baseline は 2 件ともモデルと完全一致**（予測 2.4 / 8.8）。つまり `ΔP`（パッシブのスコアサポートがタイムラインへ足す量）も、総量 `T = 0.60 × A + ΔP` も正しい。

決定的なのは、**リーダー支援を足すとパッシブ欄が動く**こと。編成 1 は `2.4 → 2.5`（+0.1）、編成 2 は `8.8 → 8.6`（−0.2）。**production は `W_P = ΔP` なので配分が約分され、パッシブ欄は動かない**（K5 / K6 でも実機が動かなかったので気づけなかった）。3 欄の再配賦そのものは実機で起きていて、その重みがモデルと違う。

必要な補正は `W_P` を 編成 1 で 2〜6% 大きく、編成 2 で 2〜3.5% 小さく。**符号が逆なので定数倍では両立しない。** 編成 2 だけ、同じ 2 人に 11% が 3 枚積まれて +33% になっている（他はすべて +11%）。**同じメンバーへ積み重なった支援は、重み `W_P` へは線形に効かないのではないか** — これが現時点の作業仮説。
