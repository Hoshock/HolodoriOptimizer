### 編成 1 はパッシブの対象選抜で説明がつく

ハッピータイプは マリン(素値合計 23613) / ロボ子(23563) / レイネ(23711) の 3 人で、ロボ子の「ハッピータイプ2人のスコアサポート効果11%」が 2 人を選ぶ。対象を強制して計算すると:

| 対象                            |                                  パッシブ欄 raw |
| :------------------------------ | ----------------------------------------------: |
| マリン + ロボ子                 | **2.4374**（実機の要求 `[2.4353, 2.5]` に入る） |
| マリン + レイネ（モデルの選択） |                                          2.3855 |
| ロボ子 + レイネ                 |                                          2.1661 |

モデルは `cards.json`（上限 Lv）の素値合計で レイネ を 1 位に選ぶが、実機は **マリン + ロボ子**を選んでいる。**レイネが育っていなければそのまま説明がつく** — 素値合計は 23514〜23711 と 0.8% の幅しかないので、Lv 差が順位をひっくり返す。衣装欄には効かないが、**パッシブ欄の対象選抜には Lv が効く**。

### 編成 2 だけは構造が合わない

アクティブ欄 67.3 から `A ∈ (67.2, 67.3]`、したがって `0.60 × A ∈ (40.32, 40.38]`。**切り上げ・四捨五入・切り捨てのどれで落としても 40.4 以下**にしかならず、実機の **40.6 とは両立しない**。しかも 3 欄の配分は projective なので、パッシブの対象をどう選んでも衣装欄は `0.60 × A` のまま動かない（`W_P = ΔP` で約分される）。

つまり 編成 2 は「衣装欄 raw = 0.60 × アクティブ欄 raw」そのものを破る。スコアサポート持ちのパッシブが 4 枚積まれている唯一の編成で、**パッシブ支援が大きいと衣装欄が増える**ように見える。ただし単発報告なので**まず再読が要る**。

## 読み取れること

1. **パッシブ支援がない 4 件（K5 / 6 / 7 / 8）は全会一致**。独立に切り上げる現行の規則は 4/4 外し（すべて実機より 0.1 高い）、「アクティブ欄との差として量子化する」形が 4/4 当てる。**現行の位相は棄却**。
2. **1 と 3 は判定に使えない。** 判定は `ceil(1.6 × A)` がどちら側に落ちるかで決まるが、この 2 件は `1.6A` が 0.1 の境界から 0.0005 / 0.0008 しか離れていない（編成を選ぶときに `A` と `0.6A` の境界距離しか見ていなかった設計ミス）。raw が 0.001 動けば答えが反転するので、1 と 3 が逆を向いたことは矛盾ではない。
3. **残る食い違いはパッシブ支援がある編成に限られる。** とくに 2 は、どの位相でも衣装欄 raw が **0.24 足りない**（実機を出すには 40.59 以上が要るがモデルは 40.35）。2 は 4 枚がスコアサポート持ちのパッシブを積んでいる唯一の編成で、モデルのパッシブ欄 raw も 8.76 と他の 3〜4 倍ある。
