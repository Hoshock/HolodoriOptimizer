## 実効値の再構成（raw なボード状態と導出値を分ける）

**実効値は手入力しない。** 各状態は 2026-09-13 の account snapshot の raw なマス集合に ON / OFF を当て、
実効値は production の `connectFactorMapOf` → `blueBoardEffects` で導出する
（`src/engine/displayScoreCategoryCorpus.fixture.ts` の `rateFrequencyBlue()`、
固定は `src/engine/displayScoreBlueWeight.test.ts`）。

snapshot は F3 の直後に取ったもので、この系列の**前**の状態なので、次の差分で観測時点を組み立てる。

| ホロメン             | snapshot からの差       | 根拠                                                                                                           |
| :------------------- | :---------------------- | :------------------------------------------------------------------------------------------------------------- |
| さくらみこ           | 発動頻度マス 3 つを戻す | ユーザーが「みこ `B-013` OFF」と書いているので、その前は ON。3 つとも戻っていることは下の「ΣF の読み」で決まる |
| 猫又おかゆ           | 発動頻度マス 3 つを外す | 同上（F0〜F3 の系列で おかゆ 側へ移したマスが、この系列では みこ 側へ戻っている）                              |
| フワワ・アビスガード | `B-018` `B-019` を足す  | `B-020` / `B-021` / `B-022` を 1 マスずつ開閉するには連結上この 2 マスが解放済みである必要がある               |

**ΣF の読み。** 状態名 F16 / F12 / F8 は ΣF そのもの（16 / 12 / 8%）。F16 は「S3' + フワワ `B-020`（+4）」、
F12 は「F16 − みこ `B-013`（−4）」、F8 は「RtM − フワワ `B-020`（−4）」なので、S3' の ΣF は 12 で、
そのうち 4 は フワワ 以外にある。**みこ が 3 マス（12%）・おかゆ が 0 マス**なら 3 つの名前がそのまま合う。

**再構成の裏づけ**（観測側だけで閉じるもの）:

1. **状態名と ΣF が一致する**（F16 / F12 / F8 がそのまま 16 / 12 / 8%）。
2. **ユニットスコアの外側の式が 9 状態とも 1 点単位で一致する**（総合力と 5 欄は観測値のまま）。
3. **ユーザー報告の「実効 rate 差はちょうど 3pt」**と、導出した みこ 42 → 39・フワワ 30 → 27 が一致する。
4. F3 から S1 への変化のうち、青の**発動率**側は フワワ の 24 → 30（`B-019` +3 / `B-021` +3、コネクト範囲外）だけ。

**もう 1 つの読み（採らない）。** 「みこ 1 マス（4%）・おかゆ 2 マス（8%）」でも ΣF の 3 つの名前は合う。
ただしその配置は F0〜F3 の **F2 と同じ**で、F2 の実機は pre-yellow の 3 欄合計が 27% 落ち込んでいる
（[display-score-20260913-frequency.md](./display-score-20260913-frequency.md)）。今回の S1 / S3' にその落ち込みはなく、
総量モデル（`支援/100 × E_blue` + 青の純増分。`W_blue` とは独立に確定している側）で必要な `E_blue` は 76 前後で、
F2 型の配置が返す 68 とは 12% 違う。**この判別はモデルを使っている**ので、観測だけで閉じた話ではない。
raw なボード状態そのものの export は取っていない。

**未確認**: フワワ が `B-018` / `B-019` / `B-020` / `B-021` / `B-022` 以外に新しく開けたマスがあるかどうかは
分からない。パラメータのマスなら表示スコアボーナスの 5 欄には効かない（総合力だけが動き、その総合力は実機の
報告値をそのまま入力に使っている）が、**もし発動率のマスを他にも開けていれば ΣR がこの表より大きい**。
ここは観測で閉じていない前提として残す。
