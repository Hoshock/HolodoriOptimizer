# ADR-023: 持っているコネクトは所持カードから導き、カード固有のコネクト効果の対応表を持つ

- Date: 2026-10-09
- Status: Accepted

[ADR-008](008-connect-effect-provisional-model.md) の Update（2026-09-11「`Card.connectEffect` は削除し、効果の一覧は形ごとの ‰ の候補として持つだけ」）と、同 Update（2026-10-02〜03「持っているコネクト（形 × ％ × 枚数）を登録し、その範囲でコネクトの最適化を行う」）の**所持の登録**の部分を置き換える。コネクトの一般モデル（範囲・‰・合成・丸め・向き）と、ボードのコネクトマスに**形 × ‰ を直接置く**入力は変えない。

## Decision

- **カード ID → コネクト効果**（既存 `CONNECT_EFFECTS` の ID。形と Lv1 / Lv2 の ‰）の対応表を `src/data/cardConnect.ts` に持つ。★5 84 枚・★4 54 枚の全件を抽出マスターから転記した【外部解析・実機未確認】。`Card` の項目には戻さず別モジュールにし、効果の定義（カードの性質）と、ユーザーがどのコネクトマスに何を置いたか（`connect-placements`）を別の概念のまま保つ。
- **持っているコネクト（形 × ％ × 枚数）は所持カードと開花段階から導く**（`connectInventoryOf`。カード 1 枚 = コネクト 1 枚、％ は `connectLevel(bloom)` の暫定モデルで 0〜4凸 = Lv1・5凸 = Lv2）。アカウントの「コネクト」で手で登録する画面と保存（`connect-inventory`）は廃止し、残っている保存は読まずに消す（2026-10-09 ユーザー指示「既存で登録しているコネクトは削除」）。「データの出力」からも `connectInventory` を外す。
- カード詳細に「コネクト」（範囲の形の図、Lv1 / Lv2 の ％、実機未確認の脚注）を出す。コネクトの配置候補をカードから提案・絞り込む機能は入れない（配置は従来どおり形 × ‰ で置く）。

## Context

★4 の収録（[ADR-022](022-star4-cards-fixed-only.md)）と一緒に、★5 全 84 枚のカード固有コネクト効果が抽出マスターからそろい、既存の 20 種（`CONNECT_EFFECTS`）の形 × ‰ と全件一致した。ユーザーの指示は「コネクトの登録を廃止し、所持カードにコネクトを紐づけることで、所持カードを登録すればコネクトのなにを持ってるか判別できるようにする」（2026-10-09）。手で登録する方式は、同じ情報（持っているカード）の二重入力で、枚数や ％ の入れ間違いが「所持に収まっていない」エラーになっていた。

ADR-008 の Update で `Card.connectEffect` を消したのは、当時カード → 効果の対応が実機確認できたカードにしかなく、ユーザーが画面の光る範囲を写すほうが確実だったため。いまは全件の対応があるので、**配置の入力は変えずに、所持の導出だけに使う**。

却下した代替案: (1) 対応表を `Card.connectEffect` に戻す — 効果の定義と配置を同じ型に混ぜると、配置の入力（形 × ‰）をカード指定に変える圧力になる。(2) 登録画面を残して所持カードから既定値を入れる — 二重管理が残る。(3) 配置もカード指定にする — ユーザーが要求していない。実機の配置（どのカードを置いたか）は保存に持っていない。

## Consequences

### Pros

- 所持カードと開花段階を登録すれば、持っているコネクトが自動で決まり、組み直しプランのコネクトの段がそのまま使える。
- 対応表のテスト（`cardConnect.test.ts`）で、全カードに効果があること・既存の 20 種を指すこと・レアリティの整合を固定できる。

### Cons

- カード → 効果の対応は外部解析で実機未確認（`pending.md` 6 / 20）。実機のカード詳細と違えば、その対応を直す。
- 5凸 = Lv2 の暫定モデルがそのまま所持の ％ になる。実機で違えば `connectLevel` を直す（1 か所）。
- 手で登録していた所持コネクトは消える（所持カードを登録していなければ、持っているコネクトは 0 になり、ボードに置いた配置が「所持に収まっていない」扱いになる）。
- 保存の封筒 `account` から `connectInventory` が消える（版は上げない。読む側は無い項目を空として扱う）。

## Update（2026-10-10）: 置いている配置と見比べる

所持の導き方は変えず、**ボードに置いている配置と見比べる場面**を足した（ユーザー指示「アカウントのコネクト、今何個使われているかもそこから見たい」「他で使われているコネクトを外さないと置けない場合、どこから取ってくるかというのを指定しておけるようにしたい」）。

- アカウントの「コネクト」と、ボードのコネクト効果の「一覧」に **使用 / 所持** を出す（`connectUsage`）。所持を超えて置いているものは消さずに赤で見せる。
- ボードで置くとき、倍率ごとに残りを出し、残り 0 の倍率を選ぶと警告して、同じ 形 × ％ を置いている場所から外して持ってくるかを選ばせる（`placementSlots`）。**超えて置くことは禁止しない**（「禁止まではしないがモーダルで警告を出す」）— ゲームでは同じカードを 2 か所に置けないが、ツールでは所持カードの登録漏れ（★4 など）でも配置を入れられるようにしておく。
- 所持カードが未登録でも見比べる（持っているコネクトは 0 枚。「いや照合する」）。却下した代替案: 未登録のあいだは見比べない（リソースの「未登録 = 制限なし」と同じ扱い）— ユーザーが採らなかった。組み直しプランのエラーは、所持カードが未登録なら「未登録です」の文言に分ける。
