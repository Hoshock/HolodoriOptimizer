# ADR-022: ★4 カードを正式なカードとして収録し、編成には自分で枠に置いたときだけ入れる

- Date: 2026-10-09
- Status: Accepted

## Decision

ゲームの ★4 カード 54 枚を、★5 と同じ `Card` 型の正式なレコードとして `cards.json` に収録する（`rarity: 4 | 5`、ID は `<holomenId>-star4-01`、`stats` は **Lv70**・2凸以上の本体値、スキルは最大開花側だけ）。値の出所は抽出マスター（HolodoriDB/holodori-db-jpn-diff、commit `6680c7c3`）で、権威順位は「外部解析」のまま（実機未確認）。読みは検索・並び用に推測で付け、公式読みとはしない。

**探索（おまかせ）の候補は ★5 だけのままにする。** ★4 はリーダーの指定・メンバーの固定として自分で枠に置いたときだけ編成に入る（`star4Pool.ts` が固定していない ★4 をエンジンの除外へ足す。「組み直すと」の候補プール・ホロメンでのリーダー指定・おかゆモード・仮想ガチャの ★5 プールも `star5Cards`）。カード一覧・カード詳細・所持の登録は全カードで、ピッカーは ★5 / ★4 の切り替えを持つ（既定は ★5）。

抽出マスターのスキル level 1 / 2 の原文は `masterSkillLevels.json` に資料として残すだけで、level 1 を 0凸の `bloomVariants` に転記しない（強化前の区間は「未確認」）。master の「ID1〜3期生」はゲーム内の所属名 AREA15 / holoro / holoh3ro に読み替える（2026-10-09 ユーザー指示）。★4 の SP に多い「ライフが N 回復」「GOOD 以上が PERFECT になる」は `SpecialSkillStructured` に `lifeRecovery` / `judgeUpgrade` を足して構造化し（試算には効かない）、未構造化のスキルを作らない。

## Context

★4 カードの固有情報（コネクト効果・スキル・パラメータ）が外部解析から全件そろい、ユーザーが実装を依頼した（依頼資料 2026-10-09）。従来は `Card.rarity` が 5 固定で、★4 / ★3 は仮想ガチャの「ホロメン単位の結果」としてしか存在しなかった（`src/data/README.md`「★5 探索プールと ★3/★4 仮想ガチャデータを混ぜない」）。

★4 を探索の候補に入れるかはユーザーの判断で「基本は入れない。ただし固定選択した時のみ入れる」（2026-10-09）。理由: 最適化は ★5 のみ対象という方針を保ちつつ、Lv70 の ★4 が上位に来ることはないので、候補を 1.6 倍にして探索を遅くする意味がない。一方で、自分で置いた編成（お気に入り・固定）を試算できないのは不便。

却下した代替案: (1) ★4 を候補に入れる — 上記のとおり遅くなるだけ。(2) ★4 を仮想ガチャ用の別データのまま置く — カード詳細・コネクトの導出（[ADR-023](023-connect-inventory-from-owned-cards.md)）に ★4 のカード単位の情報が要る。(3) `reading` を省略可にする — 並び・検索の規則（`src/ui/labels.ts`）とバリデーションが広く変わる。推測の読みは曲名（`songReadings.ts`）と同じ扱いで、既存の「reading は公式読みを保証しない」（`meta.json`）に収まる。(4) SP の追加効果 15 枚を未構造化（`structured: null`）にする — 「試算に未算入」という状態を UI に持ち込むより、試算に効かない効果として構造化したほうが文言も原文のまま出せる。

## Consequences

### Pros

- ★4 をリーダー・メンバーに置いた編成を、★5 と同じ経路（開花・ボード・コネクト）で試算できる。
- カード単位のコネクト効果（ADR-023）が ★4 にも引ける。
- おまかせの探索の速さと結果は変わらない（候補は ★5 のまま）。

### Cons

- ★4 の stats・スキル・コネクトは全件が外部解析で、実機の再確認を通していない（`pending.md` 20 に列挙）。実機と食い違えば実機を優先して `cardCorrections.ts` で直す。
- Lv70 の 2凸未満の本体値は ★5 と同じ「最大値 ÷ 1.1」の逆算で、master の `lv70Bloom0to1`（`ceil(base × 倍率 / 1000)`）と丸めで 1 ずれうる（どちらも実機値ではない）。
- `Card.rarity` を見るコードが増える（ピッカーの絞り込み・星のアイコン・プール）。★3 の実カードは依然持たない。

**Update (2026-10-09):** リーダーをホロメンで指定したとき（おかゆモードのおかゆんも同じ）は、そのホロメンの ★4 もリーダーの候補に入れる（ユーザー指示）。メンバーの枠には入らない。ピッカーのレアリティは すべて / ★5 / ★4 の 3 択（既定は ★5 のまま）。
