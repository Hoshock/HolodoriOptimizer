# ADR-011: 開花途中のスキル文言は「確認済 / 未確認」の 2 状態で扱う

Date: 2026-09-15

## Status

Accepted

## Decision

開花途中のスキル文言は、記録がある（確認済）か、記録がない（未確認）かの 2 状態だけで管理する。記録のない段階は画面に「未確認」と出し、スコアの計算には最近傍の凸（強化後の最大側のレコード）の内容をそのまま流用して、推定した文言・数値をゲーム事実と同じ顔で流通させない。

## Context

[ADR-009](009-evidence-provenance.md) の「`estimated` は残る」という帰結を置き換える。

従来は未確認の途中値を最大値から `÷1.1` して埋めていた。「試算であってゲーム事実ではない」と注記していても、推定値は画面・共有データ・解析コーパスの入力として実機値と同じ顔で流通し、次の 2 つの害が出た。

- **画面で区別できない。** カード詳細の文言が実機なのか推定なのか、読み手に分からない。
- **逆解析が推定値に依存する。** SP 欄の閉じた形は実機 20 編成で誤差 0 だったのに、恒常 0凸 を含む K5 / K6 / K7 だけ 3.8〜4.2 高く、「必要な係数は試算値の 0.89〜0.92 倍で、単一の係数では説明できない」という式の問題に見える現象が残っていた。2026-09-15 にユーザーが開発用の「開花文言」フォームで 34 枚の全区間を実機と突き合わせると、K5 / K6 / K7 は実機値を入れるだけで誤差 0 になった。ずれていたのは式ではなく入力だった。

決定の内訳:

- 最大値 ÷ 1.1 の推定は廃止する。
- パラメータの 2凸 +10% は実測で確認済みの規則なので、逆算を続ける（`derived-from-max-confirmed-ratio`）。
- テストの期待値は実機の値だけで固定する。流用値から逆算した数字をテストへ書かない。
- 記録のある variant は「未確認」にしない。抽出マスター（外部解析）由来の記録も使う。外すと実機の SP 欄の閉じた形が崩れて実機と矛盾するため。実機目視でないことは provenance の側で区別する。

## Consequences

### Pros

- 画面が「実機で確認できた文言」と「未確認」だけになり、推定文が事実として広がらない。
- 逆解析の入力から推定値が消え、SP 欄のコーパスが 20 → 23 編成に増えて誤差 0 を保った。exploratory 行の未説明差も +1.0 → +0.1 に縮んだ。
- 確認の進み具合がカード単位の `BLOOM_TEXT_VERIFIED_CARD_IDS` で追える。

### Cons

- 未確認の段階は最大側の値で計算するので、低開花のカードのスコアは高めに出る（推定で割り引いていた頃より楽観的）。実機で埋まるまでは「未確認の段階を含む試算」であることが前提になる。
- 実機で確認できなかった区間（`unknown` のまま確定したもの）と、まだ確認していない区間を、カード単位の一覧と段階単位の provenance の 2 つで見分ける必要がある。
