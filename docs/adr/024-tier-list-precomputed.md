# ADR-024: ティア表は探索の限界貢献で評価し、事前計算のデータを同梱する

Date: 2026-10-09

## Status

Accepted

## Decision

★5 全枚のティア表（リーダー / メンバーの 2 つの表、SS / S / A / B / C / D の段）は、ツールの探索そのもので評価する。カード 1 枚の価値は「そのカードを固定して残りをおまかせで探した最良のユニットスコア ÷ 全体の最良」（限界貢献の比）とし、計算が重いので `pnpm tier`（`scripts/tier/build.mjs`）で事前計算した `src/data/tierList.json` を同梱する。カードの数値を足し合わせる独自の点数は作らない。

## Context

ユーザーの依頼（2026-10-09）は、ユニットスコアを上げるうえで重要な ★5 のティア表を、今あるツールの計算を元にさまざまな観点から評価して作ること。評価の高いカードにはなぜ高いのかの説明を出し、リーダーとメンバーで表を分け、段の数は必要に応じて増減してよい。

前提は さがすの「全カード」と同じ（★5 全枚・開花最大・4 色ボード全解放・曲なし・コネクトなし・アカウント補正なし）。観点は メンバー固定 / メンバー固定でそのカードだけ 0凸 / リーダー固定 の 3 つで、段はメンバー固定・リーダー固定の比で決め、0凸の比とリーダー固定 84 通りの最良編成への採用数は説明に使う。段の下限は比の固定値（`TIER_THRESHOLDS`）で、リーダーは衣装スキルだけの差なので幅を狭くする。SS は全体の最良にほぼ届くカードだけ。1 枚ごとの評価画面は、長い説明文では分からないので、総評（1〜2 文）と評価軸の表で見せる（ユーザー指示）。

計測（単一スレッド）: 全カード前提のおまかせ探索 116 秒（23.7 億通り）、メンバー 1 枚固定 9 秒、リーダー固定 53 秒。84 枚 × 3 観点で約 100 分かかるので、画面で計算する形は現実的でない。データは ★5 のカードが増えたときにしか変わらないので、事前計算が合う。入力の指紋（`tierFingerprint`: ★5 カード・ホロメン・ボードのマス・`TIER_MODEL_VERSION`）をデータに入れ、`tier.test.ts` が現在の指紋と比べて作り直しを求める。評価の式（エンジン）を変えたら `TIER_MODEL_VERSION` を上げる。

退けた案:

1. スキルの数値から独自の点数を作る。ツールの計算（探索）と別の正典ができ、点数の重みが恣意的になる。
2. 全体のおまかせ探索の上位 N 件への出現回数。上位は同じ数枚の組み替えで埋まり、C / D を分けられない。
3. 順位の割合で段を切る（上位 10% を S など）。段の意味が「最良にどれだけ近いか」でなくなり、カードが増えると段が動く。
4. 画面で Worker 計算する。上記のとおり遅い。

## Consequences

### Pros

- 段の根拠が探索の結果そのものなので、さがすの結果と矛盾しない。説明文に最良編成のリーダー・採用数という具体が出せる。
- 開いた瞬間に出る（計算なし）。データが古くなればテストが落ちる。

### Cons

- ★5 を足す・エンジンの式を変えるたびに `pnpm tier`（4 コアで約 25 分）が要る。
- 前提が「全カード・開花最大・全解放」なので、自分のアカウントでの価値（所持・開花・ボード）とは違う。説明文の 0凸の比で開花依存の目安だけ出す。
- 探索は shortlist の近似なので、比はわずかに取りこぼしうる（さがすと同じ）。

**Update (2026-10-09):** 段の根拠を、限界貢献から仮想アカウントでの**採用率**へ替えた。ユーザー指示の要旨は、最高ユニットスコアの編成は探索で分かるので重視せず、強いという実感を定量的に評価したい（強ければ現実的な編成の多くで使われるはず）というもの。独立レビューでも、限界貢献は置き換えが効くかを測っていて噛み合う相手が 1 枚あれば高く出ること（分布が 92.9〜100% に圧縮され、A 以下の境の意味づけが弱い）、リーダーの採用数が条件なしの衣装スキルを持つリーダーに偏ることが指摘された。

- 採用率: ★5 から所持 20〜50 枚の仮想アカウントを均衡配置（1 ラウンドで 84 枚をシャッフルして塊に切り、全カードが各ラウンドにちょうど 1 回入る）で作り、それぞれで「全カード」と同じ前提のおまかせ探索を回す。持っていたアカウントのうち最高編成に入った割合を、メンバー / リーダー別に数える。
- ラウンド数は、採用率の 95% 信頼区間の半幅を p = 0.5 で 3 pt 以内にする n ≥ 0.25 × (1.96 / 0.03)² ≈ 1,068 から 1,100 とした（3,034 件）。
- リーダーは、選ばれたカードと同じ衣装スキル（構造）を持つ所持カード全部に数える。この前提では赤ボードが全員同じで、同じ衣装スキルのリーダーは同点になり、どれが 1 位かは候補の並び順で決まるだけだからである（独立レビューの指摘: 同じ衣装の 2 枚を持つ 482 件すべてで並び順の先頭が勝っていた）。
- 段の下限は採用率の固定値で、そのときの分布の切れ目に置く。限界貢献の 3 観点はデータに残し、評価画面の表と「最高スコアの編成」に使うが、段には使わない。
- 退けた案: ランダムな編成の 1 枠にカードを入れ替えて平均寄与を測る（弱い編成に偏り、現実的でない）。各リーダーの上位 N 件への出現（上位は同じ数枚の組み替えで埋まる）。
