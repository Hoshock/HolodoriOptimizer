# ADR-010: 検索向けの解説ページは静的 HTML の MPA として置く

Date: 2026-09-14

## Status

Accepted

## Decision

検索から入ってくる人向けの解説ページ（`guides/**/index.html`）は、Vue アプリのルートにせず、素の HTML を Vite の `build.rollupOptions.input` に足す MPA として置く。本文は HTML に直接書いて実行時に差し替えないので、JS を実行しないクローラでも全文が読め、直リンクも 404 にならない。

## Context

トップページは Vue の SPA で、本文は JS を実行して初めて現れる。解説ページは検索結果から直接開かれるためのものなので、HTML を返した時点で本文がそろっている必要がある。

- **ルータを入れる案は外した。** GitHub Pages は静的ファイルを返すだけで SPA 用のフォールバックを持たないので、`/guides/simulator/` への直リンクとリロードが 404 になり、`404.html` で誤魔化すことになる。`rollupOptions.input` に HTML を足すだけなら、出力がそのままディレクトリ構造になる。
- **文言を実機で差し替えて試す仕組みを解説ページへ広げる案も外した。** 同時期に、メイン画面の説明カードと共有文を localStorage の上書きで調整する開発用パネルを入れた（のちに廃止）。しかし本文を JS で差し替えると、人が見る内容とクローラが見る内容が食い違い、ページを静的にした理由そのものを失う。

## Consequences

### Pros

- 直リンク・リロードで 404 にならない。追加するビルド設定は入力の 2 行だけで、ルータもフォールバックも要らない。
- JS を実行しないクローラでも全文が読める。
- アプリのバンドルを読み込まないので、解説ページだけを開く人には軽い。
- `src/guide.css` が `src/style.css` を読むので、配色・文字のトークンはアプリと共有される。

### Cons

- 文言の変更にビルドとデプロイが要る。解説ページの文言は実機で読んで、コードで直す。
- 免責のフッタなど、アプリと共通の文言が HTML 側へ複製される。ずれないように `src/seo.test.ts` で 3 ページの一致を固定する。
- ページを増やすたびに `vite.config.ts` の入力と `public/sitemap.xml` へ追記が要る（どちらも `src/seo.test.ts` が突き合わせる）。
