# ADR-010: 検索向けの解説ページは静的 HTML の MPA として置く

- Date: 2026-09-14
- Status: Accepted

## Decision

検索から入ってくる人向けの解説ページ（`guides/**/index.html`）は、Vue アプリの中のルートにせず、**素の HTML を Vite の `build.rollupOptions.input` へ足す MPA** として置く。ルータは入れない。本文はその HTML に直接書き、実行時に差し替えない。

## Context

トップページは Vue の SPA で、本文は JS を実行して初めて現れる。検索に読ませたい説明をそこへ足すと、クロールが JS の実行に依存する。解説ページは検索結果から直接開かれることが目的なので、HTML を返した時点で本文がそろっている必要がある。

GitHub Pages は静的ファイルをそのまま返すだけで SPA 用のフォールバックを持たないため、ルータを入れると `/guides/simulator/` への直リンクとリロードが 404 になり、`404.html` で誤魔化す必要が出る。`rollupOptions.input` に HTML を足すだけなら、出力がそのままディレクトリ構造になり 404 にならない。

同時期に、メイン画面の説明カードと共有文を実機で調整するための開発用パネル（`CopyTunePanel.vue`、localStorage の上書き）を入れたので、同じ仕組みを解説ページへ広げる案が出た。

## Consequences

### Pros

- 直リンク・リロードで 404 にならない。追加するビルド設定は入力の 2 行だけで、ルータもフォールバックも要らない。
- 本文が HTML にそのまま入るので、JS を実行しないクローラでも全文が読める。
- アプリのバンドルを読み込まないので、解説ページだけを開く人には軽い。
- スタイルは `src/guide.css` が `src/style.css` を読むので、配色・文字のトークンはアプリと共有される。

### Cons

- 文言の変更にビルドとデプロイが要る。**開発用の「文言・配置」パネルの対象にはできない** — 本文を JS で差し替える形にすると、人が見る内容とクローラが見る内容が乖離し、このページを静的にした理由そのものを失う。解説ページの文言は実機で読んで、コードで直す。
- 免責のフッタなど、アプリと共通の文言が HTML 側へ複製される。ずれないように `src/seo.test.ts` で 3 ページの一致を固定する。
- ページを増やすたびに `vite.config.ts` の入力と `public/sitemap.xml` へ追記が要る（どちらも `src/seo.test.ts` が突き合わせる）。
