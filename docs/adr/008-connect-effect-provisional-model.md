# ADR-008: コネクト効果は外部データ由来の暫定モデルとして実装し、確定とは書かない

Date: 2026-09-11

## Status

Accepted

## Decision

ホロメンボードのコネクトマス（中心 / 赤 / 青 / 黄の 4 か所の人物アイコン）にカードを置くと発動するコネクト効果（範囲内のホロメンボード効果を X% UP）を、外部の公開データベース由来の範囲と ‰ を使う暫定仕様の一般モデルとして実装し（`src/data/connect.ts` の純関数）、実機確認済みとは書かない。一般規則（倍率の解釈・丸め・重複の合成・左右の向き）は実機観測と突き合わせて決め、合わない規則はケース別の定数で埋めずに規則そのものを見直し、特定のカードがどの効果を持つか（`cards.json` の `connectEffect`）は実機で確認できたカードだけ入れる。

## Context

コネクトの増幅は、4 色のボード入力がそろった 2026-09-08 から、倍率と対象マスが分からないため試算に入れていなかった（現在は `docs/ai/tmp/pending.md`「コネクト効果」）。実機のボード表示値（おかゆ 全パラ +546・S +688・発動率 +35.1% など）はマスの単純合計を超えており、この差を再現しないと総合力とスコアボーナスの試算が実機に届かない。2026-09-11 にユーザーから、外部の公開データベース（マスターデータの差分を公開しているリポジトリ）に「カード → コネクト効果 → 範囲（コネクトマス基準の相対座標）」の構造と値があるという調査結果が共有され、「仮定でよい」として一般モデルで実装するよう指示された。範囲と ‰ はゲーム画面に数値で出ない。

[ADR-002](002-game-data-text-only-hand-entered.md) は解析・ダンプ由来のデータに依存しないと決めている。今回は、値をゲーム画面で直接確かめられない領域であること、ユーザーが暫定仕様として明示的に受け入れたこと、確定の判定は実機観測で行うことを条件に、外部解析（扱いは `docs/ai/evidence-policy.md`）として持ち込む。外部のカード識別子（マスター ID）やファイル名は持ち込まず、範囲の形と ‰ の値だけをツール独自の ID で持つ。

倍率は 元値 × (1 + ‰/1000) とした。引き継ぎ資料の「‰/1000 をそのまま倍率にする（1500 → × 1.5、850 → × 0.85）」読みは、おかゆの発動率 +35.1% にもみこの +36.0% にも合わなかった。おかゆの全項目は、この倍率とマスごとに固定値を切り上げる規則で完全に一致した（`src/data/connect.test.ts`）。

外した案:

- 増幅込みの実機の表示値をそのまま入力してもらう運用を続ける — 入力が増え、ボードのマスを写す UI と二重になる。
- 増幅を実機観測だけから逆算する — 範囲の形が分からず、1 人分の観測では一般化できない。
- 外部データを確定として持つ — ADR-002 と証拠の扱いの規則に反する。
- ‰/1000 を倍率にする読み — 上の実機観測と合わない。

## Consequences

### Pros

- 単純合計を超える実機のボード表示値を、ケース別の定数なしに再現できる見込みがある（おかゆで全項目一致）。
- 範囲・‰・合成・丸めが純関数に分かれているので、実機と合わない規則が出たら 1 か所ずつ差し替えられる（重複の合成は加算 → 乗算へ 1 関数で変えられる）。
- 配置は既存の解放マスとは別のキーに保存し、旧データはそのまま読める。

### Cons

- 範囲・‰ の出所が外部データなので、ゲームの更新で変わっても気づけない。実機観測との突き合わせを続ける必要がある。
- カード → 効果の対応（`connectEffect`）は実機確認できたカードから埋めるので、当面はカードを置いても効果データ未登録で増幅なしのカードが大半になる。
- 未確認のまま置いた規則がある: レベル（5凸 = Lv2）、重複時の加算、割合・‰ の丸めなし、黄・赤・緑への適用。
- 「ボード状況を考慮しない」（全解放）探索では置くカードを決めずに増幅なしにしたので、最大育成の試算がコネクトのぶん低めに出る（2026-10-02 に解消。末尾の Update）。

**Update (2026-09-11、範囲の向き):** 範囲の向きは物理座標のままで、ホロメンの左右配置やコネクトマスの色で反転しない（ユーザーの決定「純粋に形で決まる」）。当初の「反対側のホロメンでは dx を反転する」は廃止した。

**Update (2026-09-11、入力の形):** ユーザー指示で、カードを置く形（カード → 効果の対応を `cards.json` に持つ）をやめ、コネクトマスごとに範囲の形（17 種）と倍率を直接入れる形にした。`Card.connectEffect` は削除し、効果の一覧（`CONNECT_EFFECTS`）は形ごとに知られている ‰ の候補として持つだけにした。一般モデル・暫定仕様・実機観測で規則を決めることは変わらない。

**Update (2026-10-02〜03):** 探索はコネクトのオプションを持たず、登録している（ボードで置いた）コネクトで常に計算する。代わりに持っているコネクト（形 × ％ × 枚数）を登録し、その範囲でいまの配置からユニットスコアが厳密に上がる変更だけを重ねるコネクトの最適化（遅延評価の貪欲法。目的は表示ユニットスコアだけ）を入れた。入口は [ADR-014](014-board-connect-optimize-frequency-off.md) / [ADR-015](015-optimize-with-frequency-stage.md) で組み直しプランの段になった（規則は `.claude/skills/engine-structure/`、保留は `docs/ai/tmp/pending.md` 18）。

**Update (2026-10-09):** カード → コネクト効果の対応は、抽出マスターから ★5 84 枚・★4 54 枚の全件を `src/data/cardConnect.ts` に転記した（外部解析・実機未確認）。配置の入力（コネクトマスごとに形 × ‰）は変えず、持っているコネクトを所持カードと開花段階から導くのに使い、手で登録する所持は廃止した（[ADR-023](023-connect-inventory-from-owned-cards.md)）。
