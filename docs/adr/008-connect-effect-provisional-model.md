# ADR-008: コネクト効果は外部データ由来の暫定モデルとして実装し、確定とは書かない

- Date: 2026-09-11
- Status: Accepted

## Decision

ホロメンボードのコネクトマス（中心 / 赤 / 青 / 黄の 4 か所の人物アイコン）にカードを置くと発動する「コネクト効果」（範囲内のホロメンボード効果を X% UP）を、**暫定仕様・実装仮説**として一般モデルで実装する（`src/data/connect.ts`。範囲の相対座標と増幅 ‰ のデータ、対象マスの解決、倍率の合成、丸め、レベルの決め方をすべて純関数で持つ）。範囲と ‰ の値は外部の公開データベースのスナップショット【外部情報】から引き継いだもので、ゲーム画面には数値として出ないため**実機確認済みとは書かない**。一般規則（倍率の解釈・丸め・重複の合成・左右の向き）はユーザーの実機観測と突き合わせて決め、実機と合わない規則はケース別の定数で埋めずに規則そのものを見直す。**特定のカードがどの効果を持つか**（`cards.json` の `connectEffect`）は実機で確認できたカードだけ入れ、根拠なく割り振らない。

## Context

コネクト増幅は 4 色のボード入力がそろった 2026-09-08 以来「倍率・対象マスが未確認のため試算に含めない」まま残っていた（pending 4(a)）。実機のボード表示値（おかゆ 全パラ +546・S +688・発動率 +35.1% など）はマスの単純合計を超え、この差を再現しないと総合力・スコアボーナスの試算が実機に届かない。2026-09-11 にユーザーから、外部の公開データベース（マスターデータの差分を公開しているリポジトリ）に「カード → コネクト効果 → 範囲（コネクトマス基準の相対座標）」の構造と値があるという調査結果が共有され、「仮定でよい」として一般モデルでの実装を指示された。

ADR-002 は解析・ダンプ由来のデータに依存しないことを決めている。今回は (1) 値をゲーム画面で直接確認できない領域であること、(2) ユーザーが暫定仕様として明示的に受け入れたこと、(3) 確定の判定はあくまで実機観測で行うこと、を条件に、`.claude/rules/game-facts.md` の【外部情報】の扱いと同じ位置づけで持ち込む。カードの識別子（外部マスター ID）やファイル名は持ち込まず、範囲の形と ‰ の値だけをツール独自の ID で持つ。

引き継ぎ資料の「‰/1000 をそのまま倍率にする（1500 → × 1.5、850 → × 0.85）」案は、おかゆの発動率 +35.1%（素 30 + (+2 のマス 3 個) × 0.85）と、みこの +36.0%（素 30 + (+2 のマス 2 個) × 1.5）で棄却した — 「85% UP」が元値の 85%（減衰）になる読みは実機と合わず、**元値 × (1 + ‰/1000)** が両方に一致する。おかゆの全項目（全パラ 546 / S 688 / P 528 / T 528 / 発動率 35.1）は「青のコネクトに card-2（+85%）、中心に 3 マス直線（+160%）」で、固定値をマスごとに切り上げる規則と一緒に完全一致した（`src/data/connect.test.ts`）。

却下した代替案: (1) 実機の表示値（増幅込み）をそのまま入力してもらう運用の継続 — 入力が増え、ボードのマスを写す UI と二重になる。(2) 増幅を実機観測だけから逆算する — 範囲の形が分からず、観測 1 人分では一般化できない。(3) 外部データを「確定」として持つ — ADR-002 と `game-facts.md` に反する。(4) ‰/1000 を倍率にする読み — 上記の実機観測で不一致。

## Consequences

### Pros

- 単純合計を超える実機のボード表示値を、ケース別の定数なしに再現できる見込みがある（おかゆで全項目一致）。
- 範囲・‰・合成・丸めが純関数に分かれているので、実機観測と合わない規則が出たときに 1 か所ずつ差し替えられる（重複の合成は加算 → 乗算へ 1 関数で変更可）。
- 配置は既存の解放マスとは別のキーに保存し、旧データはそのまま読める。

### Cons

- 範囲・‰ の出所が外部データなので、ゲームの更新で変わっても気づけない。実機観測との突き合わせを続ける必要がある。
- カード → 効果の対応（`connectEffect`）は実機確認できたカードから埋めるため、当面はカードを置いても「効果データ未登録」で増幅なしのカードが大半。
- 未確認のまま置いた規則がある: レベル（5凸 = Lv2）、重複時の加算、赤の左右の向き（ライフ系が左を基準）、割合・‰ の丸めなし、黄・赤・緑への適用。
- 「ボード状況を考慮しない」（全解放）探索では置くカードを勝手に決めず増幅なしにしたので、最大育成の試算がコネクトぶん低めに出る（最適なコネクト配置の探索は未実装）。

**Update (2026-09-11):** 入力の形を変えた。当初は「コネクトマスにカードを置く（カード → 効果の対応は `cards.json` に持つ）」で実装したが、ユーザー指示「コネクトマスをタッチしたらサイドバーが出てきて、効果マスの形一覧が図形で出てくる。クリックすると倍率を入力するテンキーが出てきて確定するとコネクトマスの色がそのボードの色になる。ホロメンカードを指定するよりそちらの方が楽」により、**コネクトマスごとに範囲の形（17 種）と倍率（%）を直接入れる**形にした（`ConnectSheet.vue` + `NumberPad`。保存は `connect-placements` v2 = `{ extent, permil }`。v1 のカード ID は読み飛ばす）。`Card.connectEffect` は削除し、効果の一覧（`CONNECT_EFFECTS`）は形ごとに知られている ‰ をテンキーの手がかりとして出すためだけに持つ。Decision の「一般モデル・暫定仕様・実機観測で規則を決める」は変わらない。
