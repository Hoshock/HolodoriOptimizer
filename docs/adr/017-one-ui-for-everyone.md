# ADR-017: 画面はモードを分けず、全員が同じ導線を使う（育成の前提の 3 択・組み直すと・組み直しプラン）

- Date: 2026-10-08
- Status: Accepted

[ADR-016](016-true-ranking-proxy-boards.md) の画面の入口（結果の見出しの「最適化順」のチップと進み具合のダイアログ）を置き換える。計算（探索・最適化・見込みのボード）は変えない。

## Context

最適化順・最適化・さがすのオプションは、開発者には使えるが、ほかの人には優しくない（ユーザー指摘）。問題は 4 つあった:

- 入口で何を登録すればよいか分からない（アカウントの 4 ボタンに状態が出ない）。
- 登録の量で結果の意味が変わるのに見えない（ボード未登録でも「ボード状況を考慮する」が既定 ON で、最適化順も Pt・資材の制限なしで 10 分回る）。
- 言葉が開発者の言葉（最適化順・ユニットのみ変更する・所持リソースを考慮する + 色ごと など）。
- 道具の切れ目（さがす / 最適化順 / 最適化）が、遊ぶ人の問い（「この曲で誰を出す？」「何を育てればもっと強くなる？」）と合っていない。

モック 3 案（結果のタブ化 / 「シンプル / 詳細」の切り替え / モードを分けない一本化）を見比べた。「シンプル / 詳細」は、ボードと開花の片方だけを考慮する組み合わせが要らないと分かった時点で（ユーザー判断「ボードオンで開花オフで調べることない」）、メイン画面の差分がほとんど残らなかった。

## Decision

- **モードは作らない**。開発者・よく使う人も、初めての人と同じ画面を使い、細かい条件は使う場所（組み直しプランの「条件」のタブ）に置く。
- **さがす**: 「所持カードから探す」「ボード状況を考慮する」「開花状況を考慮する」を **いまの育成で / 育てきったら / 全カード** の 3 択にまとめる。ボードと開花の片方だけを考慮する組み合わせは持たない。除外 / 選択は「絞り込み」の 1 行から開く中央のダイアログへ移す。「オプション ▼」の開閉はやめる。保存の形（`search-all` / `search-options` / `selection`）は変えない。
- **アカウント**: 登録がまだの入口にだけ「未登録」を出す（件数は出さない）。
- **結果**: 「いまのまま / 組み直すと」のタブ。「組み直すと」は ADR-016 の計算で、計算中の進み具合はタブの中に出し、終わると組み直した後の順に並ぶ（行の下に「いま n」）。**「いまの育成で」探した結果で、ボードを登録しているときだけ計算する**（未登録はタブに「ボード未登録」と出して計算しない — Pt・資材の制限なしで回っても育てきった結果とほぼ同じになり、意味が伝わらないため）。
- **組み直しプラン**（旧「最適化」）: タブは ボード / コネクト / 発動頻度 / 条件（結果を先、条件を最後）。条件は 曲 → 最適化するもの（ボード・コネクト・発動頻度、ほかのホロメンも変える、所持リソースを考慮する）→ 発動頻度の選び方（3 択と、ダイアログで選ぶ頻度マスの数）。
  - 「ユニットのみ変更する」は反転して「ほかのホロメンも変える」（既定 OFF）。外す案もあったが、ほかのホロメンの緑ボードの全員・所属のマスやコネクトでもこの編成が伸びるので残す。
  - 所持リソースの色ごとの ON / OFF は外して 1 つにする。

- **名前**: 結果のタブは「組み直すと」、シートとボタンは「組み直しプラン」。同日に「育成すると」「育成プラン」で入れたが、さがすの「育てきったら」と何が違うのか分からなかった（ユーザー指摘）。育てきったら = 全部開けた理想（Pt・キューブの制限なし、開花最大）、組み直すと = 今のランクの Pt と持っているキューブの範囲でボード・コネクト・発動頻度を組み直す（開花は登録のまま）。
- 結果のタブを切り替えても結果の高さは変えない（一覧と進み具合を重ねる）。

## Consequences

- 今までできて、できなくなったこと: ボード ON・開花 OFF / ボード OFF・開花 ON での探索、所持リソースの色ごとの考慮。どちらもユーザー判断で外した。
- 形が変わっただけで残ったもの: 除外 / 選択、頻度マスの数の固定、曲の選び直し、対象の個別 ON / OFF、頻度の選び方、最適化順（タブ）。
- 画面の規則の正典は `.claude/rules/ui-flow.md` と `.claude/rules/ui-parts.md`。

## Update 2026-10-09: 組み直しプランの「条件」をタブの列から離す

条件は入力で、ボード / コネクト / 発動頻度は 1 回の結果の見方なので、同じ 4 択のタブに並べない（ユーザー指示。モック 3 案 — 条件と結果を別ページ / 条件をシートで重ねる / タブの横に離して置く — から 3 つめを選んだ）。結果の 3 つはセグメント、条件はその右のピル形のボタン。結果のタブの下には区分のタブ（リーダー・メンバー / 所属グループ / その他）を置き、条件のときは出さない。画面の規則の正典は `.claude/rules/ui-flow.md`。
