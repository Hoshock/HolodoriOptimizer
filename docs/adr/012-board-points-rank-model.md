# ADR-012: ホロメンボードは「ホロメンランク → ボードPt の予算」と「コネクトの明示解放」で扱う

Date: 2026-10-04

## Status

Accepted

## Decision

ホロメンごとに、ホロメンランク（1〜50。任意登録）までに獲得した累積ボードPt を 4 色のボード全体で共有する予算とし、コネクトマスは配置とは別の解放状態を持つ 1 Pt のマスとして扱う。ホロメンボードの最適化（`src/engine/boardOptimize.ts`）は、固定した編成の表示ユニットスコアが高くなる解放マスを、この予算の範囲で近似で選ぶ。

## Context

2026-10-04 のユーザー指示。実機ではホロメンごとにボードを開けられる量がホロメンランクで決まり、コネクトマスの直前まで開けてもコネクト自身は勝手に開かない。ツールは「どこまででも開けられる」前提で、コネクトを常に通れる通路として扱っていたため、いまのランクで実現できるボードや、ランクに合わせた最適化を扱えなかった。

数値（ランクごとの獲得Pt・マスの必要Pt・G-025 の存在）は HolodoriDB の公開 master 差分から取った外部解析データで、実機の目視確認はしていない（ADR-009 の「外部解析」の段。出所の詳細は `src/data/boardPoints.ts` と `docs/ai/game-spec.md`）。同じマス ID が複数の tree-model にあっても、ボードPt が食い違うものはなかった。

決定の内訳:

- 制約にする資源はボードPt だけ。ピース・クリスタル・各色キューブ・コアキューブ・ホロゴールドは無限扱いにし、Dream Rank は常に 30 以上と仮定してマスの Dream Rank 条件は無視する。
- ランク未登録は「ボードPt の制限なし」（従来どおり）。0 を未登録の代わりに使わない。
- 必要Pt は通常マスが 1〜6（マス ID → cost の表は `src/data/boardPoints.ts` の 1 か所だけ）、赤 / 青 / 黄のコネクトマスが各 1 Pt、中心は 0 Pt で最初から解放済み。
- コネクトの解放はコネクト効果の配置（`connect-placements`）とは別の状態にし、「解放済みで配置なし」「直前まで開けて未解放」「解放済みで配置あり」を区別する。「未解放なのに配置あり」は保存しない。旧実装の「先のマスが解放されていればコネクトも解放扱い」という推定は撤去した。
- 途中の経路を自動で開くときは、マス数ではなく追加で必要なボードPt が最小の経路を選ぶ（コネクトを横断するならその 1 Pt も合算して解放する）。
- 予算が足りない解放は操作全体を拒否して何も変えない（途中までは開けない）。解除は常にできる。すでに予算を超えている登録は自動で削除せず、超過を表示する。
- 最適化はコネクトの配置を変えず、配置のあるコネクトは必ず解放済み（1 Pt を予算に含む）にする。ランク未登録でも、スコアに効かないマスは開けない（効くマスと、そこへ届く経路・コネクトだけ）。

## Consequences

### Pros

- いまのランクで実現できる範囲に限ってボードを入力・最適化できる。
- コネクトの解放を推定なしで数えられるので、解放マス数（最大 150 + 3 = 153）・使用Pt（最大 453）が正確になる。
- 経路の選択が Pt 基準になり、マスごとにコストが違っても最小の追加Pt で開けられる。

### Cons

- ボードPt・ランクの表は外部マスタ由来で未確認。実機と食い違えば表だけ直す（正典は 1 か所）。
- 旧データにはコネクトの解放状態がないので、初回の読み込みで推定して明示保存する（推定の規則は `src/storage/boardConnects.ts` の `inferBoardConnects`）。「コネクトの直前まで開けていて配置なし」は未解放とみなす。実機では解放済みだった可能性があるが、旧データからは判断できず、勝手に 1 Pt を消費した状態にしないほうを採った。
- ボードの最適化は近似（遅延評価の貪欲法）で、最大を保証しない。取りこぼしを減らすため、登録している状態から出発した結果とゼロから選んだ結果を比べ、登録を下回るなら登録を返す。既知の実装ギャップは `docs/ai/tmp/pending.md` 項目 8。
- 発動頻度の最適化（`liveFrequencyOptimizer.ts`）は青のコネクトを解放済みとして扱う。頻度マスの個数を比べる別の責務で、コネクトの解放はボードの最適化が持つ。
