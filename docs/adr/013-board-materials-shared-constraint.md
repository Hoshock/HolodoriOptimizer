# ADR-013: キューブ・コアキューブは「ホロメンボードの最適化」だけの、アカウント共有の資材制約にする

Date: 2026-10-07

## Status

Accepted

## Decision

色ごとのキューブ・コアキューブ（4 色 × 2 種の 8 種）を、アカウント全体で共有する有限の資材として、ホロメンボードの最適化にだけ制約として入れる。再配分できる総量は「いまのボードへ投入済みの資材 + ユーザーが登録した余り」とし、手動でボードを開ける操作は資材で制限しない。

## Context

[ADR-012](012-board-points-rank-model.md) の「各色キューブ・コアキューブは無限扱い」を、ホロメンボードの最適化に限って置き換える。ADR-012 のほかの決定（ボードPt の予算・コネクトの明示解放・手動で開ける経路は Pt 最小）は変えない。

2026-10-07 のユーザー指示。ゲームではマスを開けるのにボードPt に加えて色ごとのキューブ・コアキューブが要り、マス別の消費量の表が master から揃った。ユーザーの構想は「いまの解放状態から必要な量を逆算し、余りも含めて全体で最適化する」。

決定の内訳と理由:

- **消費量は外部 master 由来の表として持つ**（`src/data/boardMaterials.ts`。実機未確認）。ボードPt から推測しない（R-034 と R-050 は同じ 4 Pt で資材が違う）。
- **資材はアカウント全体で共有する**（ホロメンごとの別財布にしない。色をまたぐ変換はない）。ボードPt はこれまでどおりホロメンごと。
- **登録値は総所持量ではなく、いまのボードを開けた上での余り**。マスを外すと資材は全額返る（ゲーム仕様）ので、投入済みの分も再配分できる。範囲が `unit` なら変えてよいホロメン（リーダー・メンバー）の投入済み分 + 余りだけを使い、ユニット外が使っている分は回収しない。`all` は全ホロメンの投入済み分 + 余り。余りが未登録（null）の項目は制限なし、0 は「余りが 0 個」。
- **手動の操作は制限しない**。手動の編集で余りを自動で増減もしない（余りはユーザーがゲームの実際の値を登録する入力）。
- **最適化はボードPt の残りと共有の資材の残りの両方に収まる候補だけを採る**。資材に上限がある色では Pt 最小の経路だけを見ない。実グラフに、Pt 最小の経路では資材が足りず、Pt が少し多くても資材が少なく済む別の経路でないと届かないターゲットがあるため（緑 G-018 / G-021: +3 Pt・cube +200 で core 50 を避ける）。Pt・cube・core の非劣な経路をすべて評価する（`BoardGraph.planUnlockRoutes`）。
- **推奨を反映するときは、ボード・コネクトの解放・余りを同じ推奨としてまとめて登録する**。余りは総量から推奨でのアカウント全体の使用量を引いた値（`BoardPlanResult.remainingAfter`。負にせず、総量を増減させない）。

## Consequences

### Pros

- 余りの個数を前提にした、実際に開けられる範囲の推奨が出る。ユーザーの余りで試すと、資材無制限の推奨より低くなる（ユニット外も含めて全て変更した 1 回目で 1,915,524 → 1,702,541。ツール上の計算）。
- 手動操作とデータの保存形式は変わらない。

### Cons

- 資材の表は外部 master 由来で実機未確認。登録した余りが実際の所持と違えば、結果も合わない。
- 資材を絞った探索も貪欲法で、最大を保証しない（資材を絞ったほうが制限なしより高く出る例がある — `docs/ai/tmp/pending.md` 項目 8）。
- キューブ・コアキューブ以外（ピース・クリスタル・ホロゴールド・Dream Rank 条件）は引き続き制約にしていない。

**Update (2026-10-08):** 「余りは負にしない」は [ADR-015](015-optimize-with-frequency-stage.md) で変わった。キューブ・コアキューブは不足してよく、余りが負なら不足として負のまま登録する。
