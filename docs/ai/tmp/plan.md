# 開発計画: ホロドリ パーティ編成最適化ツール

『hololive Dreams』のユニット編成(リーダー 1 + メンバー 5、リーダーとメンバーは重複可)を最適化する静的サイト。設計判断は ADR-001〜003、ゲーム仕様は [docs/human/game-spec.md](../../human/game-spec.md)、権利の枠は [docs/human/rights-policy.md](../../human/rights-policy.md)、UI 制約は `.claude/rules/ui-design.md` が前提。

## 完了サマリ(Phase 0〜4.5、2026-08-31)

- **Phase 0 調査・方針**: ゲーム仕様・既存ツール・権利関係・Vite+ を調査し ADR-001〜003 と docs 骨格を作成([事前調査](../../human/tmp/20260831-prior-research.md))
- **Phase 1 足場**: `vp create`(vue-ts)+ pnpm 11.24.0、ci.yml / deploy.yml、LICENSE (MIT)。main マージで https://hoshock.github.io/HolodoriOptimizer/ に公開済み
- **Phase 2 データ層**: スキーマ(raw + structured 二重持ち)、★5 全 70 枚・楽曲 181 曲・ホロメン 54 名・所属 15 件、整合性検査を `vp test` に組込み。2026-08-31 のスキーマ拡張(`self` 対象・スコアサポートの効果単位条件)で全 4 スキル種とも構造化率 100%(テストで強制。複合衣装文の解釈は `src/data/meta.json` の notes)
- **Phase 3 エンジン**: スコアモデル + 全探索(リーダー固定 / 一部固定 0〜5 / 除外 / TOP n、同一ホロメン排他はメンバー間のみ)。1,124 万通り約 5 秒、Web Worker + 進捗 + 中止
- **Phase 4〜4.5 UI**: カードピッカー(検索 + 所属単一選択チップ + タイプセグメント、1 行 1 枚でスキル表示)、リーダー/メンバー枠スロット(固定寸法・タイプ淡色面・スキル常時表示)、除外チップ一覧、結果ランキング(金銀銅+タップで詳細モーダル)。7 回のユーザーフィードバックを経た制約は `.claude/rules/ui-design.md` に集約(モバイルファースト、390px 実測確認)
- **所持カードモード (2026-08-31)**: ページ内タブ「全カード / 持っているカード」を追加し、登録した所持カードだけを対象に最適化するモードを実装。編成フォームは `OptimizerPanel.vue` に共通化し、プールの絞り込みは除外リストの補集合で実現。所持カード ID は localStorage に保存(Phase 5 の保存項目を前倒しで実施)。所持カードモードのみリーダー省略可でリーダーも探索する(エンジンの `leader: null`。全カードモードは探索空間が大きすぎるためリーダー必須 — 2026-08-31 ユーザー指定)
- **スキーマ拡張・構造化 100% (2026-08-31)**: `BuffTarget` に `self`、`ScoreSupportBuff` に効果単位の `condition` 上書きを追加して残 27 件を構造化。詳細モーダルの状態バッジを廃止し、不発動スキル行のグレーアウト表示に統一
- **仮想ガチャ (2026-08-31)**: ヘッダ右上のアイコンから開く仮想ガチャシミュレーション(**ピックアップガチャのみ**、10 回の 10 枚目は★4 以上確定枠、有償ダイヤのみ・課金額表示、購入は確認済みの 9,800 円パックのみ)。UI はピックアップ枠(UnitSlot と同形のプレースホルダ)+ 1回/10回 の等幅ボタンで説明文なし。通常・初心者応援・スタートダッシュ・無償ダイヤ・割引単発・天井 Pt は再現しない(2026-08-31 ユーザー指示)。仕様の根拠は [docs/human/game-spec.md](../../human/game-spec.md)「ガチャと課金」。★3/★4 は「1 ホロメン 1 枚」仮定でホロメン名表示(pending 5)。最適化ツールは★5 のみで不変。あわせてヘッダのサブタイトルを削除

## 完了サマリ（期待値最適化+UI 統合 Step 1〜3、2026-09-01）

- **Step 1 タブ統合**: タブ廃止・`OptimizerPanel` 単一化。ステップは 1 さがす対象（セグメンテッドコントロール「全カード | 持っているカード」+カードを選ぶ行ボタン、状態は `holodori-optimizer:search-all`）/ 2 除外（所持と独立）/ 3 リーダー / 4 メンバー / 5 曲 / 6 さがす。メンバー枠は先頭の空きのみ有効（解除で上詰め）、使えない操作は入口ボタンで disabled
- **Step 2 期待値エンジン**: 仮定値は `src/data/live.ts`、モデルは `src/engine/live.ts`（寄与=効果量×期待カバー時間/曲長、リーダー枠は発動しない前提、カード単位で前計算）。総合期待スコア = unitScore × (1 + active + sp)。詳細モーダルは検算できる内訳（絶対値主体・%は補足、和が見出しと一致、パラメータ表に合計行+変化なしセル淡色）
- **Step 3 曲別最適化**: 曲スロット+検索つき `SongPicker`（181 曲）。worker が songId → 曲長を解決（未指定は全曲中央値 128 秒）。コンボ数は比率モデルでは順位に影響しないため未使用
- **リーダー常時おまかせ（2026-09-01）**: 探索を「組合せ 1 回列挙 × 衣装スキル同型クラス評価+最大倍率の上限枝刈り」に組み替え（`optimize.ts`）、全カード×リーダーおまかせ 7.9 億通りが約 4 秒。実行不可はプールが空のときのみ
- **UI 刷新（2026-09-01）**: 見出しは名詞ラベル・件数は行ボタン内の値・任意スロットは既定値「おまかせ」を実値表示。スキル・役割バッジは正円アイコンに統一（`SkillIcon.vue`、ラベルは aria-label）。結果一覧はリーダー行を常時表示。規則は `.claude/rules/ui-design.md` に集約済み
- **結果表示の刷新（2026-09-01）**: 候補数入力を廃止して常に上位 100 件を計算し、結果は 10 件ずつ逐次表示（「さらに10件」）。「詳細 ›」等の誘導テキストを廃止し行全体の :active で示す。リーダー行は無彩色バンド+最右列に衣装アイコン（リーダー指定時はピンも）。アイコンは開花=最右・ピン=その左の固定列
- **開花（凸）対応（2026-09-01）**: スキーマに `bloomVariants`（確認済み段階の実文言・構造化必須）を追加し、worker が（カード, 開花段階）を解決してから探索（コアは無変更）。段階仕様=1凸アクティブ/2凸パラメータ/3凸SP/4凸パッシブ/5凸コネクト（ユーザー確認済み）。実数値が非公開のため未確認段階は仮定倍率（`src/data/bloom.ts`: パラメータ×1.05・スキル×1.1）で割り戻し。UI は所持ピッカーの登録済みカードに −花＋ ステッパー、全カード時は常に 0凸。表示は花びら+数字アイコン（0凸も常時）
- **ピッカー操作性（2026-09-01）**: 所持・除外に状態フィルター「すべて | 登録済み/除外中」+絞り込みの保持（閉じても復元、種別ごと独立）。単一選択（リーダー・メンバー・曲）は選択中の項目を開いた瞬間にリスト先頭へフィーチャー。開花ステッパーの上下限は押下ごと無効化

## 完了サマリ（SEO・保存層・おかゆモード、2026-09-01〜02）

- **ピッカーのフォーカス（2026-09-01）**: モーダルを開いたときの自動フォーカスを検索入力からシート本体（`tabindex="-1"`）へ変更（モバイルでキーボードが勝手に出ないように）
- **SEO・改名（2026-09-01〜02）**: 表示名を「ホロドリ編成お助けツール」に改名（検索キーワード「編成」を名前に含める。表記は「ホロドリ」第一）。title / description 刷新、canonical・OGP・twitter:card、`public/robots.txt` / `sitemap.xml`、Google Search Console の確認メタタグを追加。OGP 画像は公式素材が使えないため未設定（自作画像は pending 8）。インデックス登録の経過は pending 8
- **保存層の後方互換（2026-09-02）**: 所持カードの読み書きを `src/storage/owned.ts` に切り出し（旧 2 形式+版番号つき新形式を読む・未知 ID を捨てない）、`src/data/published-ids.json` でカード・ホロメン ID を凍結してテストで削除・改名を検知。規則は `.claude/rules/storage-compat.md`
- **おかゆモード（開発者のお遊び機能、2026-09-02）**: フッター最下部右のおにぎりで ON / OFF（URL パラメータなし・保存しない・ON で先頭へスクロール）。ON 中はページ全体を紫に、リーダーはおかゆんのカード（ピッカーでおかゆん以外 disabled、おまかせならおかゆんの中から探索）、メンバーにもおかゆんが 1 枚（4 枚選んでもいなければ最後の枠が「おかゆん（おまかせ）」+おかゆん以外 disabled）、除外不可。エンジンは `leaderCandidateIds` / `requiredMemberHolomenIds` を汎用オプションとして追加（未充足数 > 残り枠で枝刈り）。結果はおかゆんの行のピン列におにぎり、おまかせで入ったおかゆんの枠位置は候補ごとにランダム。持っているカードモードでは、おかゆんを登録するまで所持ピッカーのボタンを「おかゆんを選んでください」にしリーダー・メンバー・実行を disabled（エラー表示ではなく方針として案内）

## 完了サマリ（スキル発動のしぼりこみ、2026-09-05）

- **Step 6 のしぼりこみ**: 実行ボタンの上に「衣装スキル発動」「パッシブ全員発動」のピル形チップ（複数選択・既定は両方 ON・`holodori-optimizer:skill-filters` に保存）。エンジンは `requireCostumeSkill` / `requireAllPassives` を葉（5 人確定）で判定して不発の編成を候補から外す（未構造化は判定不能なので残す。探索コア・枝刈りは無変更）。6 枠すべて固定（この編成のスコアを試算）では適用せず不発バッジで理由を見せる。0 件は「しぼりこみを外して再度さがしてください」。導かれた規則（既定はおすすめ状態・隣接する選択コントロールとアクションは形で分ける・差の意図を提案時に明示）は `.claude/rules/ui-design.md` に統合済み
