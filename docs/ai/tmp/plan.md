# 開発計画: ホロドリ パーティ編成最適化ツール

『hololive Dreams』のユニット編成(リーダー 1 + メンバー 5)を最適化する静的サイトを作り、GitHub Pages で公開する。設計判断は ADR-001〜003、ゲーム仕様は [docs/human/game-spec.md](../../human/game-spec.md)、権利の枠は [docs/human/rights-policy.md](../../human/rights-policy.md) が前提。

## 要件(確定)

- 技術: Vue 3 + TypeScript + Vite+ (`vp`) + pnpm。GitHub Actions → GitHub Pages(ADR-001)
- データ: 全★5 カード・全楽曲・全ホロメンの衣装スキルをテキスト DB として保持(ADR-002)
- 最適化: リーダー指定でメンバー 5 人を最適化 / 一部メンバー固定で残り枠のみ最適化 / TOP n 候補の提示(ADR-003)
- 将来対応を見込む: 特定楽曲向け最適化、ホロメンボード補正、特定カード除外
- UI: 画一的な AI 生成風デザイン(shadcn / Tailwind 的テンプレート)を避け、利用者本位のシンプルで分かりやすい手書きデザイン

## Phase 4.5: UI 作り直し(2026-08-31 フィードバック対応)

ユーザーストーリー(何も知らないユーザー視点):

1. **初見のファン**: サイトを開く → 何ができるか 1 行で分かる → 「まずリーダーを選ぶ」が最初の一歩だと迷わず分かる → 推しを探すとき、期生タブや名前検索でカードを一覧から見つけられる(70 件のドロップダウンを上から読まされない)→ ボタン 1 つで上位編成がカード形式で見られる。
2. **手持ちが揃っていないファン**: 持っていないカードをタップで除外(見た目で除外中と分かる)→ 現実的な最強編成を知る。
3. **こだわり編成**: メンバー枠(5 つ)に推しを固定して残り枠だけ最適化。5 枠全部埋めれば手動編成のスコア試算になる。リーダーはメンバーと同じカードでもよい。

対応方針:

- [ ] 固定メンバー枠を 4 → 5 に(リーダー重複可の仕様反映漏れ)。5 枠全固定はそのまま手動編成のスコア試算になる
- [ ] ドロップダウン全廃 → 検索ボックス+期生(所属)フィルタ+タイプフィルタつきのカードピッカー(タイル型グリッド、タイプ色つき)
- [ ] 除外はピッカーの複数選択モード(タップでグレーアウト・✕表示、件数表示)
- [ ] デザイン刷新: ポップな配色(タイプ 3 色をアクセントに)、丸ゴシック、ステップ導線(1 リーダー → 2 カスタム → 3 さがす)、上位 3 位のメダル色、余白・タイプスケールの整理でメリハリ
- [ ] playwright-cli で E2E 再確認+スクリーンショット
