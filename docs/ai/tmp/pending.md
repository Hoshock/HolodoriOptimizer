## 表示ユニットスコア

3. **`W_blue`（青ボード由来の配分の重み）の決定式 — 表示 5 欄で最後に残った未知数**
   - 探索の経過・棄却した候補族・残差の診断は正典（`docs/human/display-score.md`「source 分離型の projective weight」4a〜4c / 8）が持つ。ここには**まだ答えが出ていないこと**だけを置く。
   - 2026-09-13 に総量・配分の枠組みごと production へ実装した（`displayScore.ts` の `attributeDisplaySupport`）。枠組み `(C,B,P) = T × W/ΣW` と `H_C` / `H_B` / `H_P` は gauge 非依存の比で支持済みで、残差はすべて `W_blue` に帰着する。
   - **識別できていないのは 1 点だけ**: 発動頻度が 2 人に分かれ、かつ発動率の大きいメンバー側が少ない編成（F2）で、取り分がどう決まるか。採用中の member-local 型は F2 の `W_blue/H_C` を 0.023（= ボード欄 0.8 pt）低く見積もる。「青持ちの人数」でも「水着フブキ 0凸 の入力」でもないことは既存コーパスで否定済み。
   - **「編成全体の評価値どうしの差」型は F0〜F3 が gauge 非依存で 1 群として棄却した**（要求は 4 状態で 0.2208〜0.2215 に一定なのに、この族は 0.175〜0.277 とばらつく）。
   - exploratory 行（恒常みこ Lv 約 20）は総量モデルで約 +1.0 の未説明差。Lv・スキル Lv の再確認まで fit に入れない（恒常みこ 0凸の 4 スキルは `estimated-from-max` のまま）。
   - 次の観測は `display-score.md`「次の実機観測（1 つ）」の 1 件（K3 = F3 の編成で 水着みこ の青の**発動率**マスを 1 つだけ開閉する前後）。
4. **Costume / Board / Passive の 0.1% 量子化規則**
   - 切り上げ / 四捨五入が決着しない。コーパス 126 列で切り上げ 43 列・四捨五入 42 列（`displayScoreQuantization.test.ts`）。
   - 最小の矛盾集合は {K5, K6}: K5 は切り上げだと必ず 0.1 高く、K6 は四捨五入・切り捨てだと必ず 0.1 低い。**3 の `W_blue` が決まって raw の残差が 0.1% を切るまで判定できない。**
   - production は「5 欄で規則を 2 つ持たない」ほうを採り、アクティブ欄・SP 欄と同じ切り上げにそろえてある。
5. **SP 欄の発動率 UP 項**
   - スコアサポート部分 `アクティブ欄 × Σ 支援 × 効果時間 / 12000` は一致する。残差は発動率 UP つき SP を含む編成だけ（F0〜F3 で −1.6）。
   - 2026-09-13 に固定した 2 性質: **SP スキルごとに加法的**・**係数はデッキ非依存**（`displayScoreSpecialColumn.test.ts`、6 編成）。現在のタイムライン再評価型はデッキ非依存を満たさず**形として反証済み**。
   - 閉じた形が決まらない理由: 観測できている `(効果時間, 支援%, 発動率 UP%)` の組が `(12, 100, 35)` と `(11, 130, 50)` の 2 通りしかなく、3 つの依存を分離できない。**発動率 UP % の違う SP を持つカードを 1 枚だけ入れ替えた対照**が要る。
   - 恒常 0凸 のカードを含む編成は、SP のスコアサポート % が `estimated-from-max` の試算値なのでこの分析から外す。
