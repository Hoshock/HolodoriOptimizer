12. **表示スコアボーナスの内部式（2026-09-08 実装、2026-09-09 整理）**
    実機 20 ケース（status.md「実機ユニットスコア」: A / B・青ボード変更 7 例・追加データセット 9.7〜9.17）に対する `src/engine/displayScore.ts` のモデルの現状。ゴールデンは `src/engine/displayScore.test.ts`（実機値・モデル値・差を並記し、誤差の上限を regression として固定）。

    **実機で確定**
    - スコアボーナス = アクティブ + ホロメンボード効果 + パッシブ + スペシャル（各項目を小数 1 桁に丸めて加算）
    - ユニットスコア = ceil(総合力 × (1 + スコアボーナス/100) × 2.03734)（20 ケース全一致）
    - アクティブ欄は青ボードで変わらない / SP 欄はメンバー順・青ボード・リーダーで変わらない
    - 青の発動頻度の効果は単調でない（下記）

    **強い推定**
    - **アクティブ欄** = 5 人共通の 200 秒タイムライン（各秒 Σ up × p / max(1, Σ p)、確率 高 55 / 中 46 / 低 37、条件つき UP は編成条件を判定しライフ・コンボは成立扱い）。20 ケースで **±0.1pt**。
    - **SP 欄** = Σ アクティブ欄 × スコアサポート% × 効果時間 / 12000 + 発動率 UP の 効果時間 / 100 × (確率 +r のタイムライン − アクティブ欄)。20 ケースで **±0.5pt**。ただし `SP_RATE_SECONDS = 100` のゲーム上の意味は**未解明**（当てはめた定数。12000 = 120 秒 × 100% の方は解釈がつく）。

    **外部情報（実機確認はできないが構造の手がかり。2026-09-09 にユーザーから共有）**
    - 発動確率の 3 段階（低 37 / 中 46 / 高 55%、‰ の整数）は、コミュニティが公開しているマスターデータでも同じ値。**カードの基礎発動率**はこれで裏づけがある（ただしゲーム内に数値表示がないので「実機確定」ではない）。青ボードの 2 種の効果も「発動確率 UP（‰ 加算）」「クールタイム短縮（‰）」という別の効果種別として持たれている。**確定するのは効果の種別と値だけで、スコアボーナス欄がそれをどう換算するかは別問題**。
    - ゲームのサーバー応答では、スコアボーナスが**カテゴリごとの独立した値（‰ の整数）**として返る。カテゴリは アクティブ / リーダー（衣装）/ パッシブ / スキルツリー（ホロメンボード）/ スペシャル の **5 つ**。つまり現在の実装（タイムラインの差分をボード欄・パッシブ欄へ配賦する）は**サーバー側の構造の再現ではなく近似的な帰属モデル**。表示が 4 欄なのは実機 20 ケースで衣装（リーダー）由来が 0 だったからで、源が 4 種類しかないわけではない。
    - **次の逆解析対象はこの 2 カテゴリの算出式**: スキルツリー（ホロメンボード）欄 と パッシブ欄。
