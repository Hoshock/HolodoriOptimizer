4. **3 欄（衣装 / ボード / パッシブ）の配分の重み `w_i`**
   - **未解決なのは `w_i` の形だけ。** 決まったこと（位相・総量・対象選抜・`W_C ∝ 支援 %`）は
     [display-score.md](../../human/display-score.md)「量子化」が正典なのでここで繰り返さない。観測は
     [repro/display-score-20260915-costume.md](../../human/repro/display-score-20260915-costume.md)、
     固定は `displayScoreCostumeQuantization.test.ts`。
   - 表示の重みは `W = Σ (支援%/100) × w_i`。**production の `w_i`（競合で正規化した取り分）は 12 編成中 9 で外れる。**
     自由係数なしの候補の一致数: 取り分 3 / 発動確率 4 / 一様 4 / スコアUP% 3 / `up × p0` 2。
     棄却済みなので作り直さない: 定数倍 `k × ΔP` / メンバーごとの `g(s)` / `ΔP`・`ΔP/A` の単調関数 /
     逐次 marginal・単独・Shapley（カーネルが静的倍率に厳密線形なので各 source の寄与へ戻る）/
     競合の分母に静的倍率を入れたカーネル。
   - **`w_i` はタイムライン上の寄与よりずっと平ら。** 6 枚プール（ロボ子 / ポルカ / リス / 奏 / スバル / アーニャ）では
     カードごとに固定の重みが過剰決定で成立し、周期 34 秒の リス / スバル が決定的（取り分 0.87 / 0.84 に対し
     実機は ≥ 1.02 / ≥ 0.98）。
   - **次の観測**: 支援を受ける 2 人を固定して残りを入れ替える対比でプールを広げる。いまのプールは
     発動確率と発動周期が交絡していて、**`w_i` が発動確率で決まるのか周期で決まるのかを分けられない**。
     崩すには**同じタイプ・ほぼ同じ周期で発動確率だけ違うペア** — 白銀ノエル 2凸（キュート / high / 21 秒）と
     アキ・ローゼンタール（キュート / medium / 21 秒）、大空スバル（high / 34 秒）と 白上フブキ 2凸（medium / 35 秒）。
     どちらもハッピーではないので supported pair は動かない。編成候補と手順は repro の「次に要る観測」「解析の手順」。
     （**発動確率 `low` のカードは 73 枚に 1 枚もない**。2026-09-15 に「低確率のカードを足す」と書いたのは誤りで取り下げた。）
   - **`f` を出すときは `A` の量子化ぶれを必ず入れる。** モデルの `A` は表示値を 16/16 で再現するが 0.1% 切り上げぶんの
     ぶれが残り、それは要求区間の幅と同じ桁。これを忘れて「位相は 1 通り」「S2 → S3 で向きが逆」と書き、両方取り下げた。
   - コーパス 153 列は位相にも重みにも使えない（青・赤入りで raw 自体が合っていない）。
   - **production は当面 現行のまま**（位相だけ直すと配分が逆向きに崩れる。`displayScore.ts` の `finishDisplay` に

## 実ライブ・イベント

8. **イベントスコアボーナスの適用位置**
9. **実ライブスコアエンジン**
   - **「ユニットスコアが高い編成ほどライブの点数も高い」は成り立たない**（2026-09-16）。表示ユニットスコアに曲の長さが入らないことは実機確認済み（`docs/human/game-spec.md`）で、ライブ側は曲長・ノーツで決まるため、順位が一致する理由がない。
   - **いまツールが勧める手順（ユニットスコア最大の編成を選ぶ → その編成で発動頻度を最適化）はライブ期待値の最大にならない。** モデル上の反例: 所持 34 枚・リーダー ミオ固定の全 248,946 編成で、`総合力 × (1 + 期待スコア UP の時間平均/100)` を代理指標にすると、ユニットスコア 1 位の編成はライブ 23 位（頻度を最適化し直しても 573,670 対 582,882 で 1.6% 負ける）。逆にライブ 1 位の編成はユニットスコア 10 位。近似としては悪くない（上位 0.01%）が最適ではない。
   - 代理指標そのものが未検証（ライブスコア = 総合力 × (1 + スコア UP) という仮定。判定・コンボ・ノーツ数・SP の扱いを含まない）。**編成探索をライブ目的で行う機能は未実装**で、入れるなら実機のライブスコア観測が先。
