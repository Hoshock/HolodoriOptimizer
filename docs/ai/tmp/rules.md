# 未整理のルール候補（induction 記録先）

housekeep 時に必ず昇格・整理される。書き方は induction スキルを参照。

## Rules

- 詳細な最適化条件（曲指定・ボード補正などの高度な設定）は、指定しなくても既定で意味のある結果が出るようにし、指定はオプションの置き場に隔離する（2026-09-01「これらは詳細な最適化なので、普段は指定しなくて済むように」。「遊び機能は操作の単純さ優先」と同系の一般化）。想定 glob: `src/**/*.vue`

- 見出しに括弧の状態注記・言い訳（「（登録済み n 枚）」「（おまかせでもOK）」等）を付けない（2026-09-01「ださい」— 4 例まとめて否定されたため規則扱い）。件数はコントロール内の値（ラベル左・値右の設定行パターン）として置き、任意項目は「未入力+でも OK」でなく既定値「おまかせ」を実値として表示する。想定 glob: `src/**/*.vue`

## Cases

- 2026-09-01 最適化 UI: 「全カード / 持っているカード」のページ内タブを統合して 1 フローにし、所持カード選択と除外選択はオプションのステップへ移す指示（除外は所持状態と独立に可能にする）。読み取れる好み: モードのタブ分岐より「1 フロー+オプションで絞る」構成。
- 2026-09-01: `.vscode/`（エディタ設定）は「使わないので不要」と指示され削除。読み取れる好み: 使っていないエディタ固有の設定ファイルをリポジトリに置かない。
- 2026-09-01 最適化 UI: オン/オフの切替は「チェックボタンは味気ないので、選択したら色が変わるボタンみたいなのがいい」。読み取れる好み: チェックボックスよりトグル型ボタン（選択状態を背景色で示す）。
- 2026-09-01 最適化 UI: 全カード探索中の所持リスト変更不可は「モーダル内で全カードをグレーアウト」で実装したが、「カードを選ぶボタン自体を disabled にするべき」と訂正された。読み取れる好み: 使えない操作は入口（ボタン）の段階で disabled にし、開けるのに何もできないモーダルを作らない。リストは localStorage に保持。
- 2026-09-01 最適化 UI: 「カードを選ぶ」（動作ボタン）と「全カード」（トグル）を同形で並べたら「わかりにくい」と指摘。読み取れる好み: 押すと何かが起きるボタンと、状態を切り替えるボタンを同じ見た目で混在させない。状態の選択は選択肢が全部見える形（セグメンテッドコントロール等）で示す。
- 2026-09-01 最適化 UI: メンバー枠 5 つが任意の順（1 と 5 だけ等）で埋められたのを「上からしか選択できないように disabled にするべき」と指摘。読み取れる好み: 同種の連続スロットは先頭の空き枠だけ有効にし、順序に意味がない入力に飛び石の自由度を与えない（解除時は上へ詰める）。
- 2026-09-01 詳細モーダル: 「表は見やすいか、視線の順的にも」とプロ視点の再点検を要求される（セグメント化の指摘に続き 2 回目）。読み取れる示唆: 数値の表は (a) 1 列に絶対値と % を混在させない、(b) 内訳は足すと合計に一致する形で見せる、(c) 表同士の親子関係（どの数字の内訳か）を見出しと合計行で明示する。
