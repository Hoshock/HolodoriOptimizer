# 未整理のルール候補（induction 記録先）

housekeep 時に必ず昇格・整理される。書き方は induction スキルを参照。

## Rules

- コミット・push は変更内容への明示的な承認（UI 変更はサンプル画像の承認）を得てから行う。承認を仰いだ時点では push しない。承認前の変更は stash に退避して Stop hook の強制コミットを避ける（2026-09-01 ユーザー指示「pushはせず承認を仰ぐこと」）。

## Cases

- 2026-09-01 モーダル: タイトルがメイン画面の旧ステップ文面（「〜を選ぶ」等）のまま残っていたのを「練り直したほうがいい」と指摘。読み取れる好み: 選択モーダルのタイトルは、対応するメイン画面の見出しと同じ名詞ラベルにする（本体の文言を変えたら派生画面も同じターンで追随させる）。
- 2026-09-01 詳細モーダル: メンバーの個別パラメータ 3 値を「なくていい。メンバーを選ぶときのモーダルにはないよね」と削除指示。読み取れる好み: 同じカードを見せる画面同士（選択モーダルと詳細）で情報の粒度を揃え、片方にだけ細かい数値を出さない。
- 2026-09-01 さがす: 「表示する候補数 [数値入力] 件」を「ださい」と指摘。Max 100 が伝わらない点も指摘し、10 件単位のページネーションを提案。読み取れる好み: 表示件数のようなプレゼンテーション都合の設定を実行前のフォーム入力で聞かない（結果側の逐次表示で解決する）。入力の上限・制約は注記テキストでなく UI の構造そのもので伝える。
- 2026-09-01 結果一覧: 行右の「詳細 ›」の文字を「ださい」と指摘。続けてシェブロン単独も「いるか？全体がタップできる感を出したい」と却下。読み取れる好み: タップ可能の手掛かりは誘導テキスト・記号でなく、行全体の押下フィードバック（:active の背景変化）等の構造で示す。
- 2026-09-01 ピッカーモーダル: 「タップで除外 ⇄ 解除（除外中 n 枚）」等のヒント行を「タップで云々とかいう文字列があるのもださい」と指摘。読み取れる好み: 操作方法の説明文（「タップで〜」）を UI に置かない。件数はヘッダ等の値として残す。
- 2026-09-01 開花（凸）: 表示アイコンはユーザー指定で「花びらの輪郭+段階の数字」（`SkillIcon.vue` の kind="bloom"。正円の代わりに花の輪郭が枠を兼ねる）。ゲーム用語は「開花」を使う。housekeep 時に ui-design.md のアイコン節へ統合する。
- 2026-09-01 選択モーダルの操作性(ユーザー要望): 複数選択ピッカー(所持・除外)には状態フィルター「すべて | 登録済み/除外中」を追加(既定はすべて)し、絞り込み(検索・所属・タイプ・状態)は閉じても保持して次回復元(モーダル種別ごとに独立、ページ再読み込みでリセット)。単一選択(リーダー・メンバー・曲)は選択中の項目を開いた瞬間にリスト先頭へ 1 回だけフィーチャーする(開いている間は並びを動かさない)。housekeep 時に ui-design.md へ昇格候補。
- 2026-09-01 開花の設定 UI: ステップ 1 に置いた一律開花セグメントを「不要。全カードのときは開花は 0 で計算する」と却下。読み取れる好み: モード全体に効くグローバルな詳細設定を増やさず、既定値（0凸）固定でよいものは UI を置かない。カード個別の値はそのカードを扱うモーダル内でだけ設定する。
- 2026-09-01 開花アイコンの表示: 「0凸も常に表示する」と指定。読み取れる好み: 計算の前提になっている値は既定値でも省略せず、常に見える形にする（>0 のときだけ出す出し分けをしない）。
- 2026-09-01 結果一覧のアイコン列: 「開花以外のアイコンがある時開花アイコンが縦にズレるの嫌。開花は一番右で、左にピン」と指摘。読み取れる好み: 同種のアイコンは全行で同じ列（縦の線）に置き、常に出るものを最右の固定列、条件つきのものをその左にする。
- 2026-09-01 結果一覧のリーダー: 「リーダーはアイコンじゃなくて UI 的にメンバーじゃないように見せたい」→ 王冠アイコンを廃止しリーダー行だけ面（バンド）で区別。タイプ淡色の面にしたら「他は文字色でタイプ指定してるのに」と却下され、無彩色（--bg）の面+タイプは文字色のまま、に修正。さらに「リーダーは開花とか関係ないのでアイコン出したくない。開花の列に衣装アイコンにしよう」→ 一度ピンの列へ移したが「リーダーをピンすることもある」で最右(開花)の列に確定。リーダー指定で実行したときはリーダー行にもピンを出す。読み取れる好み: 役割の違いはアイコンの付加でなく構造（地の違い）で示す。同じ属性（タイプ）の表現方法を 1 つの画面の中で混在させない。計算に関係しない値のアイコンをその枠に出さない（リーダー枠に開花は無関係）。
