## Cases

- 2026-09-06 OptimizerPanel: 「ステップ 2（除外するカード）は 1 に統合し、除外するカードを選ぶボタンにする」→ Step 1「さがす対象」のセグメントの下に「除外するカード n枚」の行ボタンを置き、以降のステップを 2〜5 に繰り上げた。読み取れる好み: 除外は探索プールを狭める操作なので「さがす対象」と同じ意味単位に属する — 意味的に同じ設定は別ステップに分けず 1 つのパネルにまとめる。
- 2026-09-06 BoardSheet: 「ホロメンボードは（青）をヘッダにつける」→ モーダル見出しを「ホロメンボード（青）」に。読み取れる好み: 同名の別種（青・緑・赤）があるものは、現在 1 種しか扱っていなくても見出しで種類を明示する。
- 2026-09-06 UI 確認: 1280px のスクリーンショットを出したら「なぜスクショがモバイルじゃないの？」。ブラウザを `close` → `open` で開き直すとビューポートが既定に戻るので、開き直しのたびに `resize 390 844` をやり直す必要がある（ui-verification.md の 390px ルールの運用上の落とし穴）。読み取れる好み: ユーザーに見せる確認画像はモバイル幅のみ。
- 2026-09-06 さがす対象の相談: 「持っているカードの中で最強編成にするにはどうするかを知りたいときは、既存のホロメンボードも開花も考慮しないほうがよい。今は実現不可だが将来の編成に向けて育てるために使う」。読み取れる好み: 探索には「いま組める最強」と「将来に向けて育てる目標」の 2 つの用途があり、将来向けの探索では現在の育成状態（開花・ボード）を入れない — 育成度の差で順位が歪むのを避ける。決定（同日）: 全カードではボード・開花を考慮しない。持っているカードでは Step 5 の「オプション」（普段は畳む）で「ボード状況を考慮する / 開花状況を考慮する / 衣装スキルが発動する / パッシブスキルが全員発動する」の順に 4 件を選べる。読み取れる好み: 補助的な設定は初期表示から隠し、主導線（さがすボタン）を短く保つ。
- 2026-09-06 Step 5 オプション: 全カード時にボード・開花のチップを「選択中の濃色地のまま減光」で出したら「未選択で disabled の方が直感的。持っているカードに変えたら disabled を外し既定は両選択。外した選択は画面更新しても保持、ただし全カードに切り替えたら白に戻る」。読み取れる好み: 2026-09-05 の「効かない設定は見た目を保って disabled」（6 枠固定のしぼりこみ）と使い分ける — そのモードでは意味を持たない設定（全カードでの育成の反映）は未選択に見せ、一時的に効かないだけの設定（6 枠固定の発動条件）は見た目を保つ。保存値はどちらも保持する。
- 2026-09-06 UI 確認の落とし穴: テンプレート（`<template>`）の変更が dev サーバの HMR で反映されず、スクリプト部だけ更新された古い描画を撮って出してしまった（ユーザーに同じ指摘を 2 回させた）。撮る前に `curl` で配信中の `.vue` モジュールの該当バインディングを grep して確認し、古ければ dev サーバを `--force` で再起動する。`pkill -f vite` は自分のシェルも殺す（`vp dev` と同じ）。→ ui-verification.md の備考へ。
- 2026-09-06 Step 5 オプションの文言: 指定文言のまま縦 1 列で出したら「2 行に収められない？」「自動詞と他動詞とか文体の統一も」。→ 2 列 × 2 行の等幅グリッドにし、4 件をすべて「ツールが主語の他動詞文」に揃えた（「ボード状況を考慮する / 開花状況を考慮する / 衣装スキル発動に限る / パッシブ全員発動に限る」。「衣装スキルが発動する」はスキルが主語の自動詞で不揃いだった）。読み取れる好み: 並ぶ選択肢のラベルは主語と構文を揃える。
