# 未整理のルール候補（induction 記録先）

housekeep 時に必ず昇格・整理される。書き方は induction スキルを参照。

## Rules

- 一覧（カードピッカーのリーダー・メンバー）はあいうえお順（読み）で並べる。同じホロメンのカードはカード名（サブタイトル）の読みであいうえお順。文字コード順（英字→カナ→かな→漢字）は不可（2026-09-05 ユーザー指示。想定 glob: `src/components/**`, `src/ui/**`）。
- 読みは `holomen.json` / `cards.json` の `reading` にひらがなで手入力し、並び順・検索にだけ使う（表示しない）。英字はカタカナ読みをひらがなにする。長音「ー」は比較時に直前の母音へ正規化（想定 glob: `src/data/**`）。

- 一覧の部品（カードタイルなど）の高さは内容量で変えない — 1 行でも 3 行でも同じ高さ。複数行の文章は最大行数（効果テキストは 3 行）ぶんの固定高にそろえ、短い文は余白で埋める。複数行の文章を動かす（縦送り）のは不可（「きもすぎる」）。動かしてよいのは 1 行固定の曲名・アーティストの横スクロールだけ（2026-09-05 ユーザー指示。想定 glob: `src/components/**`）。
- 固定高で行数を増やすときは行方向の余白（行間・行同士の隙間・名前との間）を詰めて、部品全体を伸ばしすぎない（2026-09-05 ユーザー指示「少し行方向の余白を減らせ」。想定 glob: `src/components/**`）。
- はみ出しの判定は部品が置かれた場所ごとに実測する。ピッカー（シート）とメイン画面では幅が違うので、同じ文言でも一方だけ動くことがある（2026-09-05 ユーザー注意。想定 glob: `src/components/**`）。

- 同じ対象（メンバーカード・リーダーカード・曲）はメイン画面とピッカーで同じ部品を使い、幅・高さを一致させる（別部品で似せない — UnitSlot と CardTile の二重実装は却下）。メイン画面の横幅はピッカーのシートに合わせ、ステップをカード（パネル）で囲んで幅を狭めない。メイン画面は元のパネル（白いカード、ページ左右 16px + 内余白 16px）が基準。ピッカーは白い 1 枚のシート（ヘッダ → 絞り込み → 一覧、左右 16px）で、カードの入れ子や内側スクロールにしない。部品の一致は「同じ部品・同じ固定高」で担保し、幅はそれぞれの置き場に従う（メイン 324 / ピッカー 358 @390px）— 幅まで揃えるための全幅の白い帯・左右 8px の角丸ブロック・ピッカーのカードスタイルはすべて却下（「びみょう」「キモすぎるしわかりにくすぎる」） — 罫線だけの区切りは「余白の背景色も同じだと分からない」で却下。順番は番号バッジで示す（2026-09-05 ユーザー指示。想定 glob: `src/components/**`, `src/App.vue`）。
- 効果テキストは 2 行固定高で、3 行にしない・動かさない（原文は基本 2 行に収まる。収まらない例外は省略記号）。行同士の隙間は詰める（「SP と A と P の行間が空きすぎ」）。2026-09-05 に 3 行案・縦送り案の両方を経て確定（想定 glob: `src/components/**`）。
- はみ出すテキストは動かさない — 1 行テキストは省略記号、複数行は行数固定の省略記号。スクロール表示（往復 → 巻き戻し → 看板型と 3 形態）は最終的に「アニメーションバグってるからやめよ」で廃止（2026-09-05。想定 glob: `src/components/**`）。
- 結果一覧のホロメン名とサブタイトル（カード名）は隣接を意識して行間を詰め、ホロメン同士の間隔は保つ（2026-09-05 ユーザー指示。想定 glob: `src/components/Result*.vue`）。

- ピッカー（選択モーダル）にはヘッダ（タイトル・右上の ✕）を置かない。上から絞り込み → 一覧。単一選択（リーダー・メンバー・曲）は項目をタップした時点で完了なのでボタンも置かない。複数選択（除外・所持）だけ下に全幅の「完了」を置き、枚数は添えない（件数はメイン画面の行ボタンにある）（2026-09-05 ユーザー指示 2 往復。ui-design.md の「モーダルのタイトルはメイン見出しと同じ」「画面のヘッダはページヘッダと同寸」はピッカーには適用されなくなる。想定 glob: `src/components/*Picker.vue`）。

## Cases

- 2026-09-05 ピッカーを開くとヘッダの高さが変わる（60px → ページは 77px）のを「キモい」と指摘。既存規則（画面のヘッダはページヘッダと同寸法・同文字サイズ）の未遵守だった → sheet-head を 16px 余白・24px/900 の見出し・下罫線にして一致。教訓: 規則があっても実測していなかった。ヘッダ高さは playwright の boundingBox で両画面を比べる。

- 2026-09-05 ステッパー化したメイン画面で、罫線+短い接続線+上下 20/24px の余白に対し「ステップ間の白余白はないと見づらい気が」→ 余白を広げたが「余白の背景色も同じだと分からない」→ 白い帯 → 角丸ブロック（左右 8px）→「びみょう。最初のステップごとの余白の方が良かった」で元のパネルに戻し、ピッカー側をカードスタイルに揃えた。ピッカーをカードスタイル（地色 + 絞り込みカード + 一覧カード）にしたところ「キモすぎるしわかりにくすぎる。メインはいい」→ ピッカーを元の白い 1 枚のシートに戻し、幅の一致は諦めた。読み取れる好み: 画面の構造は単純に（入れ子カード・内側スクロール不可）。同じ部品なら幅の差より単純さを優先する。

- 2026-09-05 カードタイルの効果テキスト: 2 行クランプで末尾が「…」になるカード（戌神ころね「密林を舞うワイルドサマー！」の衣装スキル 52 字）をユーザーが指摘。3 行まで伸ばす案は「高さが変わるのは嫌」、2 行固定高で縦に送る案は「きもすぎる」と差し戻し → 全カードを 3 行ぶんの固定高にしたが、push 後に「メイン画面で 3 行になっていない（UnitSlot が別実装）」「メンバーの効果は基本 2 行で収まるから 3 行はやめよう」と再差し戻し → 2 行固定・部品統一へ（Rules に昇格済み）。教訓: 同じ見た目を 2 つの部品で作っていると片方だけ直して齟齬が出る。UI 変更のスクショはピッカーだけでなくメイン画面も撮る。
- 2026-09-05 曲ピッカー・Step 5 の曲名・アーティストがはみ出す場合は、ユーザー指示で「ゆっくりスクロールするアニメーション」にし、収まっているときは動かさない（省略記号の静止表示ではなく全文が読めること）。効果テキストとは別の解決（1 行の固定高を守るため）。同日、往復（alternate）→「スクロールし切ったら速度上げて先頭に巻き戻し」→ 巻き戻しも「往復キモい」と 2 度差し戻し → 看板型（WAAPI）→ 実機で「バグってる」と最終的に廃止、省略記号に戻す（Rules に昇格済み）。教訓: 装飾的な動きは実機での見え方を確認できない限り入れない。
