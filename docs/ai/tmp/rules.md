## Cases

- 2026-09-07 OptimizerPanel 実行中の表示: 「検索中のバーの近くの文字は不要。検索中のステータスバーも不要。中止ボタンも不要。ボタンにスピナーにしよう。ださくないように」→ 進捗バー・件数テキスト・中止ボタンを撤去し、実行ボタンの色と寸法を保ったままラベルを白いリング（22px・2.5px 線）に置き換えた。読み取れる好み: 数秒で終わる処理の進捗は数値で見せず、押した場所（ボタン）の中だけで「動いている」ことを示す。中止のような使われない操作は置かない。
- 2026-09-07 ヘッダの入口: 「右上のガチャメニューのところにハンバーガーメニューにしよう。右からサイドバーが出て仮想ガチャのリンクを。ハンバーガーは開いている時は CSS でバッテンに。そこで閉じられるようにしつつ、サイドバーエリア外タッチでもしまえるように。GitHub のリンクもサイドバーに。リンクの左側にアイコン」→ `SideMenu.vue`（右からスライド・scrim・Escape）+ App.vue のハンバーガー（3 本線 → ✕ の CSS トランジション）。続けて「サイドバーはヘッダにかからない方がいい。ハンバーガーの同じ位置が閉じるボタンに変化するように。背景は少し透過させて。必要に応じて文字にはドロップシャドウ」「サイドバーを開けるのはメイン画面のみ。それ以外は右上は閉じるボタンのままでいい」→ サイドバーの上端をヘッダ下端に合わせ（開く瞬間に測る）、地は `color-mix` 82% + `backdrop-filter: blur`、文字に淡い text-shadow。ハンバーガーはメイン画面のヘッダにだけあり、ピッカー・ボードなどのモーダルは従来どおり右上の ✕。読み取れる好み: 本線の外の入口（遊び機能・外部リンク）はヘッダ右上のハンバーガー → サイドバーにまとめる。サイドバーは常時表示領域（ヘッダ）に掛けず、開閉の操作は同じ場所で形を変える（ハンバーガー ⇄ ✕）。透過の地はぼかしと文字の影で可読性を確保する。
- 2026-09-07 BoardSheet: 「青以外に赤、青、黄、緑も追加する可能性がある。切り替えられるように。デフォは青。ヘッダは『ホロメンボード』に。順番は左から赤、青、黄、緑」→ 見出しから「（青）」を外し、名前行の右に 4 色のセグメント（青以外は disabled）。続けて「色を変えたらボードの色も変わるように」→ 解放マスと接続線の色を選んだ色のトークン（`--board-red/blue/yellow/green`、黄の文字は濃色）で描く。読み取れる好み: ゲーム内で色の名前を持つものは、その色で描く（選択コントロール自体は濃色地の規則のまま）。将来の選択肢はタブとして先に置き、用意できていないものは disabled で見せる（Step 0 の「ユニット」と同種 2 回目）。
- 2026-09-07 ✕ の統一: 「ハンバーガーを押した時に変化したバッテンと、各ページのバッテンのサイズが違う。前者のサイズに全て合わせて」→ 文字の ✕（20px）をやめ、線 2 本の共通部品 `CloseButton.vue` を全モーダルで使う。読み取れる好み: 同じ意味の記号（閉じる）は画面をまたいで同じ形・同じ大きさにする。同じ形を複数箇所で描くなら部品にする。
- 2026-09-07 サイドメニュー第 2 弾: 「背景透過はもう少ししていい」「メイン画面のフッタのデータ確認日とか GitHub は削除」「おかゆんモードはサイドバーに移行。一番下、スクロールが入ったとしても一番下。最初は『絶対おかゆんモードをON』、ON のときは『絶対おかゆんモードをOFF』、アイコンは同じ」「仮想ガチャの上にカード一覧・曲一覧。押したらピッカーに飛び、選んだら詳細ページ（ステータス・リーダースキル・その他スキル・コネクト効果・各開花 / ノーツ・難易度・歌唱者・作曲者編曲者）。不明な情報はプレースホルダでいい」→ 地 66%、フッタは免責のみ、サイドメニューは上に一覧・遊び・リンク、最下部に固定した行でおかゆモード（ラベルが ON / OFF、おにぎりは同じ）、`CardDetail.vue` / `SongDetail.vue`（データにない項目は「未確認」）。読み取れる好み: 本線の外の入口はすべてサイドメニューに集約し、メイン画面のフッタは免責だけにする。モード切替のような常設の操作は一覧の下端に固定する。データがない項目は行ごと消さず「未確認」で残し、将来入る場所を見せておく。一覧 → 詳細の導線は既存のピッカー部品をそのまま使う。
- 2026-09-07 注記の置き場: カード詳細のパラメータ表の下に「レベル最大・2凸以上の本体値（…）」を置いたら「情報が途中にあると読みにくい。注釈はフッターに脚注形式で。全てのページを見直すこと」→ 共通スタイル `.footnotes` / `.fn`（src/style.css）を作り、カード詳細・ホロメンボード・結果詳細の注記を末尾の ※n に移して本文側は上付きの ※n で参照。読み取れる好み: 本文は値と見出しだけで読ませ、前提や断りは脚注に隔離する（2026-09-01 の「手順の説明文で UI を補わない」の注記版）。
- 2026-09-07 サイドメニュー第 3 弾: 「サイドバーやっぱ透過しないように。開いてる時に後ろ側が少し暗くなるのはとてもいい」→ 地を不透過に戻し scrim は維持。読み取れる好み: 透過・ぼかしは不要、モーダル感は背後の減光で出す。
- 2026-09-07 カード詳細の訂正: 「ヘッダはカード一覧でいい」「色付きのカードにタレント名とサブタイトルだけ。所属（フブキの 1期生とゲーマーズ）はピッカーの所属チップを小さくしてカードの下にタグとして左から並べる。カードの中の ID2期生などの文字は削除」「開花の『強化前: 未確認』は意味がわからない。未確認でいい」「コネクト効果が一番下」「リーダースキル（衣装）ではなく衣装スキル」「結果詳細のリーダー（衣装スキル）はリーダーとだけ」「脚注の 2 行目以降の左端が揃っていない」→ 見出しは一覧と同じ「カード一覧」、色つきカードは名前+サブタイトルのみ、所属は表示専用の小さなピル（24px・12px）を左から、順序はパラメータ → 衣装スキル → スキル → 開花 → コネクト効果、脚注は番号列を固定幅の 2 列に。読み取れる好み: 詳細シートの見出しは入口の一覧名で揃える（「選択モーダルのタイトルは対応する見出しと同じ」の詳細版）。所属のような分類はカードの中に文字で書かず、下にタグとして並べる（静的ラベルにチップを使わない規則の例外 — ユーザー指示）。見出しは短い名詞 1 語（衣装スキル / リーダー）にし、括弧の補足を付けない。
- 2026-09-07 結果詳細のヘッダ: 「1位の編成とかのヘッダ、他のヘッダと高さとかフォントサイズとか合ってる？」→ 結果詳細だけ padding 12px・h3 18px のままだった（規則はあったが新旧のシートを横断して実測していなかった）。全シートのヘッダ高を一括で boundingBox 実測して 77px に揃えた。読み取れる好み: 部品を共通化した直後は、同種の全画面を一括で実測する。「スコアの数字が青色（iPhone の Chrome）」→ 最初は電話番号検出と誤診して CSS の保険を足したが、ユーザーの「検索結果の一覧の 10 個出るところの数字」で場所が確定し、原因は iOS の `<button>` 既定文字色（システムの青）。結果一覧の行ボタンに色指定がなかった。`button { color: inherit }` を全体に当てて解決。読み取れる教訓: iOS 固有の見え方（button の既定色）は Linux の Chromium で再現しないので、`<button>` の中の文字は色を明示する。症状の場所が曖昧なら先に場所を確認する。
- 2026-09-07 ボードの左右型: 「左型、右型は廃止してデフォルトをこちらで指定する。赤は常に上、緑は常に下。青と黄の左右が入れ替わる。赤の左右エリア（ライフ系 / ステータス系）も入れ替わる」+ 全 54 名の表 → `holomen.json` に `board.blueSide` / `board.lifeSide` を追加し、BoardSheet はそこから左右を引く。保存済みの `mirrored` は読み飛ばし。読み取れる好み: ゲーム側で決まっている値はユーザーに選ばせず、データとして持つ（入力の手間と誤りをなくす）。想定 glob: `src/data/**`、`src/components/BoardSheet.vue`。
