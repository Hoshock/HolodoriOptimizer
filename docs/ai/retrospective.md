# ドキュメント保守のふりかえり

ドキュメントの保守の方針と、それを決めたフィードバック・問題の記録。作業の日誌ではなく、**次に同じ形で肥大・ずれを起こさないための決めごと**を置く。決めごとがスキル・ルール・CLAUDE.md へ昇格したら、ここからは消してそちらを正典にする。

## 方針(採用済み)

- **ADR の索引(`docs/adr/index.md`)には、いま効いている ADR だけを載せる。** Superseded / Deprecated は載せない(2026-10-10 ユーザー指示「adr の index.md は superseded なものは書かない」)。経緯は置き換えた ADR の冒頭と、旧 ADR の Status から辿る。
- **決定が変わったら新しい ADR を書き、旧 ADR を Superseded にする**(`adr-convention` の規定どおり)。決定を書き換える Update を足さない。同じ話題の Update がたまって今の決まりを読むのに複数の ADR が要るようになったら、1 本にまとめた ADR で置き換える(2026-10-10 に ADR-026・027 を ADR-028 にまとめた)。
- **1 つの決まりの本文は 1 か所に置き、ほかからは参照する**:
  - 決まりと理由 → ADR
  - 実装で壊しやすいところ・識別子との対応 → `.claude/rules/`(決まりの本文を再掲しない)
  - 画面の説明 → ⓘ(意味だけ)と脚注(細かい決まり・前提・断り)
  - コードのコメント → その場の仕組みと、正典の ADR 番号
- **脚注は、その脚注が説明する画面の部分に置く。** 組み直しプランは、※1 に推奨の値の前提と断り、※2 に開いているタブの中身のぶんだけ(ボードは選び方の決まり、コネクトは置き直す範囲、発動頻度は決め方とモデル)。長い脚注は段落に分ける(`.fn-para`)。
- **挙動を変えた同じ変更の中で、その言葉を使う置き場を横断で直す**: 脚注・ⓘ・使い方のページ・`.claude/rules/`・ADR・`pending.md`・コードの先頭コメント。`rg` で用語(例:「手間」「手前の 7 マス」「リソース」)を引いてから直す。

## 2026-10-10 に見つかった問題

ユーザー指示「発散し始めているすべての脚注、解説の整理、及びドキュメントの整理、info の整理も」を受けての棚卸しで見つかったもの。

- **ADR の追記で決定が変わり続けた**: ADR-026 は Update が 3 つで、うち 2 つが決定を変えていた。今の組み直しの決まりを知るのに ADR-026 本文と Update(1)〜(3)、ADR-027 と Update を全部読む必要があった。
- **索引に置き換え済みの ADR が残っていた**: 007・014・019〜021・025〜027 が「→ ADR-…」付きで並び、索引の半分近くが履歴だった。
- **同じ決まりを 6 か所に全文で書いていた**: ADR、`engine-structure.md`(1 つの箇条が約 6,000 字)、`ui-flow.md` の「最小限で組み直す」の説明、`boardOptimize.ts` の先頭コメント、組み直しプランの脚注 ※1、`pending.md` 8。変えるたびに全部を直す必要があり、直し漏れでずれた。
- **画面の説明のずれ**: アカウントの ⓘ の「リソース」が、ボードで開けると減る変更のあとも「組み直すときにだけ使う」のままだった。ボードのシートの脚注に、使うようになったキューブの断りがなかった。「最小限で組み直す」の ⓘ が、リーダー・メンバーの緑を組み直すことに触れていなかった。
- **脚注 ※1 が 1 段落の壁になった**: ボードの決まり・コネクトの範囲・前提・断りを、どのタブを開いていても全部出していた。

## 肥大を防ぐための更新の提案(判断待ち)

| 置き場             | 足す決めごと                                                                                                                                                                                                                                                                                                             |
| :----------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `adr-convention`   | 索引は Accepted だけ(Superseded / Deprecated は外す)。決定を変える Update は書かず新 ADR に。同じ話題の Update が 2 つを超えたら、まとめた新 ADR で置き換える                                                                                                                                                            |
| `rules-convention` | ルールの 1 箇条の目安(例: 800 字)。超えるなら決まりの本文は ADR へ移し、ルールには識別子との対応と壊しやすいところだけを残す。ADR の決定本文を再掲しない。1 ファイルの目安(例: 20,000 字。いまは `ui-flow.md` 約 55,000 字・`ui-parts.md` 約 52,000 字・`ui-design.md` 約 31,000 字・`engine-structure.md` 約 30,000 字) |
| `housekeep`        | 棚卸しの点検項目に足す: 索引の Superseded、Update が 2 つ以上の ADR、目安を超えたルールの箇条・ファイル、同じ決まりを全文で書いている置き場(ADR・ルール・脚注・ⓘ・コメント)                                                                                                                                              |
| `CLAUDE.md`        | 「知識の置き場」の下に 1 行: 同じ決まりを複数の置き場に全文で書かず、正典(ADR / ルール / 脚注・ⓘ)から参照する                                                                                                                                                                                                            |
| `ui-design.md`     | 脚注の項に: 脚注はその脚注が説明する部分(タブ)に置き、長いものは段落に分ける                                                                                                                                                                                                                                             |

ルールのファイルの分割(`ui-flow.md` を組み直しプランとメイン画面に分けるなど)は、`paths:` で読み込む範囲が変わるので、目安を決めてから別に検討する。
